# 财报三表字段关系与紧凑展示研发方案

> 文档职责：反馈 #36 专项研发合同；证券分析原方案第15节为项目入口，本文件承载该专项唯一详细设计及逐字段核查清单。基线：`1d2aef06997fecc36bbd900add9496606e38f5dc`，规则 SHA `e9b11dd9bf0dcab379a20cc79b4720eaad2eb672`。截至 2026-11-16：设计中，代码未实施、未部署、反馈未回写；下述来源核验范围不等于生产数据或页面验收。

## 1. 用户目标与已核验结论

A 股/港股全部已支持财报类型的资产负债表、利润表、现金流量表应呈现可追溯、正确的层次，修复 #36 的 8 个现象；压缩行距，在同屏显示更多信息，并保证桌面、手机可读。原始数值、范围、币种、报告身份、比较口径和既有权限不变。

11 个类型的三个字段目录与布局目录按代码逐条关联共 **2,243 条类型-报表-字段记录**（相同代码跨类型重复）；191 条来源标记“其中”，其中当前程序为 32 条返回非空父字段、159 条无父字段。这个统计只证明程序输出，不证明 32 条正确或其余 159 条都应强制成树：例如当前现金流中部分父项确实挂错。其余 2,052 条无“其中”也可能是结构项、汇总项、计算指标或明细，不能按无前缀就断定其关系。33 组数量及逐条范围见第 8、9 节。

本次通过[理杏仁 A 股非金融三表字段文档](https://www.lixinger.com/api/open-api/html-doc/cn/company/fs/non_financial)对 **30 条来源标记“其中”项目**核验了具体来源列报关系，并分别对[港股非金融](https://www.lixinger.com/api/open-api/html-doc/hk/company/fs/non_financial) 15 条、[A 股其他金融](https://www.lixinger.com/api/open-api/html-doc/cn/company/fs/other_financial) 7 条、[港股其他金融](https://www.lixinger.com/api/open-api/html-doc/hk/company/fs/other_financial) 8 条、[A 股证券](https://www.lixinger.com/api/open-api/html-doc/cn/company/fs/security) 20 条、[A 股保险](https://www.lixinger.com/api/open-api/html-doc/cn/company/fs/insurance) 15 条进行了来源关系核验；其中存货、无形资产、开发支出与数据资源、利润归属、现金流融资项目又对照了[海澜之家 2025 年报](https://static.cninfo.com.cn/finalpage/2026-03-28/1225042739.PDF)的合并报表。来源和年报并不是所有类型和历史期间的通用合同。另有 **12 条**仅获平安银行 2025 年报样本支持、来源口径待核，**84 条“其中”记录**、所有非“其中”记录的具体关系以及其他发行人、历史期，尚未逐项取得同等原文证据；第 9 节逐条显示为待核验。**这是可执行方案和有限范围核验，不是 2,243 条关系全部确认。**

### 2.4 银行样本复核：贷款质量不能按相邻行直接挂父项

[平安银行 2025 年年度报告](https://static.cninfo.com.cn/finalpage/2026-03-21/1225022887.PDF)第 36 页贷款五级分类，将正常、关注、不良分项列在贷款和垫款本金总额分类中，并将次级、可疑、损失列为不良贷款的细分；贷款减值准备是紧随本金总额的独立调整项。逾期贷款、重组贷款和五级分类可能是交叉维度，不能凭排列把它们都当作同一层互斥明细。对应样本的 `bs.p_pf/sm_pf/npl`、`bs.s_npl/d_npl/l_npl` 已在第 9 节标记“发行人样本”，不以此推定其他银行、报告期及理杏仁来源均具有完全相同口径。

[平安银行财务报表附注](https://static.cninfo.com.cn/finalpage/2026-03-21/1225022889.PDF)第 49 页列现金及存放中央银行款项的组成，第 99—100 页列利息、手续费的收入与支出和净额；支持 `bs.c/bwcb` 以及 `ps.ii/ie/faci/face` 的样本层次。净额的收入和支出是相减关系，不应按“子项全部相加”实现；来源字段是否具有相同币种、期间、净额定义仍须独立核对。

## 4. 字段关系合同与研发步骤

1. 以现有 11 个来源文档快照中 `市场/财报类型/三表/代码` 为全集，给每条建立唯一记录；增加关系角色 `section`（纯组）、`line`（数值）、`detail`（其中）、`result`（计算结果）、`supplement`（附注/指标）及 `unknown`，关系类别区分“包含/其中”“加减形成”“展示分组”“比较/附注”，不可将关系全部简化成可相加父子。
2. 每条关系标来源 URL、定位/原文版本或报告页、准则、类型和报告期适用范围、复核日期、状态；仅有标题/前缀、找不到父项、来源冲突或历史类型未知为 `unverified`，不猜。以来源与发行人报告对照，结果不一致时展示来源项目、注明差异并待核实；保持证据与用户授权范围。
3. 对已经在第 2 节核验的关系，**先按上述已核验来源类型**落受控声明，其他类型按第 9 节逐项验证后登记。净利润的持续性和所有权归属在概念层分别分组，不能把两个维度的数直接加起来；加减符号不从数值符号推导，也不隐式改变其数值。
4. 用独立版本的展示元数据扩展现有字典/领域模块；每一记录的身份还须包含准则和有效期或明确“不明”，而非只用字段代码。检查孤儿、环、同维度重复和冲突；未知类型、父项缺失或无证据时保留真实数据和原标签，显示适当说明，不编造数值。先构造完整结构，再按已有可用/缺失状态过滤；父项无值时可以作为无金额的**结构标题**保留或安全提升子项，但不得造同名数值行。
5. 混合多个报告类型/期间时，只在关系一致时共享一行元数据；不一致则按类型或报告列清晰分组，不能由 `byCode` 第一条覆盖其他期。 保留旧客户端 `section/level/parent` 语义，新增层级、关系及可访问状态前先核对消费者；设计版本进入现有版本摘要/缓存策略，并核对 A 股旧参数、港股 `analysis_version` 与 409 有界重读。
6. 逐一修改资产/负债、利润、现金流的已证实关系；非报表指标单独归组，保留原字段、数值、单位及来源说明。对所有未确认项采用安全平级/原顺序与可见状态，不因视觉紧凑隐藏数据或误称已完成核验。

## 5. 三表 UI 重新设计（2026-11-16，待实施）

### 5.1 设计依据及现状

目标是同屏看到更多**完整数据行**，同时让报告期、固定表头及科目层次始终易辨认。沿用本项目“上市可转债”业务表格样式、配色和现有三表接口；以下是设计合同，不代表页面已修改或视觉验证通过。

GitHub 参考只用于交互与视觉方案，不引入其依赖或将其科目映射、会计数据照搬到本站：

- [RoboSystems StatementTable](https://github.com/RoboFinSystems/robosystems-report-components/blob/60ee3e26d26b4b3af7023bea8a3dfd5383d862cb/src/components/StatementTable.tsx)：按深度缩进、对小计加粗和分界线、数字等宽右对齐；启发本站将“层级”和“总计”分别表达，具体关系仍以本方案第 2/4/9 节证据为准。
- [BeanDesk BalanceSheet](https://github.com/SuperDaniel-cn/BeanDesk/blob/c9b7249a55dffa9e33f9dbe247fd765120cdf8bf/web/src/pages/BalanceSheet.tsx)：递归展开层次并对可展开项标注无障碍状态；启发本站按真实父子关系表达，不把任意相邻行当作父子。该项目为个人账簿报表，其科目结构不代表本站上市公司财报。
- [TanStack Table 固定列示例](https://github.com/TanStack/table/blob/564a459b74834c77631e0d6fdba7661383bbc1b4/examples/react/column-pinning-sticky/src/main.tsx)：固定列的宽度、偏移、层叠次序需要一致；[分组表头与固定列问题](https://github.com/TanStack/table/issues/5397)显示这类组合可能错位，作为本站反例来源，而非表明本站已复现同一缺陷。

当前 View 每期绘制“原值＋比较”两列、两层表头，`compare=none` 仍绘制空比较列；字段每行单位另起一行；局部 CSS 单元格 `padding:10px 12px`，首列最小 190px、整表最小 1100px；共享 `.biz-table th` 还设置 52px 高度，首列正文使用 `th`，因而单改 padding 不足以确保行高真正变紧凑。`BusinessTable` 已按导航底边计算顶部位置，并克隆 `thead` 实现浮动表头和横向滚动同步；它会新建只带共享类名的浮动表，逐个同步 `th` 宽度。**多层 `rowspan/colspan`、不同列数、固定首列及定制样式能否始终同步尚未实测**，不能把已有 `sticky:true` 当作本次吸顶验收通过。

以上仅为布局示意：金额示例来自海澜之家 2025 年报的合并资产负债表，单位在示意中由原始元折算为**百万元**；同比数仅按示例两期算术演示，不代表当前系统已输出或可比较。实际页面必须按已验证的报告币种、单位、比较状态及服务返回值展示，不能将示例数据用于真实页面。标题、报告期及报告范围来源于当前响应；一组报告期显示为一组表头，日期/年报/中报/币种不明确时显式标注，不用年份掩盖实际期末。

视觉规则：

1. **分组**用浅中性色底、边界线及清晰名称；若有同名且有值的总计行，合并成一个有值行，不再额外插空分组。无真实值的结构标题可展示，但不得伪造数值。
2. **总计/小计**用字重和细上边线区分，数值仍与同一列对齐；普通行不加粗。财务金额的正负不套涨跌含义，负号必须保留，颜色不作为唯一标识。
3. **层级**由可信 `level/parent` 生成：顶级、一级、二级及更深层分别使用 0/12/24/36px 的缩进；四级以上可按深度继续缩进，但不能把名称挤出可用宽度。保留“其中”文本，必要时加细竖向导向线；未核验父子关系保持安全平级并可查看原因，不靠外观暗示已确认。
4. **密度**以桌面正文 13px、行高约 28—32px、纵向内边距 4—6px、横向 8px 为首版目标；数值使用等宽数字、右对齐。在共享矩阵紧凑变体中同时处理从 `.biz-table th` 继承的 52px 高度及当前 10px 纵向 padding，确保表头/正文约束各自独立；单位尽量与名称同行，特殊单位、长名称可正常换行。目标是增加可见完整行数，不以截断字段、隐藏单位或缩小精度换取数量。
5. **列**以报告期为组，默认原值及当前已选比较指标；“不比较”时只显示原值一列，不留空比较列。切换列数后重新计算表头跨列、首列与滚动宽度；来源缺失显示 `—` 和可触达原因，真实 0 不被隐藏。全部口径下每期保留实际合并/母公司标识。金额、比较、0、负数、缺失及币种遵循原有数据合同。

### 5.3 表头吸顶、首列固定与滚动合同

- 页面正常纵向滚动到表头离开视口时，**完整两层表头**贴在实际可见的全站顶栏/二级导航下方；滚出表格底部后自动消失，不能遮住后续内容。顶部占位按现有 `BusinessTable.stickyTop` 和实际可见导航测量，不写死一个设备高度。
- 横向滚动仅发生在表格容器；报告期分组及其原值/比较列与正文始终同一列宽及滚动位置，滚动条、表头和正文相互同步。左侧科目列同时固定；左上交叉单元格要覆盖在固定列与表头之上，背景不透明，横滑时不能露出重影或挡住右侧数值。分组行及较深缩进也不能溢出或串列。
- 优先扩展共享 `public/shared/business-table.js` 与 `public/shared/style.css` 的矩阵能力：保留真实两行表头语义、列组跨度和共享浮动表头生命周期；克隆表头复用矩阵样式及第一列固定行为，按**叶子列**和真实分组跨度同步宽度，切换证券、三表、比较列、窗口/字体尺寸后重新测量，旧实例与旧监听清理干净。若评估认定现有克隆机制无法可靠支持该表，可在共享能力中提供原生吸附实现，但每张表只启用一种表头机制，禁止同时叠加两份浮层。
- 无交互的浮动副本对读屏隐藏且不能获得键盘焦点，原表仍有正确的行列标题与关联；若浮动表头以后承载操作，需单独定义唯一焦点和事件转发，不能造成重复朗读或重复执行。空表、加载、报错、切换报表或离开页面时销毁或隐藏浮层；不可新增业务请求、丢失横滑位置或破坏其他共享表格。

### 5.4 手机与交互

在 760px 以下保持单套表格，工具栏换行、控件触摸目标至少 44px、输入字号至少 16px；表格数据行可以保持 28—32px，因为阅读行本身不设点击操作。手机固定科目列以不遮挡至少一列完整数值为原则，初始宽度约 128—160px，受实际视口和文字长度约束；名称允许换行，完整内容可见，表头和数据区域独立保持对齐。320px 下不能把固定首列扩张到挤掉全部数值区域，用户可通过表格容器横滑查看其他报告期；读屏应知晓当前表格可横滑。

默认展开全部已确认层级，不依赖点击才能看到明细；本版不增加行内折叠按钮，以保持紧凑且避免 44px 触摸目标互相覆盖。若后续增加折叠，需单独定义 44px 目标、`aria-expanded`、键盘操作、焦点恢复、完整可达及保留展开状态，并证明无需额外取数。缺失原因不可只放 `title`：可通过可触摸且具可访问名称的统一说明入口查询；需要时点击入口使用不少于 44px 的独立触控区域，不将每个紧凑数值单元格变成微小按钮。
