## 1. 目标与现状

2026-11-09 最新验收补充：当前请求的测算、行业列表、历史来源分页、候选分页和股票详情 401 才清理私有状态并跳转登录，迟到旧请求不污染新上下文；批次列表失败后的迟到 401 独立处理且并发 401 只提示一次。来源按主体/市场/周期恢复并支持首屏外校验、失效回退与切账号隔离；历史季度跨正式策略版本查询，日周仍按当前策略过滤。当前修复树交互行为 50/50、前端 27/27；浏览器视觉、多尺寸、真机和生产未验。

用户要求 A 股、港股内容分开；日、周、季度选择同时作用于上方目标组合和下方结果批次；在表格行业列直接排除股票或行业并立即递补；移除资金设置及历史回测页面区域；指标提供说明。季度是既有历史季度，并非每月。

代码现状与本轮实现：市场/周期/公共来源已移到双表公共区域，页面移除资金设置和历史回测入口，加入来源分页、排除/恢复管理、个人状态标识、指标说明浮层和移动端触控样式；Presenter 维护市场、周期、公共来源与个人结果的独立上下文，并丢弃迟到响应。服务端保留历史资金字段，设置省略字段时保留原值，使用行业 system/version/code 身份，个人候选按完整冻结投影递补并回传排除原因；个人派生在事务内锁定来源和用户设置，显式校验仓位与 settings revision，使用不含 clientRequestId 的内容哈希，并通过迁移 193 的请求绑定保证同请求重试可复用。修复轮另外覆盖 V2 首次周默认、已有排除自动派生、失败重试、菜单事件隔离、空值展示和迟到响应上下文守卫。

本轮核对出的缺口如下；表内是静态代码证据，未执行页面或生产复现：

| 位置 | 已有能力与真实缺口 | 本方案要求 |

## 2. 页面结构与交互

```text
[A股] [港股]
当前市场概览（仅所选市场）
[每日动态] [每周正式] [历史季度]   批次 [选择]
当前市场 / 周期 / 来源批次 / 结果状态
目标组合                           已填 n/30  排除管理 (n)
  股票 | 行业 [操作] | 指标 …
结果批次（候选）
  股票 | 行业 [操作] | 原排名 | 状态 | 指标 …
```

1. A 股和港股切换时，概览、周期、批次、组合、候选、排除管理同步切换；缺数据只显示本市场空状态，不显示另一市场卡片。请求按账号、市场、周期、来源批次和序号隔离，迟到响应不能覆盖当前页面。
2. 公共周期与批次控件放在两个表格之前。切换后两个表必须显示同一来源；展示结果日期、批次、策略版本与状态。每日明确动态、每周明确正式状态、季度明确历史和实际策略版本；无结果时两表同显空状态。首次进入按激活策略显式设置默认周期：V2 为每周正式、旧季度策略为历史季度，再请求对应 kind；保留有效的用户选择，不以日结果冒充周结果。规则说明以所选源批次的策略/公式为准，不能只看 `/markets` 返回的当前默认策略。
3. 保留证券名称跳转分析、其他行区域打开详情的已有行为；操作菜单点击不得触发行点击或导航。保留候选分页、排序与全字段，个人排除的候选行标注状态及恢复入口，未加载的记录不能被误判不存在。
4. 在目标组合和候选表的行业列增加可见“操作”按钮：菜单显示“排除该股票”与“排除该行业”，明确名称、代码或行业；行业缺失时禁用行业操作并说明原因，股票仍可排除。A/H 同发行人不连带排除；行业依据源批次的体系、版本、代码，不按名称猜映射。
5. 工具栏提供当前市场“排除管理（数量）”，按行业及股票分组展示并逐项恢复。设置对该用户该市场跨日、周、季度生效；其他用户、市场不受影响。分类版本变化需标为待映射，不按同名自动匹配。设置修改只重算当前所选源批次；切换批次按最新设置重新派生，不回写已有个人历史快照。
6. 移除页面“我的资金设置”“历史回测”两个区域，以及页面首次加载和切换时为它们发出的回测请求。保留原设置、回测数据和接口及其他调用者；把现有资金区内的排除能力移到表内及排除管理后再移除旧节点、监听与渲染调用。移除资金界面不得清空已有预算、仓位或排除字段，参数按第 2.2 节冻结。

### 2.1 来源、个人状态与空态

- Presenter 分别持有公共 `sourceRunId` / 来源修订、当前 `personalRunId`、当前设置 revision 和已展示结果的 settingsRevision；下拉只选公共来源，个人结果不替代该值。上下文键包含不可复用主体、市场、策略、周期、源 run/revision、设置 revision，分页另带排序及游标/offset，详情另带证券身份。
- 进入已有排除的市场或切换源批次时，只为当前来源复用或生成一份匹配最新设置的个人结果，不后台遍历历史。没有排除且无需个人覆盖时直接展示公共结果；恢复最后一项后也须完成当前来源的结果更新。旧个人快照不被改写，不把它当成最新设置下的结果。
- 区分“首次加载”“该周期无已发布批次”“读取失败”“有效零成员”“个人结果更新中/失败”。加载或切换来源时先撤下旧上下文的表格与详情，禁止新标题配旧数据；同源重算可保留旧结果，但常驻标出其来源/revision 及“尚未更新”。设置读取失败可继续看公共结果，排除/恢复/派生保持禁用并提供重试，不能用空设置继续保存。
- `/markets` 的当前指数日期、参考仓位与已选历史批次的日期/仓位分别标明；概览就绪状态取所选周期，不把默认周渠道的状态套给日或季度。某周期暂无结果时保留周期与市场切换，排除管理仍可读取；恢复设置成功但无源可派生时，明确“已保存，暂无来源组合可更新”。
- 同主体可在内存中按市场/周期记住来源选择；离开再返回优先恢复仍有效的选择，失效时提示并回到该渠道最新来源。切账号、退出、会话失效时清空私人数据、未确认操作及缓存。同名账号重建不能继承旧主体状态。
- 历史批次列表不能把当前 `limit:20` 当全集。沿原 runs 查询的 limit/offset 和稳定排序提供历史加载入口：日/周渠道按市场、周期和当前策略过滤；历史季度按市场与季度渠道查询所有正式策略版本，不能以当前策略排除 V1 历史。首屏、分页和缓存恢复使用相同渠道规则；第 21 条及更早的季度仍可选择，不为展示历史一次性取完全部批次。翻页不能把个人 run 混回公共来源。

### 2.2 移除资金输入后的参数合同

本次行内操作只改变排除与成员，**不借此调整仓位**。首次从公共源派生时显式传入该源已冻结的 `positionRatio`；已展示同源个人组合时沿用该个人结果的有效仓位。市场预算沿用该个人结果的有效值，首次派生使用本人已存的本市场预算；缺省预算为 null，不伪造金额。历史源明确不可配置或仓位为 0 时继续空仓；仓位无法确定时阻止生成并提示，不能落入 `createSimulation` 的隐式 100% 默认值。指数“参考仓位”始终只是说明，不自动替换计算仓位。

已保存的两市场仓位、预算、总资金、备注及排除配置原样保留；隐藏的旧目标仓位不在一次排除操作中自动套用。此处是新行内入口的参数选择合同，原接口及其他调用者保留原兼容行为。参数、来源及设置快照一并进入幂等输入，服务端校验范围。摘要同时标出实际仓位、市场预算是否已配置、股票/现金占比，以及“占市场预算 / 占预设股票目标 / 占实际股票子组合”三种分母；没有总资金或预算时只展示可确定比例。

## 3. 排除、递补及失败合同

操作即时启动：冻结当前主体、市场、公共源 run、周期和设置 revision → 保存排除或恢复 → 以保存后的 revision 从同一个公共源生成个人组合 → 同时更新组合及候选状态。源组合保持不变，个人结果显式标注“个人组合”、来源批次和设置版本；禁止把个人 run 当成下一次源 run。历史季度和日周批次仅在其原质量、访问及来源合同允许时派生，不能绕过未就绪或影子限制。

复用现有 settings 及 simulations 用例、完整冻结投影和 `selection_order`；按个人排除、源资格/数据质量、异常、行业上限与原席位规则顺序递补，不重抓行情、不重算基础排名。可用候选足够则补足 30，只数不足则显示 `n/30`、空席及原因；未填席位保留现金，不能降低规则强行补满或放大预设单席权重。对零仓位或不可配置的源批次，沿源策略展示空组合和原因。提示变动只数、递补只数和结果状态。

保存及生成各自有明确进行、成功和失败状态；进行中禁止同一主体重复提交设置，失败不伪报成功。设置保存失败保留原状态及用户操作，支持重试；设置已保存但生成失败则标明“排除已保存，组合更新失败”，保留来源和 revision，提供重试生成，不能把旧组合标成新结果。409 按冲突类型处理，不静默覆盖并发变更。切换账号/市场/批次后，旧请求不能覆盖新页面；离开页面或取消等待不等于撤销服务端已保存的设置。

现有服务已按本方案补足：simulation 显式接收并在事务中核对 expected settings revision、冻结来源和设置；请求 ID 同输入复用、异输入冲突；响应丢失后即使当前设置版本前进，也按原绑定请求恢复；服务端不依赖前端先后顺序。逐项操作沿用 GET/PUT settings，合并原值并沿用 revision，不另起设置事实源。隔离 PostgreSQL 流水线已覆盖上述响应丢失恢复和异参 409；生产并发、回滚和主体删除重建仍不宣称已验。

### 3.1 设置保存与恢复语义

1. settings revision 是**整份用户设置**的版本，不是每市场单独版本。单页写操作按主体串行；多标签页/多设备依靠服务端 CAS。排除操作必须带显式 revision，合并本市场改动并保留另一市场证券列表、行业列表和隐藏资金字段。服务端校验需扩展为资金字段“省略=保留、显式空=沿原清空语义”，不能仅把旧空 DOM 的值传 null。旧客户端及显式清空行为需回归。
2. 去重键：股票为市场＋统一证券身份，行业为市场＋体系＋版本（含明确 null）＋行业代码；不按名称匹配。设置保存与派生过滤须使用相同身份口径。源批次与设置版本不匹配时标记待映射，该项不自动命中，源原有资格/分类质量门槛仍有效；未知版本保留未知及证据，不视作任意版本通配。无需新增第二份分类事实。
3. 股票和行业排除可同时命中。恢复股票只移除股票排除，若仍命中行业则标“仍被行业排除”；恢复行业不清空单股排除。恢复表示重新参与原规则竞争，不承诺进入 30 席。行业菜单说明作用于本市场该行业的全部候选并跨周期生效，不能只排除已加载行。
4. “排除管理（n）”统计本市场已保存的唯一配置项数，行业一项算一项；与“本来源实际受影响股票数”分开展示。退市、更名、当前批次未出现及待映射项仍可见、可删除，不因下拉或候选页找不到而丢弃。重复排除已排除项不产生多条配置。

### 3.2 事务、幂等与失败恢复

- `PUT settings` 保存成功后，以返回的完整设置/revision 作为唯一确认值；`POST simulations` 必须携带 `sourceRunId`、`settingsRevision`、稳定 `clientRequestId` 及冻结资金参数。会话 subject 由服务端会话传入并与账户核对，不能仅以 username 再查到的新主体替代旧会话主体。
- 服务端在同一事务合同内核验主体、源访问/质量/非影子、期望 revision 和冻结设置；可在锁外完成重计算，但写入前须核对其冻结内容仍有效。设置更新和派生提交通过同一用户行锁/等价 CAS 协调，不能只在事务开始读一次 revision。源 run、settingsHash/revision、计算版本和写入结果必须一致，事务任一步失败不留半份个人结果。
- 同主体＋simulations 用例＋请求 ID 的并发重试必须由数据库约束或事务锁保护，锁内重查，返回同一个完整结果。仅“先查询后插入”不足。响应丢失后重试先按已冻结请求识别原结果，不先读取新设置重算后误报同 ID 异参；真正异参仍 409。请求幂等与内容复用分别保留，内容哈希不含 `clientRequestId` 或请求时间等传输标识，不能以每次生成新 ID 代替恢复或导致相同内容反复落库。现役 `createSimulation` 把请求 ID 放进 inputHash，实施时须分清这两个用途并保留旧结果读取兼容。
- 不同请求 ID 命中同一内容时，仍需原子保留各请求 ID→规范化载荷哈希→结果的绑定，不能覆盖旧 run 的 request_id，或只返回复用却漏记新 ID，导致该 ID 随后能提交异参。先核对现有可复用幂等存储；若单一 request_id 列无法承载，评估最小请求元数据扩展并说明原因，只记录绑定、不复制候选或组合事实。
- 设置保存超时/响应非预期时先重读：目标改动及其余保留字段均与预期一致才认作已落库；revision 未变且内容未变可用原期望版本重试；存在其他变更则走冲突，不能盲目覆盖。组合生成结果不明时沿用原请求 ID 和原载荷；不重复保存设置或递增 revision。页面刷新后先重读权威设置，只派生当前来源，不能把浏览器草稿当已成功。
- API 客户端保留可判别的错误码、HTTP 状态及恢复所需的非敏感上下文。设置版本冲突时重读最新设置，保留“新增/移除哪一项”的意图，用户重试时在最新值上重新合并；来源不可派生时重选来源；请求 ID 异参冲突不能自动换 ID 绕过。401 清理私人状态并走原登录流程，403 不重试写入。

### 3.3 双表所需的最小响应合同

沿用原 API 及仓储投影补字段，不新建个人结果或排除接口：

| 响应 | 实施要求 |
|---|---|
| run / portfolio | 显式公共 `sourceRunId`、来源修订、策略/公式、周期、settingsRevision；个人 run 的来源取其已存源引用，不能把通用前驱字段一概当公共来源 |
| portfolio.members | 补齐 `instrumentId` 及行业 system/version/code/name；只从源冻结候选/成员批量取，不逐行查最新行业，不靠第一页候选补成员身份 |
| candidates / 详情 | 保留基础 filterStatus、selectionOrder、名次与证据；另给个人排除原因、是否入选及未入选原因，区分数据待补、年度异常、行业上限、席位已满与个人排除。复制候选后须补投影，不能把 PASS 改成 FAIL 冒充策略不通过 |
| simulation 结果 | 返回实际 run/source/revision、采用资金参数、成员及现金摘要、排除与递补差异或可读取引用；双表按同一结果上下文一次提交渲染 |

当前实现：新个人结果在已有 `input_manifest.portfolio.selectionOutcomes` 保存未入选身份与原因摘要；候选和详情同源返回 `personalNonSelectionReasons`，页面将个人排除、行业上限、席位已满、年度异常、基础规则/排名数据和零仓位分别解释，不修改基础 filterStatus。旧结果没有摘要时，只读其已复制的完整冻结候选并复用原组合规则回放；旧版行业代码排除沿原冻结载荷解释，回放成员不一致则保留“历史结果未记录具体原因”。批次摘要剔除内部整表原因，浏览器只读取本页和当前详情所需原因。生成开始及结果读取重试立即刷新常驻“更新中／尚未更新”提示，必要读取成功后解除；失败保留原重试入口。

排除行保持可见并给恢复入口，分页 total 仍有明确的原候选集合口径。生成后候选、成员与详情任一必要请求失败，保留“结果读取未完成”及重试，不能把新组合与旧排除状态拼成成功。分页和显示排序不改变递补所用原始 `selection_order`；保留当前已加载范围、排序与横滑位置，确需重置时明确告知，恢复不能依赖记录恰在已加载页。

### 3.4 变动解释与操作连续性

实现补充：结果读取可携带操作前展示的 `baselineRunId`，服务端校验它属于同一公共来源及主体；未指定时仅选择当前结果创建之前的同源个人结果。保存队列按登录主体隔离，同主体切换市场后保留失败重试入口；响应丢失后先按完整设置和冻结操作比对权威结果，确认已保存时不重复递增 revision，读取失败时仅按原载荷和原 revision CAS 重试。JSONB 字段顺序、历史行业字符串规范化、服务端默认字段和主档名称补全不应导致误判，其余市场与资金字段仍须完整比较。历史字符串行业项可展示和恢复；行业保存按体系、版本和代码去重，个人派生只按完整身份命中，不按代码宽匹配。设置与个人测算请求携带读取设置时的主体摘要，服务端比较会话主体，并在设置更新和个人测算事务中再次约束主体。个人组合的显式空预算保持为空；请求重试按本市场的冻结预算和冻结默认仓位区分省略、显式空及等价值，旧批次按旧版默认语义兼容。

本次排除反馈以操作前正在展示的**同主体、同公共来源**组合为基线，列出本次移出、递补及空席变化；没有旧个人结果时可与该公共源比较。历史调入调出另按同市场、策略、周期及清楚标识的设置范围比较，接口给两端 run/revision；无可比来源则显示不可比较。上一份有效零成员结果也是有效基线，不能用 `previous.members.length > 0` 判断是否有历史。不得沿用上一正式季度的差异去解释周/日个人操作，不将目标变动称作实际成交或收益。

操作成功后关闭菜单，保留表格位置与可访问焦点；被移出的行已不在组合中时，焦点回到结果摘要或排除管理。列表/详情各自使用请求序号并绑定同一来源上下文，加载更多不得使进行中的排除或详情失效；连续切换、同股快速点选和迟到错误也须隔离。重试只推进未完成阶段，不要求用户再次手工排除。

## 4. 指标说明及全站 UI

沿用 `bond-sub-tab`、`bond-feature-*`、共享业务表格及 `BusinessTable`，桌面保留统一吸顶和横滚；颜色、字号、边框和控件尺寸以[技术架构 5.1—5.3](技术架构.md#51-全局业务表格规范)为准。业务样式只放必要列宽和布局差异。

指标名称附近提供说明入口：PB、PE（TTM）、股息率、PB 正极值比、参考仓位、席位与权重等，内容包含含义、实际数据口径、缺值含义及适用策略版本；历史规则与 V2 各自对应，缺值显示“—”而非 0。说明框在桌面悬停和键盘聚焦可读，手机点按可打开；Esc、点击外部或关闭按钮可关闭并恢复焦点；定位不被横滑容器裁剪或超出视口，重要状态不只靠颜色或 hover。

指标说明优先复用共享入口，文案集中维护并按源策略/公式取对应版本：PB 区间及正极值比注明有效正值、实际年限/覆盖、缺口及不可评估；PB×PE 说明直接 PB 阈值通道、乘积通道以及非正/缺失 PE 的处理，直接 PB 通道通过时显示“—”不代表读取失败；股息率采用源结果口径，不把另行估算值混入；参考仓位与实际采用仓位分别解释。`null` / `undefined` / 空字符串在数值转换前判断，避免 `Number(null)`、`Number('')` 变成 0；真实零值和负值按指标合同显示，不能一律变成缺值。

手机正文按 760px 断点重排、导航按 900px 规则，宽表只在容器内横滑，触控操作区至少 44px，输入字号 16px。排除菜单和管理面板可用键盘、触屏操作，菜单需可读名称、焦点控制和状态反馈。新增可复用的行内操作菜单、指标说明框及排除状态样式，实施时优先进入共享组件与样式；在技术架构 5.1/5.3 原位补充通用规范和实际验证范围，不将本设计标成现役。

`BusinessTable` 会产生浮动表头，说明按钮在原表头和浮动表头均须有效，避免复制重复 ID、重复请求或绑定多份事件。菜单/说明定位在共享浮层，容器滚动、缩放、旋屏、来源切换和组件销毁时关闭或重新定位，清理监听和浮动节点。状态反馈可被辅助技术读取，禁用项说明原因；只读说明不得随打开而取数。

## 5. 架构与影响链路

现有金融数据源 → 入库行情、财务和分类 → 已发布或可派生的冻结选股批次及完整排名 → 选股服务和个人设置/模拟 → 现有 API → Presenter/View。页面查看、切换及排除不触发外部采集或新调度；排除与个人结果按既有用例写个人设置与个人派生记录，不修改共享批次。优先扩展现有架构，不新增平行任务、数据源、事实表或调度器；接口字段扩展限第 3 节的设置版本、来源、身份及展示所需合同。

主要落点：`public/index.html` 结构；`public/js/stock-selection.js` 渲染与事件；`public/js/presenters/stock-selection-presenter.js` 状态及请求编排；`public/js/api/stock-selection-api.js` 接口；`public/css/stock-selection.css` 页面差异；`public/shared/style.css` 和共享交互能力。第 1 节确认并已扩展 `server/routes/stockSelection.js`、`server/services/stockSelectionService.js`、`server/repositories/stockSelectionRepository.js` 及组合过滤入参，不是纯前端改版。安全沿用登录、CSRF、主体隔离和审计；私人响应沿原私有缓存合同处理。本轮新增最小迁移 `193_stock_selection_ux_request_bindings`，只保存请求到结果的轻量绑定，不复制候选或组合事实；未改外部采集、调度器或生产数据。

分层保持 View 只渲染和上报、Presenter 管状态与请求、API 客户端归一响应、服务编排权限/事务、仓储批量读写、Domain 执行原递补规则；本轮 View 未新增直接请求，Presenter 增加上下文守卫，完整分类身份匹配仍由服务端使用同一身份键。共享能力未另建框架。性能验证继续聚焦完整冻结候选及尾部递补：避免 N+1、每次改动全量下载候选到浏览器、重复复制/生成同结果；本地已实现完整候选游标投影，真实规模、耗时和超时恢复待数据库验收。
