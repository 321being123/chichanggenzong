## 一、检查与按需启动

以下以新电脑为例；旧电脑将程序、数据和日志三个路径一起切换为已核实的E盘路径。先确认日志目录存在且位于数据目录外。只有确认实例未运行、资源归本任务且有运行授权时才执行启动；停止仅针对本任务拥有的实例。

```powershell
Test-Path 'D:\pgsql\bin\pg_ctl.exe'
Test-Path 'D:\pgsql\bin\psql.exe'
Test-Path 'D:\pgdata\PG_VERSION'
& 'D:\pgsql\bin\pg_ctl.exe' -D 'D:\pgdata' status
& 'D:\pgsql\bin\pg_isready.exe' -h localhost -p 5432
```

```powershell
# 按需启动：不与其他任务或已运行实例并行操作
& 'D:\pgsql\bin\pg_ctl.exe' -D 'D:\pgdata' -l 'D:\pglogs\server.log' -w start
# 仅停止本任务拥有的实例
& 'D:\pgsql\bin\pg_ctl.exe' -D 'D:\pgdata' stop -m fast
```

固定路径缺失时先核对实际电脑、原安装记录和端口，再判断修复或安装；不从历史示例直接初始化新数据目录，不全局终止Node/Python/PostgreSQL进程。

## 二、任务环境与数据边界

- 依赖按当前锁文件准备，Windows只使用 `npm.cmd`；Python使用本机项目根 `venv`，不能复制其他电脑的虚拟环境。解释器覆盖变量以本机受保护 `.env` 为准。
- worktree默认不含 `.env`、依赖、venv、模型和数据库。先核对本任务需要的环境，不复制整份工作区，不把密钥写到命令输出、文档或Git。
- 本地Web保持 `NODE_ENV=development`、`DISABLE_SCHEDULER=1`、`DISABLE_RUNTIME_MIGRATIONS=1`。Worker不受Web禁调度开关保护，本地验收不启动生产Worker。
- 写入测试使用任务独立开发/测试库与 `DATA_DIR`；Runner使用独立 `PGTESTDATABASE`，保留test/migtest命名防护。仅修改 `PGDATABASE` 不能证明测试隔离；测试迁移开关只在测试子进程调整。
- 模型、原始PDF及历史样本按已有受控位置准备；缺失时记录未验证，不以业务库、生产连接或伪造样本补缺。
- 原生产只读快照恢复、模型复制与环境安装结果仅证明当时状态，不能作为今天库内数量和模型可用性的判断。原校验和及授权范围见历史记录。
