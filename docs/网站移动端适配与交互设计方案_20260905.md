## 1. 设计结论

沿用现有蓝紫色导航、白色卡片和红涨绿跌的视觉体系，将手机体验统一为：**顶部菜单切换栏目、正文单列阅读、统计卡片双列、宽表格局部横滑、图表支持点按、长表单适应手机键盘。**

适配覆盖主站全部栏目，以及登录、打新报告、文章分享、下修动机详情和管理后台。保持现有功能、数据字段、金融计算和权限口径；只调整展示及输入方式。

## 3. 全局布局与视觉规范

### 3.1 屏幕规则

- **内容布局以 760px 为手机分界**：760px 及以下正文单列；数字统计默认两列，长说明和长金额可整行显示。
- **主导航沿用已有 900px 档位**：900px 及以下收为“菜单”；更宽屏幕保留横排，临界宽度下由导航自身处理剩余空间，不能撑宽整页。
- 复用现有 900px 的中等屏幕网格安排；本次碰到的 600/720px 重复规则按职责就地整理，不全站重写样式。
- 320px 是窄屏兜底检查宽度，360～430px 是主要手机阅读宽度；横屏按实际可用宽度排版。

### 3.2 尺寸建议

| 元素 | 手机端设计值 |
|---|---|
| 页面左右留白 | 12px；阅读正文卡片内部 16px |
| 卡片 | 沿用 10px 圆角、白底和轻阴影；间距 12px |
| 栏目标题 / 卡片标题 | 20～22px / 16px |
| 正文 / 辅助信息 | 15～16px / 12～13px，正文行高 1.6～1.8 |
| 表格正文 | 13px，金额和比例保留现有精度、单位和正负号 |
| 输入框 / 下拉框 | 字号 16px、高度至少 44px，长字段独占一行 |
| 按钮、关闭、账户设置、复选框标签 | 可点击区域至少 44×44px；小图标通过外层留白扩大点击区域 |
| 涨跌及状态 | 沿用红涨 `#d93025`、绿跌 `#137333`；状态保留文字，不能只用颜色区分 |

表格 13px、输入 16px、控件 44px 是**拟新增的全局移动端规范**。现行架构中的桌面表格 12px、工具栏字体 13px/高度 36px 保持原口径；实施时在共享样式增加移动端覆盖，并同步《技术架构》第 5.1、5.2 节，不能由各业务页私自另定尺寸。

44px 是本方案采用的触控设计目标，参考 W3C 的增强目标尺寸说明，并非宣称网站已达到完整无障碍等级。[W3C 触控目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)

### 3.3 导航设计

手机顶部保留一行：左侧站点名返回首页，中间显示当前栏目，右侧“菜单”。顶部基础高度 52px，顶部安全区另计。

点击菜单后，在顶部下方展开可滚动面板，完整展示现有 9 个栏目；个人中心、登录及管理员入口遵循当前身份显示。选中项高亮，点击栏目后关闭菜单。复用原导航节点及 `switchMain()`，不维护另一份栏目权限表。

菜单支持再次点击关闭、点击遮罩关闭、Esc 关闭；打开时焦点进入菜单，关闭后回到触发按钮。展开期间锁定背景滚动；跨越屏幕分界时清理展开状态与滚动锁。

二级栏目仍使用当前横向页签，超出时在页签条内滑动，并把当前选中项滚入可见区域。持仓的账户选择、刷新和设置移到页签下方普通工具条，随正文滚动。常驻区域只保留主导航和当前二级页签，给数据留出空间。

表头吸顶偏移量取当前可见导航的实际下边缘；覆盖持仓、可转债和后台等现有接入点，避免继续依赖固定 `top:52px`。

## 4. 表格、图表与输入交互

### 4.1 宽表格

1. 保留全部列、原有排序和筛选。在 `.biz-table-scroll` 内横向滑动，页面本身只纵向滚动，不通过隐藏溢出来掩盖超宽内容。
2. 有溢出时显示“左右滑动查看完整数据”；没有溢出时隐藏。触屏直接滑表格，桌面继续使用现有底部同步滚动条。
3. 上市可转债、强赎、下修、安全性和持仓列表，手机优先将已有名称/代码合并显示在一个身份单元格，固定在左侧，目标宽 96～112px。仅名单型表格使用；财务矩阵和复杂多行表头保持原结构。名称允许两行，完整名称仍能通过现有详情查看；金融数值不截断。
4. 身份列样式、浮动表头和横向位置在 `BusinessTable` 中协调，不能只给原表加固定列而让浮动表头错位。浮动表头排序继续转发给原表。
5. 页面纵向滚动为主。手机取消估值表等非必要的固定高度纵向滚动框，减少“页面里面再滚页面”；弹窗内容与真正需要二维浏览的表格保留局部滚动。
6. 明细说明可以换行；持仓金额、价格、日期、比例等数据保留完整。下修动机中已有固定比例的多列表，仅对狭窄且不可读的部分恢复局部横滑，或用现有键值详情形式展示，不能把一位数字挤成多行。

数据表可以在独立容器中横向滚动，周围的标题、筛选和正文仍应适应窄屏，这是本方案采用的重排原则。[W3C 内容重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

### 4.2 图表

- **首页概览、估值走势、市场周期**：按容器宽度重算绘图区域；减少横轴标签数量，保留数据点和计算口径，避免把整张桌面 SVG 连同文字一起缩小。手机图高建议 240～280px。
- **多年财务柱图、密集多指标周期图**：保留必要绘图宽度，在图表卡片内横滑；标题、图例和区间选择留在手机可见范围。历史数据和导出内容完整保留。
- **查看数值**：点一下数据区域显示最近数据点，点空白处或切换页面关闭；鼠标仍能悬停。提示框以当前可视区域为边界定位，不能出屏或挡住主要操作。
- **滚动优先**：普通图表允许页面纵向滚动和双指缩放；横滑图表使用原生滚动，不在整张图上统一禁止触摸手势。处理 `pointercancel`，手势取消后清理提示和拖动状态。
- **市场周期边界**：手机直接复用现有数字输入和保存按钮调整。触屏浏览图表时不误拖边界，桌面保留现有拖动能力。数据只在用户确认保存后按既有流程写入。

`touch-action: none` 会关闭浏览器默认手势；手势开始后再改属性也不能改变当前手势，因此需在交互区域预先确定规则。[MDN 触摸手势说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)

### 4.3 筛选、表单和弹窗

- 搜索框手机独占一行；简单状态筛选直接显示。现有工具栏一屏放不下时，将次要条件放入可展开的“筛选”区域；复用同一组控件和筛选状态，关闭后保留已选条件及结果数量。
- 日期起止、交易字段和个人信息改为单列；短字段空间足够时可两列。金额使用小数键盘、验证码使用数字键盘、邮箱使用邮箱键盘。证券代码保持文本，保留前导零和港股格式。
- 短确认弹窗仍居中；长详情、交易录入和导入预览使用接近全屏的同一弹窗结构，标题/关闭及操作区可见，正文单独滚动。弹窗打开与关闭正确恢复焦点和页面位置。
- 输入键盘弹出后，焦点字段和确认按钮必须可达。优先使用自然滚动、动态视口尺寸及安全区留白；若目标浏览器实测仍遮挡，再在共享弹窗内增加 `visualViewport` 辅助处理。
- 上传复用现有文件选择器，手机可以选相册或系统文件；导入预览、确认和取消流程完整保留。二维码辅助区移到上传区下方。

## 6. 浏览兼容范围

目标环境为验收时的 iOS Safari、Android Chrome，以及 iOS/Android 微信内置浏览器；每次记录真实系统和浏览器版本。桌面 Chrome、Edge、Safari 做回归。未测系统或旧内核不写“已兼容”。

- 保留浏览器缩放，不设置 `user-scalable=no` 或锁定最大缩放比例。
- 弹层和长页面采用 `vh` 回退加 `dvh` 渐进增强；`dvh` 处理动态浏览器界面高度，但不能单独视为键盘遮挡已解决。[MDN 视口长度单位](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)
- 全屏弹层和固定控件使用 `env(safe-area-inset-*, 0px)` 处理安全区；涉及贴边布局时配套评估 `viewport-fit=cover`。安全区用于避开屏幕切口和底部区域。[MDN 安全区变量](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env)
- `hover` 只用于增强反馈；提示、菜单、图表读数都要有点击方式。
- 横竖屏切换及屏幕宽度变化只重排布局和重新计算图形/表头尺寸，不重新请求金融数据，不重置已输入表单、排序或筛选。
- 微信内文件下载、PDF 打开及上传使用原有入口实测；若容器限制某项能力，保留文件链接并给出对应系统浏览器打开提示，不能仅提示“成功”却拿不到文件。

## 7. 架构对齐与实施边界

当前链路保持为：

```text
外部数据源 → 既有增量采集/数据库 → 既有业务服务 → 原有 /api 接口 → 同一套响应式页面
                         ↑
                    既有 Worker 调度
```

**架构对齐结论：现有架构可以承载，缺口位于页面布局、共享组件和触屏事件。** 数据源、库表、服务计算、接口契约及 Worker 任务定义均无需因移动适配而改变；持仓实时刷新等已有行为按原服务边界执行，不能把所有接口笼统当作纯静态读取。

主站现有 40 个外部脚本标签和账户摘要/首页轻量接口是当前基线。沿用现有缓存、`defer`、加载防重和模块状态；菜单展开、屏幕旋转、图表点按不能额外调用加载入口。模块按需加载等性能专项继续以《网站性能优化研发方案》为准，避免混入本次布局改造。

| 修改位置 | 计划职责 |
|---|---|
| `public/shared/style.css` | 手机尺寸、导航、布局、表格、表单、弹窗和后台基础样式 |
| `public/shared/business-table.js` | 浮动表头偏移、横滑提示、身份列及桌面滚动条协调 |
| `public/shared/dialog.js`、现有日期控件 | 焦点/关闭恢复及触控尺寸；日期计算保持原实现 |
| `public/index.html`、`public/js/navigation.js`、`public/js/session.js` | 菜单结构与状态、身份入口、页面工具栏必要结构调整；权限仍读取 `access-policy.js` |
| 相关 `public/css/`、`public/js/` | 各业务字段布局、图表触屏、文章分类/目录、详情返回；逐模块局部修改 |
| 其余 5 个 HTML 页面、`public/js/admin.js` | 独立页面和后台兼容；在现有结构上增补，不复制第二套页面 |

同类图表的点按/提示定位确需共享时，只提取小型交互辅助到 `public/shared/`，业务绘图和金融计算仍留在原模块。使用现有原生前端、Chart.js、Vditor，不引入新的前端框架。

## 8. 实施顺序与验收

### 第一批：全站基础可用

完成主导航、二级页签、公共容器、字号/点击区域、表单/弹窗；用上市可转债列表验证共享横滑、固定身份列和浮动表头，再推广到本次同类列表。

通过条件：手机可进入所有原有栏目；页面本身不横向溢出；操作按钮、登录和返回可用。

### 第二批：主要业务浏览体验

覆盖首页、持仓、可转债、证券分析、打新、市场周期、套利和仓位对比；处理全部同类图表提示及触屏滚动。

通过条件：同一数据快照下手机与桌面字段、行数、数值、日期、排序、筛选结果一致；所有业务详情可打开并返回。

### 第三批：阅读、独立页面与后台收尾

覆盖投资笔记阅读/作者编辑、分享/日报/动机详情、个人中心、版本记录及后台全部菜单；完成跨设备回归。

通过条件：长文章、大表格、文件选择、键盘、横屏、权限和桌面回归均无阻断项，才能称“全站适配完成”。

### 验收清单

| 项目 | 可核验标准 |
|---|---|
| 宽度 | 320、360、390、430、768、1024、1440 CSS px；另检查 760/900px 分界两侧。除指定表格/图表/页签容器外，无整页横向滚动 |
| 内容完整性 | 普通文字缩放到 200% 后仍可读、可操作；金额、涨跌幅、状态、日期不截断；表格所有原有字段有可达入口 |
| 导航 | 游客、会员、管理员按原权限；菜单开关、地址直达、刷新、浏览器返回及当前栏目一致；菜单关闭恢复滚动和焦点 |
| 表格 | 横滑首列到末列、吸顶后排序、切换子页、无数据及长名称场景通过；浮动表头与原表不偏移、不串页 |
| 图表 | 点按能看到数据、提示不出屏；可从图表区域纵向滑动页面；日期区间和桌面鼠标交互正常 |
| 输入 | 实测软键盘展开/关闭、日期选择、长内容输入、确认/取消；输入值及页面状态不丢失；操作只提交一次 |
| 数据请求 | 使用同一场景对照请求日志；展开菜单、点按图表、旋转屏幕带来的额外业务 API 请求为 0，不增加外部金融 API 调用 |
| 覆盖记录 | 11 个主页面容器、6 个转债子栏目、5 个独立页面及后台 10 个菜单均留结果；注明通过数、异常数和未测环境 |
| 桌面回归 | 导航、表头吸顶、排序筛选、图表、导入导出和后台操作维持正常 |

实施时运行 `npm.cmd run test:all` 和 `npm.cmd run check:knowledge`；仅对改变行为的导航、表头/滚动、图表和输入补针对性回归，静态断言不能替代触屏验收。按仓库交付规则核对运行版本、相关接口及静态资源。浏览器、真机/视觉验收和服务启动须遵守用户的低性能模式授权边界，未进行的检查明确列为未验证。
