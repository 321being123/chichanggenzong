# INC-0050：选股交互异步状态与结果解释缺口

状态：本地修复并自动复验通过；浏览器/真机、生产待验
日期：2026-11-09

## 现象与影响

连续验收中，历史来源分页与个人排除共用或间接依赖结果上下文，先后出现结果读取失效、分页成功后加载标记不释放，以及保存失败后分页永久等待。设置保存成功但个人组合生成尚未返回时，界面仍只有旧结果标签。候选已标记未入选却只显示“四项通过”，行业上限、席位及年度异常等没有可见解释。

## 根因链路

站内冻结数据 → 个人结果及复制候选 → 服务端只投影 selected/excluded/not_selected → API → Presenter 请求生命周期与 View 状态。

数据源和基础筛选排名无异常；缺口出在异步状态归属及结果解释。历史分页不依赖个人设置 revision，却使用会被设置修改递增的 contextVersion；finally 又依赖同一守卫，导致应释放的加载标记被跳过。生成开始只写内存 pendingSimulation，表头仅渲染失败状态。组合 Domain 已有 skipped/watchlist，但创建个人结果时没有冻结原因，候选和详情也没有贯通该投影。

连续修复反复出现问题的直接原因：前一次缺仓位测试把隐藏设置回退当作成功，违背来源仓位合同；冲突测试在重试函数返回时立即断言，没有等待后台队列排空，漏掉重复保存；401 测试没有覆盖账号切换后的迟到错误，403 测试没有在拒绝前排入后续操作。上一轮据局部断言和门禁绿灯作出“已闭环”结论过于宽泛，现以本轮反例和未验范围替代。

继续核查发现首次加载的设置读取返回 401 后，清理虽已作废请求序号，调用方却继续设置来源并开始新批次读取；现清理后检查原加载守卫并立即停止，释放加载状态，市场或批次列表请求的当前主体 401 也走同一认证失效路径。新增回归确认不发送候选、组合和批次读取。

后续验收发现两个同类竞态未被旧用例覆盖：初始化将设置/行业请求转成 `{ error }` 后与批次列表一起 `Promise.all`，批次列表先以 500 结束时，迟到的 401 可能只停留在已附加但无人消费的分支；同时来源下拉始终取首条批次，既未按主体/市场/周期缓存用户选择，也未处理已选第 21 条批次不在首屏的情况。修复为每个可降级读取分支独立处理当前守卫下的 401，并对同一主体的会话失效做幂等清理/跳转；来源选择改为内存缓存，恢复时只按已知 run ID 读取一次并校验市场、周期、正式发布和非影子状态，日周渠道另校验当前策略，额外展示项不计入 API 分页 offset，账号切换/会话失效清空缓存。

再次核查发现此前“按当前策略”过滤覆盖了历史季度，V2 激活后导致已发布 V1 季度在首屏、分页和缓存恢复均不可达；旧测试只覆盖同策略批次，故 49/49 不足以证明跨策略历史合同。现季度按市场与季度渠道查询正式来源并允许跨版本恢复，日周保留当前策略过滤；新增第 22 条 V1 选择、切周期恢复和来源规则说明断言。

## 同类范围与核查结果

- 历史来源与候选分页分别检查：历史分页按自身序号、主体和市场周期判断，追加时再验证 offset；设置保存不会取消它。候选分页仍绑定其结果批次，不影响生成结果读取。
- 表头在生成开始、结果读取重试、成功和失败时刷新；切源或切主体仍按原上下文隔离迟到结果。
- 候选、详情、实际成员及个人排除用同一冻结结果解释。股票/行业交叠恢复后保留剩余原因；公共候选不增加个人状态。
- 行菜单关闭后焦点回到可见 summary，成员移除后回到摘要；相关 DOM 回归保留。

## 修复与回归证据

新个人结果在现有 manifest.portfolio.selectionOutcomes 冻结 Domain skipped/watchlist 的身份和原因，不复制候选事实。候选和详情按页透传 personalNonSelectionReasons 并显示中文；批次摘要剔除内部整表原因，避免浏览器重复下载。历史个人结果缺少摘要时，只读本结果已复制的完整冻结候选，复用 Domain 原递补规则回放解释，不修改旧结果或重抓行情。

历史结果沿其冻结的行业代码或完整身份键语义解释；回放成员必须与实际落库成员一致，否则保留原因未知，避免把当前规则的推断当作旧结果事实。原因投影回归同时验证现役候选路由透传、批次路由剔除整表原因及冻结数据不被响应格式化改写。

## 防复发措施与遗留风险

请求有效性与清理归属按实际资源设计；分页成功推进 offset 后仍须释放自身锁。回归覆盖“请求未返回→设置失败→原分页返回→下一页”和连续分页，不只验证第一次追加。组合更新提示持续到必要结果读取完成，基础资格与最终入选分别断言。
