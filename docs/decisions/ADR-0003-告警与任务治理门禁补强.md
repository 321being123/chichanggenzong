# ADR-0003：告警与任务治理门禁补强

状态：已采纳
日期：2026-09-19

> 2026-09-22 关联核对：可转债上市流通规模已登记为 `bond_listing_liquidity` 数据集。17:30 目标上市债券缺失时由现有公告任务返回 `DATASET_INCOMPLETE` 并进入重试；打新日报只消费已发布且质量通过的流通规模分区。早上公告槽位通过结果中的发布数据集白名单避免重复发布/抓取；不新增任务或事实表。

> 2026-09-22 关联核对：IPO 新增 16:30 `prediction_ready` 阶段后，`jobOrchestrator` 已将该模式与 `enrichment` 一样排除 freshness gate，避免基础分区新鲜时跳过上市前预测缺口检查；未新增调度器、数据源或事实表。

> 2026-09-25 关联核对：市场日历任务策略新增 `hk-close`、`hk-rate`、`nav-snapshot` 动态槽位解析；解析只消费 `marketState` 的明确 HKEX 日历事实，未知日不生成港股收盘/汇率槽位。动态时间由任务矩阵按规则说明，旧 `scheduleAllMarketCloses()` 同样消费市场状态。规则追踪新增跨市场日历、净值归因及即时刷新条目，回归覆盖半日收市、旧调度双市同开日和账户隔离口径；没有新增任务类型、事实表或调度器。

## 背景

`ADR-0002` 已规定任务完成、数据分区和告警恢复的不变量，但本轮复盘发现部分实现分支没有真正消费这些规则：任务契约依赖默认值补齐，数据集依赖忽略 `partitionDatePolicy`，未知任务可以取得兜底定义，具体来源告警还可能把 `source:*` 通配熔断当作接口恢复证据。只增加散文规范不能阻止同类分支遗漏。

## 决策

在现有任务调度、数据集分区和统一告警恢复链路上增加以下通用门禁，不新增平行调度器、平行数据源或平行事实表：

1. **原始任务契约审计**：`JOB_DEFINITION_SOURCE` 与 `JOB_CONTRACTS` 在合并 `DEFAULT_JOB_OPTIONS` 前由 `validateJobDefinitionSources()` 检查任务键重复、孤儿键、字段冲突、日期策略枚举、数据集注册表命中和硬依赖子集关系。阶段一报告存量默认补齐项；新增或修改任务可启用严格模式，不能把默认值当成显式声明。
2. **统一日期/分区解析**：数据集依赖必须通过 `resolveDatasetPartitionDate()` 解析分区日。`business_date` 使用槽位业务日，`previous_trading_day` 使用前一开市日，`expected_data_date` 复用任务的 `expectedDataDate()`；非法策略失败关闭。调度依赖检查与恢复证据不得各自解释日期。
3. **未知任务失败关闭**：执行、创建槽位和恢复取证路径使用 `getRegisteredJobDefinition()`；未知 `jobCode` 不得取得默认兜底定义，故障记录仍可保留供人工查看。
4. **告警证据策略注册**：`ALERT_EVIDENCE_POLICIES` 登记告警类型、验证器、作用域、是否自动收敛和证据版本。未知故障类型、通知型记录和人工类型不得自动关闭，但允许创建、发送和保留。
5. **来源作用域精确隔离**：`source:*` 仅对应来源级告警；`source:api_name` 只查询并核对同一 `api_name`。空查询、其他接口或通配熔断均不能恢复具体接口告警。
6. **规则追踪和真实分区回归**：扩展现有 `scripts/generate-job-matrix.js`，从 `governance/rule-traceability.json` 生成规则—实现—测试矩阵，并校验实现文件/符号和测试标记；测试库使用真实 `ops.dataset_partitions` 行验证非默认分区策略，不以字符串静态断言替代。

## 备选方案与取舍

- **只修改复盘文档**：不能阻止新分支绕过已有规则，否决。
- **把所有存量任务立即改为严格必填**：会把历史默认值一次性变成发布阻断，且无法区分真实业务缺口，暂不采用。
- **新增第二套任务矩阵或恢复服务**：会制造事实分叉，否决；追踪矩阵复用现有任务矩阵生成器，恢复仍复用 `verifyAlertScope()` 与 `verifySlotRecoveryEvidence()`。
- **采纳本 ADR 的分阶段门禁**：先报告存量问题并对新增/修改任务提供严格入口，同时用真实测试库和负向回归锁住关键边界，兼顾安全上线和逐步收敛。

## 影响范围

- 代码：`jobDefinitions`、`jobScheduleSlots`、`jobOrchestrator`、`jobRecoveryEvidence`、`jobAlertMailer`、`scripts/check-knowledge.js` 和现有治理回归测试。
- 文档：`docs/技术架构.md`、`docs/生产部署流程.md`、`docs/知识索引.md` 与生成的 `docs/任务接口数据集矩阵.generated.md`。
- 门禁：`npm.cmd run test:all` 和 `npm.cmd run check:knowledge`；不新增数据库迁移，不写入生产数据，不自动关闭历史无证据告警。
- 发布状态：版本 `0.8.1.72` 已完成本地测试和知识门禁；生产部署、线上 `/health` 和历史告警状态仍需单独授权与验收，不能把本地通过等同于已上线。

## 何时重新评估

出现新的任务日期语义、数据分区类型、告警作用域或证据验证器，或者阶段一审计结果要求改变存量任务阻断策略时重新评估。重新评估必须同步本 ADR、`AGENTS.md`、`docs/技术架构.md`、`docs/知识索引.md`、规则追踪 JSON 和自动门禁。
