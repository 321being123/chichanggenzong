# INC-0027：后台告警作用域与阶段判定错位

状态：0.8.1.82 标准生产部署与运行验收完成；历史告警仍待逐项取得恢复证据或授权处理
日期：2026-09-23

## 现象与影响

生产后台显示 11 条活动告警，分为四组：港股 IPO 动态来源/信号 5 条（21387、21388、21389、21416、21444）；IPO 事实同步失败 2 条（21420、21431）；可转债上市流通规模质量告警 2 条（21391、21404）；IPO 重复成功误报 2 条（21398、21424）。

生产只读核查时 `/health` 为 `ok/0.8.1.81`。核心港股事实分区正常，港股动态申购分区无有效行；利弗莫尔返回升级提示，华盛错误只记录为聚合连接失败。两个 IPO 核心槽位 18:00 与 19:30 均成功；可转债 2026-09-22 的 CN 流通规模分区已发布且质量通过，2026-09-21 的同范围分区仍需按目标上市债集合查证。历史对账脚本只读预览未发现可直接自动恢复的记录。

## 根因链路

数据源/任务阶段 → `ops.dataset_partitions` → 任务分区发布器 → 后台告警判定/恢复证据 → 后台告警列表。

- 港股动态来源尚无用户授权，但现有适配器仍请求利弗莫尔和华盛；缺失动态分区因此每天同时产生数据集和来源告警。
- IPO 16:30 `prediction_ready`、18:00/19:30 `core`、19:35 `enrichment` 共用严格核心分区要求。16:30 早于核心分区生成，19:35 只需补全却进入核心分区发布分支；失败发生时核心分区诊断也有被覆盖的时间相关性，需依新实现持续观察。
- 告警生成器遍历结果中所有诊断，未先确认本任务契约是否声明该数据集、当前模式是否实际尝试；`not_run` 也可能被当成故障。
- 重复成功 SQL 按 job、业务日和 mode 统计，合法的 18:00、19:30 两个 `core` 槽位互相触发告警。
- 历史 `bond_listing_liquidity` 告警作用域缺 `CN`，因此精确恢复证据不能匹配注册表中的正式作用域；早间模式不采集流通规模，旧运行诊断仍可能被判为流通规模故障。

## 直接原因、根本原因与保护机制失效原因

- 直接原因是一个任务内多个阶段没有独立的数据发布契约，告警与重复判定的范围大于当前任务槽位实际工作范围。
- 根本原因是完成状态、数据分区质量状态和来源准入状态未始终绑定到模式、注册表 scope 与目标分区日期。
- 保护机制已有统一 Runner、任务契约、分区注册表和告警证据验证器，但阶段发布和告警创建路径没有消费全部契约字段。

## 同类范围与核查结果

- 覆盖 `ipo_history_sync` 的 `prediction_ready/core/enrichment`、可转债公告任务的 `core/calendar`、港股 IPO `preopen/enrichment` 和通用数据集告警构造路径。
- 计划内不同时间槽位（尤其 IPO 18:00/19:30）都须由同槽位判重；数据集告警必须以模式发布白名单及注册表 `scope_key` 为准。
- 历史数据质量告警继续按数据集、市场、日期核对；无对应恢复证据的告警不能标记已恢复。动态来源没有成功探测前只可作为已知未准入条件人工确认，不得假造来源恢复证据。

## 修复与回归证据

- IPO 阶段在现有 `JOB_CONTRACTS` 声明 `publish`、`requirePublished` 和 `requireStageComplete`；16:30 不依赖未来核心分区，19:35 校验核心分区但不重新发布。
- IPO 剩余字段查询在 `prediction_ready` 按目标代码统计；补全未完成会返回失败状态进入现有重试，内部运行记录同步记为失败，防止重试被“当天已成功”短路。
- 分区核验同时匹配 `dataset_code + scope_key + partition_key`；告警生成过滤未声明/本轮未尝试的数据集和 `query_status=not_run`，并捕捉明确的质量失败/覆盖不完整。
- 未授权港股动态源在动态适配器入口安全短路，并从自动任务的来源契约声明中移除；核心 HKEX 事实仍由原任务发布。
- 重复成功只统计具有同一 `slot_id` 的定时运行，并使用槽位作为告警键的一部分。
- `npm.cmd run test:all`：测试库 `portfolio_test` 通过 142、失败 0、跳过 0；`npm.cmd run check:knowledge` 通过并命中 8 条路由。新增的 scope 回归还验证错误市场作用域不能冒充 `ipo_history/GLOBAL` 分区。
- 提交 `1928179`、版本 `0.8.1.82` 已完成标准生产部署；加密备份为 `/var/backups/portfolio/portfolio_20260923_115623.sql.gz.gpg`。线上 `/health`、`/ready`、Web/Worker/健康检查定时器均验收通过。
- 部署后历史告警只读预览扫描 46 条未解决/未确认记录，恢复候选 0、关闭 0；涉及本事故的 11 条告警仍保持活动状态。未执行生产历史数据补跑、手工确认或告警状态改写。
