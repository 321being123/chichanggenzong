## 一、目标与问题依据

解决日期提前一天、时间少 8 小时、历史任务混用当天日期的问题，并恢复招商证券账户因中间快照缺失而无法显示今日涨跌的链路。

已确认：线上 2026-09-25 汇率存在，快照代码却将 PostgreSQL DATE 映射为 09-24，导致当天汇率匹配失败。错误时区公式分布于 6 文件 7 处，另有图表区间和任务水位问题。生产 Node 与 PostgreSQL 均使用 Asia/Shanghai；改变服务器时区不能作为修复。

完整复现、生产证据和条件风险以 INC-0032 为准。本方案负责开发安排，不重复维护事故证据。

## 二、架构对齐与范围

| 分类 | 当前能力与处理决定 |
|---|---|
| 已有能力 | 任务槽位、数据分区、市场日历、汇率事实表、快照 Runner、归因完整性检查、告警恢复证据 |
| 可复用能力 | `jobScheduleSlots.normalizeBusinessDate`、`marketState`、`navAttribution.dateKey`、`replayNav.cnDate` 中已经正确的日期规则 |
| 真正缺口 | 统一日期工具及输入约定、数据库类型边界、目标日贯穿子阶段、跨时区测试、日期静态门禁 |
| 修改边界 | 只调整日期转换、参数传递、数据读取边界及相应验证；保持账户隔离、收益计算公式、人工快照保护和现有任务体系 |

不新增调度器、数据源或事实表，不做全库字段迁移，不全仓替换 `toISOString()`，不整体重构业务文件。日期工具仅收敛现有重复实现。

影响链路：数据源日期 → 数据库 DATE/TIMESTAMPTZ/旧 TEXT → 读取适配器 → 日期工具与任务上下文 → 快照/水位/接口 → 页面显示及告警恢复。

**外部文件兼容合同**：账本导出、Excel 导入、招商券商导入快照保持既有文件类型、工作表、列名/顺序、日期显示格式、币种单位和列含义。修正日期值不等于改变格式合同；以脱敏旧样本做导入/导出对照，保护人工及券商快照标识。确需改变合同应另列兼容方案，不能夹带在日期修复中。

## 三、日期与时间约定

### 3.1 三类值必须分开

| 类型 | 格式与来源 | 处理规则 |
|---|---|---|
| 业务日期 | `YYYY-MM-DD`，如交易日、汇率日、报告期 | 验证实际年月日；作为字符串传递，不转换成时刻 |
| 真实时刻 | 带 `Z` 或明确偏移的 ISO；数据库 TIMESTAMPTZ | 按时刻比较；显示日期时明确业务时区 |
| 任务目标日 | 现有槽位及分区解析结果 | 沿用原业务日/目标数据日字段，逐层传递，不用执行当天替代 |

上海业务显示使用 `Asia/Shanghai`；涉及其他市场按该字段的业务定义确定时区。市场是否开市继续由 `marketState` 判定，不能用工作日或当前时区代替交易日历。

**涉及字段的最小口径表**（纯日期不自带时区，表中时区仅定义业务日归属）：

| 字段/边界 | 业务口径 | 转换约束 |
|---|---|---|
| `market.fx_rates.rate_date`、`daily_prices.date`、`nav_history.date` | 既有估值/交易业务日；上海口径，开市事实按持仓市场 | DATE/标准日期文本直接保留年月日；不能先当成 UTC 时刻 |
| `trades.trade_date/date`、`cash_flows.date` | 账本明确填写的业务日期 | 保留日期；带时间的旧格式按既有上海账本规则解析 |
| `trades.executed_at/created_at`、`cash_flows.created_at`、`nav_history.snapshot_at` | 旧 TEXT 合同为上海本地时间 | 明确解析，不借用运行机器本地时区；不擅自改文件格式 |
| `market.fx_rates.fetched_at`、任务 started_at/finished_at | 真实时刻，无单一业务日 | 按时间戳比较；显示上海时间时显式指定时区 |
| `ops.job_schedule_slots.business_date`、目标分区日 | 上海调度日及既有分区策略 | 市场开市日、前一交易日等交给已有解析器，不等同执行日 |
| T07 成功水位、T08 dataAsOf | 所发布数据实际覆盖日 | 核实底层数据合同，不能用 now 截日代替 |
| 港股 listing/offer 日期、公告事件锚点 | 来源明确的香港业务日期；时刻按 Asia/Hong_Kong | 纯日期直接保留；实际时刻先按市场转换，不假设驱动类型相同 |
| T11 外部文件日期、T12 新鲜度输入 | 来源业务日期或显式时间字段 | 先确定来源与单元格类型；不能一律补 8 小时 |
| T13 市场周期图表截止日与美债来源日 | CN/HK 日期型图表窗口按上海/香港共同业务日；美国来源观察日期仍按原值保存；手工文件当前日期边界按北京时间 | 图表日历年截点已修正并纳入缓存版本；用户确认北京时间后，两个 US/10 手工导入入口均用上海业务日限制最多 6 个日历日的前向填充；原始观察日期不变。无真实来源文件样本，6 日规则仍按现有软件合同保留 |

此表不能替代来源合同；未明确项在 B00 留样并登记决定，禁止实施者凭显示习惯选择时区。

### 3.2 最小公共能力

共享工具落点固定为 `public/shared/core-date.js`，沿用 `public/shared/nav-math.js` 的 CommonJS/浏览器双用方式，从现有正确实现收敛能力；不再建立第二份服务端日期工具。该工具已在 R1 落地。工具仅包含：

- 严格校验业务日期，以及在来源边界转换明确的 `YYYYMMDD` 格式。
- 将真实时刻转换为指定业务时区的日期或显示时间。
- 本次图表需要的纯日期年份区间计算；闰日减到非闰年时取当年 2 月最后一天。不新增月份加减、通用月末收敛或相对日期能力；既有日历逐日运算保持在原职责中。

现有 `todayCN/cnDate/nowStr` 可保留薄包装以兼容调用方，内部统一委托。核心工具不得猜测英文日期字符串或无偏移时间字符串的语义。

工具不做智能日期猜测，不解析“昨天”等相对时间，不新增 moment/dayjs 等日期依赖，不承担市场开闭市判断或外部取数职责。

旧账本需要 `YYYY-MM-DD HH:mm:ss` 的字段，继续保留原格式，明确其含义为上海本地时间；本次不改变历史字段存储结构，也不把旧字符串直接传给通用 Date 解析器。

### 3.3 数据库边界

- DATE 优先在 SQL 用 `::text` 输出业务日期，避免先转 Date 再尝试还原。
- TIMESTAMPTZ 需要取业务日期时，先明确时区后格式化；不直接截 ISO 日期。
- 不在本次直接修改全局 pg OID 1082 解析器；该变更影响所有依赖 Date 的消费者，需要单独完成兼容盘点后再决定。OID 1184 的真实时刻语义保持不变。
- 已有例外：`server/scripts/repairFxRateHistory.js:4` 顶层调用 `types.setTypeParser(1082, value => value)`，对所在进程共享的 pg 类型解析器有副作用。只允许在独立脚本进程运行，禁止由 Web/Worker 或测试主进程 require。当前指定目录引用搜索未发现常驻代码引用，但这不构成自动隔离保证；T14 必须检查引用路径、入口副作用与进程隔离回归，不能为复用日期函数引入该脚本。
- 合法的 UTC 日历运算、Excel 序列号换算和真实时刻 ISO 序列化继续保留。

## 六、生产恢复与发布安排

### 6.1 代码发布

**发布授权独立登记**：生产部署须有用户明确针对发布的指令（文字或语音均可），记录授权消息及批次范围。本方案批准、“更新文档”“开始开发”均不构成部署授权。已有明确部署指令在其范围内有效，无须对同一授权反复请示；范围之外不能自行扩大。文档本地提交也不表示已推送或已部署。

按仓库标准流程完成版本记录、本地验证、提交推送、Git 部署和 systemd 检查。版本号按实施时最新版本递增，不在本方案写死下一版本。

本项目本次发版条目采用“新增/优化/修复”分类前缀，同版本按新增→优化→修复排序；沿用 `add_changelog.py` 同步 `CHANGELOG.md` 与 `public/changelog.json`。面向用户写实际结果，如“修复持仓涨跌因日期错位而不显示”，不只写“修正 cnDate 公式”。这是本方案明确的发版验收要求。

发布验收必须检查相关接口及静态资源版本、任务运行记录和数据分区，不能只看 `/health`。涉及本地服务刷新时按项目低性能模式及当前授权执行，无法完成的运行态验收如实记录。

### 6.2 历史数据处理

代码正确不代表缺失快照自动恢复；历史补算作为独立步骤：

1. 先只读生成账户、日期、缺失/疑似错误类型、可用行情汇率、保护锚点和预计影响行数清单。
2. 优先核对招商证券账户 2026-09-25；7—8 月缺口分别核实，不默认属于同一原因。
3. 对同类港股账户做同口径核查。无法证明已存在记录错误时，不覆盖原值。
4. 提供具体备份、补算、差异比较及回滚范围，按项目规则单独取得生产数据写入确认后再执行；确认前不生成同步 SQL。
5. 复用原快照 Runner，保持账户隔离、幂等性、人工校准和券商导入保护。仅消费对应日真实数据，缺依据继续报告缺失。
6. 净值、收益归因、分区与告警恢复证据一致后关闭事故；不能手工清状态制造成功。

### 6.3 回滚

- 代码回滚遵循标准 Git 发布流程；若回滚到仍有日期缺陷的旧版，不得继续执行受影响的生产补算。
- 数据回滚只恢复经过确认且本批确实变更的记录，依据行级备份和差异清单操作；不能恢复整个数据库覆盖其他正常写入。
- 发现错误日期写入或金额差异无法解释时停止后续补算，保留运行 ID、输入依据和差异结果。

### 6.4 缓存失效、最长影响窗口与性能

2026-09-28 代码核对结论如下；这是发布方案，不代表缓存已清理。

| 缓存/留存层 | 当前实现 | 发布处理及影响窗口 |
|---|---|---|
| 快照汇率 Map | `navSnapshot` 每次运行从库中建局部 Map | 新版本新运行重新建键，不存在需删除的共享键前缀；确认旧版本任务已结束或按既有发布流程退出，不能让其继续产出 |
| 节假日内存缓存 | `holidays` 使用 `_cache/_cacheDay`，按日复用 | 按标准流程重启 Web/Worker，首读重建；所有相关进程完成切换后不再保留旧键。重启完成前不验收 |
| 汇率事实与新鲜度 | `fxRate` 直接读库；普通路径 `<24h`，实时路径同业务日 `<5min` 复用 | 24h/5min 是采集新鲜度阈值，不是数据库错误记录的 TTL。历史行不会自动删除，不能宣称脏数据最多留 24h；已确认错日记录需按 6.2 定向处理 |
| 浏览器脚本/页面状态 | 旧页面可能持续运行旧函数 | 更新实际变更脚本资源版本，重新加载后验收；已打开页面未重载前没有可承诺的最长窗口，不算部署后新页面验证通过 |
| 市场周期 HTTP 缓存 | `applyPublicCache` 默认 max-age=60，ETag 按查询和数据水位生成 | 若 T13 改变响应日期语义，应使对应响应版本/ETag 随修复变化，并核查实际代理规则。仅等待 60 秒不够：旧 ETag 可继续获 304；新版本生效且中间层遵循该头时，旧新鲜响应最多保留 60 秒，之后应获取新响应 |

当前已查路径没有可直接套用的“日期缓存键前缀清理”操作，禁止猜测 Redis 键或清空全部缓存。若实施发现额外缓存层，先登记具体键、生命周期、失效方式与最长窗口；窗口不明就保持该项未验收。

V12 必查 `public/index.html` 及所有实际引用入口：变更 JS 的 `?v=` 随发布更新，新 `core-date.js` 必须在消费者前加载。保存页面引用 URL、资源响应及运行版本的核对结果，不能只更新 package.json 就判定浏览器已加载新实现。

性能基线随 B00 留档：同一输入下的转换耗时、数据库查询数、外部调用数。日期工具保持纯计算，可复用 Intl 格式器；避免在持仓循环逐条查汇率。修复不能增加页面触发的外部取数或重复全量读取。冷/热缓存分别对照，记录测量条件、重复次数与结果；明显退化需先解释并修正，再发布，不虚构未经测量的耗时指标。
