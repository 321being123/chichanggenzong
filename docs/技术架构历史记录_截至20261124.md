## NAS 旧触发机制及验收记录

- **历史 NAS 副本（2026-10-30）**：方向为 **NAS 主动拉取**，服务器不发起任何出站请求。服务器侧新增只读导出入口 `/usr/local/bin/portfolio-backup-export.sh`——仅支持 `list` / `latest` / `group:<时间戳>`，只读 `/var/backups/portfolio`，组名白名单校验，不实现写操作；备份目录通过 ACL 默认项让 `ubuntu` 账号可读每日新建备份（原先 `700 root:root` 不可读）。NAS 专用 ed25519 公钥在 `authorized_keys` 中限定 `command=` 为该脚本并禁用 pty/转发，参数取自 `SSH_ORIGINAL_COMMAND` 且不经 shell 展开；因 `ubuntu` 是 `(ALL) NOPASSWD: ALL`，该 `command` 限制是必要前提。NAS（绿联 DX4600 / UGOS Pro，内网）侧把每组打成 tar.gz 按组名幂等落盘、保留 8 份、`flock` 防重入并校验 tar 完整性；因其普通账号无法配置系统级定时任务（`crontab` 缺 setgid 位、`/var/spool/cron/crontabs` root 独占、无 sudo/docker 权限、`/etc/systemd/system` 只读），触发放在家里 Windows 计划任务（周日/周三 05:00，`StartWhenAvailable` 补跑），数据路径仍是服务器→NAS 直连、Windows 仅触发不中转。该副本与服务器同城同址，只覆盖硬盘故障、误删、勒索加密与整机损坏，**不构成异地容灾**；解密口令仍只保存在服务器 `/etc/portfolio/backup.env`，必须离线另存，否则服务器整机丢失后 NAS 上的密文不可解。**2026-10-30 副本可恢复性已验证**：NAS 侧两份密文哈希与各自 `.sha256` 一致、清单完整，服务器侧对同组 gpg 解密 + `gunzip -t` 通过且内容为有效 PostgreSQL dump；整库导入演练未做。另注意 `.sha256` 内记录的是服务器绝对路径，跨机校验不能用 `sha256sum -c`，需比对哈希值本身。操作步骤、保留策略与已知边界见[生产部署流程](生产部署流程.md)。
