后两页的处理方式写在这里，避免下一轮重复摸索：
这两页不是"改个发送方式"就行：包含多步表单提交、DELETE、FormData 文件上传、三路并发读取，
且上传不能带 JSON 头。必须按资源（分类／文章／评论／用户／任务）拆成客户端方法后逐组切换，
混在一处改会让失败提示与幂等语义失控。

### 后两页（表单型）实际做法

- `knowledge.js`：八种形态逐处改。保存草稿/发布时正文已是序列化好的 JSON 串，走入口时**透传不再二次序列化**；
  文件导入不设 JSON 头让浏览器自带 multipart 边界；删除类操作原来靠异常捕获区分"网络异常/服务端拒绝"，
  改为按状态码是否为 0 区分，提示文案一字未改。
- `admin.js`：64 处但形态规整，用语法树定位 `fetch(api(...))` 按选项决定换成 get/post/put/del/request，
  只有 `Content-Type: application/json` 的头换成入口的 JSON 头（同时带上遥测），上传保持不带 content-type；
  响应读取统一由 `.json()` 改为已解析的 `payload`。改完用语法树复查、并断言文件内不再有 `fetch(` 与 `.json()`。
