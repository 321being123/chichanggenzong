# INC-0017：IPO发行阶段详情修复未进入生产

状态：跟踪中
日期：2026-09-10

## 现象与影响

生产环境的燧原科技（688801）打新详情仍显示“所属行业：待补全、业务赛道：待补全”，发行阶段预测也仍来自旧日报，未显示当前方案要求的实时事实、待公布字段和可能涨幅区间。

## 根因链路

数据源 → 数据库 → 服务 → 接口 → 页面/任务 → 运行环境：

- 本地代码已增加发行阶段资料补全、19:30 公告刷新、19:45 日报刷新、预测区间和实时详情接口，但这些修改仍在工作区，尚未进入 `origin/master`。
- 生产 `/health` 虽返回版本 `0.8.1.11`，但生产首页静态资源仍引用 `js/ipo.js?v=0.8.1.10`；生产详情接口仍返回旧的 `ipo_reports` Markdown，未执行实时数据库详情分支。
- 生产新股历史接口对 688801 的行业和主营业务仍为空；当前 195 条 A 股新股中有 4 条缺行业、4 条缺主营业务，说明不是单只股票脏数据。

## 直接原因、根本原因与保护机制失效原因

- 直接原因：方案代码没有完成提交、推送、生产部署和发行资料补数闭环。
- 根本原因：只核对了版本号和本地测试，没有把线上接口、静态资源和目标股票同类集合作为发布验收门槛。
- 保护机制失效：版本号复用 `0.8.1.11`，无法仅靠 `/health` 判断 IPO 业务代码是否已上线；生产验收未强制检查详情接口是否走实时事实分支。

## 同类范围与核查结果

生产只读核查时间：2026-09-10。`/api/ipo/history?type=cn_stock&limit=500` 返回 195 条；缺行业和主营业务的代码均为：`301686`、`601091`、`688837`、`688801`。生产随机缓存参数复核后首页仍为 `js/ipo.js?v=0.8.1.10`，688801 详情仍为旧 Markdown。

## 修复与回归证据

- 工作区已完成局部修复：发行阶段资料质量门禁、结果字段待公布状态、发行阶段预测区间、实时详情读取、19:30/19:45 调度和前端缓存版本均已实现。
- 本地 `npm.cmd run test:all`：128 通过、0 失败、0 跳过；Python 测试 72 通过；前端测试 37 通过；`npm.cmd run check:knowledge` 通过。
- 本地服务 `/health` 返回 `0.8.1.11`，本地首页已引用 `js/ipo.js?v=0.8.1.11`，接口已验证实时数据库详情分支。

## 防复发措施与遗留风险

- 发布后必须同时核对提交版本、Web/Worker/健康检查定时器、首页资源版本、目标详情接口、历史列表字段状态及同类缺口数量。
- 生产部署和一次性发行资料补数尚未执行；补数涉及生产历史数据写入，需要用户明确授权。完成发布和补数后，重新核查 4 条缺口、预测阶段/区间以及 688801 详情，全部通过后关闭本事故。
