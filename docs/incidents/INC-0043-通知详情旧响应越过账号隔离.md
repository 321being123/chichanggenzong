# INC-0043：通知详情旧响应越过账号隔离

截至 2026-10-26｜本地通知前端｜已局部修复，专项、全量与本地运行检查通过；未部署。执行证据和相关表单、编码修复统一见[原反馈方案 14.12.4](../意见反馈与版本发布闭环研发方案_20261023.md#14124-整体复测后的局部修复2026-10-26本地未部署)。

## 根因与同类范围

此前多轮修复保护了快照、内存列表及铃铛，却未覆盖详情请求完成后的写入。清缓存只能删除已有内容，不能取消已发出的 Promise；旧成功响应仍会写入正文，旧失败仍会关闭当前详情。

数据源与数据库、投递和接口权限不是本次直接原因：复现用真实前端脚本与可控延迟响应，不需要修改数据库；已授权返回给 A 的数据在 A 请求结束前切到 B 后被前端再次显示，不是接口把 A 的通知查询给 B。

同类核对覆盖通知详情的条目入口和地址栏入口、返回列表、退出清缓存、已读完成后的本地状态及反馈跳转；沿用原列表序号与用户名＋不可复用身份，不增加第二套缓存或请求框架。

## 防复发与边界

通用判据：异步结果写入当前通知界面前，必须仍属于当前请求和当前账号；详情还必须属于当前编号。成功和失败分支均校验，作废详情不得再发已读请求。

`notification-interaction.test.js` 以可控 Promise 覆盖换账号、换详情、旧错误和返回列表，不以检查源码有某个符号代替行为验证；原 `notification-cache.test.js` 继续覆盖账号与身份组合。未做浏览器视觉、实际触屏/键盘、真机或生产验收。
