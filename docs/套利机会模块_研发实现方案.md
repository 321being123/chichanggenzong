# 套利机会模块研发实现方案

> 状态：待研发  
> 编制日期：2026-08-08  
> 适用项目：`portfolio-server`  
> 参考产品：[集思录套利模块](https://www.jisilu.cn/data/taoligu/)

## 1. 结论

GitHub 暂未找到可直接接入、数据可信且覆盖本需求的完整开源项目。本项目不复制集思录数据，只参考其产品形态，在现有 Node.js + PostgreSQL + 原生前端架构内实现。

第一期只做以下 3 类，不做中概股私有化：

1. A 股套利：现金选择权、要约收购、换股吸收合并。
2. 港股私有化。
3. 港股供股权。

首次历史同步范围固定为“执行当天往前 1 个自然年（含当天）”，禁止默认回补 3 年。后续只做增量同步并写入数据库。

## 2. GitHub 调研结论

| 项目 | 可复用内容 | 不能直接使用的原因 | 结论 |
|---|---|---|---|
| [ZHOUJIXIAN/arbitrage-cn](https://github.com/ZHOUJIXIAN/arbitrage-cn) | 套利列表的基础页面思路 | 业务是 LOF 和可转债打新；失败时会生成模拟净值；仓库元数据未提供明确许可证 | 不引入代码 |
| [CNife/my-scripts/arbitrage_calculator](https://github.com/CNife/my-scripts/tree/main/arbitrage_calculator) | 单个换股案例的计算思路 | 参数写死，只覆盖单案例，没有数据同步、数据库、后台审核和许可证 | 仅校验公式思路 |
| [Rockyzsu/stock](https://github.com/Rockyzsu/stock) | 早期财经数据抓取样例 | 业务不匹配，代码陈旧且存在依赖 Cookie 的抓取方式 | 不使用 |
| [easyquotation](https://github.com/shidenggui/easyquotation) | 通用行情封装 | 当前项目已有带数据库缓存、批量查询和异常保护的腾讯行情服务 | 不重复引入 |
| [AKShare](https://github.com/akfamily/akshare) | 通用证券数据接口 | 没有覆盖本需求的完整事件识别、条款解析和审核流程 | 不作为核心实现 |

结论：没有满足“3 类事件 + 官方公告 + 条款解析 + 审核发布 + 实时行情 + 可持续增量同步”的可直接复用项目。研发时只借鉴公开公式和页面字段，不复制来源不明的代码。

## 3. 产品范围

### 3.1 用户页面

在现有主导航增加“套利机会”，页面内只设置 3 个页签：

- A 股套利
- 港股私有化
- 港股供股权

页面默认只展示“审核通过且尚未结束”的事件。每行必须显示公告原文链接、事件数据更新时间和行情时间；行情缺失时显示 `--`，不得用模拟价格替代。

### 3.2 列表字段

#### A 股套利

| 字段 | 说明 |
|---|---|
| 代码、名称 | 目标证券 |
| 币种、现价、涨跌幅 | 来自现有腾讯行情缓存 |
| 现金选择权价格、套利空间 | 有现金选择权时展示 |
| 换股参考价、换股比例、换股套利空间 | 有换股方案时展示 |
| 类型 | 要约收购、现金选择权、换股吸收合并 |
| 方案摘要、当前进程 | 来源于公告及人工复核 |
| 公告、更新时间 | 官方公告链接和最近条款更新时间 |

#### 港股私有化

| 字段 | 说明 |
|---|---|
| 代码、名称、现价、涨跌幅、市值 | 目标证券及行情 |
| 注销价、理论套利空间 | 私有化对价与目标股价比较 |
| 首次公告日、当前进程 | 方案公布、股东会、法院会议、完成或终止 |
| 要约人、持股比例 | 公告披露信息 |
| 过户处、交易方式、人数条件 | 公告披露信息，无内容时留空 |
| 可卖空、备注 | 明确有可靠来源时才填写 |
| 公告、更新时间 | 港交所披露易原文和最近更新时间 |

#### 港股供股权

| 字段 | 说明 |
|---|---|
| 正股代码、供股权代码、名称 | 正股与可交易供股权的关联 |
| 正股价、供股权价、涨跌幅 | 批量读取行情缓存 |
| 供股价、供股比例 | 公告条款 |
| 理论套利价值、理论套利空间 | 按正股、供股权和认购成本计算 |
| 供股权交易期、付款截止日、新股上市日 | 公告关键日期 |
| 章程、公告、更新时间 | 港交所披露易原文 |

### 3.3 管理后台

自动发现的记录先进入“待审核”，不得直接出现在用户页面。后台增加一个最小审核区，支持：

- 查看候选事件和关联公告；
- 修正证券、类型、价格、比例及关键日期；
- 通过、驳回或结束事件；
- 对单个事件重新解析；
- 手动触发一次增量同步。

第一期不做自动交易、收益回测、券商费用计算、消息推送、中概股私有化和移动端专用布局。

## 4. 数据来源与复用边界

### 4.1 官方公告

| 市场 | 主数据源 | 用途 | 备注 |
|---|---|---|---|
| 港股 | [港交所披露易](https://www1.hkexnews.hk/search/titlesearch.xhtml?lang=zh) | 私有化、协议安排、供股公告及文件 | 生产主数据源 |
| A 股 | [巨潮资讯](https://www.cninfo.com.cn/new/index) | 深沪公司公告和附件 | 生产主数据源，新增适配器统一使用 HTTPS |
| A 股 | 上交所、深交所公告原文 | 补充和原文跳转 | 不单独建立第二套重复数据 |
| A 股可选 | [Tushare `anns_d`](https://tushare.pro/document/2?doc_id=176) | 有对应权限时作为公告补充 | 非必需，不能阻塞主流程 |

集思录只作为字段和交互参考，不调用其会员接口，也不依赖其 Cookie、登录态或数据。

适配器使用的官方检索入口：

- 港交所：`GET https://www1.hkexnews.hk/search/titleSearchServlet.do`，传入日期、分类、分页和语言参数；
- 巨潮资讯：`POST https://www.cninfo.com.cn/new/hisAnnouncement/query`，传入交易所、日期、关键词和分页参数。

### 4.2 港交所公告分类

第一期检索以下官方分类，并在入库后用标题规则再次筛选：

- `17100`：受要约公司公告；
- `17150`：要约公司公告；
- `17450`：集团重组或协议安排；
- `17600`：私有化、撤销或取消证券上市；
- `18500`：供股公告；
- `25100`、`25200`、`25400`：收购、私有化相关通函；
- `26800`、`31100`：供股文件及相关公告。

分类中会混入延迟公告、结果公告、盈利预警或上市决定，不能按分类直接发布，必须经过标题分类、事件合并和后台审核。

### 4.3 A 股公告关键词

按交易所和自然月检索以下核心关键词：

- 要约收购报告书、要约收购报告书摘要；
- 现金选择权、异议股东收购请求权；
- 换股吸收合并；
- 换股实施、收购请求权、终止、完成。

前三组用于发现事件，后一组用于更新已存在事件的进程，避免将所有带“终止”或“完成”的公告误判为新事件。

### 4.4 行情

直接复用 `server/services/tencentQuote.js`：

- 浏览器不直接请求外部行情；
- 服务端一次批量查询当前页全部证券，禁止逐行请求；
- 先读 `market_quote_cache`，60 秒内直接复用；
- 有效新行情写入数据库后再返回；
- 上游失败保留旧缓存并标记陈旧，禁止用 0、随机数或估算价覆盖。

## 5. 数据同步方案

### 5.1 首次同步：只同步 1 年

设首次执行日为 `D0`，同步区间固定为 `[D0 - 1 个自然年, D0]`，不自动扩大区间。

执行流程：

1. 在 `ops.data_sources` 登记 `hkex_announcements`、`cninfo_announcements` 数据源。
2. 读取 `ops.sync_cursors`；数据集没有成功游标时才进入首次同步。
3. 港交所“全部证券”检索单次最多覆盖 1 个月，因此从起始日开始拆为 12 个连续月窗口，每段不超过 1 个月，按分类顺序串行抓取并完成分页。
4. 巨潮资讯按交易所、自然月和关键词串行抓取并完成分页。
5. 每条原始响应先写 `ops.raw_records`，再标准化写入公告、事件及套利业务表。
6. 每个窗口成功后立即提交窗口游标，任务中断后从最后成功窗口续跑。
7. 全部窗口完成后记录首次同步完成时间和范围。

若在 1 年窗口内发现某事件的最初公告早于窗口，只标记“历史起点不完整”，不得静默向前回补超过 1 年的数据；如确需补充，由管理员针对该事件手工执行定向补录。

### 5.2 后续增量同步

- 调度频率：每天 `21:30`（`Asia/Shanghai`）执行一次，服务启动时执行一次断点补偿检查。
- 每个数据源分别记录上次成功同步到的 `cursor_to`，下次严格从该时间点继续拉取到本次任务开始时间。
- 港交所和巨潮检索接口只支持日期范围时，以 `cursor_to` 所在日期作为开始日期并包含当天；这只会重复游标当天的数据，依靠来源唯一键幂等更新，不使用固定天数回看。
- 本次任务的结束时间在开始执行时固定，全部分页和入库成功后才将 `cursor_to` 推进到该时间；任一分页失败都不推进游标，下次继续补拉同一区间。
- 只更新发生变化的公告和事件，不重复处理全年数据。
- 单数据源串行执行，设置请求间隔、超时和最多 2 次重试；连续失败后保留游标并记录质量问题。

生产环境首次 1 年回补属于数据写入操作，研发完成后须单独获得执行许可；本方案本身不触发生产同步。

### 5.3 唯一键与幂等规则

- 港交所公告：优先使用 `NEWS_ID` 作为 `source_key`，`FILE_LINK` 规范化后作为第二重去重依据。
- 巨潮公告：优先使用 `announcementId`，缺失时使用规范化后的 `adjunctUrl`。
- 同一公告重复抓取：更新元数据和原始内容，不新增公告。
- 同一证券、同一事件类型、相邻公告链：关联至同一个套利事件。
- 新公告修改价格、比例或日期：保留原公告关联，只更新当前有效条款和 `terms_updated_at`。

## 6. 事件识别与审核

### 6.1 处理流水线

```mermaid
flowchart LR
    A["官方公告检索"] --> B["原始记录入库"]
    B --> C["标题分类"]
    C --> D["下载并提取公告正文"]
    D --> E["识别证券、价格、比例和日期"]
    E --> F["合并到事件链"]
    F --> G["后台人工审核"]
    G --> H["公开套利列表"]
    H --> I["批量读取行情并计算理论空间"]
```

### 6.2 自动解析

复用项目现有 Python 子进程模式和 PyMuPDF（`fitz`）PDF 提取能力，不新建另一套运行环境。解析器输出固定 JSON，不直接写数据库，由 Node.js 服务校验后入库。

至少提取：

- 目标证券、参考证券或供股权代码；
- 现金对价、注销价、供股价；
- 换股比例、现金补偿、供股比例；
- 首次公告日、交易期、付款截止日、上市日；
- 要约人、持股比例、交易方式；
- 事件进程和原文定位依据。

解析结果必须附带 `confidence` 和原文片段位置。价格、比例、证券代码或币种任一关键字段低于可信阈值时，只生成待审核候选，不计算公开套利空间。

### 6.3 状态

- 事件状态：`proposed`、`in_progress`、`completed`、`terminated`、`expired`。
- 审核状态：`pending`、`approved`、`rejected`。
- 公开条件：`review_status = approved` 且事件未结束。
- 公告修订后关键条款变化：事件自动回到 `pending`，审核前继续显示上一版已审核条款并标记“有待审核更新”，不能直接覆盖公开数据。

## 7. 数据库设计

复用现有 `event.documents`、`event.company_events`、`ops.data_sources`、`ops.raw_records`、`ops.sync_cursors` 和 `ops.data_quality_issues`，新增以下两张表。迁移编号在实际研发时使用当时的下一个顺序号；按当前代码可预留为 `054_arbitrage_cases`。

### 7.1 `event.arbitrage_cases`

| 字段组 | 主要字段 |
|---|---|
| 标识 | `case_id`、`market`、`strategy_type`、`source_id`、`source_key` |
| 证券关联 | `target_instrument_id`、`reference_instrument_id`、`rights_instrument_id` |
| 事件关联 | `company_event_id`、`primary_document_id` |
| 状态 | `event_status`、`review_status`、`reviewed_by`、`reviewed_at` |
| 通用条款 | `currency_code`、`offer_price`、`cash_choice_price`、`cash_component`、`swap_ratio` |
| 供股条款 | `subscription_price`、`rights_units_per_new_share`、`rights_ratio_numerator`、`rights_ratio_denominator` |
| 日期 | `announced_at`、`terms_updated_at`、`expected_completion_date`、`rights_trade_start`、`rights_trade_end`、`payment_deadline`、`listing_date` |
| 港股字段 | `offeror`、`offeror_holding_pct`、`registrar`、`transaction_method`、`headcount_required`、`shortable` |
| 审计 | `description`、`raw_payload`、`formula_version`、`created_at`、`updated_at` |

约束：

- `market` 只允许 `CN`、`HK`；
- `strategy_type` 只允许 `a_cash_offer`、`a_share_swap`、`hk_privatisation`、`hk_rights`；
- `(source_id, source_key)` 唯一；
- 价格和比例必须大于 0；布尔字段无法确认时必须为 `NULL`，不能默认成“否”；
- 为 `strategy_type + event_status + review_status`、目标证券及更新时间建立索引。

### 7.2 `event.arbitrage_case_documents`

字段：`case_id`、`document_id`、`relation_type`、`announced_at`、`created_at`。

用途：保留一个事件从首次公告、修订、股东会结果到完成或终止的完整公告链；`case_id + document_id` 唯一。

第一期不新增行情快照表。当前列表指标由已入库条款和现有行情缓存即时计算，避免形成重复行情数据源。

## 8. 计算口径

页面统一规定“套利空间为正数时代表理论上有价差”，与来源页面可能存在的正负号差异隔离。

### 8.1 现金选择权、现金要约及私有化

```text
理论套利价值 = 现金对价 - 目标证券现价
理论套利空间 = (现金对价 / 目标证券现价 - 1) × 100%
```

### 8.2 换股吸收合并

```text
每股理论对价 = 参考证券现价 × 换股比例 + 每股现金补偿
理论套利价值 = 每股理论对价 - 目标证券现价
理论套利空间 = (每股理论对价 / 目标证券现价 - 1) × 100%
```

### 8.3 港股供股权

`rights_units_per_new_share` 表示认购 1 股新股所需供股权数量，不能默认等于 1。

```text
每股新股总成本 = 供股价 + 供股权现价 × rights_units_per_new_share
理论套利价值 = 正股现价 - 每股新股总成本
理论套利空间 = 理论套利价值 / 每股新股总成本 × 100%
```

### 8.4 统一规则

- 第一阶段展示的是未扣佣金、印花税、融资成本和滑点的“理论毛空间”，页面必须明确标注。
- 涉及不同币种时，使用同一时点的数据库汇率；缺少有效汇率时不计算。
- 任一必需价格缺失、停牌、过期或小于等于 0 时不计算。
- 供股权不在可交易日期内时，不作为“当前可交易机会”展示。
- API 同时返回 `formula_version`、`quote_as_of` 和 `data_as_of`，前端不自行实现第二套公式。

## 9. 后端与 API

### 9.1 建议文件

- `server/services/arbitrageService.js`：查询、事件合并、审核和统一计算。
- `server/services/arbitrageAnnouncementSync.js`：首次同步与增量同步编排。
- `server/services/hkexAnnouncement.js`：港交所适配器。
- `server/services/cninfoAnnouncement.js`：巨潮资讯适配器。
- `server/scripts/extractArbitrageDocument.py`：公告正文提取与结构化解析。
- `server/scripts/backfillArbitrage.js`：首次 1 年同步和指定事件定向补录入口。
- `server/jobs/arbitrageSync.js`：调度任务入口。
- `server/routes/arbitrage.js`：公开接口。
- 现有 `server/routes/admin.js`：仅新增审核和手动同步接口，不拆新后台框架。

### 9.2 公开接口

```text
GET /api/arbitrage?type=a_stock&page=1&page_size=50
GET /api/arbitrage?type=hk_privatisation&page=1&page_size=50
GET /api/arbitrage?type=hk_rights&page=1&page_size=50
GET /api/arbitrage/:caseId
```

列表响应至少包含：`rows`、`data_as_of`、`quote_as_of`、`stale`、`formula_version`。服务层先查已审核事件，再对当前页证券做一次批量行情查询并统一计算。

### 9.3 管理接口

```text
GET   /api/admin/arbitrage/candidates
GET   /api/admin/arbitrage/:caseId
PATCH /api/admin/arbitrage/:caseId
POST  /api/admin/arbitrage/:caseId/reparse
POST  /api/admin/arbitrage/sync
```

管理接口沿用现有管理员鉴权和审计日志。同步接口接到请求后创建后台任务并立即返回任务编号，不让 HTTP 请求长时间阻塞；同一数据集同时只允许一个任务运行。

## 11. 异常与安全规则

- 上游返回空列表时，不删除数据库已有事件，也不自动把事件标记为结束。
- 公告解析失败时保留原始记录并生成质量问题，候选继续处于待审核。
- 同步失败不得推进成功游标；连续失败后停止本轮任务并记录错误。
- 外部请求设置超时、响应体上限、官方域名白名单和重定向校验，防止任意 URL 下载。
- 公告正文、标题和备注不得直接作为 HTML 插入页面。
- Token、Cookie 和可选 Tushare 凭证只能从环境变量读取，严禁写入代码或数据库原始记录。
- 不长期保存公告 PDF 二进制，只保存官方链接、摘要、哈希、提取状态和必要结构化字段。

## 12. 测试与验收

### 12.1 自动化测试

1. 3 类公式及边界值测试，结果精确到 `0.01` 个百分点。
2. 港交所和巨潮响应固定样本测试，不依赖测试时访问外网。
3. 首次同步区间严格为 1 年、港交所严格拆成 12 个且每段不超过 1 个月的窗口测试。
4. 增量同步从上次成功 `cursor_to` 接续、日期边界、分页、断点续跑和重复公告幂等测试。
5. 空响应不删数据、失败不推进游标、旧行情不被无效值覆盖的测试。
6. 公告分类误报、条款修订、事件合并和重新进入待审核的测试。
7. 行情批量查询测试，确保当前页没有逐行外部请求。
8. 公开接口只返回已审核且未结束事件的权限测试。
9. 管理接口鉴权、官方链接白名单和文本转义测试。
10. 迁移可重复执行、调度任务注册及互斥锁测试。

### 12.2 验收标准

- 页面只有 A 股套利、港股私有化、港股供股权 3 个页签，不出现中概股入口和类型值。
- 首次同步查询范围不早于执行日往前 1 个自然年，数据库无越界自动回补记录。
- 同一官方公告重复同步不产生重复数据，任务中断后可以从成功窗口继续。
- 所有公开记录都能追溯到至少一份官方公告，并已经人工审核通过。
- 理论套利空间由后端统一计算，抽取样例与人工计算误差不超过 `0.01` 个百分点。
- 页面没有直接访问集思录、港交所、巨潮或腾讯行情；所有数据经过服务端和数据库缓存。
- 上游失败时页面仍能读取已有数据，并明确显示陈旧状态。
- 集思录接口、Cookie 和登录态均不是系统运行依赖。
