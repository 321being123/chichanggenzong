# INC-0021：可转债安全性子页漏加载

状态：代码已修复，已获用户授权，生产部署待执行
日期：2026-09-14

## 现象与影响

进入“可转债 → 可转债安全性”后，表格一直显示“正在加载安全性数据”，用户看不到安全性列表。

## 根因链路

数据库快照 → `/api/bond-safety/bonds` → `loadBondSafety()` → 可转债二级导航：

1. 生产数据库已有 2026-09-11 的已发布安全性快照，公开接口完整列表返回 200 和 310 条有效数据。
2. `public/js/navigation.js` 只调用 `initBondCycleSub()`，由 `public/js/bond-cycle.js` 按子页分发加载函数。
3. `switchBondSub()` 漏掉 `sub === 'safety'` 分支，安全性页面只切换显示状态，没有调用 `loadBondSafety()`，因此浏览器没有发起列表请求。

## 直接原因、根本原因与保护机制失效原因

- 直接原因：安全性子页分发缺少 `loadBondSafety()`。
- 根本原因：为消除上市列表重复请求而调整导航入口时，只验证了“不要额外加载安全性”，未同时验证“进入安全性必须加载”。
- 保护机制失效：现有导航测试只检查静态结构和禁止重复加载，没有覆盖每个子页的实际加载分发。

## 同类范围与核查结果

- 周期、估值、上市、强赎、下修五个子页均有对应加载分支。
- 安全性后端任务、快照、分区水位、公开接口和生产服务均正常。
- 当前生产版本 0.8.1.21；修复版本为 0.8.1.22，已获用户授权，尚未部署。

## 修复与回归证据

- `switchBondSub()` 已补回安全性加载分支。
- `bond-cycle-frontend.test.js` 已增加安全性分发回归断言。
- 静态资源版本已更新，后台安全评分说明统一为 08:30。

## 防复发措施与遗留风险

- 后续导航测试必须覆盖“每个子页进入时调用对应加载函数，且不加载其他子页”。
- 部署后需验收安全性深链接、无 `sub` 默认入口和其他五个子页；本次不涉及数据库同步。
