## 0. 一页结论

**网站运行正常，主要风险集中在数据跨模块传递、状态含义和异常体验。应先修正会误导用户的结果，再优化界面。**

| 视角 | 最需要处理的问题 | 证据 |
|---|---|---|
| 研发总监 | 估值安全性关联失效、日报分区水位错误、异地备份未启用 | 308/308 条估值安全性空白；10-21 分区却记录 7-15 水位；生产异地开关为 0 |
| 用户 | 快速切换证券可能显示上一只；官方公告链接被隐藏；首页局部失败拖累其他卡片 | 离线倒序响应复现；两只债券共 34 个链接展示位置被过滤；失败分支复现 |
| 产品经理 | 到期兑付被叫作强赎、脏名称直接发布、数据完整含义不清 | 6 只到期公告映射强赎；2 只新债名称混入正文；安全性缺失仍显示估值数据完整 |

同时保留一个**受限权限下的进程退出风险 R-1**：已在独立 Node 子进程复现，未向生产发送异常请求。普通登录用户不具备前置权限时无法触发该路由，不能写成"任何用户都能打挂网站"。

已确认的正常项：Web、Worker、健康检查定时器 active，数据库/Redis ready；55 项首页静态资源无 404；账户、个人中心、后台概览、标杆、自选等 5 个私有接口匿名请求均返回 401；A 股/新债日历、研究与市场页面公开接口可读。港股 IPO 的 503 是明确暂停行为，不算网站宕机。

产品观察类（初查 P-2/P-3/P-5 保留为 P-11—P-13）：版本演进以修复为主、外部数据源单点可抹掉整块功能、未闭环清单只增不减——均属规划/治理观察，不计当前故障，供决策参考。

### 1.2 问题清单

#### P1（稳定性风险，已限定触发条件）

**R-1 账户名二次解码可能使 Web 进程退出〔B〕**
- `server/middleware/auth.js:94` 的 `decodeURIComponent` 在 try 外；仓位公开设置路由直接使用异步 `assertOwnership`，没有 `asyncHandler` 包装（`server/routes/positionComparison.js:31`）。
- 在独立 Node 22 子进程调用实际函数，参数名为 `100%`，得到 `URIError`、退出码 1；未连接数据库或攻击生产。全项目无 `unhandledRejection` 进程级兜底（server.js/app.js/worker.js 均无处理器）。
- **触发边界**：须先通过登录和 `benchmark_publish` 能力检查（或管理员身份）；普通账户接口多数已用 `asyncHandler(assertOwnership)` 包装（accounts.js:143 起 15 处），不是"任何登录用户都可触发"。
- 建议局部消除重复解码、包住异步中间件并加合法百分号账户回归。不可通过吞掉全局异常后继续运行来掩盖问题。

#### P2（维护风险，不等同于现存越权漏洞）

**R-2 后台未登记路径默认仅检查员工身份〔B〕**
- `adminCapabilityForPath()` 对未知路径返回 null，外层继续执行（`server/routes/admin.js:40-59`）；当前 `/overview`、`/audit` 是有意采用员工权限的入口，其余已登记接口有能力校验。
- 尚未确认一个普通员工能越权操作的现有运维接口。风险在未来新增接口漏登记；建议为明确公开给员工的路径设白名单，并验证其余路由都登记能力。不是已证实的 P0 越权。

#### 工程维护观察（下列不因风格差异直接判定漏洞）

**R-3 异步错误处理风格并存〔B，P2〕**
- **证据**：`server/routes/knowledge.js` 22 个端点、`ipo.js` 5 个、`meta.js` 1 个全未用 asyncHandler 统一兜底（grep 计数 0），靠各自手写 try/catch；对照 `accounts.js` 40 处、`admin.js` 58 处使用 asyncHandler。两种写法本身不构成漏洞；需按异常分支核验，不能由未使用某个包装器推定会崩溃。
- **影响**：修复建议是统一走 asyncHandler（已失控的进程应记录错误并有序退出），不是重写路由。

**R-4 共享校验复用不足〔B，P2〕**
- **证据**：`server/middleware/validate.js:4-91` 仅被 accounts.js、positionComparison.js 引用；knowledge（22 端点）、admin（61 端点）、import、marketVolatility 均各自手写校验。
- **影响**：其余文件有各自校验，不能推定为"没有校验"；错误响应格式仍需统一核对（有的带 requestId，有的纯文本），排障成本高。

**R-5 Redis 降级边界需持续核验〔B/C，不计当前故障〕**
- 生产 `/ready` 已确认 Redis 正常。`server/config.js` 在生产 `REDIS_REQUIRED=1` 且连接失败时会抛错，并非所有情况下都静默退回内存。
- 无配置时的退回路径仍存在（config.js:68-81、app.js:87-93、rateLimit.js:17-23），但本次未验证生产配置缺失场景；记录为配置约束检查，不能宣称线上会话正在丢失。

**R-6 迁移单文件 7,686 行，多代数据结构并存〔B，P2〕**
- **证据**：`server/db/migrations.js`（163 个迁移函数，migration001→048+）；`bond_history` 归档于 `ops.legacy_bond_history_20260812`（migrations.js:2159-2479），与 `bond_unified`/`stock_unified` 兼容视图并存。
- **影响**：任何迁移改动都是超大文件的合并冲突热点；新接手的人极易读写错层。

**R-7 测试通过仍缺部分跨模块业务不变量〔A/B，P1〕**
- 本次 194 个测试入口全通过，但线上仍有 R-13、R-14、P-6、P-7 等错误，说明测试结论与真实跨模块数据正确性之间仍有缺口。

- *初查另记（降为待核实备注）*：bondRedemption.js、bondRevision.js、meta.js、telemetry.js 在 `server/test/*.test.js` 中未见路由级文件直接引用；复核指出"文件无引用≠无 HTTP 覆盖"，该判据不足，路由级覆盖情况建议专项核实后定论。

**R-8 项目根目录残留本地敏感文件（已被 gitignore 拦住，但不该在这）〔B，P2〕**

**R-9 安全加固待评估，不认定 CSRF 已失守〔B/C〕**

### 1.3 复核轮生产实测新增问题

**R-13 估值模块丢失全部安全性评级〔A/B，P1〕**
- 线上估值列表 308/308 条 `safety_level` 为空；"安全"筛选返回 0 条，而独立安全性摘要已有安全 78、低风险 103、中风险 96、高风险 30、未评级 1。

**R-14 日报分区显示已发布，但实际水位停在旧日期〔A/B，P1〕**

### 2.1 问题清单

#### 主体验问题（初查发现，静态证据，优先级以第 4 节为准）

**U-1 页面坏了会"永远转圈"，不告诉用户出事了〔B〕**
- **证据**：`public/js/home-dashboard.js:281-287`（catch 里只 `console.error`，不渲染失败态）；`public/index.html:101,105`（初始占位"正在加载…"）。首页"近期打新安排/可转债风险分布"两个卡片就这样。投资笔记的搜索/分类加载分支——`public/js/knowledge.js:171-185` `ksLoadArticles` 没有 try/catch（首次 `loadKnowledge` 有捕获），断网=无声卡死+控制台未捕获异常。
- **影响**：用户分不清"坏了"还是"慢"，也没有重试按钮，只能整页刷新。

**U-2 样式缓存版本不同步，存在旧样式风险〔B，P2〕**
- **证据**：`public/index.html:10` 用 `?v=__APP_VERSION__`（随发版自动变），`login.html:9` 用 `?v=0.8.2.1`（钉死），`admin.html:9`、`share-knowledge.html:8`、`ipo-report.html:8`、`bond-revision-motive.html:8` 用 `?v=0.8.0.12`（更旧）；服务端自动替换 `__APP_VERSION__` 的页面只有 4 个（`server/middleware/versionedStaticPages.js:4-9`）。
