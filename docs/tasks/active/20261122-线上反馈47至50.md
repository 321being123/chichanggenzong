## 已确认事实、已排除假设

### #47

- 现行 DOM 四个筛选均为原生 `select`（`bond-val-eval/safety/alert/data`），不是按钮；「全部评价」确为估值结果筛选。
- 无箭头根因：`public/css/bond-valuation.css` 的 `.bond-val-toolbar select { background: var(--bg-surface); }` 以简写清除了共享样式在 `.bond-val-toolbar select` 上设置的 `background-image` 箭头和 `padding-right`。
- 需同时把首项与 `aria-label` 明确为「估值」，避免与安全性/预警/价格数据并列时语义含混；不新增第二个筛选控件。

### #48

- 卡片当前对 `currentDrawdown`、`maxDrawdown` 硬编码 `color: th.up`（红），缺失时仍为红；同页明细表已使用 `trendColor`，零/缺失中性。
- 修复应复用涨红跌绿语义：负值绿色、零/缺失中性；不回撤数值本身。

### #49

- 服务端 `computeNavAttribution` 先取任意较旧正日价作为基准，再以日期不等于应有收盘日判 `basis_price_not_confirmed`；未让同账户已确认的退市固定价参与基准选择，因此即使当前估值合法为 `manual_delisted`，归因仍不完整，卡片显示横线。
- 当前估值 `fxImpact=0` 是周末汇率未更新的合法结果；有证据的真实汇率变化需用合成夹具验证其可计入。不是前端 `currentDate === today` 条件误拦。
- 基准重建 `snapshotTotal` 仍会优先取旧日价；只把 `complete` 改为 true 会造成期初总资产与归因不闭合，必须让基准、当前估值和重建共用同一选中固定价。
- 与 #46 重叠：两者都改 `server/services/navAttribution.js` 的价格/基准读取；#46 还改 `navAttributionRepository.js`、`replayNav.js`、`accounts.js` 路由与 `core-trade.js`。本任务只做 #49 所需的最小局部改动，不改仓储查询契约，整合时按 #46 在前、本任务在后的顺序复核冲突。

### #50

- `ssHelp()` 生成 `<button class="ss-metric-help">ⓘ</button>`；目标组合与候选表头均在同一家族。现有共享浮框已支持 mouseover、focusin、click、Escape 和关闭按钮。
- 修复应把可交互载体改为表头标题文本本身（保留 `data-ss-metric-help`/`data-ss-help-text` 与 `tabindex`），移除圆形 ⓘ 视觉；市场状态标签的独立说明保持原样。
