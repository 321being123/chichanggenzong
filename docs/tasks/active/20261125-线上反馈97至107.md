## 已确认事实、已排除假设

- `#97` 前端默认 30s 超时只是表象；根因是 `getCreationOptions` 对每个候选窗口重复计算全表数据版本/转债校准样本并全量核验一级行业，慢查询叠加后超过 30s。不是单个无索引查询或日历口径错误。
- `#98` 根因是刷新时先 `panel.hidden=true` 再重建，文档高度瞬间塌陷使浏览器把滚动位置钳制回顶部；并非浏览器锚点或表格吸顶逻辑。
- `#99A` 根因是提交成功后服务端没有广播、教师端也没有订阅/轮询，人数只在手动刷新时变化；提交入库本身正常。
- `#99B` 是 `.classroom-btn-group` 默认左对齐且不定宽；同类弹窗仅此底部金额面板，其他共享弹窗沿用既有居中操作区，不受影响。
- `#101` 根因是 `jobFieldLabel` 对未登记字段统一返回「任务信息」且 `formatJobObject` 逐层平铺；内部码没有值映射。
- `#104` 重复「营业总收入」来自 `rep_group` 在多来源/多报告期上下文不一致时退化为 `null`，导致代表行判定失败并补出同名分组标题。
- `#105`/`#106` 是固定首列宽度与表格居中规则作用到分组标题/科目列；`#107` 是 `pct_pt` 直接拼接英文单位。
- `#100` 根因是 `hkSecurityAnalysis.loadHkAnalysisInputs` 误把 `readLatestRatePairUpTo({baseCurrency,quoteCurrency,date})` 写成三个位置参数，仓储解构全为 `undefined` 后查询恒空但不报错；`00570.HK` 为 HKD 市值 + CNY 财报，所有跨币种比值落入 `fx_rate_missing`。不是 `market.fx_rates` 缺数据，也不是币种方向错误。
- `#102` 根因分两层：入库侧港股官方 `reportType` 缺失/别名未识别时显式写 `period_type='unknown'`；读端 `stockSelectionRepository` 只按 `IN ('annual','semiannual','q1','q3')` 过滤，unknown 记录整条被排除，已公告中报回落旧年报。三表与港股概览已在 SQL 中按 `report_period_label` 归一，不在此缺陷范围。
- `#103` 根因是 Tushare `cb_basic/cb_rating` 把上海新世纪评级机构后缀 `sti` 拼在等级后，主同步与评级历史写入未清洗；列表直接透出主档评级，估值折现率/新鲜度/Python 评级序数按整串匹配失败。原回填脚本仅处理 `sti` 的部分路径，主链未统一。
