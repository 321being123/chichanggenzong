# 股票筛选页面交互优化研发方案

文档职责：本次页面交互、实施及验收方案；业务规则仍以[投资策略选股中心研发方案第 27 章](投资策略选股中心研发方案_20261102.md#stock-selection-v2)为权威。

截至 2026-11-09：基于 `9af95b2458d895b71ac870d49303f0a229606e20` 及用户确认设计；**待实施、待验证**，不代表页面或接口已改变。范围是股票筛选页面及其必要的个人组合链路；不新增月度结果。

## 1. 目标与现状

用户要求 A 股、港股内容分开；日、周、季度选择同时作用于上方目标组合和下方结果批次；在表格行业列直接排除股票或行业并立即递补；移除资金设置及历史回测页面区域；指标提供说明。季度是既有历史季度，并非每月。

代码现状：市场页签已存在，但 `ssRenderMarkets` 遍历两个市场并同时显示卡片；周期选择器嵌在结果批次内部，组合在其下。`ssState` 已按市场、周期及批次加载；当前接口提供 daily、weekly、quarterly，季度历史策略与日周策略不得混称。个人设置、完整冻结候选投影、按原顺序过滤与席位/行业上限递补已有实现，现有界面需先保存设置再触发个人测算；不能把已有能力视为本交互已完成。`createSimulation` 禁止以个人批次作为来源，需持续保留原公共来源 ID。

## 2. 页面结构与交互

```text
[A股] [港股]
当前市场概览（仅所选市场）
[每日动态] [每周正式] [历史季度]   批次 [选择]
当前市场 / 周期 / 来源批次 / 结果状态
目标组合                           已填 n/30  排除管理 (n)
  股票 | 行业 [操作] | 指标 …
结果批次（候选）
  股票 | 行业 [操作] | 原排名 | 状态 | 指标 …
```

1. A 股和港股切换时，概览、周期、批次、组合、候选、排除管理同步切换；缺数据只显示本市场空状态，不显示另一市场卡片。请求按账号、市场、周期、来源批次和序号隔离，迟到响应不能覆盖当前页面。
2. 公共周期与批次控件放在两个表格之前。切换后两个表必须显示同一来源；展示结果日期、批次、策略版本与状态。每日明确动态、每周明确正式状态、季度明确历史和实际策略版本；无结果时两表同显空状态。默认值遵守当前策略及已有页面契约，不以日结果冒充周结果。
3. 保留证券名称跳转分析、其他行区域打开详情的已有行为；操作菜单点击不得触发行点击或导航。保留候选分页、排序与全字段，个人排除的候选行标注状态及恢复入口，未加载的记录不能被误判不存在。
4. 在目标组合和候选表的行业列增加可见“操作”按钮：菜单显示“排除该股票”与“排除该行业”，明确名称、代码或行业；行业缺失时禁用行业操作并说明原因，股票仍可排除。A/H 同发行人不连带排除；行业依据源批次的体系、版本、代码，不按名称猜映射。
5. 工具栏提供当前市场“排除管理（数量）”，按行业及股票分组展示并逐项恢复。设置对该用户该市场跨日、周、季度生效；其他用户、市场不受影响。分类版本变化需标为待映射，不按同名自动匹配。设置修改只重算当前所选源批次；切换批次按最新设置重新派生，不回写已有个人历史快照。
6. 移除页面“我的资金设置”“历史回测”两个区域，以及页面首次加载和切换时为它们发出的回测请求。保留原设置、回测数据和接口及其他调用者；移除资金界面不得清空已有预算、仓位或排除字段。个人测算继续采用现有资金参数合同，并在组合摘要说明实际采用的仓位及权重口径；缺省与原合同一致，不因移除界面悄然改策略。

## 3. 排除、递补及失败合同

操作即时启动：冻结当前主体、市场、公共源 run、周期和设置 revision → 保存排除或恢复 → 以保存后的 revision 从同一个公共源生成个人组合 → 同时更新组合及候选状态。源组合保持不变，个人结果显式标注“个人组合”、来源批次和设置版本；禁止把个人 run 当成下一次源 run。历史季度和日周批次仅在其原质量、访问及来源合同允许时派生，不能绕过未就绪或影子限制。

复用现有 settings 及 simulations 用例、完整冻结投影和 `selection_order`；按个人排除、源资格/数据质量、异常、行业上限与原席位规则顺序递补，不重抓行情、不重算基础排名。可用候选足够则补足 30，只数不足则显示 `n/30`、空席及原因；未填席位保留现金，不能降低规则强行补满或放大预设单席权重。对零仓位或不可配置的源批次，沿源策略展示空组合和原因。提示变动只数、递补只数和结果状态。

保存及生成各自有明确进行、成功和失败状态；进行中禁止同一范围重复操作，失败不伪报成功。设置保存失败保留原状态及用户操作，支持重试；设置已保存但生成失败则标明“排除已保存，组合更新失败”，保留来源和 revision，提供重试生成，不能把旧组合标成新结果。409 冲突重新读取最新设置并保留用户意图，由用户重试，不静默覆盖并发变更。切换账号/市场/批次后，旧请求不能覆盖新页面；结果不明时按幂等合同重试，不重复创建不一致结果。

现有服务虽支持个人结果及 revision 保存，实施时须核验并补足：simulation 显式接收并在事务中核对 expected settings revision、冻结来源和设置；请求 ID 同输入复用、异输入冲突；不能只依赖前端先后顺序。逐项操作如沿用 GET/PUT settings，须合并原值并沿用 revision，不另起一套设置事实源。

## 4. 指标说明及全站 UI

沿用 `bond-sub-tab`、`bond-feature-*`、共享业务表格及 `BusinessTable`，桌面保留统一吸顶和横滚；颜色、字号、边框和控件尺寸以[技术架构 5.1—5.3](技术架构.md#51-全局业务表格规范)为准。业务样式只放必要列宽和布局差异。

指标名称附近提供说明入口：PB、PE（TTM）、股息率、PB 正极值比、参考仓位、席位与权重等，内容包含含义、实际数据口径、缺值含义及适用策略版本；历史规则与 V2 各自对应，缺值显示“—”而非 0。说明框在桌面悬停和键盘聚焦可读，手机点按可打开；Esc、点击外部或关闭按钮可关闭并恢复焦点；定位不被横滑容器裁剪或超出视口，重要状态不只靠颜色或 hover。

手机正文按 760px 断点重排、导航按 900px 规则，宽表只在容器内横滑，触控操作区至少 44px，输入字号 16px。排除菜单和管理面板可用键盘、触屏操作，菜单需可读名称、焦点控制和状态反馈。新增可复用的行内操作菜单、指标说明框及排除状态样式，实施时优先进入共享组件与样式；在技术架构 5.1/5.3 原位补充通用规范和实际验证范围，不将本设计标成现役。

## 5. 架构与影响链路

现有金融数据源 → 入库行情、财务和分类 → 已发布或可派生的冻结选股批次及完整排名 → 选股服务和个人设置/模拟 → 现有 API → Presenter/View。页面查看、切换及排除不触发外部采集或新调度；排除与个人结果按既有用例写个人设置与个人派生记录，不修改共享批次。优先扩展现有架构，不新增平行任务、数据源、事实表或调度器；是否需要接口字段扩展以实现事务 revision 核验为准。

主要落点：`public/index.html` 结构；`public/js/stock-selection.js` 渲染与事件；`public/js/presenters/stock-selection-presenter.js` 状态及请求编排；`public/js/api/stock-selection-api.js` 接口；`public/css/stock-selection.css` 页面差异；`public/shared/style.css` 和共享交互能力；必要时扩展 `server/routes/stockSelection.js`、`server/services/stockSelectionService.js` 及仓储原事务。安全沿用登录、CSRF、主体隔离和审计。设计阶段没有修改数据库、接口或调度，实施时按实际影响评估迁移需求。

## 6. 实施与验收

1. 明确当前 UI、设置参数及各渠道的实际行为，设计状态和错误文案；扩展服务端 revision 原子校验、幂等及来源权限，再接表格操作和个人派生。
2. 调整市场与周期布局、移除两个区域及无用请求、实现排除管理与指标说明；对共享样式进行适用性核对，避免复制组件。
3. 回归 A/H 市场隔离、三周期和批次联动、个人/公共标签及快照、排除股票/行业与恢复、双表操作、超过 30 名递补、行业上限、候选不足、空仓、缺行业、分类版本、分页与原详情导航。验证多用户、A/H 证券、跨周期、revision 冲突、请求乱序、幂等重试、保存成功生成失败及切换来源；核对无外采、无多余回测请求。
4. 执行相关前端、服务、真实仓储/数据库和权限回归，按影响范围执行知识门禁；统一发布前对最终代码树运行 `npm.cmd run test:all`，有效证据按生产部署流程复用。核对 320/360/390/430/768/1024/1440px、760/900px 分界、键盘与触屏，视觉及真机在用户允许后执行并分别记录；低性能模式不擅启浏览器、截图或开发服务器。
5. 实施后同步选股专项方案、技术架构 5.1/5.3 及 9.2、知识索引和任务卡；涉及合同变化时核对路由与对应权威文档。单独区分本地实现、自动测试、视觉、真机与生产结果。

本文件仅为设计，尚无实施或测试结论；真实布局、性能和候选不足时的体验均待实现后验证。
