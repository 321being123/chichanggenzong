# INC-0044：智能导入账号切换与事件核对

截至 2026-10-28：本地代码已修复、专项及全量测试通过；生产及浏览器/真机未验，未核查或改写生产数据。

## 根因与影响链路

1. 智能导入原来只比较账户名称。账号实体变化或 A→B→A 切换期间，文件读取、识别、扫码和提交响应可能仍写入当前预览或账户状态；多行提交还可能在切换后继续发送后续行。
2. `/api/data/:name` 返回顶层账户对象及 `trades`；原事件核对按 `data.trades` 读取，缺失时使用前端旧缓存。隔离复现中服务器没有该 ID、旧缓存有该 ID，却被误判为已保存。

账号和账户隔离仍由现有会话与接口鉴权负责；本问题发生在已发出异步请求的结果回写及客户端核对，不改变数据源、数据库表、账本或接口返回格式。

## 本地修复与同类范围

智能导入按用户名、不可复用账号实体、账户和切换代数绑定；切换、退出或离开交易页清理旧预览、扫码和提交状态，返回后由用户主动重新生成二维码。文件读取、Excel/图片识别、扫码回包、整批提交与事件核对均检查所属范围；旧批次不得继续提交新账户或修改新预览。账户加载按请求序号及身份丢弃迟到响应。事件核对只消费服务端顶层有效交易列表，缺失或无权限时失败关闭，不用旧缓存冒充成功。

## 验收与未闭环

`smart-import-identity.test.js` 使用可控 Promise 检查同名新账号、A→B→A、文件读取、扫码、识别、提交、切页和账户加载；`local-endpoints.test.js` 使用隔离 PostgreSQL 生成事件，验证真实账户读取结果可核对已保存 ID、不能把仅存在于旧缓存的 ID 判成功。全量测试 241 通过、0 失败、0 跳过；跨标签页身份变化、浏览器/真机及生产实际影响范围未验，不能据此宣称线上事故发生或已消除。
