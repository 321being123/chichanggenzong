# INC-0006：港币汇率预算等待误熔断

状态：本地已修复，生产待授权发布
日期：2026-09-04

## 现象与影响

2026-09-03 收紧汇率策略后，后台港币汇率任务失败，`/api/hkrate` 返回 HTTP 500，持仓对比也可能因汇率请求异常失败。生产没有被写入错误汇率：最近有效汇率仍为 `0.859029`（2026-09-03），10 个账户均保持该值；但 2026-09-04 没有生成新的汇率记录，产生了 53 次无效自动重试。

## 根因链路

页面每 15 分钟刷新一次 `/api/hkrate`，持仓对比也会调用 `ensureHkRate()`；统一 Guard 按汇率策略的 1 次/分钟、24 次/日和最小间隔拦截过于频繁的请求，并返回 `BUDGET_WAIT`。`server/jobs/hkRate.js` 的通用捕获逻辑把所有 `errorType=rate_limit`（包括内部 `BUDGET_WAIT`）再次写成 `CIRCUIT_OPEN`，且没有携带恢复时间，形成永久来源熔断。随后任务编排只能每分钟探测一次，计划槽位在 90 分钟截止前反复等待，最终失败。

同时，`/api/hkrate` 原本未捕获 `ensureHkRate()` 的异常，因此没有走“读取最近有效汇率”的回退；持仓对比的 `Promise.all` 也没有捕获同一异常。

## 直接原因、根本原因与保护机制失效原因

- 直接原因：内部预算等待和真实上游限流共用 `rate_limit` 类型，汇率适配器没有区分两者。
- 根本原因：昨天的限额整改只验证了 Guard 和任务矩阵，没有把页面定时刷新、持仓对比、适配器错误转换、路由回退和存量熔断状态串成一条端到端链路。
- 保护机制失效原因：测试没有模拟“策略当天收紧且已有计数”的过渡场景；生产只读审计未检查汇率来源的实际 15 分钟调用模式，也未发现文档 24 小时与迁移代码 1 小时最小间隔不一致。

## 同类范围与核查结果

已核查汇率任务、`/api/hkrate`、持仓对比、前端 15 分钟刷新、`external_call_budgets`、`external_circuits`、`job_runs` 和 `market.fx_rates`。汇率入口共 3 个：每日任务、汇率路由、持仓对比；没有其他隐藏的 `ensureHkRate` 调用。生产现存熔断仅为汇率来源级历史误熔断，未发现其他来源同样由 `BUDGET_WAIT` 打开熔断。

## 修复与回归证据

- `hkRate.js`：`BUDGET_WAIT` 只向编排层透传；真实上游限流才写熔断，并保留错误码、接口范围和恢复时间。
- `market.js`、`positionComparison.js`：抓取失败统一回退最近一次有效汇率，不阻断页面和对比计算。
- 迁移 `135_exchange_rate_budget_recovery`：将汇率最小间隔统一为 24 小时，并关闭“因达到日保护线而误开的、无恢复时间的”历史熔断，保留原错误详情供审计。
- 新增 `server/test/hk-rate-guard-regression.test.js`，覆盖误熔断排除、缓存回退和迁移约束；最终发布前还需运行全量 `npm.cmd run test:all` 与 `npm.cmd run check:knowledge`。

## 防复发措施与遗留风险

- 以后限额方案必须逐入口盘点“任务、路由、页面定时刷新、业务服务和脚本”，并做一次真实错误对象的端到端传播测试。
- 策略变更验收必须带入存量预算计数和已有熔断状态，验证“收紧当天”不会把等待变成永久失败。
- 发布前增加生产只读调用频率审计和文档/迁移代码一致性检查。
- 本次代码和迁移尚未按生产流程发布；生产旧熔断和 2026-09-04 汇率缺口仍待获得线上部署授权后处理。
