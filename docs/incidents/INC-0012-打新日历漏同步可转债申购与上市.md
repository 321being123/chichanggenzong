# INC-0012：打新日历漏同步可转债申购与上市

状态：已修复、已部署并完成生产补录与日报核验。
日期：2026-09-08；生产核验：2026-09-09。

## 现象与影响

- 丰茂转债（123283）官方公告已明确2026-09-09上市，但打新日历没有上市事件。
- 润禾转02（123285）在2026-09-08申购，日历和标准主档均未及时出现。

## 根因链路

Tushare `cb_issue/cb_basic` 与交易所/巨潮公告 → 可转债主档及 `event.instrument_events` → 18:05打新日历。

1. 08:00主档任务按上一交易日取数，`cb_issue`截止到2026-09-07，无法看到9月8日新发行数据。
2. `cb_basic.list_date`是原有上市事件的主要入口；交易所上市公告虽然已被公告链看到，但未解析、写入统一生命周期事件表。
3. 18:05打新日历只读数据库，却没有依赖可转债发行事件分区；上游缺失时仍可能按旧事实生成。
4. `cb_issue`混在主档任务中，强赎又有独立07:45公告任务，与07:40公告历史任务重复查询相同官方窗口；扩大到60天日常重叠只能增加请求，不能解决当天时序问题。

## 修复

- 保留既有 `convertible_bond_announcement_history_sync` 作为唯一可转债公告采集任务：07:40处理前一收盘日后的公告，17:30补当天公告和生命周期事实。
- 同一批官方公告在本地路由为发行/上市、下修/转股价和强赎事件；删除独立07:45强赎定时任务。
- `cb_issue`从08:00主档任务移出，只在17:30生命周期槽位调用一次；首次全量，之后按成功游标回退3天增量。
- 官方PDF解析申购日、股权登记日、上市日、债券代码/简称和发行规模，官方事实优先于Tushare快照。
- 新增 `bond_issuance_events` 数据集分区及事件集合质量校验；18:05打新日历同时依赖 `ipo_history` 与可转债发行事件分区，失败时保留上一份有效日报。
- 附加调度槽位允许覆盖主任务的日期策略，07:40使用 `afterTradingDay`，17:30使用 `weekdays`。
