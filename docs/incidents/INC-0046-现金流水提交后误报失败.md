# INC-0046：现金流水提交后误报失败

状态：跟踪中（本地修复，尚未部署）
日期：2026-10-29

## 现象与影响

资金转入页面提示 `isCurrent is not defined`。该错误发生在 POST 响应返回之后，不能据此判断账本未写入；以新 ID 重复提交可能产生第二笔流水。按用户提供的账号和截图金额进行最小范围生产只读核对，发现一笔匹配的当日入金；无法仅凭截图断言是否存在用户未提供的其他尝试，不对生产记录作任何修改。

## 根因与范围

`public/shared/core-returns.js` 的 `addCashFlow` 在请求返回后调用未定义的 `isCurrent`，异常被 catch 当成“记录失败”。同函数承担转入与转出，均受影响。服务端 `tradeLedger.addCashFlow` 在返回响应前已提交事务，按相同 ID 预检去重；旧页面每次点击新建 ID，因而不能依靠服务端幂等阻止用户重试产生新流水。净值记录使用独立的账户守卫，同类检查见本任务测试。

## 修复与验证

本地补齐账户、登录身份和代次守卫；提交中防重复点击；结果未知时保留原 ID 与载荷（当前标签页 sessionStorage，不可用时回退内存），明确提示先核对流水并允许原载荷重试。首次明确拒绝或确认成功后清理；已发生未知结果时，即使重试遇拒绝或版本冲突也保留原 ID，不能据此推断原请求未提交。确认成功后的界面刷新异常提示已记录，不再误称流水失败。前端定向覆盖成功、转入/转出、并发点击、网络和服务端错误、同标签页刷新重试、账户切换、拒绝后改正及刷新异常。跨标签页和关闭标签页后的自动去重不在此保证范围，仍需先核对流水。

生产只读核验不等于线上修复或全部账户排查；完整回归、浏览器和生产发布验收见[任务卡](../tasks/active/20261029-资金流水响应修复.md)。
