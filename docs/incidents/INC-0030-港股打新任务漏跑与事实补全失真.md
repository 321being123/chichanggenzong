## 根因链路

1. 调度：三个港股任务的 `weekdays=true` → `isSlotDayAllowed` → `isWeekday` → `isCnTradingDate`。9 月 25 日在 CN 休市表内，生产 HKEX 官方日历却为开市；当日没有三段任务槽位，最后一轮停在 9 月 24 日。服务存活不能保证目标市场的任务生成。
2. 解析：现有招股书解析结果不包含预计上市/配发/定价时间表，候选 SQL 也不检查这些字段；价格、每手数和招股窗口齐全即可 complete，后续候选为零。
3. 价格：Maximum Offer Price 被识别为价格上下限相等；`syncHkexProspectusFacts` 又以相等为依据写最终价。用现有 Python 解析器对上限 69.88 的最小文本重放，得到 low=high=69.88；03228 已落库原文证据包含 Maximum Offer Price。
4. 质量：`recomputeCompletenessForStoredRow` 合并旧 JSON 后只更新 At 键，177 条保留 Date 键 missing；总体 missing 判定继续读取旧键。9 月 24 日 19:40 招股书补全 candidates=0/enriched=0/succeeded，事实分区按 186 行发布，没有用应补字段集合验收。
5. 页面：招股截止后不再生成申购事件，上市日期缺失又无法生成上市事件；历史表固定“仅官方事实”，认购列固定“已验证”，与已展示的 HKIPOx 参考信号不一致。信号空值分支遗漏服务端 open 阶段，已上市缺配发字段也可能显示“尚未到阶段”。

数据源 → 统一原文/缓存 → IPO 事实与主档 → 同步服务与分区 → 日历/历史 API → 页面各层已有能力，但阶段字段及质量验收未形成闭环。
