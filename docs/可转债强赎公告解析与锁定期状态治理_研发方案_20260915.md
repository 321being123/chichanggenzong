## 1. 结论

豪美新材于2026年5月25日决定暂不提前赎回“豪美转债”，承诺期为2026年5月26日至2026年11月25日，并明确从2026年11月25日后的首个交易日起重新计算强赎触发天数。因此在锁定期内，豪美转债的最终业务状态必须是“暂不强赎”，不能显示“已满足待确认”。官方依据：

- [深交所《关于不提前赎回“豪美转债”的公告》](https://disc.static.szse.cn/download/disc/disk03/finalpage/2026-05-26/17608569-eb07-4f5b-8186-4cb7b0ca6898.PDF)
- [巨潮资讯相关董事会决议公告](https://static.cninfo.com.cn/finalpage/2026-05-26/1225329065.PDF)

现有统一强赎视图已经具备“正式决定优先于数学触发结果”的基本能力。页面仍显示“已满足待确认”，说明有效的不强赎事实没有以正确期限进入最终状态视图。直接原因只能落在以下三类之一：

1. 公告未进入 `event.convertible_bond_call_events`；
2. 公告已入库，但事件类型、证券归属或 `no_call_until` 解析错误；
3. 公告事实正确，但生产视图或迁移版本未使用该有效事件。

本地库截至2026年8月24日的快照中，豪美转债没有任何强赎事件，统一视图只能继续使用价格触发结果。结合强赎功能上线时间、最初31天扫描窗口和后来统一公告任务的3天增量重叠，当前最可能的根因是：**强赎解析器接入了已经推进的共享公告游标，但没有建立自己的历史投影水位和一次性全量回补，上线前的旧公告没有被自动解析。**

实施前仍须对生产库做一次只读SQL核查，最终确认属于“事件缺失”还是“期限错误”；两种情况均由本方案覆盖。

## 2. 目标与非目标

### 2.1 目标

- 豪美转债及全部同类转债在有效不强赎期内不再进入“已满足待确认”。
- 官方公告只采集一次，解析器升级时优先重放已缓存文档，不重复调用外部接口。
- 强赎公告覆盖提示、不强赎、决定强赎、实施、完成、到期兑付等完整生命周期。
- 公告发现、证券匹配、PDF提取、字段解析和最终状态均有独立质量证据。
- 任务不得因“接口成功返回”或“发现了部分公告”而误报整条强赎事实链完整。
- 强赎监控、股债分析、上市转债列表、估值和生命周期继续读取同一份强赎状态。

### 2.2 非目标

- 不改变强赎条款中的股价触发公式。
- 不引入盘中价格计算正式强赎天数。
- 不增加新的定时任务、公告供应商或强赎事实表。
- 不新增“期限待确认”等平行业务状态枚举。
- 不为本期需求新增任意历史日强赎状态表或数据库函数。
- 不用大模型结果直接覆盖官方事实；OCR或模型只能用于提取候选，最终必须通过规则校验。
- 不在页面请求中调用交易所、巨潮、Tushare或腾讯接口。

补充（2026-09-16 规范核查）：强赎公告缓存重解析和下修动机输入默认处理全部待办对象，不再在业务函数内设置 10、50、2000 等隐藏条数或接口调用上限；确需人工调试分批时只能显式传入参数，结果必须标记为 `partial/degraded` 并保留待续跑状态。接口调用量和异常止损统一由任务槽位与 Guard 管理，不能由单个接口函数自行截断。

### 3.2 真正缺口

1. **历史覆盖缺口**：新增强赎消费者后直接复用共享公告游标，没有强赎解析器自己的首次回放水位。
2. **文档关系未接通**：强赎解析仍以URL下载PDF，事件写入未维护已有 `document_id`，无法形成稳定的“缓存文档→解析结果”关系。
3. **完成判定过宽**：`bond_redemption_events` 的 `quality_status` 被硬编码为 `passed`；分区发布校验也尚未对该数据集强制检查解析质量。
4. **解析版本不闭环**：冲突更新没有同步更新 `parser_version`、`document_id`，也没有旧版本待重解析队列。
5. **不强赎语义不足**：缺少锁定开始日、重新计数规则；重新计数首日虽可由交易日历派生，但尚未统一对外表达。
6. **零观察日语义错误**：有效锁定期内没有可计数交易日属于“业务不适用”，不能标为数据不完整。
7. **匹配失败静默跳过**：同一公司多只转债或标题缺少明确简称时，无法唯一匹配的公告不会形成可追踪待办。
8. **历史计算会读未来事件**：按目标交易日重算时，当前 LATERAL 查询未限制 `announced_at <= targetDate`。
9. **日期错误会被静默清空**：当前 `waive` 的截止日不晚于公告日时直接置空，会掩盖跨年推断等解析错误。
10. **测试覆盖不足**：现有测试主要检查关键词和代码字符串，没有真实公告正文、历史回放、日期边界和最终状态的端到端断言。

## 4. 目标架构

```text
上交所/深交所官方采集；失败保留游标并重试
        ↓
ops.raw_records（原始公告元数据，只采集一次）
        ↓
event.documents（PDF字节哈希、缓存位置、提取文本和提取质量）
        ↓
强赎候选分类与证券唯一匹配
        ↓
event.convertible_bond_call_events（版本化结构化事件）
        ↓
有效期状态机 + call-v1数学进度
        ↓
analytics.convertible_bond_call_latest（仅当前最新状态）
        ↓
强赎页 / 股债分析 / 上市列表 / 估值 / 生命周期筛选
```

统一公告任务保留一个外部采集入口，但内部拆分为可独立验收的四个阶段：

1. `discovery`：公告列表完整采集并写入原始层；
2. `document`：PDF按URL和内容哈希缓存、提取文本；
3. `projection`：强赎解析器按自身版本重放文档并写事件；
4. `reconciliation`：校验官方事件、数学进度和最终状态是否一致。

共享公告游标只证明公告列表采集到了哪里；强赎解析器必须在现有 `ops.sync_cursors` 中维护消费者级投影水位：

- `scope_key=convertible_bond_call_projection:call-event-v3`
- `dataset_code=bond_redemption_events`
- `last_success_date=该解析器版本已完整投影到的公告日期`

`dataset_code`始终使用数据集编码，不存解析器版本；版本放在 `scope_key`，日期放在 `last_success_date`。升级到v4时建立新的版本化作用域，以“v4水位追平且旧版本待处理数清零”为切换条件，不把旧作用域误当成当前完成证据。

## 5. 数据结构调整

### 5.1 复用 `event.documents`

`event.documents.content_hash` 已存在，本期固定其语义为“PDF原始字节SHA-256”，不再新增同义的 `pdf_hash`。文档记录补齐以下可重放信息：

- 本地受控缓存位置或已提取正文；
- 正文哈希 `text_hash`，放在提取元数据中，与 `content_hash` 严格区分；
- 提取方式：文本层、OCR；
- 提取状态：`complete / partial / failed`；
- 页数、文本长度、失败原因和提取时间。

`event.documents` 是生命周期、套利和公司事件共用表。本期默认将上述提取信息统一写入既有 `raw_payload.extraction`，避免仅为强赎给共享表扩散一组专用列。只有后续确认某字段需要跨业务高频过滤、建立索引或数据库约束时，才增加正式列；迁移前必须盘点所有写入和读取消费者、验证旧数据兼容及回滚方案。

同一PDF只下载一次。解析器升级、重试和专项回补优先读取缓存；只有缓存不存在或 `content_hash` 校验失败时才定点重新下载。

### 5.2 扩展并接通现有强赎事件表

保留 `no_call_until` 作为正式锁定截止日，并增加或明确以下字段：

| 字段 | 处理方式与用途 |
| --- | --- |
| `decision_date` | 新增；董事会或公司作出决定的日期 |
| `lock_start_date` | 新增；不强赎承诺开始日 |
| `no_call_until` | 已有；不强赎承诺截止日，含当日 |
| `validity_basis` | 新增；明确日期区间、明确重新计数日、期限推算、锁定至到期日 `through_maturity`、人工确认 |
| `document_id` | 已有；接通缓存文档写入和冲突更新 |
| `parser_version` | 已有；事件更新时必须同步更新 |
| `parse_status` | 已有；`complete / partial / failed` |
| `details` | 已有；保存页码、原文证据、置信度、错误码、显式重新计数规则和历史解析摘要 |

`next_count_start_date`默认不新增落库列：服务层通过 `no_call_until` 和 `market.trade_calendar` 派生截止日后的首个开市日，并可作为API派生字段返回。只有公告明确指定的重新计数规则与该派生结果不等价时，才将显式日期和原文证据保存在 `details`，由服务层优先使用且执行一致性校验。`through_maturity` 没有下一轮重新计数，派生值必须为空。

高频筛选和状态判断使用正式列；候选证据和暂未标准化内容继续放入 `details/raw_payload`。不新建第二张强赎事实表。

### 5.3 历史追溯

- 原始公告和文档内容不可因解析器升级被覆盖或删除。
- 事件表保存当前标准结果；旧解析摘要写入 `details.parse_history`。
- 同一来源公告仍以现有唯一键幂等更新。
- 冲突更新必须同时更新 `parser_version`、`parse_status`、`document_id`和字段证据。
- 每日增量和旧版本重放并发命中同一 `source_id + source_key` 时使用条件式更新：解析器主版本高者优先；同版本按 `complete > partial > failed` 保留较高质量结果；同版本同质量必须由相同文档哈希产生确定性结果。旧版本或低质量结果不得反向覆盖，冲突须记录诊断。

## 6. 解析器功能覆盖

### 6.1 事件分类

| 标准事件 | 标题/正文表达示例 | 关键字段 |
| --- | --- | --- |
| `warning` | 可能满足、预计触发、触发条件、强赎提示 | 提示日期、触发区间 |
| `waive` | 不提前赎回、不行使、不实施、暂不赎回、不提出赎回方案 | 决定日、锁定起止日、重新计数规则 |
| `exercise` | 决定行使提前赎回权、触发并赎回 | 决定日、赎回类型 |
| `implementation` | 赎回实施、最后交易日、最后转股日、停止交易 | 登记日、最后交易/转股日、赎回价 |
| `completion` | 赎回结果、完成赎回、摘牌、终止上市 | 完成日、摘牌日、实际赎回结果 |
| 到期兑付子类型 | 到期兑付、到期偿付、到期赎回 | 到期日、停止交易/转股日、兑付价格 |

migration147 已通过正式事件过滤实现“`warning`不能覆盖正式决定”。本期不重复实现状态规则，只用解析器与视图回归测试守住该行为。

### 6.2 不强赎期限表达

必须覆盖：

- `YYYY年M月D日至YYYY年M月D日`；
- `未来三/六个月内（即……至……）`；
- `自……起三/六个月内`；
- `自本次董事会审议通过后N个月内`；
- `以……之后首个交易日起重新计算`；
- `以……为首个交易日重新计算`；
- `若为非交易日则顺延`；
- `至本转债到期日为止不再行使赎回权`、`至转股到期日均不行使赎回权`等锁定至到期日表达；
- 跨年日期、省略第二个年份、中文数字月份、不同连接符和PDF拆行。

解析顺序：

1. 优先提取同一“不强赎决定”句段中的明确起止区间；
2. 其次提取明确的重新计数日期并反推锁定截止日；
3. 再使用董事会日期和明确期限进行日历推算；
4. 公告明确写明锁定至到期日时，以转债主档到期日作为 `no_call_until`，并标记 `validity_basis=through_maturity`；不得仅因截止日为空就推断为锁定至到期日；
5. 仅有“不赎回”决定、无法确认截止日时，保留 `waive + partial`，不新增业务状态枚举；页面根据这两个字段显示“已公告不强赎，期限待确认”，不得回退到“已满足待确认”。

不得在整份PDF中简单选择最大的日期。股东减持计划、付息日、到期日等无关日期必须通过章节和句段上下文排除。

### 6.3 日期校验与错误处理

- 普通期限满足 `lock_start_date <= no_call_until < maturity_date`；公告明确锁定至到期日且 `validity_basis=through_maturity` 时，允许 `no_call_until = maturity_date`；任何情形均不得晚于到期日；
- 锁定开始日通常不早于决定日，允许公告日晚于决定日；
- 派生的重新计数首日必须是 `no_call_until` 之后的首个开市日；
- 最后交易日不得晚于最后转股日；
- 登记日、赎回日、停止交易日之间必须满足公告时序；
- 跨年省略年份时，按相邻明确日期和事件时序推断，不能使用整份PDF中的最大年份；
- 任一冲突均转为 `partial` 并记录错误码，不猜值。

`through_maturity` 只有在公告原文证据与主档到期日一致时才能标为 `complete`。主档到期日缺失或与公告日期冲突时保留原文候选并置为 `partial`，不得把无截止日的普通不强赎公告永久锁定。

现有“`waive` 且截止日不晚于公告日就直接清空 `no_call_until`”的规则必须改为显式校验失败：保留候选值与原文证据，写入错误码并置为 `partial`，禁止把跨年年份推断错误静默变成空值。

### 6.4 证券匹配

匹配顺序固定为：

1. 公告中的转债代码；
2. 转债标准简称及别名；
3. 发行人公司身份＋公告正文中的唯一转债；
4. 同公司只有一只有效转债时的受控兜底。

同一公司存在多只转债且无法唯一确认时，禁止默认选择第一只；必须保存为“待匹配公告”质量问题，后续重试或人工确认。

### 6.5 PDF异常

- 文本层字符过少或乱码时标记为扫描件候选；
- OCR只负责恢复文本，结果仍需通过字段和时序校验；
- PDF下载失败、超过大小限制、加密、损坏或OCR失败均保留公告元数据和失败原因；
- 单份文档失败不回滚其他成功事件，但该数据集不得被标记为完全通过。

## 7. 强赎状态机

### 7.1 状态优先级与时间口径

```text
已完成
  > 已公告强赎/到期兑付
  > 有效不强赎锁定
  > 临近到期
  > 数学已满足/接近/跟踪
  > 数据不完整
```

时间口径分成两类，不能混用：

1. `analytics.convertible_bond_call_latest` 是无参“当前最新状态”视图，允许展示最近非交易日新发布的正式公告，不承诺任意历史日 as-of。
2. `convertibleBondRedemptionService.js` 按 `targetDate` 重算历史进度时，事件查询必须增加 `announced_at <= targetDate`，并继续排除 `warning`，防止未来公告污染历史结果。

本期监控页只需要当前状态，因此不新增参数化视图、函数或历史状态表。若以后出现正式回测或历史审计接口，再单独设计参数化 as-of 查询，不能拿当前最新视图冒充历史快照。

### 7.2 锁定期口径

当 `trade_date <= no_call_until`：

- `business_status=waived`；
- 页面显示“暂不强赎，锁定至YYYY-MM-DD”；
- 数学进度标记为“不适用/锁定期内”；
- `data_status=complete`，前提是官方事件及期限完整；
- 锁定前累计天数不能影响最终状态。

当锁定期结束：

- 从交易日历派生的截止日后首个开市日起重新累计；
- 只纳入该日及之后的有效交易日；
- 未形成完整30日窗口不代表数据缺失，应按实际已发生的有效观察日计算；
- 真正缺行情或停牌证据时才标记 `incomplete`。

未来交易日历可能尚未覆盖锁定截止日之后。此时：

- 锁定期内继续按已确认的 `no_call_until` 展示，不要求提前知道重新计数首日；
- 派生的 `next_count_start_date` 返回空，并附 `calendar_status=not_covered` 和“截止日后首个交易日待日历确认”；
- 不得用“截止日+1个自然日”开始计数，因为该日可能是周末或休市日；
- 日历补齐后自动重新派生；若已经越过截止日仍无日历覆盖，则保持上一份有效状态、将数据标为 `incomplete` 并告警。

`validity_basis=through_maturity` 时不进入上述重新计数流程；到期后由到期兑付、停止交易或完成事件接管状态。

### 7.3 部分解析保护

若已经确认公司作出不强赎决定，但锁定截止日尚未解析：

- 数据层复用 `business_status=waived` 与 `announcement_parse_status=partial`；
- 页面显示“已公告不强赎，期限待确认”；
- 建立高优先级重解析告警；
- 不自行按监管最低期限推算并冒充公告明确日期；
- 在期限补齐前采用保守保护，不能落入 `met_pending`；这只是数据安全保护，不代表法律意义上的永久不赎回。

现有视图对 `waive + no_call_until IS NULL` 返回 `waived` 的行为予以保留，但必须由 `parse_status` 和页面文案明确区分“期限完整”与“期限待确认”。

## 8. 任务、游标与质量门禁

统一公告任务返回以下分阶段统计：

- `discovered`：发现公告数；
- `call_candidates`：强赎候选数；
- `classified`：事件类型已确认数；
- `matched`：证券唯一匹配数；
- `documents_ready`：文档可解析数；
- `parse_complete`：关键字段完整数；
- `parse_partial`：部分成功数；
- `unmatched`：无法匹配数；
- `download_failed / extract_failed`：文档失败数；
- `pending_old_parser`：旧版本待重解析数。

完成门禁的实际落点：

1. 在 `convertibleBondAnalysis.js` 中根据上述统计计算 `bond_redemption_events` 的诊断结果，删除固定的 `quality_status: 'passed'`。决定类公告存在 `partial/failed/unmatched`、文档失败或旧版本待处理时，不得输出 `passed`。
2. 在 `datasetPartitionRegistry.js` 的 `areJobDatasetsPublished` 中，将数据集编码 `bond_redemption_events` 纳入严格质量校验：只有 `diagnostics.quality_status === 'passed'` 才视为发布完成。其底层事实表是 `event.convertible_bond_call_events`。
3. `jobScheduleSlots.js` 已通用支持依赖项的 `requireQualityStatus`，无需为强赎再写专用分支。只有未来某个定时任务声明依赖 `bond_redemption_events` 时，才在该任务的 `datasetDependencies` 中配置 `requireQualityStatus: 'passed'`。
4. 公告采集完整才能推进共享发现游标；原始公告已落库但解析未完成时，可以推进发现游标，但不能推进强赎投影水位。
5. 已缓存文档的重解析不产生外部调用；告警只在对应公告完成匹配和解析后关闭，空查询或普通任务成功不能作为恢复证据。
6. 失败保留上一份有效业务状态，不用空值覆盖正确历史事实。

质量状态建议统一为：所有必需阶段通过时为 `passed`；存在可恢复的部分解析、匹配或旧版本积压时为 `stale`；阶段执行异常时为 `failed`。任务最终的 `succeeded/degraded/failed` 由现有编排规则据数据集发布结果决定，不另造状态体系。

## 13. 测试方案

### 13.1 解析器样本

回归语料先由P0从现有库导出，再由P3回补结果增量补充。人工标注范围固定为：

- 两年窗口内所有 `waive / exercise / implementation / completion / 到期兑付` 候选公告100%标注；
- 所有 `partial / failed / unmatched` 和同公司多债候选100%标注；
- `warning` 按交易所分层抽样：上交所、深交所各至少30份，不足30份则全量；样本必须覆盖纯文本、PDF拆行和扫描/OCR版式；
- 新增解析模板必须把对应失败样本加入永久回归集，不能只保留成功样本。

标注字段和代表场景包括：

- 豪美：六个月明确区间＋截止日后首个交易日重新计算；
- 京源：三个月区间＋指定日期若非交易日顺延；
- 起帆：明确首个交易日重新起算；
- 同日公司公告＋券商核查意见；
- 同公司多只转债；
- 跨年、省略年份、PDF拆行和扫描件；
- 提示、决定、实施、完成、到期兑付全事件类型。

关键字段要求100%与人工标注一致；无法解析必须明确失败，不能输出错误日期后仍标记完整。

### 13.2 状态边界

- 锁定开始日前、开始日、截止日、截止日后首个交易日；
- 截止日为周末或休市日；
- 交易日历未覆盖截止日之后，重新计数日应待确认且不得按自然日开始计数；
- 锁定期内股价已经满足15/30；
- 锁定期结束后第1、15、30个有效交易日；
- 锁定期内转股价变化；
- `waive + no_call_until为空 + partial` 必须显示期限待确认，不能显示数学已满足；
- 后续提示公告不能覆盖不强赎决定；
- 后续正式强赎决定可以按时序改变业务状态；
- 明确“至到期日不再行使”的公告必须锁定至到期日，普通空截止日不得误判为该类型；
- 目标交易日之后才发布的公告不得污染该目标日的重算结果。

### 13.3 任务与数据质量

- 共享公告游标已很新，但强赎投影水位为空时仍能回放历史；
- PDF缓存存在时重解析外部调用数为0；
- 单份PDF失败不丢其他成功结果，但 `bond_redemption_events` 的 `quality_status` 不能为 `passed`；
- 严格发布校验必须拒绝强赎质量非 `passed` 的分区；
- 模糊证券匹配不会写错债券；
- 解析器版本升级后旧记录全部进入队列且最终清零；
- 空查询和普通任务成功不能关闭解析告警。

### 13.4 全链一致性

一致性按两组口径分别验收：

1. **当前状态消费者一致**：同一查询时点，强赎监控、股债分析、上市列表、估值和生命周期读取同一当前最新官方事实；周末或休市日新公告应可立即进入当前状态。
2. **历史目标日一致**：传入同一目标交易日时，所有历史重算只允许读取该日及以前公告，不与无参当前最新视图直接对比。

以下位置在各自同一口径内的业务状态、锁定截止日和数据日期必须一致：

- `/api/bond-redemption`；
