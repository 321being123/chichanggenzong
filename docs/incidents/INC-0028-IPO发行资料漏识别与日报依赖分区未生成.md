# INC-0028：IPO发行资料漏识别与日报依赖分区未生成

状态：本地修复及回归通过；等待 0.8.1.84 标准生产部署与定向数据验收
日期：2026-09-23

## 现象与影响

生产新股 `301660` 的 IPO 发行行业 PE 为空，字段诊断为 `document_not_found`；16:30 `prediction_ready` 因预测资料不完整失败，18:00 `core` 仍因发行 PE 状态为 `pending` 失败。当天 18:05 日历/日报任务依赖可转债上市流通规模分区，但分区未发布而被阻断。用户提到的 `73.66` 未找到同口径公告依据，不能当成已核实数值；发行人风险公告披露 C39 行业最近一个月平均静态 PE 为 `73.18`，口径基准日 `2026-09-18`，见[公告原文](https://paper.cnstock.com/html/2026-09/23/content_2272026.htm)。

## 根因链路

交易所公告发现/巨潮备源 → PDF 解析 → `ipo_history` 与增强诊断 → 16:30/18:00 IPO 阶段 → 可转债流通规模分区 → 18:05 日历/日报依赖门禁。

- 深交所 IPO 列表查询对 `301660` 返回空，但巨潮 `hisAnnouncement` 存在发行风险特别公告；文档角色识别未覆盖风险特别公告，故不能解析公告中的 C39 PE。
- PE 解析未识别“中证指数有限公司发布的……最近一个月平均静态市盈率”表述，也未保留公告口径基准日。
- IPO 事实标准化曾仅根据有发行价/上市日把空发行 PE 推断为亏损。该推断缺少公告证据，也无法识别本例正式披露的亏损状态。
- 可转债流通规模 SQL 在参数化查询中把 `LIKE 'cninfo%'` 写成 SQL 字符串。`%` 被 psycopg 当成参数格式符，查询报错，流通规模事实和数据集分区无法发布，随后阻断日报。

## 直接原因、根本原因与保护机制失效原因

直接原因是发行风险公告漏识别、发行 PE 空值被赋予错误的待补全状态，以及流通规模查询的百分号格式冲突。根本原因是公告标题分类/解析覆盖不足、亏损状态没有坚持证据驱动，以及 SQL 参数化中没有把 LIKE 模式作为绑定参数。现有字段质量诊断、Guard、日报分区依赖门禁正确保留了缺口并阻止不完整日报。

## 同类范围与核查结果

- 发行资料缺口可能影响任何仅在投资风险特别公告中披露行业 PE、且交易所公告列表检索未命中的 A 股新股；修复继续遵循交易所优先和现有 CNINFO 备源，不新增公告源或采集任务。
- 空发行 PE 的旧推断可能影响所有尚未解析到发行 PE 的新股；修复后只有官方原文明确“尚未盈利”才将状态记为 `loss`。
- `LIKE` 百分号冲突仅定位于 `sync_bond_listing_liquidity.py` 的巨潮旧记录筛选；同文件查询模式通过绑定参数传入。

## 修复与回归证据

- 加入发行风险特别公告识别及既有 CNINFO `hisAnnouncement` 回退；行业 PE 解析保存 `as_of`、来源角色和文档 URL。
- 发行人 `loss` 状态只由公告“尚未盈利”证据设置；历史字段诊断保留公告时间口径和来源。
- `sync_bond_listing_liquidity.py` 将 LIKE 值改为绑定参数。
- IPO Python 单元回归：89 项通过、0 失败、0 错误；`server/test/ipo-history-sync.test.js` 通过。全量 `npm.cmd run test:all`：142 项通过、0 失败、0 跳过；`npm.cmd run check:knowledge` 通过。部署和生产定向补跑待验收。

## 防复发措施与遗留风险

- 发行公告的标题分类、正文解析、口径日期与证据来源由单测覆盖；亏损状态不从上市/发行价等间接字段推断。
- 可转债流通规模查询保持只经既有生命周期 Runner 写入，日报继续要求正式目标日分区通过质量门禁。
- 生产恢复必须限于确认缺口的 IPO 代码和日报所需流通规模业务日；仅当巨潮 Guard/接口策略放行并获得有效公告响应时才能补出事实，不能把 `73.66` 写成已核实数据。部署后记录 Web/Worker/健康检查、目标分区及日报结果。
