## 快速入口（按需读取）

1. 遵守已加载AGENTS；知识写入先读[公共规则0节](知识库公共规则.md#0-每次任务的最小必读)，详细规则只读本次动作所需章节。
2. 按任务描述＋实际文件筛选机器路由，只提取命中的read/readSections/update/checks/expandOn；不要默认全文读取路由表和架构。
3. 在下方主题中定位当前摘要与证据入口，再读相关完整章节/约束；重叠读取合并，同会话未变内容复用。
4. 冲突、缺证据、根因不明、跨模块或高风险时扩读；历史按证据需要读取。规则全文/指定章节的明确要求仍优先。
5. 一个任务一个对话、另开对话统一部署时，开发与发布均读[公共规则第6节](知识库公共规则.md#6-多agent写入与整合顺序)；任务交接沿用[任务卡模板](tasks/README.md)，发布步骤沿用[生产部署流程](生产部署流程.md)。不依赖汇总全部聊天。

## 统一工作流

开始：确认项目根、Git 基线和未提交改动；按路由读取资料；记录不确定点。

诊断：从数据源、数据库、服务、接口、页面和运行环境检查完整链路；区分直接原因、根本原因与保护机制失效原因；检查同类对象和同类功能。

知识判断：按知识库公共规则先判断必要性及替代关系，明确不新增、就地更新、合并删除或归档；核对旧状态、证据和未闭环范围。

收尾：用实际 `git diff --name-only` 再跑一次路由；更新命中文档；重要取舍写 ADR，重大或重复问题写 Incident；运行 `npm.cmd run check:knowledge`。
