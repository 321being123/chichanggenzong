## 2. 总体架构对齐结论

- **严格遵循单一链路与扩展现有架构原则**：
  - 不新增平行定时任务、不新增平行数据源、不新增平行事实表、不引入第二套调度器。
  - **模拟股市（#80–#83）**：全部复用现役 `classroomRepository.js`、`classroomPrecheckService.js`（含已有 `verifyCandidateBatch`）、`classroom.html/js/css`。

  - **上市可转债（#85）**：复用现役 `server/repositories/convertibleBondListServiceRepository.js`（读取 `market.convertible_bond_daily_metrics`）、`convertibleBondListService.js`、`bond-list-contract.js`、`bond-list-presenter.js` 与 `bond-list.js`。
  - **财报三表（#86–#88）**：扩展现役 `lixingerReportMetrics.js`、`lixingerDatasetAdapter.js`、`stockProjectionRepository.js`、`stockStatementsRepository.js`、`companyFinancialIncrementalSync.js`、`stockStatementService.js` 与 `stock-analysis-statements.js`，沿用统一 Guard、官方限流（单股单批 `MAX_METRICS_PER_REQUEST = 128`）与既有 `stock_financial_reports` 任务契约。
- **部署与数据同步边界**：
  - #80–#83、#84、#85 与 #87–#88 **无生产业务数据写入**。
  - #86 涉及理杏仁原生 `y2y/c2c`（及子口径）存储与历史重采：须先以单股样本跑通「采集 → `stockProjectionRepository` 写入 → `stockStatementsRepository` 回读 → 三表接口」全链路，再确定是否需要数据库迁移；**生产历史批量重采属于生产数据写入，上线后必须另行取得用户明确授权再通过既有受控入口分批执行**。

## 4. 模块二：港股个股分析指标补齐与缺失证据治理（#84）

### 4.1 已有能力、可复用能力与真正缺口

| 指标 | 当前代码状态（`hkSecurityAnalysis.js`） | 已有 / 可复用能力 | 真正缺口与误导风险 |
|---|---|---|---|
| **静态市盈率 / 三年平均市盈率** | `latestAnnual.profit > 0` / `avgProfit > 0` 拦掉亏损股 | A 股 `stockValuation.js` 使用 `signedRatio`；港股 `pe_ttm` 已展示负值 | 亏损股应允许输出负值，与 `pe_ttm` 和 A 股口径对齐 |
| **扣除商誉市净率** (`pb_ex_goodwill`) | `goodwill !== null` 拦掉未列报商誉公司 | 资产负债表采集覆盖元数据（`requested_metric_codes`、`complete`） | `goodwill=null` 可能是未披露也可能是未采到；**严禁**仅凭有资产负债表就按 `0` 计算，否则会高估可计算覆盖率 |
| **动态市盈率** (`pe_forecast`) | 生产代码**已有**中报/季报年化 PE 公式 | `latestInterim` 存在时直接年化 | 仅缺港股专属文案（「最新中报/季报年化」）及可触屏查看的缺失原因 |
| **上市至今年化收益率** | 硬编码 `null` | `market.daily_bars` + `market.adjustment_factors` | 未验证上市初期行情覆盖与首尾复权因子；历史较短时若标「上市至今」会误导用户 |
| **分红率 / 累计分红率 / 平均股息率** | 全部硬编码 `null` | `dividends` 事件表、`annual` 盈利、`daily_valuations` 股本/市值 | 缺完整财年分红覆盖证据判定（空事件不能直接当 `0%`）；缺事件归属财年优先规则与股本推算「估算」标注 |
| **旧快照更新** | `FORMULA_VERSION = 'hk-5'`（`hkSecurityAnalysis.js:11,435`） | 已有版本比对自动重算机制 | 改动指标公式后必须递增 `FORMULA_VERSION`（`hk-6`）并验收旧快照更新 |

### 4.2 详细开发设计

- **文件**：`server/services/hkSecurityAnalysis.js`、`public/js/stock-analysis.js`、`public/css/stock-analysis.css`
1. **亏损股静态 PE / 三年平均 PE**：
   - `peStatic`：`cap.value > 0`、`latestAnnual` 有效且 `profitInMarket !== 0` 时计算 `cap.value / profitInMarket`（亏损输出负值）。
   - `peThreeYearAvg`：连续 3 年年报可换算且 `avgProfit !== 0` 时计算 `cap.value / avgProfit`（亏损输出负值）。
2. **扣除商誉市净率（严格区分“真无商誉”与“未采到”）**：
   - 当 `goodwill` 为有限数值（`>= 0`）时，直接换算扣除计算。
   - 当 `goodwill == null` 时，**必须同时满足**：该期合并资产负债表存在采集覆盖证据且 `coverage.complete === true` 且 `requested_metric_codes` 包含商誉科目（证明已向官方请求且来源未披露），才按 `goodwill = 0` 计算并在 `field_status.pb_ex_goodwill` 记录 `goodwill_not_disclosed_treated_as_zero`；否则保持 `null` 并写明原因（`goodwill_not_collected` 或 `source_batch_incomplete`），绝不虚增覆盖率。
3. **动态市盈率**：
   - **完整保留生产既有港股中报/季报年化公式**，不改既有计算逻辑。
   - 前端针对 `market === 'HK'` 将副标题改为「最新中报/季报年化」；当 `pe_forecast == null` 时输出明确原因（如「最新报告已为年报，暂无新一期中报/季报年化」）。
4. **分红率 / 累计分红率 / 平均股息率（严格覆盖证据 + 估算标注）**：
   - **完整财年分红覆盖证据判定**：仅当分红采集游标/覆盖证据确认该股已完成分红同步（非未采集/采集失败）且无现金分红事件、同时 `dv_ttm === 0` 时，才对盈利财年输出 `payout_ratio = 0`、`average_dividend_yield = 0`（累计盈利 `> 0` 时 `cumulative_payout_ratio = 0`，累计亏损仍为 `null` 并说明「历史累计亏损，不适用」）；缺少分红覆盖证据时保持 `null` 并标 `dividend_coverage_unverified`。
   - **事件归属与股本推算**：
     - 分红事件归属财年**优先使用已核验的 `fiscal_year` 字段**（无 `fiscal_year` 时才按除息日做保守归类并标明）；
     - 若通过 `total_share` 或 `market_cap / close` 推算公司分红总额，结果必须显式携带 `is_estimated: true` 与 `basis: 'estimated_from_shares'`，前端在对应卡片副标题/说明中标注「按股本估算」，不冒充官方公告分红总额。
5. **上市至今年化收益率（覆盖校验 + 实际起算日标注）**：
   - 校验港股 `daily_bars` 与 `adjustment_factors`：要求首尾两端均有有效 `close > 0` 与 `adj_factor > 0` 且区间不少于 30 天，按后复权口径计算年化收益率。
   - 比对最早有效复权行情日 `actualStartDate` 与证券 `list_date`：
     - 若 `actualStartDate` 在 `list_date` 后 30 个自然日内，标注为「上市至今（起算日 `actualStartDate`）」；
     - 若 `actualStartDate` 明显晚于 `list_date`（历史行情覆盖较短），仍可展示区间年化，但卡片副标题必须明确标出**「区间年化（自 `actualStartDate` 起）」**，绝不误标为「上市至今」；
     - 若缺复权因子或样本不足，保持 `null` 并输出缺失原因。
6. **移动端可触屏查看的缺失原因 & 旧快照升级**：
   - 所有为 `--` 或带估算/区间标注的指标卡片，使用原生 `<details>` / 可点击按钮弹窗呈现原因说明（键盘与触屏均可打开，不依赖鼠标 hover）。

### 5.2 「历史新低」精确定义（防误导口径）

1. **价格口径**：统一采用**收盘价口径**（而非盘中瞬时最低价），避免盘中毛刺与不同数据源 `low` 缺失导致口径漂移；页面复选框旁提供可触屏查看的简短说明（tooltip/说明按钮）：「当前现价低于此前全部已收盘交易日的历史最低收盘价（不含今日；历史不足时标记不参与）」。
2. **基准窗口（严格排除当日）**：
   - 从 `market.convertible_bond_daily_metrics` 读取每只目标转债在 **`trade_date < target_trade_date`**（严格排除当日）且 `close > 0` 的：
     - `prev_min_close = MIN(close)`
     - `history_days = COUNT(*)`
     - `history_start_date = MIN(trade_date)`
3. **命中条件与边界**：
   - **严格创历史新低（不含平前低）**：`is_historical_low = Boolean(hasSufficientHistory && bondPrice > 0 && prev_min_close > 0 && bondPrice < prev_min_close)`。
   - **历史不全处理**：若 `history_days < 20`（如刚上市新债）或历史日线缺失（`prev_min_close == null`），判定 `historical_low_status = 'insufficient_history'`、`is_historical_low = false`（不误报为历史新低）；勾选「仅看历史新低转债」时排除此类标的，并在列表统计处标明（如「已排除 N 只历史覆盖不足转债」）。
   - **盘中实时价说明**：盘中叠加腾讯实时现价时，若盘中跌破 `prev_min_close` 会命中、随后反弹回升至 `>= prev_min_close` 时会退出命中，属实时价格筛选的预期行为，在说明文案中一并写明。

### 6.2 严格财报比较口径与守卫定义（#86）

1. **保留生产既有守卫**：
   - 完整保留 `stockStatementService.js` 中对**流量期间依据（`hasFlowPeriodBasis`）**、**比较基期匹配（`sameIdentity` / `sameYearMonthDay` / `isPreviousQuarter`）**与**币种未核实（`isCurrencyUnverified`）**的既有守卫，不得为追求“多出数字”而放宽跨币种、跨合并范围、跨财年或跨列报口径的比对。
2. **逐项比较口径定义**：
   - **基期定义**：
     - 同比（`yoy`）：上年同报告期类型且同财年位置（A 股按 `standardDate` 同月日，港股非自然财年按同财年顺序与 `period_type` 匹配）；
     - 环比（`qoq`）：资产负债表为上一相邻报告期期末时点；利润表/现金流量表仅在**单季口径**或**半年口径**下对比上一相邻同长度期间（累计流量不做跨长度环比）。
   - **适用科目与比率变化单位**：
     - 金额类科目：变化率为百分比（`%`，如 `+12.34%`）；
     - 比例/百分比类科目（如流动资产占比、毛利率）：优先展示原生值；本地推算时明确采用**百分点差值（`pct pt`，如 `+1.25 pct` 或 `+1.25个百分点`）**而非“百分比的百分比”，并在列说明中标注；
     - 含负数金额科目：原生值优先；本地推算按 `(本期 - 基期) / Math.abs(基期)` 时须明确标注「含负基期估算」且仅当 `基期 !== 0` 时计算（若评审确认某类负基期不展示变化率则保持留空并给原因）。
   - **原生值与本地推算值标注区分**：
     - 每个比较单元格携带 `yoy_source: 'lixinger_native' | 'local_derived' | null`、`qoq_source: 'lixinger_native' | 'local_derived' | null`；
     - 前端对本地推算值提供轻量视觉区分（如细微标记或 tooltip 注明「本地推算」），与「理杏仁原生」清晰区分，不混为一谈。
   - **单季拆算前提条件**：
     - 仅当两期累计报表的**币种、合并范围（`statement_scope`）、财年（`fiscal_year`）与列报口径**全部可比且相邻连续时，才允许拆算单季（如 `Q2单季 = H1 - Q1`）；任一条件不可比时禁止拆算并标注 `comparison_basis_uncomparable`。
3. **报告期维度与竖表头子行规则**：
   - **资产负债表**：严格按**时点表**处理，不拆算单季/半年流量（仅在理杏仁实测确认存在且有明确业务含义的维度下才展示对应列，否则统一单行「当期」）。
   - **利润表 / 现金流量表**：
     - 选择「年报」：单行「当期」；
     - 选择「半年报」：适用金额科目拆为「当期 / 半年」两行（比率/占比类维持单行「当期」）；
     - 选择「季报」：适用金额科目拆为「当期 / 单季」两行（比率/占比类维持单行「当期」）；
     - 选择「全部」：**按每列各自实际报告期展示**（年报列只填当期、季报/半年报列按实际口径填报，不强行制造无意义的空白子行）。
