# 可转债周期功能研发方案

> 状态：待开发  
> 适用项目：`portfolio-server`  
> 方案版本：`cycle-v1-135-55`  
> 核心口径：价格中位数 + 转股溢价率中位数 × 动态权重  
> 最终权重策略：100 元及以下为 20%，100～135 元线性提高，135 元及以上按 55% 封顶

## 1. 需求背景

现有一级入口“转债安全性”调整为“可转债”，其下设置两个子页面：

1. **可转债安全性**：保留现有功能、接口和计算逻辑；
2. **可转债周期**：新增本方案定义的市场整体估值周期功能。

周期功能依据《可转债估值波动探讨》的核心思路：

- 可转债整体存在明显周期，不能只观察单只转债；
- 平均价格和平均溢价率容易被妖债、极高溢价转债影响；
- 使用全市场价格中位数和转股溢价率中位数，降低极端个券干扰；
- 可转债接近面值时偏债性，溢价率影响较低；
- 可转债价格升高后逐渐偏股性，溢价率对整体估值的影响应提高；
- 周期指标用于判断市场所处位置，不直接给出买卖建议。

参考文章：

- [《可转债估值波动探讨》](https://www.yuque.com/cunzai/dkzk12/ert4a7moo9dtfx1s?singleDoc)

## 3. 已确认的业务规则

### 3.1 当日样本

数据源使用 Tushare `cb_daily` 当日全市场数据。

符合以下条件的记录进入价格样本：

- 代码符合可转债代码规则：`110 / 111 / 113 / 118 / 123 / 127 / 128`；
- `trade_date` 为目标交易日；
- `close` 为有效数字且大于 0；
- 同一 `ts_code + trade_date` 只保留一条。

在价格样本基础上，符合以下条件的记录进入溢价率样本：

- `cb_value` 为有效数字且大于 0；
- `cb_over_rate` 为有效数字；
- 债券收盘价有效。

不按当前是否仍上市过滤历史记录。历史某日只要存在有效 `cb_daily` 行，就代表该转债当时进入市场样本，避免只保留当前存续转债造成幸存者偏差。

### 3.2 最低数据质量要求

当日必须同时满足：

- 有效价格样本数不少于 **100 只**；
- 溢价率覆盖率不少于 **90%**；
- 覆盖率计算方式：`有效溢价率样本数 ÷ 有效价格样本数`；
- 上游单日返回条数若达到接口上限 2000 条，视为可能截断，不生成正式指标；
- 数据为空、数量突降、字段缺失或单位异常时，不覆盖上一份有效结果。

极高价格和极高溢价率只记录到诊断信息，不因主观阈值随意删除。核心算法通过中位数自然降低极值影响。

### 3.3 三项基础指标

对每个有效交易日计算：

```text
价格中位数 P = median(有效转债收盘价)
转股溢价率中位数 R = median(有效转股溢价率)
转股价值中位数 C = median(有效转股价值)
```

其中：

- `P`、`C` 单位为元；
- Tushare `cb_over_rate` 的单位是百分点，例如接口返回 `35` 表示 `35%`；
- `R` 按百分点参与后续公式，不能先转换成 `0.35`。

转股价值中位数用于页面解释和数据诊断，不重复加入综合估值公式，因为价格、转股价值和溢价率之间存在直接关系。

### 3.4 动态权重

最终公式：

```text
溢价率权重 W = min(55%, max(20%, 20% + (P - 100) × 1%))
```

等价分段规则：

```text
P ≤ 100：W = 20%
100 < P < 135：P 每提高 1 元，W 提高 1 个百分点
P ≥ 135：W = 55%
```

示例：

| 价格中位数 P | 溢价率权重 W |
|---:|---:|
| 95 | 20% |
| 100 | 20% |
| 110 | 30% |
| 120 | 40% |
| 130 | 50% |
| 135 | 55% |
| 145 | 55% |

55%是明确上限，不继续随价格提高，避免出现 180 元对应 100%、200 元对应 120%等失去业务含义的结果。

### 3.5 综合估值

```text
综合估值 S = P + R × W
```

示例：

| P | R | W | 综合估值 S |
|---:|---:|---:|---:|
| 95 | 60% | 20% | 107.00 |
| 120 | 30% | 40% | 132.00 |
| 135 | 20% | 55% | 146.00 |
| 145 | 20% | 55% | 156.00 |

`S` 越高，表示可转债市场整体估值越高。该值是内部综合指标，不代表某只转债的合理价格。

### 3.6 历史分位

周期位置使用最近 **1260 个有效交易日（约 5 年）** 的综合估值计算滚动分位：

```text
历史分位 Q =
（窗口内小于当前值的数量 + 0.5 × 等于当前值的数量）
÷ 窗口有效样本数 × 100
```

规则：

- 窗口包含当前交易日；
- 历史不足 1260 日时，使用当时已有历史；
- 少于 252 个有效交易日时，只展示综合估值，不输出正式周期分位；
- 历史分位保留 1 位小数；
- 历史回填必须按交易日升序计算，防止使用未来数据；
- 页面读取已经落库的分位，不在浏览器实时重算。

### 3.7 周期区间

| 历史分位 Q | 周期位置 | 页面含义 |
|---:|---|---|
| `0 ≤ Q < 20` | 低位 | 综合估值处于近五年较低区域 |
| `20 ≤ Q < 40` | 偏低 | 综合估值低于历史中位区域 |
| `40 ≤ Q < 60` | 中位 | 综合估值处于历史中部 |
| `60 ≤ Q < 80` | 偏高 | 综合估值高于历史中位区域 |
| `80 ≤ Q ≤ 100` | 高位 | 综合估值处于近五年较高区域 |

页面只使用“低位、偏低、中位、偏高、高位”，不使用“应该买入、应该卖出”等交易指令。

## 5. 数据源与更新策略

### 5.1 使用接口

| 用途 | Tushare 接口 | 字段 |
|---|---|---|
| 交易日 | `trade_cal` | `cal_date,is_open` |
| 可转债日线 | `cb_daily` | `ts_code,trade_date,close,cb_value,cb_over_rate,bond_value,bond_over_rate` |
| 基础映射 | `cb_basic` | 复用现有可转债全量任务已经请求的字段 |

`cb_daily` 官方限制为单次最多 2000 条，至少需要 2000 积分。生产实现前再次核对官方字段、权限和更新时间。

官方文档：

- [Tushare 可转债行情 `cb_daily`](https://tushare.pro/document/2?doc_id=187)
- [Tushare 可转债基础信息 `cb_basic`](https://tushare.pro/document/2?doc_id=185)

### 5.2 首次历史回填

首次回填从 `2017-01-01` 开始按交易日请求 `cb_daily`：

1. 使用 `trade_cal` 生成开市日清单；
2. 按交易日升序逐日拉取；
3. 每日先保存原始事实，再计算当日聚合；
4. 样本少于 100 只的日期只保存原始事实，不发布周期指标；
5. 每完成一个交易日即提交事务并更新同步游标；
6. 中断后从最后成功日期继续，不重复全量重跑；
7. 请求限速按 2000 积分账户保守执行；
8. HTTP 429、5xx、超时采用有限次数退避重试；
9. 权限、字段或参数错误立即停止并记录，不无限重试。

预研数据中，首个满足“至少 100 只且覆盖率不低于 90%”的有效日期为 `2018-12-07`。正式回填仍以生产数据库实际校验结果为准。

### 5.3 每日增量

现有 `syncConvertibleBondUniverse()` 已在每天上海时间 16:40 获取一次全市场 `cb_daily`。周期功能必须复用这次返回：

```text
现有可转债全量任务
        ↓ 同一份 cb_daily
保存单债日线 + 保存周期原始事实
        ↓
计算当日市场中位数、权重、综合估值和滚动分位
        ↓
原子写入当日周期结果
```

禁止新增另一个每日任务重复调用同一日 `cb_daily`。

如果现有任务因上游失败未取得有效数据：

- 当日不生成新周期记录；
- 页面继续读取上一有效交易日；
- 任务运行记录标记失败；
- 下一次任务只补缺失日期。

### 5.4 页面读取

页面请求只读取 PostgreSQL 聚合结果，不访问 Tushare，不扫描单债明细，不现场计算全市场中位数。

## 6. 数据库设计

通过下一顺序版本化迁移新增两张表，不修改或删除现有安全性表。

### 6.1 原始日度事实表

建议表名：

```sql
market.convertible_bond_daily_metrics
```

字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `instrument_id` | `BIGINT` | 关联 `core.instruments` |
| `trade_date` | `DATE` | 交易日 |
| `source_id` | `SMALLINT` | 数据源 |
| `close` | `NUMERIC` | 收盘价 |
| `conversion_value` | `NUMERIC` | 转股价值 |
| `conversion_premium_pct` | `NUMERIC` | 转股溢价率，百分点 |
| `bond_value` | `NUMERIC` | 纯债价值 |
| `bond_premium_pct` | `NUMERIC` | 纯债溢价率，百分点 |
| `raw_payload` | `JSONB` | 对应上游原始行 |
| `ingested_at` | `TIMESTAMPTZ` | 入库时间 |

约束和索引：

- 主键：`instrument_id + trade_date + source_id`；
- `close > 0`；
- 按 `trade_date DESC` 建索引；
- 同步必须批量 `UPSERT`，禁止逐条执行数十万次 SQL。

`close` 虽已存在于 `market.daily_bars`，此处仍保留同一份 `cb_daily` 的同步价格，确保转股价值、溢价率和价格来自同一市场日期及同一上游记录。写入时同时维护现有 `market.daily_bars`。

### 6.2 周期聚合表

建议表名：

```sql
analytics.convertible_bond_cycle_daily
```

字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `trade_date` | `DATE` | 交易日 |
| `formula_version` | `TEXT` | 固定为 `cycle-v1-135-55` |
| `universe_version` | `TEXT` | 样本规则版本 |
| `bond_count` | `INTEGER` | 有效价格样本数 |
| `premium_count` | `INTEGER` | 有效溢价率样本数 |
| `coverage_ratio` | `NUMERIC` | 覆盖率 |
| `median_price` | `NUMERIC` | P |
| `median_conversion_value` | `NUMERIC` | C |
| `median_conversion_premium_pct` | `NUMERIC` | R |
| `premium_weight` | `NUMERIC` | W，数据库保存 0～1 小数 |
| `composite_value` | `NUMERIC` | S |
| `rolling_percentile` | `NUMERIC` | Q，0～100 |
| `cycle_level` | `TEXT` | 五档周期位置 |
| `source_id` | `SMALLINT` | 数据源 |
| `diagnostics` | `JSONB` | 缺失、异常、覆盖率等诊断 |
| `calculated_at` | `TIMESTAMPTZ` | 计算时间 |

约束和索引：

- 唯一键：`trade_date + formula_version + universe_version`；
- `bond_count >= 100`；
- `0 <= coverage_ratio <= 1`；
- `0.20 <= premium_weight <= 0.55`；
- `0 <= rolling_percentile <= 100` 或为空；
- 按 `formula_version, trade_date DESC` 建索引；
- 历史聚合永久保留，不按最近 30 份清理。

公式升级时写入新的 `formula_version`，使用已有原始事实重新计算，不重新请求全部历史数据，也不静默覆盖旧版本。

### 7.3 计算顺序

```text
读取某日 cb_daily
  → 字段标准化
  → 代码与数值校验
  → 按 ts_code 去重
  → 批量保存日度事实
  → 计算 P、R、C、样本数和覆盖率
  → 数据质量校验
  → 计算 W
  → 计算 S
  → 读取此前最多 1259 个同版本有效日
  → 计算 Q
  → 计算周期位置
  → 原子 UPSERT 当日聚合
```

纯算法模块不得访问数据库和网络，保证可以用固定样本做单元测试。

## 15. 预研依据与局限

预研样本：

- 有效区间：`2018-12-07` 至 `2026-07-24`；
- 有效交易日：1849 日；
- 每日有效转债数量：101～548 只；
- 平均溢价率覆盖率约 99.96%。

三种权重方案的历史结果非常接近，未证明“完全不封顶”具有稳定优势。历史上价格中位数不低于 135 元的日期仅约占 5%，且主要集中在 2025～2026 年。因此：

- 135 元对应 55%延续了“价格越高、溢价率越重要”的业务逻辑；
- 55%封顶用于控制公式边界，避免权重无限放大；
- 当前公式必须版本化，后续只有在新增完整市场周期和独立验证后才考虑升级；
- 本指标属于研究工具，不能替代独立投资判断。
