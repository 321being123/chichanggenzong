# INC-0019：IPO实时详情遗漏XGBoost与赛道热度

状态：跟踪中
日期：2026-09-10

## 现象与影响

生产日报中的燧原科技（688801）已有 A 股、科创板、XGBoost 预测和半导体热度修正，但点击代码进入的实时详情只显示最终涨幅、行业、主营业务和“上市前版”，没有展示模型来源、模型基准涨幅、热度赛道及赛道修正，用户看到的内容与上线前方案不一致。

## 根因链路

数据源 → 数据库 → 服务 → 接口 → 页面/任务 → 运行环境：

- 发行资料、`business_exposure` 和 `predictions` 已正确写入 PostgreSQL。
- `/api/ipo/report/code` 的 `buildCnStockLiveReport` 为避免旧日报覆盖新补数据，直接读取实时事实，但只选择 `pred_return/pred_date/prediction_context`，渲染时也只输出最终涨幅和预测版本。
- XGBoost 的基准值、赛道系数、样本数和受控修正虽已在 `predictions` 快照中保存，却没有进入实时详情展示层。

## 直接原因、根本原因与保护机制失效原因

- 直接原因：实时详情接口字段选择和 Markdown 组装遗漏预测解释字段。
- 根本原因：日报详情和实时详情没有共用同一组展示契约；已有测试只验证可转债详情底部统计，没有覆盖 A 股发行阶段实时详情。
- 保护机制失效：历史接口有预测上下文测试，但未对 `688801` 这类发行阶段 A 股详情做 XGBoost/赛道回归断言。

## 同类范围与核查结果

已只读核查生产：

- `688801` 返回 `market=CN`、科创板、半导体、上市前版，预测值和资料事实存在；问题是详情解释层缺失，不是证券市场分类错误，也不是模型未运行。
- 同一生产日报已包含 XGBoost 预测详情和当前赛道热度表，说明缺口集中在 `/api/ipo/report/code` 实时 A 股详情分支。
- 本次修复按 A 股实时详情分支处理，不改港股事实和可转债详情链路。

## 修复与回归证据

- [x] 局部补齐实时详情读取 `base_pred_return`、赛道修正、赛道系数、样本数和可信度，并展示 XGBoost 与热度赛道。
- [x] 增加 Node 接口源码回归断言，防止详情再次退化为只有最终涨幅。
- [x] 本地全量测试与知识门禁：`npm.cmd run test:all` 通过 128/128，`npm.cmd run check:knowledge` 通过。
- [ ] 按生产部署铁律发布后核对 688801 详情、A 股历史、日报和服务版本。

## 防复发措施与遗留风险

- 后续 A 股发行阶段详情必须同时核对“市场=CN、预测模型、热度赛道、预测区间、待公布字段和资料状态”。
- 详情只读已入库快照，不在页面请求时重新调用外部数据源；生产发布前不执行历史或模型数据同步。
