# INC-0031：港股待补日历包含已上市股票与中文名回退缺失

状态：本地修复与验证完成，待生产部署
日期：2026-09-26

## 现象与影响

港股打新日历“官方资料待补”列表显示了已经上市的股票，部分股票名称显示“中文名待补”。截图中待补列表共 30 只。用户因此难以区分仍未上市的新股与已进入上市交易的证券。

## 根因链路

HKEX IPO 记录与证券主档 → `loadPendingHkIpoFacts()` → `/api/ipo/calendar` 的 `pending_hk_stocks` → `public/js/ipo.js` 待补列表。

1. 待补查询只限制近期开售日期和 `data_completeness.status='retryable'`，没有排除 `ipo_history.ipo_status='listed'`、`core.instruments.status='listed'` 或已经到达的实际上市日期。事实补全缺口于是被误显示为当前待补 IPO。
2. 港股日历、历史列表和详情只使用 `ipo_history.security_name_cn`、腾讯行情缓存名称和 IPO 英文名，没有读取已存在的 `core.instruments.name`。当腾讯名或 IPO 中文名为空时，证券主档已有的中文名仍不可见；同步任务也没有将该主档中文名补入 IPO 展示字段。

## 直接原因、根本原因与保护机制失效原因

- 直接原因：日历待补查询没有校验上市状态和实际上市日期。
- 根本原因：港股 IPO 项目事实的完整度状态与统一证券主档的生命周期状态没有在用户可见的待补列表中共同核验；名称展示也没有复用标准证券主档。
- 保护机制失效：既有数据质量 `retryable` 只说明仍有 IPO 字段待补，并不代表证券仍未上市。页面把资料完整度当作上市阶段过滤条件使用。

## 同类范围与核查结果

- 2026-09-26 的前序生产核查已确认 `06727.HK`、`09856.HK` 的统一主档状态为 `listed`，上市日期分别为 2026-09-21、2026-09-22，而 IPO 事实记录当时仍缺上市时间。本次待补列表查询会将同类数据纳入候选。
- 只读检查还确认 `02523.HK`、`03228.HK`、`03757.HK`、`06700.HK`、`06731.HK`、`09607.HK` 仍为 `pre_listing`，但生产 IPO 事实和证券主档当时都没有中文名。港交所官方[主板中文新上市页面](https://www2.hkexnews.hk/New-Listings/New-Listing-Information/Main-Board?sc_lang=zh-cn)已列出这些代码的中文名；问题还包括名称补全链路未接入港交所现有中文页面。
- 截图中的 30 条是缺资料候选数量，不能据此断定 30 条都已上市。修复按真实 IPO 状态、主档状态和上市日期过滤，不按截图中的证券名称或代码写入状态。
- 本地业务库当前没有可用于逐代码核对的港股 IPO 记录；因此行为由回归夹具覆盖。没有据此执行生产历史数据修改。

## 修复与回归证据

- `server/routes/ipo.js` 的待补列表排除 IPO 状态或统一证券主档状态已上市、已写入实际上市时间以及上市日期已到的对象；仍未上市且资料可重试的对象继续进入列表。
- 港股日历、历史列表、详情通过现有 `core.instruments` 查找中文名称。选择名称时优先采用已存在的中文 IPO 名称、腾讯缓存名或证券主档名，只有没有中文时才回退英文名。
- `server/services/hkexIpo.js` 在既有探针计划中增加港交所主板/GEM 中文新上市页解析；只在每日现有 `enrichment` 阶段请求，并与英文官方事实按证券代码合并。`upsertHkIpoFacts()` 将官方中文名写入现有 `ipo_history.security_name_cn`，不新增名称映射或数据表，不写死证券名称。
- `server/jobs/hkIpoSync.js` 在现有 Tencent 名称补全之后，将统一证券主档中已有的中文名补入 `ipo_history.security_name_cn`；已有中文值保持不变，英文值允许由中文值替换。已上市过滤修复仍会从日历待补列表排除上市 IPO/主档/上市日记录。
- 针对性回归：`node server/test/ipo-history-contract.test.js`、`node server/test/hk-ipo-facts.test.js` 均通过。
- 全量测试：`npm.cmd run test:all` 通过 145 项，失败 0、跳过 0；`npm.cmd run check:knowledge` 通过。名称夹具覆盖官方中文版解析、名称合并以及只在 enrichment 阶段加入中文探针。
- 用隔离测试库实际请求 `/api/ipo/calendar?market=HK&days=30` 返回 HTTP 200，确认查询语句可执行。测试库没有港股 IPO 样本，因此本地没有生产历史数据覆盖证据。
- 本地代码尚未部署，未执行生产名称回填或历史数据同步；线上名称会在发布后由每日 enrichment 增量补齐。

## 防复发措施与遗留风险

- 日历“待补”列表必须同时核对 IPO 事实状态、统一证券主档状态和实际上市日期。
- 中文名称优先复用已落库的行情缓存与统一证券主档；页面请求不得临时回源。
- 生产仍运行此前部署版本。在获准发布前，线上日历和中文名称表现不会改变。本机 3000 端口的旧进程也未重启；按工作区的低性能模式要求，没有未经允许启动或重启开发服务。真实历史覆盖需在标准部署后按授权进行只读核对。
