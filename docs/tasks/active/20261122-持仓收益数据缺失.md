## 追加实现：交易录入自动补齐成交日收盘价（2026-11-22）

### 根因与条件

- 两个账户同属本人、同证券、同一历史成交日先后录入时，交易接口本身只刷新当前行情；历史收盘价补齐原先只由前端在 `pickedDate < today` 时另发的 `recompute-nav` 间接完成，且 `recomputeNav` 依赖已有净值行并按账户读取 `daily_prices`。没有净值行的账户会直接返回 `no_nav`，不会触发 `backfillDailyPrices`；有净值行的账户也可能因现金收益结算的版本竞争在补价前 409。
- 生产只读证据只用于定位：交易接口已返回 200，随后 `recompute-nav` 返回 409；Web journal 同秒附近记录“账户版本已变化”，对应 `settleCashIncome` 的读后写版本校验。不能据此认定第一账户价格的具体写入时刻，也不能推断第二次 HTTP 的完整结果。
- 既有前端只检查 `jj.ok`，对 409/400 没有提示；本实现保留 HTTP 兼容语义，新增结构化字段由新页面提示。

### 最小补丁

- `ensureTradeClosePrice`（`server/jobs/replayNav.js`）：交易事务提交后独立执行，不进入账本事务。仅处理成交日 `< 今天`；按市场日历找该成交日对应的应有收盘日（周末/节假日回退到最近开市日）。本账户与共享价同时读取并先做同日冲突核对：
  1. 本账户与其它账户同一「市场 + 代码别名 + 精确日期」的 `confirmed` 正价若出现不同价格（含本账户已有 confirmed 与另一账户不同价）→ `shared_close_conflict`，整日不写；
  2. 本账户已有 `confirmed/final` → `already`；
  3. 本账户只有 confirmed 非 final → `local_close_not_final`，不让共享/网络结果冒充终盘；
  4. 本账户无可用的公开确认价、共享有 `confirmed/final` → 复制到本账户并只保留公开来源/资格字段，标记 `shared_close_reuse` → `reused`，零网络；
  5. 真缺 → 只对该证券该收盘日调用现有 `backfillDailyPrices(..., start=end, { qualifiedOnly: true, businessDate })` → `fetched`；
  6. provider 无数据/失败 → `pending` 并带原因，交易仍算已保存。
- 当天/未来成交日直接 `skipped`（`today_close_flow`），不写盘中候选或成交价；现有收盘任务继续负责当日正式收盘。页面仍由当前统一估值读取同日确认价，未经收盘不在此补正式终盘。
- `backfillDailyPrices`/`backfillHkDailyPrices` 增加可选 `qualifiedOnly`/`businessDate`：交易定点补价只写 `quality=confirmed`、`is_final=true` 且日期等于请求成交日的行；provider 多返回的日期和候选行一律不落库。默认重算行为不变。
- 本账户精确读取复用 a6218313 的 `navAttributionRepository.listOwnPricesAt`，共享读取复用 `listSharedConfirmedAt`；删除本轮新增的 `accountsRepository.listPricesAtIdentity`，不复制第二套 SQL。共享账户 evidence 不整包复制，只保留 `origin/provider/price_adjust/market_basis/qualification/terminalEvidence` 等公开资格字段。
- 交易路由 `POST /api/accounts/:name/ledger/trades`（含幂等重复命中）在 `applyTrade` 提交、当前行情刷新后返回独立的 `closePrice` 结果；批量期初事件保持现有导入补价任务边界，不逐条外采。
- `recomputeNav` 将现金收益结算改为 `settleCashIncomeForRecompute`：仅对已知 409 版本竞争在最新状态有限重试一次；仍失败、其它结算失败或结算明确 `partial` 时立即返回 `pending/ok=false`，不读取/重放净值、不写快照、不清除 `nav_dirty_from`。401/403 授权异常原样抛出；其它失败保留原 `httpStatus` 但按待重算报告，不包装成成功。
- 路由保留异常原状态码；现金结算待重算按原因返回 409（版本竞争/partial）或原失败状态码（其它失败）并带结构化 `reason/cashSettlement/warnings`，历史净值日期未闭合保持原有 400 语义。同一原因只产生一条警告。
- 既有历史 replay 的逐证券补价范围保持原默认 `fromDate..today`；本轮未把该范围改成 `d..lastNavDate`，避免与该问题无关的回归。新定点流程只按选中证券和成交日取价。
- `public/shared/core-trade.js` 手工录入复用 `captureSmartImportScope` / `isSmartImportScopeCurrent`（账户、登录身份、generation）：交易、重算、重载任一 await 后校验；离开又返回或同名换人也不接收迟到响应。账号切换后只有 `r.ok` 才提示“已记入原账户”；`r.ok=false`/网络异常提示结果未确认。同一登录主体切账后可继续重算原账户，页面状态不应用迟到结果。补价仍待完成时不会立即从旧重算入口重复取价。兼容旧服务只有 `error`、没有 `ok` 字段的响应。
- 冲突证据只记录原因码和数量级，不记录账户名、证券代码或交易金额；不新增平行采集器、任务或事实表。
