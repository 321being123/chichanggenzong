# 可转债下修动机评分功能研发方案

> 状态：`motive-v1.1` 止血修正版已实现；本地历史评分回填与公告前样本外回测已执行但未达上线门槛，生产输入同步与发布仍需单独授权
> 编写日期：2026-08-30  
> 适用项目：`portfolio-server`  
> 方案版本：`cb-revision-motive-v1.1`
> 产品位置：现有“可转债｜下修监控”列表 + 新增单债“下修博弈详情”页  
> 已确认权限：主 Tushare 为 6000 积分，允许使用 5000 积分接口  
> 核心目标：区分“满足下修条款”和“发行人有强烈下修动机”，识别值得优先研究的可转债

## 1. 需求背景

现有下修监控已经能够回答：

- 当前是否处于不下修锁定期；
- 正股是否满足下修价格条件；
- 已满足多少天、最快还需多少交易日；
- 是否受每股净资产底线限制；
- 是否已经提议、表决、实施或拒绝下修；
- 公告、行情、条款和计算数据是否完整。

但“满足下修条款”只代表公司取得了提议下修的权利，不代表董事会愿意下修。历史研究显示，发行人的决定还取决于回售和到期压力、未转股规模、偿债能力、大股东持债、企业性质、历史下修行为、股权稀释及市场环境。

本功能在现有下修监控上增加“发行人动机判断层”，输出可解释的动机评分和阻碍因素。功能定位是研究辅助，不把事件博弈描述为无风险套利，也不直接提供买卖或仓位建议。

参考依据：

- 《攻守：可转债投资实用手册》提出避免回售、促转股、配售方自救等下修动机；
- 现行交易所规则要求预计触发前提示、触发当日决定、次一交易日开市前披露；
- 近年研究普遍确认历史行权、回售和偿债压力、大股东持债、企业性质及价格压力具有预测价值；
- 下修收益主要来自提议前的预期差，提议后继续追逐下修幅度的收益稳定性较差。

## 2. 本期目标与边界

### 2.1 本期目标

- 在现有下修监控列表中只增加一个可点击字段“动机等级”；
- 点击“动机等级”进入该转债的独立“下修博弈详情”页，展示评分结论、逐项计算方法和本次评分使用的原始数据；
- 使用主 Tushare 6000 积分权限接入并落库 `top10_cb_holders`、`pledge_stat` 等数据；
- 建立完整的可转债前十大持有人历史，不能只保存基金持仓汇总；
- 复用现有下修条款、触发计数、公告事件、行情、财务、实际控制人和安全性数据；
- 建立独立触发周期样本，区分“提议下修、明确不下修、未公告视为不下修”；
- 使用历史时点可见数据进行回测，避免未来数据泄漏和幸存者偏差；
- 第一版使用可解释、版本化的规则评分，并用历史样本校准强弱分档；
- 首次全量数据入库，后续按报告期、公告日和同步游标增量更新；
- 页面和接口只读数据库，禁止因查看页面重复调用外部接口；
- 上游失败、空结果或异常值不得覆盖上一份有效数据。

### 2.2 本期不做

- 不重写现有下修条款解析、计数重置、锁定期和净资产底线逻辑；
- 不新建重复的下修监控列表页，只新增单债“下修博弈详情”页；
- 不提供自动交易、买卖建议、目标收益率或仓位建议；
- 不使用盘中行情，第一版统一按最新完成交易日计算；
- 不在第一版上线黑盒机器学习在线预测；
- 不因财务状况差而直接认定“值得参与”，动机和安全性必须分开显示；
- 不把缺失的大股东持债、财务或质押数据按 0 处理；
- 不修改可转债安全性现有评级算法。

- 现有代码已经在 `TUSHARE_ENABLE_5000_ENDPOINTS=1` 时调用 `top10_cb_holders`，但只筛选基金并写入 `fundamental.convertible_bond_fund_holdings`；
- 缺少全部前十大可转债持有人逐名、逐报告期历史；
- 缺少大股东持债比例、减持幅度、是否清仓和投票回避风险的标准化事实；
- 缺少控股股东质押历史；
- 缺少独立下修触发周期和对应决策标签；
- 缺少按历史时点保存的下修动机评分和组成项；
- 现有下修页面只能显示数学进度，不能解释发行人为什么可能下修或不下修。

## 4. 核心业务模型

本功能必须分开计算四个结果，禁止合并为一个含义模糊的总分：

1. **下修动机分**：如果具备提议条件，发行人愿不愿意下修；
2. **触发成熟度**：距离形成正式下修决策窗口还有多远；
3. **下修可执行性**：是否处于锁定期、是否有足够下修空间、是否受净资产底线限制；
4. **安全性**：即使动机很强，这只转债是否存在明显信用和兑付风险。

### 4.1 页面分类

| 分类 | 条件 | 页面含义 |
|---|---|---|
| 强动机·临近窗口 | 动机分 ≥ 70、成熟度 ≥ 70、可执行性通过 | 发行人动机和事件时点均值得优先研究 |
| 强动机·中期观察 | 动机分 ≥ 70、成熟度 < 70、可执行性未永久受阻 | 动机较强，但尚未进入近期决策窗口 |
| 强动机·高风险 | 动机分 ≥ 70、安全性为中风险或高风险 | 可能被迫下修，但信用风险不能忽略 |
| 有动机 | 50 ≤ 动机分 < 70 | 有部分支持因素，证据不足以称为强动机 |
| 动机较弱 | 动机分 < 50 | 当前缺少足够的主动或被动下修压力 |
| 暂不可执行 | 锁定、净资产底线阻挡、条款或关键数据不完整 | 不进入近期强动机候选排序 |

“强动机”只描述发行人的潜在决策倾向，不等于“安全”或“建议参与”。

## 5. 下修可执行性前置检查

### 5.1 必须检查

- 是否为当前上市交易的公开可转债，排除定向和私募；
- 下修条款是否解析完整；
- 是否仍处于明确不下修锁定期；
- 当前是否被 `floor_blocked`；
- 正股、转债、转股价、PB和交易日是否同一有效市场口径；
- 公告质量门禁是否正常；
- 是否已经进入提议、表决或实施阶段，避免把已经公开的事实继续当作预测；
- 是否存在重大退市、违约、评级和交易流动性风险。

### 5.2 预估下修底价

```text
预估下修底价 = max(
  当前可取得的正股20个交易日交易均价,
  最新交易日交易均价,
  最近一期每股净资产（条款要求时）,
  每股面值（条款要求时）
)
```

说明：

- 法定底价最终以股东大会召开日前的市场数据为准；
- 预测阶段没有真实股东大会日期，因此该值只能标记为“动态预估”，每日更新；
- 正股交易均价使用成交额与成交量计算，不能用收盘价均值替代；
- 净资产底线必须沿用现有条款解析结果，不能对所有转债一刀切；
- 任何一项必需输入缺失时，不输出正式下修空间。

### 5.3 可执行空间指标

```text
预估下修空间 = 当前转股价 ÷ 预估下修底价 - 1
预估下修后转股价值 = 100 × 最新正股价格 ÷ 预估下修底价
转股价值提升 = 预估下修后转股价值 - 当前转股价值
```

默认研究门槛：

- 预估下修空间不少于 10%；
- 预估转股价值提升不少于 8 元；
- 低于门槛仍展示动机分，但标记“下修空间有限”，不进入“强动机·临近窗口”。

阈值属于 `motive-v1.1` 规则的一部分，后续只能根据公告前样本外回测结果版本化调整。

## 6. 下修动机评分

总分 100 分，所有组成项必须随每日结果落库，页面能够解释加分和扣分原因。

### 6.1 历史行为与条款惯性：25分

| 指标 | 初始规则 |
|---|---:|
| 近2年曾成功实施下修 | +12 |
| 近2年成功实施2次及以上 | 额外 +4 |
| 上一次完整触发周期选择提议下修 | +5 |
| 曾缩短或提前终止不下修期限 | +4 |
| 连续明确或默认不下修 | 每次 -4，最多扣12 |
| 最近一次股东大会否决下修 | -6，并显示表决风险 |

本维度最终限制在 0～25 分。历史事件只能使用评分日以前已经公告的事实。

### 6.2 回售与偿债压力：30分

| 指标 | 初始规则 |
|---|---:|
| 已进入回售期或剩余期限不超过2年 | +6 |
| 剩余期限不超过1年 | 额外 +3 |
| 回售条款已开始计数 | 按进度给0～6分 |
| 剩余转债规模 ÷（货币资金＋交易性金融资产）> 1 | +6；比值 > 2 再 +2 |
| 流动比率 < 1 | +3 |
| EBITDA ÷ 负债合计 < 5% | +3 |
| 财务费用 ÷ 营业收入 > 10% | +2 |
| 资产负债率 > 60% | +2 |

本维度最终限制在 0～30 分。

财务压力只提高“可能被迫下修”的动机，不提高安全性。财务数据缺失时不给分，也不得按 0 代入。

“剩余规模低于发行规模”不作为压力指标，因为正常转债存续期间该条件通常天然成立；剩余规模/发行规模仅在第6.3节作为未转股比例，达到70%或90%时才计分。

### 6.3 促转股压力：20分

| 指标 | 初始规则 |
|---|---:|
| 未转股比例 ≥ 70% | +5；≥ 90% 给8分 |
| 剩余转债规模 ÷ 正股总市值 ≥ 10% | +5；≥ 20% 给7分 |
| 当前转股价值 < 80元 | +3；< 70元给5分 |

本维度最终限制在 0～20 分。

未转股比例统一按 `remain_size ÷ issue_size` 计算。规模和市值入库后统一使用元，禁止亿元、万元和元混算。

### 6.4 大股东与公司治理：15分

| 指标 | 初始规则 |
|---|---:|
| 实际控制人为自然人或民营企业 | +4 |
| 大股东/实际控制人及一致行动人当前合计持债比例 ≥ 25% | +4，同时标记“持债股东表决回避” |
| 大股东初始高比例配售，后续已减持超过50% | +4 |
| 大股东初始高比例配售，后续已清仓 | +6，替代上一项，不重复累计 |
| 控股股东质押比例 ≥ 20% | +2；≥ 40%给3分 |
| 预估下修到底后控制权仍有安全余量 | +2 |

本维度最终限制在 0～15 分。

持债比例高代表价格诉求，但持有可转债的股东对下修议案需要回避表决，因此必须同时显示“动机”和“表决风险”，不能把高持债比例简单解释为议案更容易通过。

### 6.5 市场和价格压力：10分

| 指标 | 初始规则 |
|---|---:|
| 转债价格 < 100元 | +4；100～110元给2分 |
| 转债价格处于自身近120个交易日20%以下分位 | +2 |
| 全市场近3个月提议下修率处于近3年60%分位以上 | 仅作市场背景，不计入本债动机分 |
| 同行业近6个月已有提议下修案例 | 仅作市场背景，不计入本债动机分 |

本维度最终限制在 0～10 分。市场环境只使用评分日以前的事件，不能使用未来完整月份统计；跨债种或同行信息未经样本外验证不得解释为本债发行人的直接动机。

## 7. 触发成熟度

触发成熟度不加入动机分，单独计算：

| 条件 | 成熟度 |
|---|---:|
| 已满足下修数学条件，等待董事会响应 | 100 |
| 滚动窗口最快还需1～3个交易日 | 85 |
| 最快还需4～5个交易日 | 70 |
| 最快还需6～10个交易日 | 50 |
| 已开始计数但最快还需超过10日 | 30 |
| 尚未形成有效计数 | 10 |
| 明确锁定、净资产底线阻挡或数据不完整 | 0 |

预计触发提示公告作为数据质量和事件确认信号展示，不额外重复加到动机分。

## 8. 安全性与阻碍因素

### 8.1 安全性

直接复用现有可转债安全性结果：

- 安全、低风险：允许进入“优先研究”筛选；
- 中风险：显示“强动机·高风险”；
- 高风险或未评级：不得显示为低风险机会，但仍可保留真实动机分；
- 安全性数据落后或缺失：显示数据不完整，不按安全处理。

### 8.2 主要阻碍

页面至少识别：

- 不下修锁定期；
- 每股净资产底线阻挡；
- 预估下修空间不足；
- 转股价值提升有限；
- 连续多次不下修；
- 国企股权稀释约束；
- 大股东仍持债导致表决回避；
- 下修后控制权压力；
- 剩余规模已经很小，促转股必要性弱；
- 信用、退市或流动性风险；
- 关键数据缺失或过期。

## 9. 历史样本与回测口径

### 9.1 独立触发周期

新增“下修触发周期”事实，每只转债每次重新起算形成一个独立周期：

```text
cycle_start_date：本轮第一个有效观察交易日
first_match_date：本轮第一个满足触发价格的交易日
trigger_date：正式满足下修条件的交易日
decision_date：董事会决定或按规则视为不下修的日期
cycle_end_date：提议、不下修、重新锁定或下一轮重新起算日期
```

短期主标签：

- `proposed`：本轮触发后董事会提议下修；
- `explicit_no_revision`：公告明确不下修；
- `implicit_no_revision`：未按规则履行程序，视为本次不下修；
- `unknown`：公告或计数不完整，不进入正式训练和回测。

次级标签：

- 股东大会通过、否决或终止；
- 是否实施；
- 是否下修到底；
- 下修幅度；
- 未来6个月内是否再次提议下修。

### 9.2 样本时期

- 2022-08-01以后作为主样本，适用现行较完整的信息披露规则；
- 2018年至2022-07-31作为辅助研究样本，不能与新规样本等权混合；
- 历史退市、强赎退出和已经完成转股的转债必须保留，禁止只回测当前存续转债。

### 9.3 防未来数据泄漏

- 截面行情取评分日收盘数据；
- 财务指标只使用评分日前已经公告的报告；
- 持有人数据按报告公告日可见，不能按报告期结束日提前使用；
- 质押、控制人和评级只使用当时有效记录；
- 历史行为只统计评分日前已经发生的周期；
- 同一发行人的重复周期不能随机拆到训练和测试两端造成记忆泄漏；
- 验证按时间滚动，至少保留最近完整年度作为真正样本外测试。

### 9.4 回测交易口径

回测只用于检验评分是否有研究价值，不在产品中输出交易指令：

- 信号在交易日收盘后生成；
- 使用下一交易日可成交价格建仓，禁止使用信号日收盘价假设成交；
- 短期策略在提议或不下修结果公开后的首个可成交时点退出；
- 中期策略单独回测，最长持有6个月，不与短期结果混合；
- 计入双边费用、0.30%往返滑点假设、停牌和无法成交情况；
- 单券等权、单发行人只保留一只、禁止用退市后已知结果反向筛选。

### 9.5 上线门槛

只有同时满足以下条件，页面才使用“强动机”标签：

- 样本外“70分及以上”组提议下修率不低于35%；
- 同期提议下修率至少达到全样本基准的2倍；
- 评分分档与实际提议率基本单调；
- 扣除0.30%往返滑点后的短期组合收益为正；
- 强动机组不能只由少数单一发行人或单一年度贡献；
- 关键输入字段完整率不低于95%。

未达到门槛时，页面只能显示“研究评分”，不得显示“强动机”。

- `motive-v1.1` 中，部分输入缺失或历史样本外回测未通过时仍保留原始分数和明细，但不得输出“动机偏弱/存在动机”等预测等级；已提议、待表决、已通过、已实施等状态只展示公告事实，不作为预测结果。完成回测后必须升级模型版本并显式打开校准开关。

## 12. 服务、任务和接口方案

### 12.1 服务拆分

新增 `server/services/convertibleBondRevisionMotiveService.js`，职责仅包括：

- 读取已经落库的市场、条款、事件、持有人、财务、质押和安全性事实；
- 计算可执行性、动机分、成熟度和解释文本；
- 幂等写入每日评分；
- 提供历史回填和质量审计函数。

现有 `convertibleBondRevisionService.js` 继续负责下修数学进度和页面查询，不把动机公式塞入现有计数函数，避免破坏已经稳定的核心逻辑。

### 12.2 后台任务

建议新增两个任务：

1. `convertible_bond_revision_motive_inputs_sync`
   - 首次全量回填；
   - 日常只处理新财报、新持有人报告、新质押截止日和新持债变动公告；
   - 复用现有外部接口主备、预算、熔断、游标和失败保留机制。

2. `convertible_bond_revision_motive_calculate`
   - 在下修公告、可转债行情、正股行情和安全性数据完成后运行；
   - 只读取数据库，不调用外部API；
   - 单券失败不覆盖上一份有效评分，任务输出完整率和失败清单。

调度顺序并入现有08:15可转债串行计算链，具体分钟以现有任务编排避免重叠为准，不另建并行重复刷新链路。

### 12.3 接口

#### 12.3.1 下修监控列表接口

扩展现有 `GET /api/bond-revision`，不新增重复列表接口。列表至少返回：

```text
motive_level
motive_trade_date
model_version
```

第一版只把 `motive_level` 显示为新增列，其他评分明细不塞入列表。接口继续使用数据库排序和分页，禁止把全量数据发到浏览器后排序。

#### 12.3.2 单债下修博弈详情接口

新增只读接口：

```text
GET /api/bond-revision/:tsCode/motive-detail?tradeDate=YYYY-MM-DD
```

- `tsCode` 必须精确校验为可转债代码，不允许拼接 SQL；
- `tradeDate` 可选，缺省读取最新有效评分；指定日期时读取该日期对应的评分快照；
- 一次返回评分摘要、五维计算明细、可执行性计算、原始输入快照、来源引用、模型版本和计算时间；
- 不在请求过程中调用 Tushare、公告网站或行情接口；
- 找不到评分时返回明确的“尚无评分数据”，不得临时用不完整数据现算；
- 原始记录只返回本次计算实际使用的业务字段，过滤 Token、请求头、内部凭证和无关载荷。

建议响应结构：

```text
bond
score_summary
dimension_calculations[]
executability_calculation
input_snapshot[]
source_references[]
model_version
calculated_at
```

保留的筛选能力：

- 强动机·临近窗口；
- 强动机·中期观察；
- 强动机·高风险；
- 动机分区间；
- 只看可执行；
- 排除数据不完整。

## 14. 历史回填方案

### 14.1 首次全量

1. 回补2018年以来公开可转债主档和历史生命周期；
2. 回补2022-08-01以来完整下修触发周期，旧制度样本单独保存；
3. 对历史样本逐券拉取 `top10_cb_holders` 全报告期数据并落库；
4. 回补对应正股财务、质押、控制人和股东数据；
5. 复用现有行情、估值、条款、转股价和公告历史；
6. 按交易日升序生成历史特征和评分；
7. 完成样本外回测后才允许打开“强动机”标签。

### 14.2 日常增量

- 新交易日只计算当日评分；
- 新公告只重建受影响转债的相关周期；
- 新财报只刷新对应发行人的财务维度；
- 新持有人报告或持债变化公告只刷新对应转债的治理维度；
- 评分公式升级使用新 `model_version` 回补，不覆盖旧版本；
- 内部缺口通过日期差集发现，不能只依赖已经越过缺口的游标。
- 持有人接口单批最多调用10次；达到上限或接口停止后，未实际请求的对象不推进游标并返回 `partial`，由下一批继续。

### 14.3 本地回填与回测记录（2026-08-31）

- 使用 `server/scripts/backtestConvertibleBondMotive.js --apply --backfill-scores` 按 `2022-08-01` 至 `2025-12-31` 的触发周期回填历史评分，并以 `2025-01-01` 起作为样本外窗口；信号日只读取公告日前已入库事实，退出收益扣除 0.30% 往返成本。
- 本地结果：364 个可评估周期、34 个提议下修，样本外 156 个周期；关键输入完整率为 0%，70 分以上组为 0 个，样本外扣成本平均收益为 -0.1943%。结果已写入 `analytics.convertible_bond_revision_motive_backtests`，因此 `motive-v1.1` 保持禁止输出预测等级。
- 该结果是模型安全门禁，不代表“没有下修动机”；在持有人/质押等关键事实补齐且新版本回测达标前，页面只能展示研究分和公告事实。

## 18. 主要风险和控制

| 风险 | 控制方式 |
|---|---|
| 下修基础概率低 | 使用分档实际提议率，不用整体准确率制造虚高 |
| 同一公司反复触发造成样本泄漏 | 按时间滚动并控制发行人重复样本 |
| 大股东名称难匹配 | 保存原始名和标准名，低置信匹配进入人工核查，不强行归类 |
| 持有人快照披露滞后 | 使用 `announced_at`，另以持债变动公告补充精确日期 |
| 高财务压力被误解为低风险机会 | 动机和安全性分开，风险不抵消、不加分 |
| 下修底价日期尚未确定 | 明确标记动态预估，不冒充最终股东大会底价 |
| 规则过拟合历史 | 固定样本外年度、版本化公式、上线门槛和年度复核 |
| 6000积分接口被重复调用 | 首次全量入库，后续按报告和公告游标增量，页面只读库 |
| 空数据覆盖有效值 | 所有数据源统一验证、幂等写入、失败保留旧值 |
