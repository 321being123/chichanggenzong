## 2026-11-01 0.9.1.13 → 0.9.1.15 逐只估值历史补数（连发三版，前两版都白跑）

**为什么发了三次**：补数脚本本身是新的，两个缺陷只有在真实环境才暴露——`0.9.1.13` 部署后预演返回 0 行（适配层把官方区间接口的批量请求静默吞掉）、`0.9.1.14` 修好取数后仍然命中 0 行（官方日期是 `20260828`、分区键是 `2026-08-28`，脚本直接字符串比对）。`0.9.1.15` 才是第一次真正写进库。

| 版本 | SHA | 改什么 | 结果 |
|---|---|---|---|
| 0.9.1.13 | `789ec19c` | 新增数据层入口 `readStockValuationSeriesBatch` ＋补数脚本；默认范围＝当前在交易转债正股∪持仓∪自选∪已分析 | 预演 0 行，未写入 |
| 0.9.1.14 | `a4734239` | 适配层 `resolveValuationSeries` 由「100 只批量」改「单只循环」（官方区间接口实测只接受单个证券，多只一律 400 `ValidationError`） | 取到 23,133 行，但命中 0 行 |
| 0.9.1.15 | `65baf9c9` | 脚本把官方 `YYYYMMDD` 归一成 `YYYY-MM-DD` 再与分区键比对 | 正常 |

**根因两条（都是「看起来切了其实没切」的同类）**：
