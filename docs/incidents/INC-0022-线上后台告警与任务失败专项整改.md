# INC-0022：线上后台告警与任务失败专项整改

状态：跟踪中（代码与授权生产维护已完成，进入 3 个交易日观察）
日期：2026-09-14

## 现象与影响

生产只读核查发现 15 条活动告警，其中 2 条为最近 24 小时新增，13 条为 9 月 6—11 日历史遗留。重复等待、任务失败和告警未按后续成功收敛叠加，造成后台页面看起来像同时发生多个故障；港股 IPO 下游还出现“日历数据已存在但当天分区缺失”的阻塞。

## 根因链路

外部接口 → Guard/Worker → `ops.job_schedule_slots` 与 `ops.dataset_partitions` → `ops.alert_notifications` → 后台任务页。

1. 港币汇率等待结果丢失 `recoverAt`，每轮按固定短延迟继续尝试；页面和持仓对比也会触发实时汇率任务。
2. 港交所交易日历一次写入未来数月，旧 Worker 把 `dataAsOf` 当成业务 `partition_key`，下游按当天业务日查询不到分区。
3. 巨潮旧 HTTP 入口返回 403，被写成来源级永久熔断；HTTP 子阶段异常时还可能返回成功形态。流动性候选部分失败也曾被质量门禁误判为通过。
4. `920025` 凯达重工存在真实资料缺口，不能用估值或推断填充。
5. 告警只有槽位/任务粗粒度，恢复后无法准确关闭历史记录；Worker 对 Git 内节假日文件没有写权限。

## 直接原因、根本原因与保护机制失效原因

- 直接原因：错误分类和作用域不足，让“可等待”“需人工”“数据真实缺失”混在同一重试/告警路径。
- 根本原因：业务分区、数据覆盖水位、来源接口和告警生命周期没有形成一一对应的稳定键。
- 保护失效：等待恢复时间未结构化传递；接口级 403 没有有界退避；成功状态没有验证数据质量和分区；历史告警没有后续成功收敛规则。

## 同类范围与核查结果

- 已覆盖 Node/Python 外部 Guard、港币汇率、港股交易日历、CNINFO 公告、可转债流动性质量、IPO 定向补齐、节假日配置、任务编排和后台告警页面。
- 新增 `server/scripts/reconcileAlertHistory.js` 与 `server/scripts/repairHkTradeCalendarPartitions.js`，默认只读；生产写入需要备份、目标清单和确认环境变量。
- 本地回归覆盖恢复时间、连续缺失退避、告警作用域、接口级 403 计数、业务分区语义和运行时休市日历路径。

## 修复与回归证据

- 迁移 151：`alert_notifications.scope_type/scope_key`、历史作用域回填约束和 `external_circuits` 403 连续计数。
- 汇率页面改为只读缓存；新鲜度门禁才触发一次受保护刷新。外部等待使用准确 `recoverAt`，缺失时为同一槽位 30/60/120 分钟退避，连续 3 次转阻塞。
- `partition_key` 与 `data_as_of` 分离；CNINFO 403 按具体接口 30/60/120 分钟退避，连续 5 次才转人工权限阻塞；流动性部分失败不再标记质量通过。
- 告警按槽位、任务、数据集分区、来源接口收敛；历史状态通过 `status=history` 查询。休市日历运行时副本改为 `/opt/portfolio/data/holidays.json`。
- 验收复核补齐三项边界：熔断查询为空时不再误判恢复；历史槽位失败需原槽位恢复或连续 3 次后续成功才能进入人工对账，数据质量告警仍只认数据恢复；Node/Python 成功探测均按实际关闭的接口名同步收敛告警，通配熔断对应 `source:*`。
- 已通过：港币汇率 Guard 回归、任务编排回归（95 项）、迁移 151 重复执行、Node/Python 通配熔断告警收敛集成回归及全量测试；全量结果为 130 通过、0 失败、0 跳过，Python 项目虚拟环境编译通过。

### 二次专项研发落地（2026-09-15）

- 运行时和历史对账统一使用 `verifyAlertScope()`：槽位/任务按原槽位或同模式后续成功核验，数据质量告警必须看到目标分区已发布且质量通过，来源接口必须全部相关熔断关闭并有新的 `last_success_at`；空查询、手工关闭和仅日期水位均不能自动关闭。恢复失败写入 `job_alert_resolution_failed` 审计，恢复通知使用稳定告警键做一次性去重。

- 二次专项代码和测试已完成，生产发布与授权范围内的定向操作已执行；本文件的最终状态继续以本节生产记录和后续 3 个交易日观察为准。
