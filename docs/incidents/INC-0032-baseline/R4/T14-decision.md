## 合法保留的日期处理

- B00 指出的 `navAttribution` 五处交易日字符串截取对应 `trades.date`、`trades.trade_date`。迁移初始表和迁移 042 均声明为 `TEXT`；净值快照的 `date` 同样是 TEXT。这里不接收 PostgreSQL DATE。文件内 `dateKey(Date)` 已显式按上海时区格式化真实 Date。
- `marketState` 和任务水位查询将 PostgreSQL DATE 输出为 `::text`；日历年份/逐日运算从纯日期构造 `T00:00:00Z` 后使用 UTC getter，属于不依赖主机时区的纯日期计算。
- ExcelJS 日期/序列号按 Excel 日期合同转换的 `toISOString().slice(0, 10)`，经 T11 的三时区真实解析回归确认不偏移。
- `market.quoteDateCN` 把腾讯行情明确带 `+08:00` 的真实报价时刻转换为上海日期；固定 8 小时在此处表示明确的 Asia/Shanghai 转换，不作为通用日期截断规则。
- `US/10` 手工 CSV/XLSX 的 `source_date` 是用户输入纯日期；现有导入只在日期间隔内向前展开，最长 6 个日历日，并保持原始 `source_date`。用户确认时间按北京时间，因此上传路由和 CSV 脚本的 `today` 末端截断统一使用 `Asia/Shanghai`。原始文件发布者/样本仍未提供，不能据此扩展或更改现有 6 日规则；跨时区固定边界回归见 T13 决策。

## OID 1082 决定

- 全项目源代码搜索仅发现 `server/scripts/repairFxRateHistory.js` 在文件顶层设置 OID 1082 解码器；仓库内无 Web、Worker 或测试入口导入该脚本。
- 保持业务读路径在 SQL 边界显式使用 `::text`，不改变全局 node-postgres OID 1082，也不改变 OID 1184 的真实时刻语义。
- 该维修脚本继续只允许作为独立 Node 进程直接执行。若未来将其改为共享模块，必须先拆除顶层全局解析器副作用并补进程隔离回归。
