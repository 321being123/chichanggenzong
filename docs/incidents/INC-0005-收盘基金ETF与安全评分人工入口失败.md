# INC-0005：收盘基金/ETF与安全评分人工入口失败

状态：跟踪中（0.7.0.11 已生产发布）
日期：2026-09-02

## 生产发布与验收

- 首次修复版本 `0.7.0.10` 发布后，独立验收发现公开安全评分快照接口返回 HTTP 500；日志确认是公开读取路由缺少 `isConfigured` 引入，立即补齐并加入回归断言。
- 修订版本 `0.7.0.11` 已按标准流程发布，生产提交、Web、Worker、健康检查定时器、`/health` 和 `/ready` 均正常；公开安全评分接口已纳入发布验收。
- 本次不执行生产数据同步：三个失败对应的数据已在生产恢复，修复仅调整代码和任务边界。

## 现象与影响

生产后台出现 3 条失败记录：LOF/ETF 收盘任务 `383581` 在 15:10 和 15:27 两次提示“收盘记录存在缺失，成功 0、失败 6”；可转债安全评分计划 `397522` 的人工补跑在 14:18 提示 Tushare 达到本任务外部请求上限 0。前者在 16:28 自动第 3 次成功，6 条收盘价格已落库；后者在 14:20 正式计划成功，生成了 2026-09-01 快照。影响是产生了不必要的失败告警和延迟，不是最终数据丢失。

## 根因链路

### LOF/ETF 收盘

腾讯批量行情 → `market_quote_cache`/进程 Map → `marketClose.recordCloseOne` → `daily_prices` → 收盘任务告警。

上一轮批量降调用改造后，批量响应缺少基金/ETF代码时，`fetchWithRetry` 的 `quoteMap` 分支只重复读取同一份不完整 Map，没有重新发起请求；6 条记录因此连续失败。该分支还把 Map 的本地检查次数计入 `externalCalls`，使任务记录的 12、24、30 次不能代表实际腾讯请求数。

### 安全评分人工入口

共享标准行情/财务层 → `bondSafetyTushare.fetchBondSafetySourceFromDatabase` → 安全评分快照。

`bond_safety_refresh` 的任务契约已经是无外部接口、单次外部调用 0 次，但人工 Runner 和 `/api/bond-safety/refresh` 仍默认传入外部模式，触发统一 Guard 的 0 次上限。它不是 Tushare Token 整体失效，也不是安全评分公式错误。

## 直接原因、根本原因与保护机制失效原因

- 直接原因：共享批量响应部分缺失且没有缺失集合的补取动作；人工入口与任务契约的读取模式不一致。
- 根本原因：优化只统一了“请求入口”，没有把“失败后的补偿动作”和“人工入口”纳入同一数据集契约。
- 保护机制失效原因：收盘任务把本地 Map 校验当成外部请求计数；安全评分契约虽正确拦截了违规外部调用，但入口没有默认使用本地标准层，导致可避免的人工失败告警。

## 同类范围与核查结果

已核查生产计划、运行记录、告警、基金/ETF 持仓、当日 `daily_prices`、腾讯行情缓存和统一身份映射。当前基金/ETF 持仓共 6 条记录、5 个代码：`160719`、`160723`（两个账户）、`161226`、`510900`、`511880`；当日 6 条价格全部存在，5 个代码均有有效腾讯映射。已核对安全评分人工与自动两个入口，均已统一到数据库只读模式。未发现需要生产补数的事实缺口。

## 修复与回归证据

- 收盘任务：缺失代码按统一映射一次性有界补取；同一代码本次任务不重复补取；本地 Map 检查不计入外部请求数；Guard 实际调用数成为任务结果的唯一计数来源。
- 安全评分：`runBondSafetyRefresh`、统一 Runner、服务默认值和后台刷新接口均只读标准层；任务定义同步为无外部来源、`retryPolicy=local`、不计入外部预算。
- 回归：`marketclose.test.js` 13 项通过；`bond-safety.test.js` 22 项通过；`job-orchestration-regression.test.js` 95 项通过。完整测试和数据架构验收待最终修改树完成后执行。

## 防复发措施与遗留风险

- 所有有 `quoteMap` 的批量行情逻辑必须同时提供缺失集合补取和有界次数；不得再把本地读取循环作为外部请求数。
- 所有 `externalApis=[]` 的计算任务，自动、人工、页面和启动补漏入口都必须默认只读标准层；如保留兼容外部适配器，必须显式传入受控模式，不能由任务默认触发。
- 本次代码尚未按生产流程发布；发布后连续观察 3 个交易日的收盘完整率、`job_runs.external_call_count`、腾讯请求次数和安全评分 `externalCalls=0`。生产部署或数据同步需另行取得授权。
