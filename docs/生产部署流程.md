### 版本文案格式（强制）

- 每条版本说明必须以 `新增：`、`优化：` 或 `修复：` 开头，不能使用无分类前缀的文案。
- 同一版本内的条目固定按 `新增 → 优化 → 修复` 排序；`add_changelog.py` 会校验前缀并自动排序。
- 历史版本记录也必须遵守同一格式；发现旧记录缺少前缀时，先统一修订后再发布。

### Windows Python（固定方式）

- Windows 部署前更新版本记录时，固定使用项目根目录 `.\venv\Scripts\python.exe`。
- 不使用 `WindowsApps\python.exe`，它只是应用商店占位程序，可能无输出直接退出。
- 不再猜测 `ipo-report\venv` 等虚拟环境路径；先用 `Test-Path .\venv\Scripts\python.exe` 确认固定路径存在。
- 可转债公告默认只走上交所/深交所批量接口；交易所失败或分页不完整时保留游标等待重试，不自动切换巨潮。只有确认 Tushare `anns_d` 已开通权限后，才在生产环境配置 `ANNOUNCEMENT_TUSHARE_FALLBACK=true` 启用独立最后备源，禁止把 Token 写入代码或文档。
- 可转债上市公告书、前十持有人和上市流通明细补全优先走上交所/深交所官方公告 PDF；按正股代码和上市日期查询，发行结果/上市数量先在同一交易所内兜底，交易所无资料、下载失败或解析失败时再走 CNINFO 兜底。旧巨潮事实可在定向重算时按同一优先级迁移，最终按实际来源记录。

净值归因规则类修复如果只读取已有 `positions`、`nav_history`、`daily_prices` 重新计算，默认不生成迁移或补写历史行情；用户明确要求“数据同步”时，部署后应按目标账户重读现有数据并验收归因结果，只有确认存在事实缺口时才执行定点数据补写。

数据同步不属于每次部署的固定步骤。仅当本次变更涉及数据库结构、历史数据、日报、模型产物或其他生产数据写入时，先向用户说明同步内容和影响，并询问是否执行。只有得到明确同意后，才生成同步 SQL 或执行数据同步。

招商证券净值专项修复脚本必须显式传入 `--confirm-production`，先生成 `/var/backups/` 数据库备份，再在事务内校验目标交易、人工锚点和错误快照数量；脚本可重复执行，已修正数据不会再次改写错误记录。补齐任务返回 `partial` 时必须保留缺失日期/代码并告警，不得以“成功”收口。

禁止事项：

- 禁止 SFTP 或 SSH 直接覆盖生产代码、模型文件或配置文件；
- 禁止未更新版本记录就部署；
- 禁止跳过本地验证、Git 提交或部署后验收；
- 禁止以“紧急修复”为由省略流程。紧急修复可先恢复服务，但必须立即补齐完整发布流程。

### 可转债强赎公告补录工具

强赎公告已并入 `convertible_bond_announcement_history_sync`：07:40按收盘日次日口径处理盘后公告，17:30按工作日口径补当天公告，不再存在独立07:45任务。历史缺口或部署前漏数仍统一使用 `deploy/backfill_bond_call_announcements.py`；它复用 `deploy_password.py` 的密钥登录与 `run_sudo`，在服务器上执行同一套解析入库逻辑，不通过SFTP/SSH覆盖生产代码。

```powershell
# 只读核查：列出窗口内“巨潮能搜到但未入库”的公告（不写库、不备份）
.\venv\Scripts\python.exe deploy\backfill_bond_call_announcements.py --audit --from 2026-08-28 --to 2026-08-30

# 生产补录：先备份数据库，再执行同步，最后验证事件与页面统计
.\venv\Scripts\python.exe deploy\backfill_bond_call_announcements.py --sync --from 2026-08-28 --to 2026-08-30 --confirm-production

# 只补某只正股（传 6 位正股代码）
.\venv\Scripts\python.exe deploy\backfill_bond_call_announcements.py --sync --from 2026-08-20 --to 2026-08-30 --stock 300870 --confirm-production
```

- `--sync` 必须显式传入 `--confirm-production` 并取得用户授权，否则直接拒绝执行。
- 默认在补录前 `pg_dump` 备份到 `/var/backups/`；已确认有可用备份时可加 `--no-backup` 跳过。
- 备份固定用重定向 `>` 而非 `pg_dump -f`：postgres 用户对 `/var/backups` 无写权限，`-f` 会报 Permission denied。
- 核查时 DB 对比窗口比搜索窗口向前放宽 10 天：巨潮会返回窗口起始日之前的公告，窗口不一致会把已入库公告误判为遗漏。
- 无可转债公司的误命中公告（如“现金管理提前赎回”）由 `pickInstrument` 返回 null 自动跳过，不是漏数。

历史投影因旧公告缓存缺失、旧解析器积压或重复失败事实无法通过严格质量门禁时，使用受控重建工具：

```powershell
.\venv\Scripts\python.exe deploy\rebuild_bond_call_projection.py --history-start 2024-09-01 --to-date YYYY-MM-DD --confirm-production
```

- 执行前必须取得生产数据写入授权；工具首先启动并校验标准加密数据库备份。
- 本地导出仅接受 `call-event-v3/complete` 且公告正文完整的已验证基线；基线外缺口仅从上交所、深交所官方源读取，分页不完整立即终止。
- 交易所结果优先复用生产既有强赎事件的证券映射；带明确可转债证据但仍无法匹配的公告继续阻断，无转债证据的普通公司债或资金产品“赎回”标题只记录忽略数量。
- 受控重建遇到交易所匿名接口的瞬时单并发占用时，按 Guard 恢复时间有界退避，最多重试 5 次、累计等待约 30 秒；分页不完整、权限拒绝或熔断不得据此放行。
- 所有目标事件完成证券匹配、正文提取和 v3 解析后，才在事务内替换历史重复/失败投影、推进水位、按重建证据恢复质量问题并发布分区；任一项不满足均在清理旧投影前退出。
- 基线压缩包只通过 SSH 标准输入写入服务器临时目录；远端执行输出先写临时日志再回传，基线和日志在执行结束后自动删除。禁止用 SFTP 或 SSH 覆盖生产代码。

## 5. 部署后验收

依次确认：

1. 服务器提交版本与 GitHub `master` 一致；
2. `portfolio-server.service`、`portfolio-worker.service` 和 `portfolio-worker-health.timer` 状态正常；
3. `http://127.0.0.1:3000/health` 返回预期版本；
4. 本次相关接口和页面正常；
   - 涉及可转债安全性的版本必须额外核对公开 `GET /api/bond-safety/bonds` 返回 200 和最近快照；外部适配器未配置时也不得因展示状态判断而阻断数据库快照读取。
5. 如用户已同意执行数据同步，确认相关数据、日报或模型结果已写入 PostgreSQL；
6. 前端版本记录可见且与本次更新一致；涉及可转债估值的版本，还要复核估值历史完整性和接口 `stale` 状态；涉及外部接口熔断探测的版本，还要确认恢复时间已到的来源能够重新探测，且 `probe_in_flight` 不会因 Worker 重启长期保持为 `true`。

涉及网站性能优化时，必须额外验收：

- `curl -sI --http2 https://<域名>/` 确认 HTTP/2；对 JSON、JS、CSS 请求确认 `Content-Encoding: gzip`、单一 `Cache-Control`，公共接口第二次带 `If-None-Match` 返回 304。静态 location 必须保留 `proxy_hide_header Cache-Control`，避免 Node `express.static` 的默认 `max-age=0` 与 Nginx 缓存头重复。
- 并发请求超过 30 个首页静态资源时不得出现 429；`limit_conn` 只能位于动态 `location /` 内，不能配置在 `server` 级影响 HTTP/2 静态资源并发流。
- Nginx 日志包含 `request_time`、`upstream_connect_time`、`upstream_response_time`；必要时用 `curl -w` 记录 `time_connect`、`time_appconnect`、`time_starttransfer`、`time_total`。
- 首页冷启动与回访分别记录 LCP/CLS；首页卡片保持固定最小高度。账户接口确认摘要请求不返回交易/净值历史，进入持仓页仍能加载完整数据。
- 修改 Nginx 前备份实际生效的 `/etc/nginx/nginx.conf`、`/etc/nginx/conf.d/portfolio.conf`；模板仓库文件不包含生产 `http` 块时，回滚必须同时恢复服务器备份，不能只回滚 Git 模板。

涉及统一任务调度、任务依赖或数据集发布门禁变更时，还必须确认 Worker 已加载新任务定义，并核对受影响任务的计划时刻、上游任务依赖、目标业务日分区及质量状态。IPO链路变更重点检查：`ipo_history_sync` 的18:00核心、19:30核心和19:35补全阶段均已生成计划实例，`ipo_calendar_refresh` 为18:05/19:45且只在对应时段的 `ipo_history` 基础分区质量通过后执行；19:30核心槽位使用方案声明的 `freshnessGate=false`，避免晚间公告被前一轮水位短路。代码部署本身不等同于人工补数，不得顺带手工触发生产采集。

### 独立远程验收命令（Windows/Codex）

- 通过 Paramiko 执行多行远程脚本时，优先复用 `deploy/deploy_password.py` 的 `run_sudo`（内部使用 `shlex.quote`），或使用 `exec_command('sudo bash -s')`，通过标准输入写入脚本后调用 `shutdown_write`。
- 禁止把 Python `repr()` 的结果直接拼入 `bash -c`；`repr()` 生成的是 Python 字面量，不是 Shell 安全引用，会导致远程解析失败。
- 远程 Shell 解析失败时，先确认实际验收命令是否执行；如果未执行，明确记录“未执行验收命令、未影响服务”，再改用上述安全方式重试。

任一项不通过，部署状态为失败，不得宣称已上线。
