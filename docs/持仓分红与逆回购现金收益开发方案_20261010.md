## 1. 目标与已确认口径

从每个账户最近一次有效券商现金导入基准日之后，自动补入股票分红和逆回购净收益，使现金、总资产、净值及收益归因使用同一份账本。基准已包含的历史到账金额不得再次增加；缺少有效基准的账户暂停自动补算，提示补充基准。

| 项目 | 开发口径 |
|---|---|
| 股票分红 | 按实际分红资格和实际到账日计入现金；属于投资收益，不增加投入本金 |
| 补录交易 | 按真实交易日重建资格；补录分红资格日前卖出时撤销多计分红，资格日后卖出仍保留应得分红 |
| 港股账户 | 本次按内地个人通过港股通购买处理；税率按每次分红证据确定 |
| 逆回购本金 | 使用账户中的人民币可用持仓现金，不使用现金类证券市值；向下取整到 1,000 元整数倍 |
| 逆回购期限 | 用户确认基本每个交易日做一天期逆回购；模型每日将可用现金滚动投入一天期。沪市 GC001 为方案默认品种，账户可选择深市 R-001，不混合两市场利率；具体市场尚未由用户指定 |
| 利率 | 每日有效市场利率优先；备用1.3%仅至2026-10-10，之后缺失停止递推并待补；市场计算仍estimated |
| 手续费 | 每次本金 × 百万分之一，最低 0.10 元；金额精度及舍入按券商规则核对 |
| 开始日期 | 最近有效券商现金导入基准之后；不依据代码部署日或任务运行日推断 |

用户已明确要求逆回购收益计入持仓现金。本方案据此决定：逆回购净收益在估计结算到账日自动写入同一 `cash_flows` 账本，状态为 `estimated`，参与系统现金、总资产、净值和后续回购本金计算；不增加投入本金，不要求每笔手动物化。不计入尚未到期的未来利息，也不把本金返还再算一次收益。

系统没有真实逆回购成交记录时，市场日利率和默认全额投入只能得到估算收益。账本同时返回确认现金、估算净增额和含估算的系统现金，页面明确显示“含逆回购估算”，不得称为券商实收。券商实际分红净到账、逆回购本金、成交利率及费用替换对应估算，不能再叠加一笔收入。本轮用户另授权公告与交易支持的港股分红、A股递延税估算入账；实收仅作可选替换，不要求上传流水。

## 3. 港股通及 A 股分红规则

### 3.1 港股通不能简单按股票名称固定 20%或 28%

财政部、税务总局及证监会[财税〔2016〕127号](https://shanghai.chinatax.gov.cn/gate/big5/shanghai.chinatax.gov.cn/tax/zcfw/zcfgk/zhsszc/201701/t429623.html)规定：内地个人投资 H 股的股息通常由 H 股公司按 20%代扣；非 H 股由中国结算按 20%代扣。外国预提税的抵免需要有效凭证和申请，系统不得自动视为已退税。

部分公司分红先发生发行人层面的扣税，再发生港股通个人扣税。例如中国移动[2019 年业绩公告的历史税务说明](https://www.chinamobileltd.com/sc/file/view.php?id=226449)说明相关名义持有人及港股通安排中的 10%预提税。若某次事件确证先扣 10%，再对余下 90%扣 20%，100 元税前分红净额为 72 元，综合扣减为 28%。该历史样例仅解释两层计算，不能替代该公司当前每次分红公告，更不能推广到全部红筹股。

每个事件保存发行人扣税率、港股通扣税率、各层计税基数、净额/毛额标识、适用投资者、规则生效区间和证据。一般模型为 `净额 = 毛额 × (1－发行人税率) × (1－港股通税率)`；公告或结算规则有特殊基数时按实际规则处理。上游已给出港股通税后金额时禁止再扣一遍。

证据优先级：券商实际净到账及扣税记录 → 中国结算对应分派信息 → 该次发行人公告。没有证据不能猜额外 10%；仅有一般 20%政策时可展示暂估值，但不标记已核实。按事件支持带依据的人工纠正，不建立永久“28%股票名单”。

港股通资格、人民币兑付和到账时点需按互联互通结算规则核验，不能直接套用 A 股登记日。上交所[2026 年港股通风险揭示书](https://www.sse.com.cn/lawandrules/sselawsrules2025/global/hkexsc/c/c_20260605_10820839.shtml)说明分派涉及换汇、清算与扣税，到账可能晚于香港市场派息日。优先使用实际港股通人民币净额；缺少时按有来源的结算汇率估算，保存原币和汇率日期，不使用实时汇率每日重估已到账现金。

### 3.2 A 股税款须与卖出行为关联

A股个人流通股递延税按每日日终净增减股数、FIFO及自然月/自然年持有期限重建；逐次卖出关联独立税事件，免税、授权补税估算与缺证据分别展示，到账日不得早于派息/卖出日。期初购入日未知、调整/不闭合或历史规则不支持即待核验，不猜购入日。A股可重建的FIFO卖出补税按max(公告派息日,卖出日)估计扣款日写estimated/authorized_deferred_tax_calculation并减少现金；evidence保存授权、批次、规则及dateBasis，不称实际扣款日。只有导入基准之后的扣款估计进入收益，基准吸收不重复扣税；已确认实际扣税替换同一事件，重算不会再叠加。未知购入日、调整或持仓不闭合继续待核验。官方公告明确2015年101号个人暂不扣缴条款并保存documentId/原文时，初始毛额可作为本次已授权分红计算净额，仍estimated。分红解析v4保存该证据及独立原始版本。

按[税务总局股息红利差别化政策](https://www.chinatax.gov.cn/n810341/n810755/c1797427/content.html)核对持有期限与卖出补税：一个月以内 20%，一个月至一年 10%，超过一年免税；适用的递延扣税不能在派息时简单全部扣掉。以实际买卖批次和有效规则重建税款，进口期初仓位缺少购入日时标记税款待核验，允许实际扣税记录确认，不猜持有年限。

[Tushare `repo_daily` 文档](https://tushare.pro/document/2?doc_id=256)定义weight日加权价和close收盘价，单位%；以weight估算年化日利率，不以close替代。

**本机准入已通过**：34/34交易日及本机权限通过；上交所质押式回购概览10-09 GC001的WEIGHT_RATE=1.283%与Tushare weight一致，按%除100。利率曲线的T日1.391及五日均值不能作为同口径交叉证据。准入原文/哈希/权限/采集时间保存ops.raw_records；仅完成日观测，不承诺上游固定发布时间或未来20日观察。

受控命令：`node server/scripts/probeTusharePermissions.js --probe=repo-daily --code=204001.SH --target-date=2026-10-09 --trading-days=34 --official-probe --json`。复用既有探测/行情服务；repoSourceAdmission核验连续交易日差集、重复、字段、百分数转小数、权限及采集时间，与[上交所质押式回购概览](https://bond.sse.com.cn/data/statistics/overview/Pledgerepo/)同日同证券WEIGHT_RATE交叉验证。官方人工探测经统一Python Guard及具体repo_overview策略，未知额度为NULL；原文缓存命中不联网，分页不完整或身份/日期不匹配拒绝。不是自动行情备源，不新建任务/调度或市场事实表。报告分admitted、pending_evidence、rejected，与字段passed分开；cashIncome必须admitted才使用市场利率，即使标准字段已存在也不能绕过；修订报告保留原始版本，页面/计算只读本地准入证据。生产凭据与定时运行未验收。

## 5. 数据模型：扩展现有现金账本

### 5.1 统一现金事实

扩展既有 `cash_flows`，不增加第二套账户现金流水，也不创建与其平行的估算流水表。正式 `flow_type` 包括 `external_transfer`、`dividend`、`dividend_tax`、`repo_interest`、`repo_fee`；正式 `origin` 包括 `manual`、`imported`、`system`；`status`区分 `confirmed`、`estimated`及已撤销版本。只有当前有效记录参与汇总。既有类型缺失的记录兼容为外部入出金，迁移核对导入证据后填来源，不能猜已有手工行是系统收益。

现金增加计正数、扣税/费用计负数。用户已授权的逆回购 `estimated`记录自动入账，其他待核验估算默认只作明细；本轮用户另授权现有数据计算：有已实施CNY税后金额且交易股数闭合的A股分红，以authorized_dividend_calculation和授权证据标识后可参与汇总；港股具公告税务、资格及历史汇率时按授权估算入账，缺实际到账不再阻塞计算。已确认的分红可入账。确认现金与估算净增额分开返回，系统现金为二者之和。用户账户自动回购政策启用，其他用户账户独立选择，不扩大授权范围。该政策版本及生效边界进入审计，禁止开关变化造成重复物化。所有投入本金和收益率外部净现金流只累计 `external_transfer`。

新增正式字段：到账时间、币种、原币金额、人民币金额、统一证券 ID、分红事件引用、来源、质量状态、计算版本、基准引用和事件唯一键。数据库日期统一收敛为 `date DATE`，不长期保留两份可独立写入的 TEXT/DATE 日期：迁移先统计并隔离无效旧日期，转换时验证行数和日期不变；API 从 DATE 序列化为上海业务日 `YYYY-MM-DD`，查询用 `::text`或共享日期工具，禁用 UTC 截日。临时过渡双字段必须由数据库约束/单一写入入口保证同源，并有删除旧字段的完成条件。

人民币/原币金额、每股股息采用至少 `NUMERIC(24,6)`，比例/年化利率采用 `NUMERIC(24,12)`；中间值保留精度，最终到账按券商规则四舍五入至分。不把税率当两位小数金额，不在每股金额入库时调用旧 `round(...,2)`。保留原有 JSON 日期/金额接口兼容，不直接把 double 精度作为金融结算规则。税务明细、资格证据、利率来源、计息区间和原始响应引用保存 JSONB；查找、排序和去重字段不得只塞入 JSONB。

自动流水按“账户＋收益事件＋现金类型”唯一，修订不产生重复当前金额。结合项目已有审计能力保存前值、后值、版本、原因、操作者/任务和来源版本；发布迁移前确认现有审计是否能承载完整修订，否则在同一账本下补充版本历史。复用迁移 047 已有的 `accounts.id`及 `cash_flows.account_id`关联，不再假设项目没有账户主键；实施前检查孤立引用及 FK 验证状态，并覆盖删除、重命名、导入与备份还原。

**整包保存的具体机制采用 `origin`隔离**：将 `accounts.js`现有账户范围全删改为同一事务内仅删除 `origin='manual'`的客户端可管理行，再插入/更新本次手工行；服务端过滤 `system`/`imported`行，不能将完整响应里的后台收益回传为手工行。客户端不能指定来源升级权限；与自动/导入 ID 冲突的写入拒绝，不覆盖原行。后台结算和保存共用账户锁、账户/现金流版本，失败整体回滚；普通流水删除接口也只准删除本人手工行。导入批次只能由受控导入入口替换对应批次，实际记录确认系统事件须经过收益服务。

备份还原采用专用受控流程，先核对基准、政策版本、事件唯一键和来源，完整恢复后重新校验；不能借普通整包保存绕过来源保护。自动记录只可通过受控撤销、事实修订或实际到账替换，不进入普通入出金的任意删除流程。必须测试“旧页面保存未携带收益”和“页面回传含收益”两分支。

### 5.2 标准分红与利率

`corporate_actions` 补充可追溯的分派事件键、修订关系及适用投资者/金额口径，区分预案、通过、实施、更正和取消。半年、年度与特别分红分别识别，不只按财政年度去重。检查现有 ON CONFLICT 是否更新每股金额等修订字段；不完整新版本不得覆盖有效金额。

建议新增标准层 `market.repo_daily_rates`：当前 `market.daily_bars`没有期限、加权年化利率及利率单位语义，不能把利率伪装成股票价格。新表是独立数据类别，不是同一利率的平行事实表；已有通用利率标准表若实施审计发现可完整承载则复用，不重复创建。字段包括 instrument_id、trade_date、source_id、tenor_days、weighted_annual_rate、close_annual_rate、unit、source_revision、raw_record_id、ingested_at 和 quality_status；年化统一存小数，1.3% = 0.013。唯一约束及索引覆盖证券/交易日/来源，质量校验验证日期、期限、单位和有限数值，不把所有异常或负值静默改为 0。

账户逆回购启用状态、品种、回退利率、费率和最低费用保存带生效日期及版本的账户政策。修改政策默认向后生效；历史重新估算必须明确范围并保留旧依据。

账户×证券覆盖表增加购入通道及交易单位两项。当前用户已明确全部港股经港股通购买，无需重复确认；导入/新建账户仍保存通道标识，其他用户及未来香港券商直持账户不得套用港股通税制。通道未知的事件进入待核验，不凭证券代码判断购买通道。交易单位以券商原始列名/说明、证券主档和导入批次为证据，保存原始数量、原单位及换算系数，内部股票数量统一为股、债券为相应标准单位。不能把“华泰上交所都按手”当通用事实，单位不明即阻止相关资格重建；仅凭成交金额看似合理不能通过。核查所有历史导入、手工交易及持仓基准，避免只修新导入后重复换算已有标准数量。

## 6. 统一计算与补录纠正

### 6.1 基准与分红资格

建立单一的按日期计算账户现金/收益服务，复用账本事务、账户锁和 dirty_from。账户摘要、完整账户、净值快照、历史重放及归因都调用该服务，不继续维护不同公式。

1. 选取最近有效券商现金基准；只加入其已结算边界之后的交易、外部资金和收益。只有日期没有时间的旧基准按已导入当日收盘口径处理；同日不再猜补，允许实际记录定向核验。
2. 分红资格独立使用可靠历史持仓基准及实际交易/结算规则。现金基准不能代替股权资格基准；登记日前已卖出的证券仍要纳入候选核查。资格日前的券商持仓快照可向前/向后重建，但必须证明区间交易完整。
3. 仅有实收证据的事件进入确认现金；已实施且公告、金额、资格及计算证据完整时按本轮授权进入估算现金。预案与未来分红只展示待发生；取消撤销原估计。缺少实际港股通到账信息的估算流水显式标为 estimated，不能宣称券商准确余额。
4. 补录/修改/删除真实资格日前交易时重建事件：从 1,000 股修正为 600 股，每股税后 0.8 元，则撤销原 800 元并将当前有效分红改为 480 元，差额为 −320 元；资格日后卖出不撤销应得分红。
5. 从最早受影响的业务日逐日重算分红、可用现金、逆回购本金及后续净值。更正时间仅作审计，不把补录日当收入日。基准以前已由实际现金吸收的事件不修改基准，不再次扣减。

缺少历史资格、送转拆合股改变数量却未处理、买入批次不完整或证券映射冲突时，将相应对象留在待核验队列，不退回当前持仓数量硬算。其他完整对象可以继续；账户结果展示缺口，任务不能报全部成功。

**基准前事件不静默丢弃**：自动入账写入前校验 `effective_date > anchor.date`；同日/更早事件进入 `before_anchor_not_backfilled`清单，按账户、类型、证券统计数量和已知金额，附原因及基准引用。不改业务日期绕过过滤。资格日在基准之前、到账日在基准之后的分红仍可纳入候选，前提是有完整历史资格证据。重新导入基准后，原自动收益保留审计但不再参加该基准后的续算；基准前清单是已解释排除项，不自动当故障或恢复证据。

### 6.2 逆回购按可用现金逐日估算

先核对[上交所回购交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/bond/trading/currency/c/c_20250606_10781048.shtml)和[实际占款天数及 365 天计息规则](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20170519_4313753.shtml)。一日期限不等于每次只计一个自然日；交易日、首次清算日、到期清算日、资金可用日及可取日均需有交易/结算日历依据。

每日使用该日交易、外部资金、已到账分红及已到期回购后的人民币可用现金，不把未来收入、应收分红、未到期本金或现金类证券当可用资金。若现有现金只有折合人民币总额，先区分可用人民币与外币/冻结额；无法确认则保留估算状态，不能冒充实际可用资金。

计算公式为 `利息 = 本金 × 当日年化利率 × 实际计息天数 / 365`，`净收益 = 利息－手续费`。每笔费率固定为本次用户确认值；选取满足本金整数千元且费用可支付的最大本金。若券商先收费用，需满足 `本金＋手续费≤可用现金`；若到期从回款扣费，按已验证清算规则执行。恰好 1,000 元这一边界必须实测手续费时点后确定，不将费用扣成负现金。

交易日前可用余额影响当日本金；收市后才到账的分红不能回填为此前已投入。已有数据只有日终现金时采用“日终资金在下一可交易日投入”的明确估算口径，避免时间穿越。遇到长假，以清算日期计算计息天数，资金重新可用后才可再次投入。

**节假日计息属于首期正确性门禁**：不采纳“一日品种固定一天、接受低估”的简化，也不新增节前择时或改选多日期限策略。一日品种本身可以有多自然日占款，依据实际清算日历一次算足并只扣一笔手续费；未到期/未可用不得重复投入。回购到期资金可能已可用而其实际占款计息区间尚未结束，须分别表示，不能只凭计息终日冻结资金。可用日与确认/估计利息入账日亦分别核验。官方例子中一日品种占款五天，不是一律节前最后一个交易日占款最多；不硬编码“春节11天”或“最后 N 日”。日历证据缺失则该笔留待核验，不固定按一天入账。

用户补充确认日常做法为“每天做一天期，周四享受周末利息”，据此将每日滚动作为默认行为。普通周、周五和次周一均正常清算时，周四一天期按周五至周日三天计息，使用周四该笔成交/估算利率；这笔只有一次交易和一次费用，不按周末额外生成交易。周五若本金已可用，仍可做新的一天期，该笔按其自身清算区间和周五利率计息，不能因周四计息覆盖周末而错误禁止周五复投。周末不生成新交易，资金可用与计息区间分别建模。以上为依据交收规则推导的普通周示例，节假日必须使用所选市场的实际日历重新计算，不能固定所有周四都为三天。

**利率回退仍为 1.3%**：不采纳近期 N 日中位数替换。它改变用户已确认政策，也无法证明目标日真实利率；近期 1.38%–1.65%的范围没有完整证据，不能当长期市场下限。真实对应日利率晚到后替换当日回退记录，并递推其后收益及本金。

利率下修的重算须区分估算投入与真实成交：仅为模型生成的后续回购，按修正后该日可用现金重新计算满足整数千元及费用可支付条件的本金，保证不透支，并记录原本金、新本金、差额及原因。下修情形不超过原估算投入；上修可按原“每日全额可用现金”政策增加估算本金，因此不把 `min(原投入, 修正可投入)`作为所有修订的永久公式。已有券商真实成交本金、利率和费用为不可猜改的事实，不能为了数学对齐自动缩减；若真实成交与修正现金倒挂，记录对账缺口并阻止后续无依据确认，等待补齐遗漏资金或更正事实。重算按真实业务顺序处理现金、本金可用与费用，不只把负余额截为零。

每日市场利率补齐只将 `rate_basis`从 `fallback`改为 `market_daily`，收益仍为 `estimated`，因为日加权利率不是用户成交价。只有有效真实成交/到账证据才变为 `confirmed`。继续沿用既定估计结算日入账政策，不改为“连续 N 日缺失后才入账”；次日修订同一事件当前版本及审计，通常不是每天两条有效现金流水。先核对真实日利率采集时刻与收益结算时刻：结算前已入库则直接使用，避免不必要的回退修订。

来源明确无权限、未准入或准入失败时禁止使用市场利率；仅2026-10-10及之前允许1.3%估算，之后停止递推待核验，不能无限显示短暂延迟。瞬时缺失按现有数据集时效/槽位截止门禁转 stale，并显示连续缺失交易日数及最后有效日期，不自造市场阈值。记录 `admission_blocked`及可恢复原因；权限修复由受控人工探测，临时失败由现有 Runner/Guard 恢复，避免每季度另建第二套调度。需要新增周期准入复核时先扩展现有任务模式并登记契约，不能自动创建常年重复无权限请求。

逆回购本金占用保存在计算明细中。账户总资产仍包含该本金，新增资产仅为净收益；可用现金与被占用本金分别展示，不把本金返还记成收益。现金确认在实际/估计结算到账时点；未到期应计收益单独标注，不能同时放入现金和应收。实际交易或到账替换估算时，以同一事件标识撤销旧估计并重算，避免双计。

### 7.1 任务扩展与阶段契约

逆回购行情扩展现有 `convertible_bond_universe_refresh` 的共享中国市场收盘采集职责，以独立阶段发布 `repo_daily_rates`；该 Runner 当前为次日 08:00 采集前一交易日，不把 15:10 的股票报价当成当日最终回购日利率。当天最终利率暂缺可先按 1.3%估算，次日入库后按对应业务日纠正；这一路径每天取已完成交易日真实市场利率，页面无外部请求。

分红扩展现有统一公告采集层及 `arbitrage_sync` 的官方公告发现入口，在同一来源窗口去重后增加分红分类/解析阶段，保留套利消费者职责。首次实施先核查现有窗口、分页、市场及休市日覆盖是否能完整承载；共用原始采集不等于套利候选集合能覆盖分红。以独立模式/阶段声明持仓相关分红范围，不能只用当前正持仓，也不能跳过持仓区间内已卖对象。若既有 Runner 的窗口确实无法承载，先补此 Runner 的模式和覆盖契约，不复制公告请求另起链路。

`company_financial_incremental_sync` 当前只采当前可转债正股财报，不承载普通持仓或港股分红；`stock_analysis_refresh`为只读任务，保持本地计算。净值 `nav_snapshot`也保持不联网，复用其本地阶段和历史重放入口处理待结算/待修订收益。所有手工补算、启动补偿和定时执行调用同一服务。

| 阶段/模式 | 发布的数据集（拟登记名称） | 依赖及完成条件 |

| 官方分红发现/解析 | `stock_cash_dividend_facts`，范围含市场和目标证券集合 | 覆盖窗口及分页完整、事件身份和解析质量通过；空结果必须有已核验无新增证据 |

## 8. 实施顺序与验收

采用 P0a/P0b/P1/P2/P3 分阶段交付，每期独立验收和可回滚；P0a负责已有现金口径重构及已知错误纠正，P0b增加收益类型骨架。每期安全门禁不能推迟到最后一期。

| P0a | 统一旧现金/本金内核、日期精度、origin来源保护，不自动产生收益 | 先固化各入口基线，未涉旧错误的结果零差异，已知错误按独立修正清单通过。日期/金额迁移与来源保护分别验证，可独立回滚。没有新收益类型写入，不把现金一致性修复当收益已实现 |

每期代码交付运行 `npm.cmd run test:all`、日期及知识门禁，按本地服务交接流程更新已运行服务并核验 `/health`、相关接口及静态资源版本。低性能限制下不得自行启动新的开发服务器。生产发布、生产同步按独立授权及部署流程执行，不因本方案修订而执行生产回填。

### 8.1 待核验对象的处理与关闭

复用持久化质量/收益待办链路，按账户、证券、事件、原因和版本去重；保存首次发现、最近尝试、缺失证据、负责人/入口、下一步及处理状态。待核验不是无限重试状态；空查询、用户隐藏或普通任务成功不能算证据补齐。

| 原因 | 终态路径 |
|---|---|
| 基准同日时点不明 | 补充券商时点/明细后确认已覆盖或需入账；证实基准包含则解释性排除 |
| 缺历史资格、购入批次或单位 | 补入原始对账单/交易/单位依据后重建并验证；不能用当前持仓或任意税率自动闭合 |
| 通道、税务或港股到账不明 | 公告与通道/税务/历史汇率完整后可计算；实际结算/扣税证据只升级为确认，不是计算前置条件 |
| 回购日历或真实成交与余额冲突 | 补齐对应市场日历/资金事实并对账，完整后续跑 |
| 来源不可用 | 保留来源阻塞状态和估算标识；来源恢复只解决利率缺口，不自动确认实际收益 |

允许账户所属用户通过受控入口明确“本事件不参与”并写原因，终态为 `excluded_by_user`，保留差额/缺证据审计，不计成功覆盖或质量恢复；后续新证据可重新打开。任何保守默认税率/历史数量需逐事件明确授权并保持估算，不能自动用来清空队列。基准前已解释排除保留为独立终态，不当永远待办。页面分别显示未完成、已解决、用户排除、来源阻塞及基准前不补数量。

### 8.2 量化对账与任务运行

P0a报告每入口/账户/日期的基线差异总数、预期修正数和未知差异数，未知差异必须为0。P1/P3有完整真实明细的账户/日期按券商精度对账，未知现金差额为0；至少覆盖实际具备证据的全部启用账户及典型分红事件，不能要求凭空凑3个账户或对没有证据的日期报通过。差额已解释并不自动等于零，税款/换汇/到账时点必须分别列项。

P2确定性验收要求利率单位、整数本金、清算日期、每笔税费和修订幂等与参考计算逐项一致；估算与真实成交的差异单独报告，不能要求日加权估算与个人成交无证据差异为0。实施后以连续20个所选市场交易日作为影子观察目标，记录覆盖、回退日数、修订次数、差额和真实凭证覆盖；数据未齐继续观察不伪报通过，不臆造 X%收益准确率门槛。

补录事务只保存交易、脏起点和持久化重算待办，不同步递推三年历史、不跨全部账户持锁。基准前交易若影响基准后分红资格，资格证据可向前检查，但现金补算仍从有效基准后开始。复用现有本地Runner/持久化队列，单账户去重合并最早脏日期，分批读取、计算并以输入版本比较和账户短事务提交；长区间计算不持账户锁，旧版本发现新交易后重排而非覆盖。

与定时净值任务共用账户锁、数据版本和数据集依赖：待重算账户显示旧快照及待更新状态，不发布假完整；其他账户正常执行。进度显示目标区间、已处理业务日/总日数、剩余阶段、下一尝试时间和最后进展。时长预算先测实际账户和最长有效区间的耗时、锁等待及批次延迟，再登记内部运行SLO；运行截止复用现有槽位截止/超时，达到即持久化partial并续跑，不能作为业务完成上限。纯方案阶段不编造已经达成的秒级性能结论。

### 8.3 监控指标
