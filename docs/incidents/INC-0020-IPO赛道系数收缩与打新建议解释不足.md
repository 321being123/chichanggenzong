# INC-0020：IPO赛道系数收缩与打新建议解释不足

状态：跟踪中（本地已修复，生产待授权）
日期：2026-09-10

## 现象与影响

小样本赛道先按 `n/(n+5)` 向 1.0 收缩，再叠加最终上下限，导致一年内新股本来就少的赛道系数普遍被压低；业务可信度又参与系数折扣，形成二次减弱。打新详情只展示结果，无法核对模型输入、赛道修正和建议评分过程。

## 根因链路

已入库 IPO 首日表现 → `ipo_lib_sector.py` 计算赛道热度 → `sector_heat` / `prediction_context` → IPO 预测与建议 → `/api/ipo/report/code`、日报详情。

## 直接原因、根本原因与保护机制失效原因

- 直接原因：赛道热度使用样本收缩和最终上下限；业务分类可信度被当作历史表现折扣；解释字段没有完整落库和展示。
- 根本原因：把“分类证据可信度”和“历史表现系数”混成一个数，且用面向保护的限制替代了可审计的直接计算。
- 保护机制失效原因：只有最终结果回归，没有对公式、样本收缩、系数上下限和详情解释完整性的契约测试。

## 同类范围与核查结果

已覆盖所有 A 股 IPO 赛道热度计算、个股赛道上下文、XGBoost/线性兜底预测、日报和实时详情接口；不是只修燧原科技单只股票。港股独立研究评分口径不在本次范围内。

## 修复与回归证据

- 赛道系数改为“赛道稳健中位数 ÷ 同窗口全市场稳健中位数”，取消样本收缩和最终上下限。
- 业务可信度仅作为分类证据展示，不再折扣赛道系数；样本数继续展示。
- `prediction_context.calculation_detail` 增加模型输入/补位、原始输出、板块校准、赛道修正、市场温度、最终区间；`advice_calculation` 增加逐步评分。
- 本地 IPO Python 回归 `75/75`，Node IPO 接口回归 `35/35`；交付前继续执行全量测试和知识门禁。

## 防复发措施与遗留风险

新增公式不收缩/不设最终上下限、可信度不折扣、详情字段和评分步骤的回归断言。生产数据库中已有的旧 `prediction_context` 不会因代码部署自动重算；如需线上历史记录全部切换到新口径，必须另行授权生产重算/补数。
