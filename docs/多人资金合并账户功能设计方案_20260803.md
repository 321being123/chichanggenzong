# 多人资金合并账户功能设计方案

> 设计日期：2026-08-03  
> 适用模块：持仓管理  
> 目标案例：招商证券账户由 33 人共同出资，证券账户统一投资，但每个人的份额、市值、入资、取款和收益需要单独核算  
> 本文仅做产品与数据方案设计，不包含代码、数据库或生产数据修改

## 一、方案结论

采用类似公募基金的“份额制”。

- 招商证券账户仍是唯一的真实投资账户，持仓、交易、现金和总资产只维护一套。
- 33 个人作为该账户下的“出资人”，每个人持有一定数量的份额。
- 账户设置一个“单位净值”；全新账户通常从 `1.000000` 开始，现有招商证券账户切换时使用启用日已有的最新有效净值作为份额起点。
- 入资时按当时单位净值申购份额；取款时按当时单位净值赎回份额。
- 每个人当前市值 = 个人当前份额 × 当前单位净值。
- 系统只做账务登记，不发起真实转账。资金实际进入或离开券商账户后，由管理者确认登记。
- 一期只提供管理者汇总表，不给 33 个人分别创建登录账号。

不能按“累计出资金额占比”长期直接分摊总资产。有人中途入资或取款后，历史占比会变化，直接按本金比例分摊会把老投资者已经产生的收益错误分给新投资者。份额制可以解决这个问题。

## 二、计算示例

假设 33 人合计投入 100 万元，起始单位净值为 `1.000000`。

| 出资人 | 初始投入 | 获得份额 |
|---|---:|---:|
| 张三 | 30,000 元 | 30,000 份 |
| 李四 | 50,000 元 | 50,000 份 |
| 其余 31 人 | 920,000 元 | 920,000 份 |
| 合计 | 1,000,000 元 | 1,000,000 份 |

一个月后，招商证券账户总资产变成 110 万元：

```text
单位净值 = 1,100,000 ÷ 1,000,000 = 1.100000

张三市值 = 30,000 × 1.10 = 33,000 元
李四市值 = 50,000 × 1.10 = 55,000 元
```

此时张三取款 10,000 元：

```text
赎回份额 = 10,000 ÷ 1.10 = 9,090.909091 份
剩余份额 = 30,000 - 9,090.909091 = 20,909.090909 份
剩余市值 = 20,909.090909 × 1.10 = 23,000 元
```

取款完成后：

- 张三累计投入：30,000 元；
- 张三累计取款：10,000 元；
- 张三当前剩余市值：23,000 元；
- 张三累计收益：`23,000 + 10,000 - 30,000 = 3,000 元`；
- 公共账户总资产应由 110 万元降到 109 万元；
- 总份额同时减少到 990,909.090909 份；
- 单位净值仍为 `1.100000`，取款本身不会被算成投资亏损。

页面必须同时显示“净投入”和“当前市值”。净投入只是累计入资减累计取款，不代表现在还能取多少钱；真正的剩余资产看当前市值。

## 三、业务口径

### 3.1 账户类型

在现有账户上增加类型：

- `单人账户`：保持当前全部功能和算法不变；
- `多人合并账户`：启用出资人、份额和申购赎回功能。

招商证券现有账户采用“从今天开始管理”的初始化方式，不追溯各个出资人的历史份额。账户设置中增加“启用多人模式”按钮，点击后进入初始化向导；完成出资人当前市值录入和金额核对后，原账户原地切换为多人模式。

这个操作不会新建另一个招商证券账户，也不会搬迁或重建已有持仓、交易、现金、账户净值和历史数据，只是在现有账户下面新增一层出资人份额账本。多人份额历史从启用日开始，启用日前只保留公共账户历史，不提供个人历史市值。

存在已确认的出资人流水后，不能直接改回单人模式。

### 3.2 份额净值

```text
账户单位净值 = 账户总资产 ÷ 账户总份额
个人当前市值 = 个人当前份额 × 账户单位净值
个人占比 = 个人当前份额 ÷ 账户总份额
```

账户总资产继续使用现有招商证券账户的总资产结果，即持仓市值加现金。股票、基金、转债、港股等资产不需要再按 33 人复制保存。

单位净值与现有收益页的“收益净值”概念相近，但应单独保存：现有净值用于账户收益曲线，新单位净值同时承担出资人申购、赎回和市值核算，不能只依靠前端临时计算。

### 3.3 入资规则

一期固定使用“上一有效交易日收盘单位净值”确认份额，避免同一天先后录入造成价格不一致。

```text
新增份额 = 入资金额 ÷ 确认单位净值
```

- 全新账户第一次初始化时单位净值为 `1.000000`；现有招商证券账户按方式 C 切换时，使用启用日已有的最新有效净值。
- 同一天确认的所有入资和取款使用同一个单位净值。
- 资金尚未实际进入券商账户时只保存为“待确认”，不增加份额、不增加账户现金。
- 管理者确认到账后，系统才同时生成出资人份额流水和账户入金流水。

### 3.4 取款规则

```text
赎回份额 = 取款金额 ÷ 确认单位净值
取款后份额 = 取款前份额 - 赎回份额
```

- 取款金额不能大于该出资人的可取市值。
- 支持“取固定金额”和“全部退出”两种方式。
- 尚未真实从券商账户转出时为“待确认”，不减少份额。
- 确认后同时生成份额减少流水和账户出金流水。
- 全部退出时以全部剩余份额计算最终金额，避免留下极小零头份额。

### 3.5 收益口径

每个人显示以下指标：

```text
净投入 = 累计入资 - 累计取款
累计收益 = 当前市值 + 累计取款 - 累计入资
未实现收益 = 当前市值 - 剩余成本
已实现收益 = 历次取款金额 - 对应赎回份额的成本
累计投入回报率 = 累计收益 ÷ 累计入资
```

“累计投入回报率”只作为容易理解的简单回报率，不标成年度收益率。以后如需比较不同入资时间的真实资金效率，再增加资金加权收益率，不放进一期。

## 四、页面设计

多人合并账户在持仓管理二级导航中增加“出资人”页；单人账户不显示该页。

### 4.1 顶部概览

显示四项：

- 公共账户总资产；
- 当前单位净值；
- 总份额；
- 当前出资人数。

同时显示核对状态：`已平账`、`待确认流水`或`金额不一致`。

### 4.2 出资人汇总表

| 字段 | 说明 |
|---|---|
| 出资人编号 | 账户内唯一，避免重名 |
| 姓名 | 汇总表展示名 |
| 状态 | 持有中、已退出 |
| 累计入资 | 历次确认入资合计 |
| 累计取款 | 历次确认取款合计 |
| 净投入 | 累计入资减累计取款 |
| 当前份额 | 当前仍持有的份额 |
| 资产占比 | 当前份额占总份额比例 |
| 当前市值 | 当前份额乘当前单位净值 |
| 已实现收益 | 已取款部分产生的收益 |
| 未实现收益 | 当前仍持有部分产生的收益 |
| 累计收益 | 当前市值加累计取款减累计入资 |
| 累计投入回报率 | 累计收益除以累计入资 |

表格默认按当前市值倒序。支持按姓名搜索，支持只看持有中或已退出。

### 4.3 单人详情

点击出资人后打开详情，显示：

- 当前市值、份额、占比、剩余成本和累计收益；
- 个人市值历史曲线；
- 每次入资、取款、份额变化、确认净值和操作备注；
- “登记入资”和“登记取款”按钮。

一期不展示“这个人具体拥有多少股某股票”。证券实际由公共账户统一持有，个人资产按份额核算；如以后确有需要，可按占比提供只读的穿透持仓估算，但不能把估算数量当成真实证券持仓。

### 4.4 导入与导出

支持批量导入 33 人初始数据，模板字段：

```text
出资人编号、姓名、日期、类型（入资/取款）、金额、备注
```

导出一个 Excel，包含两个工作表：

- `出资人汇总`：当前所有人的资产和收益；
- `资金明细`：全部人员历次入资、取款和份额变化。

不生成 33 个独立账号，也不接入支付、银行卡或自动转账。

## 五、现有账户初始化

招商证券账户固定采用方式 C：只从启用日开始管理，不追溯 33 人过去的份额变化。

### 不采用：方式 A，所有人同一天开始投入

适合本案例中 33 人在同一开始日共同出资的情况。

1. 选择起始日期；
2. 导入每个人的初始投入；
3. 单位净值设为 `1.000000`；
4. 每个人初始份额等于初始投入；
5. 校验 33 人投入合计是否等于该日起始账户总资产。

这是最简单、最准确的初始化方式。

### 不采用：方式 B，历史上分批加入或取款

必须导入每个人真实的入资、取款日期和金额，并按日期顺序重算份额。历史账户现金流也要能与这些记录对应，否则只能标记为“历史不完整”，不能宣称历史收益精确。

### 本次采用：方式 C，只从今天开始管理

直接导入启用日每个人确认的当前市值作为期初权益，从启用日开始计算。系统明确标注“个人份额与收益从本日开始”，不使用原始出资金额倒推出历史收益。

启用流程：

1. 在招商证券账户设置中点击“启用多人模式”；
2. 系统读取启用日招商证券账户的最新总资产；
3. 手工录入或批量导入 33 人在启用日确认的当前市值；
4. 系统读取启用日已有的最新有效账户净值作为初始单位净值，并按“个人确认市值 ÷ 初始单位净值”生成每个人的期初份额；
5. 展示 33 人当前市值合计与招商证券账户总资产的核对差额；
6. 差额符合规则后确认，账户原地切换为多人模式；
7. 从下一笔入资或取款开始，全部通过个人份额流水管理。

初始化时不强制把单位净值重置为 `1.000000`，而是沿用启用日已有的最新有效账户净值作为多人份额账本的起点。它只用于确定初始份额的计量尺度，不代表继续追溯个人历史收益；确认后保存为独立的多人份额净值起点，也不修改现有公共账户收益页的历史净值。若启用日没有任何有效账户净值，才使用 `1.000000`。

初始化完成前只显示预览，不写入正式份额账本。必须满足：

```text
全部出资人期初市值合计 = 招商证券账户初始化日总资产
```

考虑份额数量和金额显示都会四舍五入，允许的初始化绝对差额为：

```text
|招商证券账户总资产 - 全部出资人期初市值合计| <= 启用日每份净值
```

差额不超过启用日每份净值时允许确认，并保存实际差额用于后续核对；差额超过一份净值时必须阻止确认并提示重新核对。内部仍使用高精度份额计算，不能为了平账把差额随意加到某个出资人名下。

## 六、数据设计

### 6.1 账户扩展

在现有 `accounts` 增加：

| 字段 | 含义 |
|---|---|
| `account_mode` | `single` 或 `pooled`，默认 `single` |
| `pool_start_date` | 多人份额账本起始日期 |

现有账户使用不可变 `account_id`，新增表全部通过 `account_id` 关联，不再使用账户名称作为长期关联键。

### 6.2 出资人表 `pool_investors`

| 字段 | 含义 |
|---|---|
| `id` | 不可变主键 |
| `account_id` | 所属公共账户 |
| `investor_code` | 账户内唯一编号 |
| `display_name` | 姓名或展示名 |
| `status` | `active`、`exited` |
| `joined_at` | 首次加入日期 |
| `exited_at` | 全部退出日期，可空 |
| `note` | 备注 |
| `created_at/updated_at` | 创建和更新时间 |

唯一约束：`account_id + investor_code`。

### 6.3 份额流水表 `pool_unit_events`

这是个人资产核算的权威来源，确认后不直接修改或删除；录错时使用“冲正原流水，再录入正确流水”。

| 字段 | 含义 |
|---|---|
| `id` | 流水主键 |
| `account_id` | 公共账户 |
| `investor_id` | 出资人 |
| `event_type` | `initial`、`subscription`、`redemption`、`reversal` |
| `effective_date` | 生效日期 |
| `pricing_nav_date` | 使用哪一天的单位净值定价 |
| `amount` | 入资或取款金额，保存正数 |
| `unit_nav` | 本次确认单位净值 |
| `units_delta` | 份额变化，入资为正、取款为负 |
| `cash_flow_id` | 对应现有账户现金流，待确认时为空 |
| `status` | `pending`、`confirmed`、`reversed` |
| `reversed_event_id` | 冲正对应的原流水，可空 |
| `note` | 备注 |
| `created_by/created_at` | 操作者和操作时间 |

金额使用 `numeric(20,2)`，单位净值和份额至少保留 8 位小数，禁止使用浮点数长期保存。

### 6.4 单位净值快照表 `pool_nav_snapshots`

| 字段 | 含义 |
|---|---|
| `account_id + date` | 唯一键 |
| `total_asset` | 当日公共账户总资产 |
| `total_units` | 当日确认后的总份额 |
| `unit_nav` | 当日单位净值 |
| `net_capital_flow` | 当日已确认净入资 |
| `source_snapshot_at` | 对应现有账户资产快照边界 |
| `calculation_version` | 算法版本 |
| `status` | `valid`、`stale`、`error` |
| `calculated_at` | 计算时间 |

不单独保存 33 份股票持仓，也不必永久保存每人每天一张重复快照。个人任意日期的份额由份额流水累计，市值由该日份额乘该日单位净值得到。

## 七、与现有持仓账本的衔接

现有数据职责保持不变：

```text
招商证券账户
  ├─ positions：公共持仓
  ├─ trades：公共交易
  ├─ cash_flows：账户真实入金/出金登记
  └─ nav_history：公共账户总资产和收益历史

新增份额层
  ├─ pool_investors：33 个出资人
  ├─ pool_unit_events：每人的入资、取款和份额变化
  └─ pool_nav_snapshots：公共账户单位净值
```

多人账户中，原来的“资金转入转出”入口应改为从出资人详情发起，避免出现一笔账户入金没有归属到任何人的情况。

确认一笔入资或取款时必须在服务端同一个事务中完成：

1. 锁定账户；
2. 校验出资人和可用份额；
3. 读取确认单位净值；
4. 写入份额流水；
5. 写入对应的现有账户现金流；
6. 提升数据版本并标记受影响日期后的净值待重算；
7. 全部成功后提交，任一步失败则全部回滚。

待确认流水不进入以上正式账本。确认后如需改错，必须冲正，不能只删除个人流水或只删除账户现金流。

## 八、必须处理的异常

- 出资人取款超过当前市值：拒绝；
- 公共账户总资产小于全部出资人市值合计：显示不平账并停止新的确认；
- 有账户现金流但没有对应出资人：多人模式下标记异常；
- 有出资人份额流水但没有对应账户现金流：标记异常；
- 历史净值缺失：停止该日期之后的精确回放，不能静默估算；
- 回填失败：保留上一份有效单位净值，不覆盖成半成品；
- 重复导入：按账户、出资人、日期、类型、金额和导入批次去重；
- 账户重命名：不影响出资人和份额，因为全部通过 `account_id` 关联；
- 出资人重名：通过唯一的出资人编号区分；
- 金额显示四舍五入：内部高精度计算，页面只在最后一步保留两位小数。

## 九、实施顺序

### 第一期：满足当前 33 人管理

1. 在现有账户设置中增加“启用多人模式”，原账户原地切换，不新建账户；
2. 增加多人账户类型、出资人表、份额流水表和单位净值快照表；
3. 按方式 C 完成初始化向导和 33 人当前市值批量导入；
4. 增加出资人汇总页、个人详情、入资、取款和导出；
5. 入资取款与现有账户现金流使用同一事务；
6. 增加平账检查和启用日之后的历史重算；
7. 单人账户保持原样。

### 暂不纳入一期

- 33 人分别登录查看；
- 银行卡、微信、支付宝或券商自动转账；
- 每个人独立下单或拥有独立证券持仓；
- 管理费、业绩报酬、分红再投资和税务计算；
- 按个人占比展示虚拟股票数量。

## 十、验收标准

1. 招商证券原账户可通过“启用多人模式”原地切换，已有持仓、交易、现金和公共账户历史保持不变。
2. 33 人期初市值合计与启用日账户总资产的绝对差额不超过启用日每份净值。
3. 启用日前不生成个人历史市值，个人份额与收益从启用日开始。
4. 没有中途资金变化时，每个人市值严格按份额占比分配。
5. 新出资人在账户已经盈利后入资，只按当时净值获得份额，不分享加入前的收益。
6. 某人取款后，其份额和市值正确减少，取款本身不改变单位净值、不记为亏损。
7. 某人全部退出后份额归零，历史入资、取款和收益仍可查询。
8. 任意日期全部出资人未取整市值之和等于公共账户总资产。
9. 取款超过个人可取市值时无法确认。
10. 已确认流水冲正后，个人份额、账户现金和历史净值同步恢复。
11. 多人账户不能产生无出资人归属的普通入金或出金。
12. 修改招商证券账户名称不会丢失任何出资人数据。
13. 现有单人账户的持仓、交易、收益和现金流功能不受影响。
14. 导出的汇总表能在同一张表看到 33 人各自的投入、取款、剩余市值和收益。

本方案的核心边界是：公共证券账户负责“钱整体投得怎么样”，份额账本负责“这笔总资产分别属于谁”。两者通过确认后的入资、取款流水原子关联，不能各自独立修改。
