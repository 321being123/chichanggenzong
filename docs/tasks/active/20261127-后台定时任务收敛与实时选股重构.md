## 已确认事实、已排除假设

- 现行 `loadPbWindow` 原 SQL：仅取 `pb IS NOT NULL`，逐日 `DISTINCT ON` 按
  `CASE WHEN s.source_code LIKE 'lixinger%' THEN 0 ELSE 1 END, v.source_id` 选唯一行；
  `marketDays` 基于 `daily_valuations` 的 `COUNT(DISTINCT trade_date)`，**不滤 pb**。
- 测试夹具大量直接 `INSERT INTO market.daily_valuations`，不会经过应用写入入口；因此本轮在
  `stock-selection-data-semantics`、`pipeline`、`readiness-db` 三个 DB 测试的夹具后显式调用投影重建，
  不使用“投影为空时静默回退”的旁路。
- `server/services` 目录角色为 `service_legacy`（新文件默认被架构门禁拦截）；已在
  `governance/architecture-boundaries.json` 将 `pbProjectionSync.js` 登记为 `application`、
  `pbProjectionRepository.js` 登记为 `repository`。
- `lixingerOfficial.callEndpoint` 原实现会写 `ops.raw_records` 与接口权限状态；本轮新增
  `persist:false` 只读探针选项，探针仍走统一 Guard，但不写业务表。
