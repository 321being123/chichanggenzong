## 先读什么

每个任务先阅读：

1. `AGENTS.md`：强制规则与交付标准。
2. 本文件：按任务选择权威资料。
3. `governance/knowledge-map.json`：按任务描述和实际改动文件匹配必读、必更新资料与检查。

不要默认全量读取文档。根因不明、跨模块、数据、权限、安全、任务调度或部署变更时，必须扩大阅读范围。

## 统一工作流

开始：确认项目根、Git 基线和未提交改动；按路由读取资料；记录不确定点。

诊断：从数据源、数据库、服务、接口、页面和运行环境检查完整链路；区分直接原因、根本原因与保护机制失效原因；检查同类对象和同类功能。

收尾：用实际 `git diff --name-only` 再跑一次路由；更新命中文档；重要取舍写 ADR，重大或重复问题写 Incident；运行 `npm.cmd run check:knowledge`。

## 平台约定

Git 仓库中的本索引、`AGENTS.md` 和路由表是唯一项目事实来源。平台私有 Memory 只能辅助召回，不得写入或裁决项目事实。

| 平台 | 状态 | 接入方式 |
|---|---|---|
| Codex | 已接入（2026-07-27 起） | 工作区根 `AGENTS.md` 入口 + 项目 `.codex/config.toml` 关闭自带记忆 |
| WorkBuddy | 已接入（2026-08-29 起） | 工作区根 `AGENTS.md` 自动注入；私有记忆只做指针，规则见根目录 `AGENTS.md` 的"多 Agent 协作：记忆路径统一规则" |

机制说明：WorkBuddy 每次会话自动读取工作区根目录 `AGENTS.md`（不读 `portfolio-server/AGENTS.md`），因此路由靠根目录入口文件转发。它没有类似 Codex 的记忆开关配置项，只能靠规则约束，不要臆造配置。

未验证的平台不得宣称已接入，也不得复制本项目的事实到私有记忆。
