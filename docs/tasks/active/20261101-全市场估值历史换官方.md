## 1. 为什么单独立项

`market.daily_valuations`（逐只证券 × 交易日 × 来源）目前是**新旧来源并存**：

- 官方行只在 `convertible_bond_universe_refresh`（转债正股任务）覆盖到的业务日落库，实测 2026-10-29 共 **5570 行**；
- 更早日期全部是 `tushare` 写入的历史行，**没有整段重取**；
- 读取侧已经做了择优（0.9.1.11 起按日期 `DISTINCT ON` + 官方优先），所以页面不会出现两个点，但**同一天的数值仍可能来自旧来源**：
  旧来源是整体法口径下的逐只估值，官方是官方口径，个别证券的 PE / 市值会不同。

这不是「改个来源标签」就能收口的：换源区间覆盖全市场约 5000+ 只 × 十余年交易日，属于**批量回填 + 口径复核**，必须单独立项，带预演、分批、可回滚。

## 2. 已确认事实（写卡前核对）

| 事项 | 事实 | 出处 |
|---|---|---|
| 表主键 | `(instrument_id, trade_date, source_id)`，来源不同就是两行 | `market.daily_valuations` 建表 |
| 官方批量能力 | 数据层 `official.resolveValuationRows({codes, tradeDate})`（按日、按代码集）与 `resolveValuationSeries({codes, startDate, endDate})`（按代码、按区间） | `server/dataAccess/marketDatasets.js` |
| 全市场代码清单 | 仍靠 Tushare `daily_basic` 当日分区得到候选代码集，官方只补这些代码的估值 | `readStockValuationRows` |
| 官方区间限制 | 单次请求年份差 >10 年直接 403，已在适配层分段（0.9.1.10） | `lixinger-range-chunking` |
| 读取择优 | 分析页序列、转债分析缓存、格雷厄姆输入均已官方优先 | 0.9.1.11 / `marketGrahamRepository.listInputs` |
| 总市值聚合 | `stockRepository.totalMarketCap` 按 `priority ASC` 取一行，官方优先级已在 2026-11-01 的迁移 181 修正为优先于 Tushare | 迁移 `181_lixinger_official_priority` |

## 3. 缺口（本卡要解决的）

1. **历史段没换**：`daily_valuations` 里 2026-10-29 之前的行仍是 Tushare 数值。
2. **口径差异没量化**：同一证券同一天，两来源 PE / 总市值差多少、差在哪些行业，没有样例对照。
3. **回填没有脚本**：现在没有「按代码区间整段回填官方估值」的一次性脚本，也没有预演模式。
4. **写入口径未统一**：官方与备源按代码混合落库是既有设计（官方覆盖到的代码用官方、其余用备源），历史回填必须保持这一约定，不能整批套一个来源。

## 4. 实施方向（待评估，不是已定方案）

- **候选 A（推荐先试）**：按代码分批（例如每次 200~500 只）× 长区间（分段 ≤10 年，适配层已支持），对每批调 `resolveValuationSeries`，只要官方返回的日期就写官方行；批间保存持久化进度，可中断续跑。
- **候选 B**：按交易日逐日调 `resolveValuationRows`，逻辑最简单，但交易日数 × 单日请求量太大，按官方额度（1000 次/分）估算不可接受，仅适合补单日缺口。
- 两种方式都必须：默认只读预演（打印将写入行数、覆盖日期范围、与旧来源的差异抽样），`--apply` 才写；写前记录旧行快照；失败不覆盖已有有效行。

## 5. 验收标准

1. 指定区间的每个交易日，官方行数与该日全市场股票只数一致（允许官方缺该证券时保留旧来源，但必须逐日记数与列明缺口）。
2. 抽样 20 只证券 × 5 个日期，逐字段（pe/pe_ttm/pb/总市值）与官方接口原始响应一致。
3. 读取侧抽样：个股分析页、转债分析、格雷厄姆输入三处，同一日期只返回一个数值且来源是官方。
4. 回填后 `market.daily_valuations` 的官方行覆盖日期连续（按日期差集检查，不能只看 `MAX(date)`）。
5. 预演与实跑行数对得上；中断后续跑不重复、不丢进度。

## 6. 风险与前置

- **数据量**：十余年 × 全市场，写库与请求量都远超一次性脚本的常规规模；需先在生产以外用测试库跑一遍计时。
- **口径变化外溢**：逐只估值换官方后，转债正股估值、债券安全性、格雷厄姆、总市值聚合的数值都可能变，页面阈值与历史对比需同步复核。
- **旧来源是否保留**：`daily_valuations` 允许两来源并存（读取已择优），因此回填**不需要删除旧行**；若后续要清理旧行，必须单独评估（`stock_unified` 等视图可能依赖）。
- **生产窗口**：回填必须在服务器执行（项目铁律：数据补齐服务器自理），并且要避开定时任务高峰。

## 7. 明确不做

- 不改 `daily_valuations` 的表结构与主键。
- 不动公告、可转债条款、交易日历、IPO 事实等其他数据集的来源。
- 不因为回填而调整页面阈值——阈值调整是独立事项。

### 8.2 范围与方案（2026-11-01 两次按用户口径修正）

**范围＝按需，不是全市场**。转债只算「当前仍在上市交易」的：

| 来源 | 只数 |
|---|---|
| 当前在交易的转债（最近交易日仍有转债行情）→ 其正股 | **308**（转债 311 只，2026-10-30 实测） |
| 持仓 + 自选（经 `securityIdentity` 归一，含港股/转债代码） | 45 |
| 已分析过（`analytics.stock_overview_latest`） | 21 |
| **并集** | **361**，其中在 `daily_valuations` 有行的 **327** 只 |

对应仍是 Tushare 的行：**197,832 行**（2025 起 125,456 行）。官方现有 1,002 行（仅 2026-10-29）。
> 为什么不全量：历史行只有两处按天回看——个股分析读该股全部历史、转债分析回看 **500 天**；其余消费方（债券安全性、转债列表、下修服务、全市场总市值）只要当日或最近一条。全市场 59.7 万行基本没人读，只让表从 122 MB 翻倍。全市场仍可 `--scope=all` 显式执行。

**两处口径修正（都踩过）**：
1. `bond_unified.status='listed'` 不可靠：生产列出 1,080 只转债，但实际当天在交易的只有 **311 只**，其余是历史摘牌没更新状态。改用「最近交易日仍有转债行情」判定。
2. `public.positions.code` 全是无后缀格式（105 行全部如此，且混着 `01958.HK`、`113627.SH` 这类代码），直接字符串比对 `canonical_code` 会 0 命中或跨市场误配。持仓/自选统一走 `securityIdentity.resolveCanonicalCode` 归一后再传参（实测 45 个代码全部解析成功）。

按「代码批(100) × 日期区间」取官方，适配层内部按官方 ≤10 年跨度自动分段：327 只 ≈ **4 批**，多数区间落在 2025-01～2026-10 → **约 4~8 次**官方请求（按日逐日要 9,610 次）。

**只写现有分区已有的 (证券, 交易日)，不新增日期分区**——新增日期会连带改变「全市场总市值按日聚合」「M2 市值比月末采样」的输入集合，属于另一件事。旧 Tushare 行不删（读取端已官方优先，保留可回溯）。

**本地无法真实预演**：本机连的是隔离测试库，理杏仁 Guard 策略状态为 `unknown`，官方调用被判不可用（`resolveValuationSeries` 返回 0 行）；生产同一接口正常（2026-11-01 实测单只 000001 三个月返回 64 行、`2026-08-28 pe_ttm 5.2021`）。本地与生产用的是**同一个 token**（哈希一致，排除凭证失效；也不是限流——限流会返回 429 并记熔断，不会静默返回空）。因此真实预演只能在服务器做。

### 8.6 规则修正：能补就补（2026-11-01 第二轮，0.9.1.16）

用户指出「只往已经有数据的日子写」不合理——官方有值就该补进来。复核后确认三点：

1. **上一版的理由站不住**。实测放开后新增 **652,577 行**，其中落在「当日库中证券数 ≥ 4500」的繁忙日期上的是 **0 行**。按日汇总总市值的 `readTotalAShareMarketCap` 带 `MIN_UNIFIED_MARKET_COUNT = 4500` 门槛，当日不足 4500 只就改走官方中证全指或 Tushare，**稀疏日期本来就绕开这张表**，所以按日总市值与 M2 市值比不受影响。上一版把「新增日期」当成必然改下游，是没核门槛就先立规矩。
2. **顺带发现更要紧的缺陷**：候选集原先按「该证券还有没有 Tushare 行」筛。8.5 的清理把 327 只里 320 只的 Tushare 行删光，**再跑一次名单会塌成 7 只**，`--scope=watched` 形同失效，且不报错。现改为「scope 内且 `daily_valuations` 里有一行」，与来源无关。
3. **范围没变**：仍是当前在交易转债正股 308 ∪ 持仓自选 45 ∪ 已分析 21 ＝ **327 只**；其余 5,263 只（391,855 行旧来源）不动。

预演实测（生产只读，361 只全段取官方）：新增 **652,577 行**，`daily_valuations` 591,484 → **1,244,061**；按年新增 2021–2024 共 27.9 万、2010–2020 约 25 万、2000–2009 约 7 万、2025/2026 仅 1.7 万/1,827（后两年本来就齐）。另有 46 行落在完全空白的日期（1991 年、各 1 只股票），同属门槛以下，按用户「能补就补」一并写入。
