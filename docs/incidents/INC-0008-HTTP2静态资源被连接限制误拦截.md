# INC-0008：HTTP/2 静态资源被连接限制误拦截

状态：已关闭  
日期：2026-09-05

## 现象与影响

首页 HTML 和健康检查均返回 200，但用户打开网站时页面无法正常使用。生产 Nginx 错误日志显示同一访问来源的多个 JavaScript 请求被 `portfolio_conn` 拒绝，返回 429；`session.js`、`navigation.js`、`arbitrage.js` 等启动脚本缺失后，页面表现为“打不开”。

## 根因链路

Nginx 启用 HTTP/2 → 首页约 50 个 JS/CSS 通过同一连接并发请求 → `limit_conn portfolio_conn 30` 配置在 `server` 级，对静态 location 同样生效 → HTTP/2 并发请求达到阈值 → 关键静态脚本返回 429 → 前端无法完成初始化。

数据库、Express 服务和业务接口没有故障；Web、Worker、健康检查定时器及 `/health` 在故障期间均正常。

## 直接原因、根本原因与保护机制失效原因

- 直接原因：两份 Nginx 模板把连接限制放在 `server` 级，和“静态资源必须不限流”的注释及设计目标相冲突。
- 根本原因：从 HTTP/1.1 切换到 HTTP/2 后，未重新验证连接限制对并发流的实际影响。
- 保护机制失效：发布验收只逐个检查代表性 JS/CSS 的状态、压缩和缓存头，没有模拟一次性并发加载 30 个以上静态资源；配置回归也没有校验 `limit_conn` 所在作用域。

## 同类范围与核查结果

- HTTPS 与公网 IP 临时 HTTP 两份模板存在相同作用域问题，已同时修复。
- 首页共发现 50 个本地 JS/CSS 引用；修复后通过单个 HTTP/2 会话并发请求，50/50 均返回 200。
- 修复后生产 Nginx 最近错误日志中新增连接限制错误为 0。

## 修复与回归证据

- 修复版本：`0.7.0.33`，生产提交 `9e303b4`。
- 将 `limit_conn portfolio_conn 30` 和 `limit_conn_status 429` 移入动态 `location /`，静态 JS/CSS、图片和字体不再受连接数限制。
- 自动回归新增断言：两份模板只能出现一次连接限制，且位置必须在动态 location 内。
- `npm.cmd run test:all`：115 通过、0 失败、0 跳过。
- 生产验收：`nginx -t` 通过；Web、Worker、健康检查定时器均 active；`/health` 返回 `0.7.0.33`；公网首页返回 200。

## 防复发措施与遗留风险

- Nginx 连接限制只允许用于动态请求，不得放到 `server` 级或静态 location。
- HTTP/2 相关发布必须并发请求至少 30 个首页静态资源，状态码全部为 200 才能通过验收。
- 浏览器视觉验收不属于本次故障恢复证据；协议层、资源完整性和生产日志已完成验证。
