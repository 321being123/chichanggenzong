## 1. 目标和范围

在同一个开发对话中完成理杏仁官方 API 的受控接入、全部授权范围接口能力、现有业务的数据层选源与可替换数据集切换、测试和交接。理杏仁逐步成为主要来源的方向在本次统一实现：对已验证权限、覆盖和口径的数据集设置其为优先源；不能等价替换的逐项保留原来源并给出证据和缺口，不以猜测实现替代，也不把未完成宣称为整体完成。这里的逐项核验是同一任务的必要工作顺序，不是拆分开发批次或另开对话。

授权范围：官方目录中 A 股、港股、A 股及港股指数、行业和宏观的非基金、非美股内容。基金、基金经理、基金公司、基金持有人/基金跟踪等基金相关子接口，以及美股指数和宏观接口中的美股相关指标均排除；涉及美国宏观指标但是否属于用户所说“美股”有歧义时先单独列为待确认，不调用、不自动排除整个宏观接口。具体接口和指标按官方文档建立白名单，目录项数不是已获权限或已接入业务的数量。用户已提供官方凭据，按受保护配置处理，不重复请求或写入文档。旧 GeoScope 中转停止使用；旧迁移、原始记录和历史证据保留以维持追溯。

本次要求研发方案，不等于授权生产部署、生产历史全量回放或生产数据修订。开发隔离、版本及发布仍遵守仓库既定规则；如需要生产结构变更、历史数据或生产数据写入，说明范围与影响并另行征求确认。

## 2. 现状、复用与缺口

| 项目 | 已有或可复用 | 真正缺口 |
|---|---|---|
| 分层 | `server/dataAccess/marketDataGateway.js` 有中立估值/报价入口，仓储负责标准事实读取；已有 Guard、原始记录、策略和 Runner | 默认估值适配器为空，仅默认接腾讯报价；股票分析及若干任务仍直接依赖具体供应商。分层检查通过不等于全部来源已切换 |
| 官方接入 | 官方 skill 描述请求方式、分类及接口；公司信息接口使用官方 HTTPS POST、请求体 token | 独立官方凭据、请求、接口/指标白名单、各接口权限与真实响应尚未验证；旧中转的权限及缓存不可沿用 |
| 业务数据 | 已有证券身份、标准事实、游标、质量及发布分区 | 各数据集的字段、时间、单位、覆盖、主备和所有消费者需逐项对照并在数据层接线 |
| 旧中转 | 本任务工作目录已移除运行适配器、股票行业回退和后台入口 | 尚未全量测试、提交或发布；历史迁移不应删除，不能误用旧身份和缓存 |

## 3. 架构与影响链路

理杏仁官方 API → 统一请求保护和官方数据适配器 → 原始记录及字段归一 → 现有标准事实与仓储优选 → 数据网关的中立数据合同 → 既有服务／任务 → 现有站内 API／页面。原 Runner 承担采集、游标及发布，不新增平行事实表、平行任务或第二调度器。只对确有缺口且现有机制无法承载的结构提出变更，实施前说明原因、迁移和回滚。

- 上层提出证券、日期范围、字段、完整性及新鲜度要求，不传供应商、URL、token 或主备角色；业务计算仍在业务层。
- 仓储负责库内候选事实、来源版本、质量优选与追溯；网关负责在允许采集时外部选源与回退；适配器负责协议和转换。避免仓储外采、网关重排库内版本或业务第三次选源。
- 沿用现有统一数据合同与公开 API；日期、币种、单位、证券身份、复权、行业分类及财报口径不能为适配而悄悄改变。数据来源和原始证据供审计，不要求页面理解供应商字段。
- 用户页面的普通读取、换页和交互不触发外采；沿用现有手动刷新和任务入口。后台配置只暴露受权限保护的状态、掩码与诊断信息。

## 4. 全范围清单与业务对照

实施时以本地官方 1.0.43 文档和官方版本查询为起点，自动枚举分类、接口、方法、URL、参数、分页、响应字段、特殊约束、基金/美股排除与凭据要求；核对 URL 为允许的官方主机，分类白名单不能执行任意 URL。版本不一致按 skill 更新并留版本证据，不执行或入库 skill 的密钥文件。对每个允许接口登记：文档版本、实际权限、可调用契约、对应数据集／消费者、字段与单位、验证样本及结果。一个接口即使暂时没有站内消费者，也需完成安全受控的数据层调用支持和相应测试；不得因此新增无需求的页面、调度或事实表。

同一任务覆盖以下既有业务映射，并从代码、任务定义及消费者搜索补全清单，禁止把示例表当全部范围：

| 数据域 | 官方候选接口族 | 现有影响链及核对重点 |
|---|---|---|
| 证券身份、公司、行业 | `cn/company`、`hk/company`、公司 profile/industries、行业 constituents | 股票分析、身份及行业读取；证券代码、市场、生命周期、申万/港股行业版本与层级 |
| 股票财报与估值 | A/H 股 fundamental、fs、营收构成等 | 股票分析与财务标准事实；财报类型、合并范围、币种、报告期、披露时间、PE/PB、ROA 和市值单位 |
| 日线和指数 | A/H 股及指数 candlestick、index constituents/fundamental | 持仓补价、历史净值、指数基准、市场周期；交易日、复权、停牌、行情延迟、成分时点 |
| 宏观 | `macro` 中授权指标 | 市场周期及已有宏观任务；数据频率、发布时间、单位和历史修订 |
| 分红及公司事件 | 公司 dividend、announcement 等 | 股票分析与现金收益；方案/实施状态、每股单位及日期，官方公告原文和去重 |
| 其他已使用且有官方对应数据 | 在接口清单与代码盘点中逐项列明 | 对应 Runner、表、API 与页面；核对字段、权限、覆盖、用途及切换结论 |

实时行情、可转债专属字段、交易日历、IPO 和公告原文不得推断已有等价接口；现有腾讯、交易所、港交所、Tushare 或其他来源在无等价证据时继续提供数据。公告原文及招股书遵守既有官方优先合同，分红事实按现有原文和税务约束执行；金融分类、官方 IPO 行业与行业 PE 不因公司分类映射而被改写。基金和美股现有业务继续使用已有来源，不调用本次排除的理杏仁数据。

## 5. 数据契约与选源

每个数据集冻结范围、主键、字段、币种/单位、质量、新鲜度、空值、数据日期、发布时间、报告期和修订版本。先检查本地有效事实；在原用例允许采集且数据不满足时，网关按该数据集策略优先官方理杏仁，再使用已验证口径一致的备用来源。主源有效时不调用备源。权限受限、网络故障及合同允许的缺项可按策略回退；非法参数、程序错误和任务止损不得借回退掩盖。成功空结果与异常、缺字段、部分分页分开处理；不能把空结果视为覆盖完成或覆盖有效事实。

原始响应经凭据与个人信息边界检查后留证并关联来源、接口、范围、时间和哈希；转换一次后写既有标准表。跨来源合并只允许经验证的同口径字段，保留逐字段来源；同证券同日期不得重复统计，部分财报不得顶替完整事实。新鲜度按数据集合同判断；历史窗口按游标和必要重叠增量补齐，分页中断不推进完成水位；更正幂等且可追溯。实时、日线、财报及公告分别定义有效期，不能套统一缓存时间。

## 6. 安全、额度和运行保护

- 凭据只放本任务受保护环境配置及批准的服务器配置，禁止写 Git、原始记录、请求诊断或返回给浏览器。用户提供的密钥不能与旧 GeoScope 密钥复用或混淆。
- 官方 skill 1.0.43 明示限速为每分钟最多 1000 次、每秒最多 36 次；429 等待 1 秒后重试，网络超时或 5xx 最多重试 5 次，间隔依次为 1、2、4、8、16 秒。上述数值来自用户提供的官方 skill；其按账号、凭据还是其他范围统计仍待官方核验，不能把每接口分别当作独立额度。重试服从现有 Guard、任务止损与熔断，计入真实调用；429 应有有界尝试，避免无限循环。
- 所有真实请求经过现有 Guard 与来源/凭据隔离；核对官方版本文档中每秒、每分钟限制及其范围，在多进程和所有接口共享情形下实现并验证，不能简单逐接口复制总额度。旧中转声明的 10000 次额度不能未经核实套到新官方账号。
- 分类权限逐接口留证；401、403、429、5xx、超时、非法 JSON 和空数据分别处理。重试必须计入每次真实调用并服从统一熔断和上游限制；对永久拒绝不反复探测或绕过。错误需脱敏并保留可诊断状态。
- 初次覆盖范围和必要实源样本遵循最小请求与已有任务的预算；不发起未授权生产全量回采。生产凭据、权限及数据结果与本地证据分开记录。

## 7. 整体实施与验收

本方案由同一开发对话完成以下全部工作，内部可以按依赖顺序编写和测试，但不按业务拆成交付批次：

1. 盘点官方完整目录与排除项、旧来源和所有业务消费者，形成覆盖矩阵；核查原 Runner、标准表、路由、页面及相关专项约束。
2. 建立官方来源的安全配置、白名单、协议、跨进程限流、权限、分页、缓存、幂等和追溯；验证账号实际权限，不以旧中转结果代替。
3. 在数据层完成所有授权接口的受控调用及数据集映射；把对应业务的供应商直接调用收口到统一合同。符合验证条件的现有业务数据集统一切为官方优先，其他逐项保留已验证来源并注明阻塞；删除旧 GeoScope 运行入口。
4. 在独立环境执行真实小样本与确定性测试：身份及单位、日期/时区、复权、财报口径、分页、并发、限流、失败回退、重复写入、缓存、游标、质量分区与上层等价；覆盖各接口及相关业务，核对原调用链所有消费者。
5. 执行架构检查、`npm.cmd run test:all` 与 `npm.cmd run check:knowledge`；按低性能模式和资源归属进行本地运行验收。浏览器、真机、生产或不可访问接口未验证的边界必须明确，不能由静态检查代替。
6. 同步技术架构、知识索引、专项方案、任务卡及实际命中的专项文档；固定提交并交接统一发布。整体完成须有完整矩阵，逐项标明已切换／保留原源及证据、用户排除、外部权限或口径阻塞；如必需项未完成或验证失败，任务继续保持开发中，不能以部分通过声称整体完成。

回滚以数据集选源策略和对应代码版本为单位，保留原始记录与已有效事实，不删除历史数据；记录版本、切换前后来源、影响范围和恢复证据。若确需结构迁移，另给可逆步骤与上线窗口，不将历史清理混入切换。

## 8. 待核实与完成定义

官方账号权限、接口实际速率/额度适用范围、各接口样本、所有现有业务映射及关键字段等价关系均待实施时验证；上述分类与候选接口仅为设计输入。数据层覆盖全部授权接口、每个已有适用数据集都有可核查的切换或保留结论、所有强制测试通过、文档和交接完成，才可称本次开发完成。发布和生产专项验收另依既定流程记状态，不把计划当现役机制。
