## 3. 股票池、市场准入与日期

### 3.1 股票池

A股覆盖沪、深、北交所普通人民币股票；港股覆盖港交所主板及GEM普通股，均以目标日实际上市、未生效退市的身份事实为准。ETF、基金、REIT、优先股、权证、牛熊证及无普通股权益可比口径的证券不进入股票池。不是只筛当前持仓、自选或恒指成分股。

按市场交易证券识别身份；同一市场多柜台只保留标准主交易柜台，避免把同一股票重复排名。A/H双重上市分别保留，不用证券名称猜发行人；无法唯一归属时标待核验。主档抓取分页或生命周期集合不完整，阻断该市场正式发布。

### 3.2 指数代理

两市场使用理杏仁官方“总市值加权”指标后缀`mcw`，库内沿用已有`valuation_method='market_cap_weighted'`，不能因别名另存成第二种方法。市场准入只判断有效PB：`0 < PB < 2`。`PB=2`不准入；PB为空、非有限数或不为正是数据异常，不解释为市场便宜。PE缺失可标展示缺项，不能因只读PE失败抹去已验证的PB；必需PB缺失则不能发布可投资组合。

页面名称必须是“中证全指PB（A股市场代理）”“恒生指数PB（港股市场代理）”，不能标“精确全市场整体PB”。指数替代仅用于市场环境，不替代个股数据，也不把港股股票池缩为恒指成分股。

复用`market.index_valuation_history`的指数/方法/日期/来源键；不新增第三套市场估值事实表。既有`market.market_valuation_daily`保留原消费者职责，确需兼容投影时在同一写入链完成。不同方法的恒指官网文件或其他来源不能无标识接入本策略；官网旧PE文件缺PB时更不能推算PB。

官方文档提供两地指数估值及加权方法，支持这一接口选择；权限和逐日覆盖仍由本项目实际核验：[港股指数文档](https://www.lixinger.com/api/open-api/html-doc/hk/index/fundamental)、[A股指数文档](https://www.lixinger.com/api/open-api/html-doc/cn/index/fundamental)。

### 3.3 季度日与信息截止日

每个市场以本地交易日历确定季度最后一个有效交易日`T`。价格和指数估值取`T`的正式收盘数据；信息可见截止为`T`当地收盘时刻。只有公告日期、没有时刻的数据，保守地从下一本地交易日视为可用，不能把当日盘后公告带入当日收盘筛选。

下一交易日由原Runner检测待生成季度，依赖数据就绪后计算；执行日期晚于`T`也不得吸收`T`之后的新公告。管理员日常试算使用明确目标日，标为预览，不替换正式季度组合。

`trade_date/period_end/fx_date`为DATE，`knowledge_cutoff/published_at`为TIMESTAMPTZ；查询DATE按`::text`读取，日期计算复用`core-date`及现有交易日历。目标日贯穿Runner、缺口、适配、落库和发布，不用执行当天或UTC截日替代。

## 4. 个股指标与四项硬过滤

本版规则集命名为`investment_essentials_adapted_v1`，A/H分别登记策略版本、适配版本、风险版本及公式版本。PB、PE、市值、股息的股份口径、币种与可见时点必须一致。

| 规则 | 通过条件 | 数据语义 |
|---|---|---|
| R01 当前PB | `0 < PB ≤ 1.5` | `T`收盘价与当时已披露的最新合并归母权益口径 |
| R02 十年PB | `(T减10个日历年, T]`内至少一条有效PB严格大于1 | 每日按当时可见权益；多来源同日择一，不跨身份拼历史 |
| R04 股息率 | 税前现金股息率严格大于0 | `T`前12个月已实施、已除息的现金分红，对应股份单位统一后除以`T`收盘价 |
| R05 净资产 | 归母权益折人民币`≥10,000,000,000`元 | 不含少数股东权益；取当时已披露最新合并报表 |

保留R04/R05编号便于与用户原方案对应；R03审计机构规则已删除，不复用该编号隐含其他条件。

**PB与PE口径。** 优先消费已核验的标准估值。PE排名与页面展示统一使用**滚动十二个月（TTM）**市盈率 `market.daily_valuations.pe_ttm`（2026-11-05 用户要求，取代原「固定静态 PE」）。**不能有的股票用TTM、有的用静态**：TTM 缺失即判待补（`pe_ttm_unavailable`），不静默回退静态 PE，避免同一批里两种口径混排；`loadUniverse` 里现算的 `pe_static`（总市值÷最近一期已公告年报归母净利）保留作排查参考，不再参与排名与页面展示。公司总市值÷归母利润或权益的等价计算，必须确认总股本与公司权益相配。A/H股票不能用“H股流通市值÷全公司净资产”作PB；存在不同价格股份类别时，使用经验证的对应每股指标/股份范围，缺证据标`PENDING`。保留负利润事实，禁止把负PE当低估值优先。

自算时先把报表每股归母权益`BPS`、完整年度每股归母利润`EPS`按已生效送转/拆合股调整为`T`股份单位，再按`T`的报价币种→报表币种历史汇率换算价格：`PB = price(T) × FX(报价币种→报表币种,T) / BPS`，`PE = price(T) × FX(报价币种→报表币种,T) / EPS`。A/H每股权利或股份类别不等价时不能套总普通股数分摊；必须验证对应类别每股权益/利润分配。同币种FX为1，无`T`报价取此前最近有效汇率并记录实际日；历史每日PB逐日执行相同公式与当日可见版本。

**汇率。** 港股报表可能为CNY、HKD或USD等，不能统一当HKD。净资产门槛按报表币种使用报告期末当日已存在的历史汇率，非报价日取此前最近有效报价，保存实际汇率日、方向和来源；未知币种或历史汇率缺口待补，不用现汇倒算。PB/PE跨币种计算按对应已冻结公式处理，不能把净资产门槛的期末汇率机械套给价格估值。

**分红。** 股息率包含普通及特别现金股息并单独标记特别股息；不含送股、回购、预案或取消方案。按除息日计入滚动区间，同时要求实施证据在截止时点已知。送转、合并拆股后历史每股金额统一到`T`股份单位；分红币种换算记录历史日期和来源。股息率为税前策略指标，账户港股通扣税不进入跨股票排名。供应商`dyr`只有在窗口、分红状态与股份口径核验一致后才可直接复用。

**数据缺失与“不符合”分开。** 每规则返回`PASS/FAIL/PENDING/NOT_APPLICABLE`及证据。不得把缺数据补0。R02是“存在一次”的条件：找到可靠`PB>1`证据即可证明通过，十年序列有其他缺口不反向推翻这一正证；尚未找到时，只有应有历史完整才能判不通过，否则待补。上市不足十年的股票不凭上市前空白判失败，但仍需满足下一节年度异常检测所需历史。

## 5. 排名、异常识别与风险

### 5.1 排名顺序与并列

同一市场先完成硬过滤、身份/交易资格和必需数据核验，形成冻结排名池`N`。PB升序、PE（TTM）升序、现金股息率降序，分别采用竞赛排名`1,2,2,4`；综合分为三个名次之和，越小越优。

盈利且PE有效的股票单独按PE升序排名。若有`P`家盈利股票，亏损和已核实零利润股票的PE分统一为`P`，不把它们追加为`P+1`，以保留原方案约定；同时展示“亏损/零利润”状态。若`P=0`，所有PE分设为`N`，避免零分特例影响解释。利润或股份分母未知属于待补，不能混入亏损组。

原始精度排序，不按页面四舍五入值判并列。总分并列按PB升序、股息率降序、标准证券代码字典序稳定决胜，最终保存`selection_order`；不能依数据库行顺序决定第30只。异常剔除在首次排名后执行，不重算三项名次，组合从后续顺序补位。

### 5.2 异常利润与现金分红

设`Y`为截止`T`已完整披露的最新实际财年，使用**Y之前十个完整财年**作比较，不把Y包含进比较和：

`profit(Y) > Σ profit(Y-10 … Y-1)` 或 `cashDividend(Y) > Σ cashDividend(Y-10 … Y-1)`，满足任一则排除。年度净利润为有符号归母利润，不取绝对值，不把历史亏损清零；负的十年合计可能触发排除，这是该规则本身的结果，要展示比较数值。

因此所需的是“最新一年＋此前十年”，共11个完整财年，不能仅采10年。港股按公司真实财年处理，不能全部硬写12月31日；变更财年造成非12个月期间需明确可比口径，未核验不强行年化。分红年度按对应财年归属，并核实该年现金分红披露已完整；未披露的末期分红不能记0或提前计入。

年度分红异常比较用公司同一权益范围的现金总额，A/H分红先按发行人经济事件去重，不能把两地公告各算一次；股息率仍用对应证券每股现金分红。无分红必须有完整核验的零分红证据。应有历史缺报、缺更正版本或年度分红未完整披露为`PENDING`。若有可靠成立/经营年限和财报证据，确认公司本身尚不足11个完整财年，则按本版“历史长度不满足”资格前提暂不入选，保留未来可重新符合的状态；上市年限短不能单独证明经营历史短。不得把供应商没覆盖的老公司假装成历史长度不足，也不把尚未发生的年度留作永远无法补齐的数据任务。

### 5.3 风险增强边界

本版排除目标日已知的ST/*ST、明确退市风险或已生效终止上市对象；停牌或缺可靠可交易报价者暂缓入选。非正权益、币种/身份/股份范围冲突、无法消解的财报版本冲突不得入选。每项存原因和证据；临时停牌不等于永久策略失败。

近20个实际交易日成交额中位数、换手率、特别股息占比作为流动性及持续性提示。本版不擅自增加未经确认的成交额硬阈值，也不把“审计机构筛选”改名为风险增强重新加回。

## 6. 组合、行业限制与资金测算

### 6.1 等权与不足30只

每市场固定30个等权目标席位。设市场资产预算`B_m`、用户设置的目标股票仓位`p_m∈[0,1]`，每只目标金额为`B_m × p_m / 30`。实际入选`n≤30`时，股票总额为`B_m × p_m × n/30`，未填席位留现金；不因只有几只合格股就把单只权重放大。

从排名顺序遍历，跳过风险、行业超限或缺数据股票继续补位；遍历完整合格集合仍不足30只，发布真实数量和留现金比例。策略合格股少是有效结果；未核验股票可能改变名次是数据不完整，两者不能混写。

### 6.2 行业20%的基准

沿用原方案“行业金额不超过总资产20%”的含义，在两级资金管理下，明确为**每个市场独立资产预算`B_m`的20%**，不直接写死每行业最多6只。约束为`行业入选只数 × p_m / 30 ≤ 20%`。

例如`p_m=70%`，同行业8只占市场预算18.67%，可通过，9只占21%，不能通过；`p_m=100%`时最多6只。若`p_m=0`，只生成观察名单与现金配置，不称为可买入组合。权重按精确数值约束，页面舍入不能使边界失真。

行业采用各市场的一级行业：A股申万2021一级、港股恒生行业分类一级；保存分类体系、级别、版本、有效时间及原始标签。缺分类待核验；不能把大量未知对象放在“其他”来绕过上限。两市场行业不直接混算；如展示总资金行业分布，只用版本化映射后的共同类别并标映射未完成项，不以当前分类倒填历史。

### 6.3 市场预算与参考仓位

用户分别填写A/H市场资金占比`b_A/b_H`及`p_A/p_H`，要求`b_A+b_H≤1`；未分配部分为总资金现金。预算与偏好归登录用户所有，共享的是策略和标准事实，不读取别人的账户。市场不准入时该市场本轮有效股票目标为0，资金留在本市场预算，不自动转给另一市场。

PB参考仅展示原输入的情景：PB=1.5参考30%、PB=1.0参考50%、PB=0.7参考70%、PB≥2本轮不配置。不新增线性插值或自行补分段档位；其他PB值显示相邻情景，由用户输入仓位。未设置仓位时默认`p=100%`仅作“满仓模型组合”的标准行业约束与席位计算，并明确不是建议仓位；不输出个人买入金额。输入不同仓位的个人测算复用同一排名与组合算法，连同参数保存，不能覆盖公共标准季度快照。

只有明确总资金和两市场预算后，才可展示金额加权总敞口`b_A×p_A×n_A/30 + b_H×p_H×n_H/30`；绝不直接把两个PB参考仓位相加。

A/H重复暴露按`company_id`提示，展示两只股票及其各自权重；有完整用户预算才显示合并金额。无法核实发行人关联时标关联待核验，不强行合并或剔除。

### 7.2 覆盖率报告

报告按`市场×数据集×年份/季度×证券/公司`输出：应有对象/观测数、有效数、明确不适用数、真实缺失数、失败/未尝试数、来源、可见日期证据、可续补范围。PB分别报告“存在PB>1证据覆盖率”和“完整十年有效交易日覆盖率”，不能用一项代替另一项；因退市或未上市而不应存在的日期不计缺失。

先用库内查询审计，再按真实缺口调用原入口。财报按公司去重，A/H重复发行人只采相同财务事实一次；估值与每股分红按证券处理。补齐成本以“剩余证券×不超过官方跨度的日期段×必需接口类别＋公告解析缺口”估计，列预计调用量、实测耗时、权限/订阅成本是否已覆盖及失败续跑成本；没有报价或实源样本时填待核，不编造费用、覆盖百分比或完成天数。

可先执行便宜且有确定证据的PB/规模等排除，减少无关长历史外采；仍须对完整股票池保存逐项决策，报告全市场覆盖与必需候选覆盖两种分母。不能只给最有希望的30只补数后宣称完成全市场排名。

### 7.3 正式发布门槛

正式季度发布要求：股票池完整；指数PB精确可用；每一可能入选对象均完成可证明的排除或全部必需核验；排名池没有影响结果的未知缺口；规则、行业和资金约束通过。明确已因R01失败的股票，无需为了本次排名补齐其无关十年财报，但缺口仍计入覆盖报告。

未知对象或失败分段可能改变名次时，只能保存“部分数据预览”，不得发布正式可投资组合，即便已算出30只。原正式快照保留，但页面必须区分上季历史与本季度未就绪，不能把旧结果标成本季度最新。

## 8. 历史时点与回测

历史读取以“截止时点可见版本”为准，不以`is_current_version=true`或最新财报汇总表直接还原历史。财报日期、实际公告时点、采集时刻、修订可见时刻分别留存；官方数据返回`reportDate/date`不能未经验证当公告日，更不能把期末日当公告日。

复用财报`source_version/raw_record_id`及原始记录，按可见时点选择版本。原分红事实是可变当前投影，须通过既有`ops.raw_records`保留每次状态/金额版本及发布时间证据，历史计算重新归一当时版本，不新增第二份分红事实表。证券生命周期、股本、行业也需可追溯版本；缺历史依据时返回不可还原，不能用今天的状态代替。

供应商历史PB如按后来重述财报回算，属于修订后序列；未经验证不得称PIT（当时可见）。回测使用当时可见报表/股本/价格重建，或使用已证实具有PIT语义的序列。无法还原的区间不生成正式收益曲线，保留缺口原因和可用起点。

指数代理的历史同样需要当时成分及估值方法证据，不能以今天成分回算旧日指数PB。已核验的官方历史指数序列可直接复用；若提供者不能说明历史修订/成分语义，相关市场回测区间标不可还原，不擅自拿当期个股PB平均补指数PB。

回测引擎复用同一四项过滤、排名、异常检测和组合函数，按季度滚动；起点由实际覆盖推导，禁止写死2015年。评估十年策略表现可能需要更早十年的PB及11个完整财年输入，数据起点不能只往前采十年。开发交付包含回测能力、数据可用区间和验证结果，不把回测模块推给以后。

执行模型：信号后下一可交易日按未复权开盘价模拟调仓；停牌、涨跌停无法成交或缺执行价则保留待成交现金/旧仓，不虚构成交。公司行为使用未复权价格＋真实现金分红及股数变化，或经验证的全收益方式二选一，禁止重复加股息；退市按实际可得处置证据，没有处置价保留未估值风险，不默认为零损失。

两市场分别以本币及可选人民币报告年化、回撤、波动、夏普、换手、费用、现金占比、行业集中度和股息贡献。基准使用沪深300与恒生指数，收益类型与股息处理必须可比，价格指数不能冒充全收益指数。费用按市场、交易日期和交易方向版本化；夏普无合格无风险序列时不输出伪精确值。净资产增长/估值变化的精确收益归因不作为首版必交指标，除非能证明拆分口径和闭合误差。

验证包括不同市场环境的至少三个可还原历史窗口、未来数据泄漏反例、退市及停牌、分红送转、成本敏感性和按时间划分的样本外区间。没有足够可还原数据时标`not_evaluable`并披露实际支持区间，不能包装成历史验证完成，也不能以目标收益率作为工程验收条件。

## 9. 架构与任务编排

### 9.1 对齐结论和影响链路

继续使用现有Node单体、PostgreSQL六个schema、数据访问层、Guard和独立Worker，不引入新调度器、平行财务/行情表或逐股分析循环。

```mermaid
flowchart LR
  S[已准入数据源与正式公告] --> G[现有dataAccess适配和Guard]
  G --> R[ops原始记录与core身份]
  R --> F[market及fundamental标准事实]
  F --> Q[批量仓储与时点读取]
  Q --> D[纯规则及组合算法]
  D --> P[analytics选股与回测结果]
  P --> A[鉴权API及Presenter]
  A --> V[手机与桌面View]
  W[原Worker及Runner] --> G
  W --> Q
```

Route只做协议和权限，service编排用例/事务，domain只接收事实做纯计算，repository批量SQL和库内版本优选，dataAccess统一处理外部来源和字段归一。新文件登记到既有架构角色及前端加载合同，复用现有`check:data-architecture`。

| `stock_analysis_refresh: selection_preview/selection_backtest` | 外采为0，只用已验证标准事实；保存预览/回测结果，不发布或推进正式季度分区 |

新增数据集名称属于现有分区注册表中的逻辑合同，底层仍是原标准表或选股产物，不复制事实。注册表为新数据集支持精确CN/HK作用域及`T`，必要的动态scope扩展须兼容旧CN/GLOBAL消费者；不把旧分区改名或把当前版本汇总当历史证明。`stock_analysis_refresh`原有转债共享行情任务级依赖只适用于原模式，选股模式必须按本市场契约解析依赖，不能让港股被A股转债分区卡住；单股模式的目标日限制也不能误套给新增历史模式。行业/汇率等非日频依赖在清单中记录实际有效期及来源分区，不能强求不存在的每日公告。

季度自动触发由现有调度入口在交易日检查尚未生成的季度并排队，人工运行、补数、续跑、CLI均进入同一Runner。A/H各自槽位、范围锁、进度、事务和发布指针；同批触发形成两条独立执行，不使用一个横跨两市场的提交事务。季度计算任务不等待另一个市场成功。

请求固定`market/targetDate/quarter/mode/strategyVersion/requestId`。剩余证券、日期段、财报种类/字段、失败原因、下一次续跑时间保存在现有槽位请求/结果、游标和质量记录中。分批仅是内部执行方式，不是分多次开发；队列没清空不得完成。取消、Guard控制错误、租约失效立即上抛；旧执行令牌不能提交新发布。

### 9.3 状态与隔离

执行状态沿用原任务状态；候选质量为`passed/partial/failed`，业务准入为`eligible/market_closed/insufficient_candidates`等，分别保存。PB≥2属于正常业务关闭，不触发采集失败告警；PB缺失是数据故障。一个市场失败不能撤销另一个市场已发布分区。

同一季度更正重算生成新revision，保留旧结果与更正原因；发布指针按市场、季度和策略版本原子比较更新。运行中断/质量失败不移动指针，`not_run`不报本阶段故障。告警及恢复证据复用现有精确作用域规则，不能用普通任务成功或空查询恢复选股数据缺口。

2. 现有财报增加可空`available_at/availability_basis`等可见证据字段，或先复用经核验的同义字段；按原`source_version`追加修订，不覆盖旧报告。现有分红状态版本保留在原始记录，并补可查的来源键/发布时间证据；缺证据的旧行标未知，不把迁移日或期末日填成历史公告日。
3. 财务与分红投影改为实际币种，身份入口校验HKEX；A股旧数据保持CNY语义。历史错误币种仅在有原始证据的明确范围内修复，不全库猜测替换。
4. 指数PB复用原列，存方法/来源；单指数单日只能按当前策略选取一个有效值，但保留原表跨来源主键，不新加破坏多来源的唯一约束。
5. 运行幂等键含策略版本、市场、目标日、运行类型及输入哈希（包含资金/行业等计算参数）；个人运行还须含所有者。正式季度采用`(market,quarter,strategy_id,revision)`条件唯一索引，预览和个人运行不受该正式索引误限；正式发布采用范围锁＋预期前一版本比较，失败事务不留下半个组合。
6. 候选常用指标用NUMERIC，倍数为无量纲，股息率/权重为小数，权益金额为原币元；DATE和TIMESTAMPTZ分开。外键不跨环境复用数字ID；清单保存来源键、原始哈希和关键值副本，避免依赖可变当前投影。
7. 索引至少覆盖`runs(market,run_kind,as_of_date,published_at)`、`candidates(run_id,total_score,selection_order)`、`candidates(company_id,run_id)`、`financial_reports(company_id,period_end,available_at)`及原始分红版本查询路径；最终按EXPLAIN实测调整。
8. 组合数量/行业合计/权重在发布事务内校验；行级CHECK不能冒充跨行总量约束。迁移重复执行、旧版读取兼容、失败回滚及版本更正须用真实隔离PG验证。
9. 回滚先关闭本功能入口及新增模式，恢复旧应用版本；保留已采有效事实及选股历史，不能通过删共享行情/财务或清空原分区回滚。结构删除只在确认无消费者后另行安排。

1. 数据层 `readIndexConstituents`（官方 `hk/index/constituents`）取在册成分；生产实测参数 `{stockCodes:['HSI'], date}`、需 `Accept-Encoding: gzip`，返回 `constituents` 列表；无等价备源，取不到即空，不拿旧名单冒充当期成分。

3. 落库：`upsertDailyValuationRows`（带 `currency_code`，HKD 不当人民币）/ `upsertDailyBarRows` / `listCodesWithRecentBars`（已有行情不重复请求）。单位换算只在落库前一次：`dv_ttm` 百分数点→小数、`total_mv` 万元→元。

| 每日/周度可能污染既有质量分区 | `stock_selection_snapshot_cn/hk` 计数按所有已发布季度成员聚合，修订也可能相加 | V1 合同保留；V2 结果逻辑分区按渠道隔离且绑定精确 run_id，不跨策略、revision 汇总 |
| 只改 Runner 会丢上下文或永远不完成 | 编排器白名单与 `SELECTION_STAGE_KINDS` 未含 daily/weekly | 把入队、去重、领取、恢复、上下文、完成证据及告警作为同一改造范围 |

### 27.3 范围与不变条件

原稿确认的 V2 范围：A 股、港股各最多 30 只，独立计算；每交易日动态计算、每周最后交易日正式发布；行业多选排除、指定股票代码排除与恢复；保存每日/每周与个人结果、保留 V1。用户排除不包括自动排除持仓，也不新增自动下单或改真实持仓。

V2修改R01/R02，并按用户要求取消市场指数PB配置门槛。R04/R05、11财年异常识别、竞赛排名及并列决胜、风险类别/排除范围、行业集中度、固定30席预算和留现金沿用基线合同；停牌缺当日估值的状态汇总按27.4修正，不能声称现役代码已完成。研发先固定V1样本，不照抄旧设计覆盖现役分红/汇率修复，也不增加R03、成交额阈值或改变负PE排名规则。

**市场估值代理不再决定是否配置。** 中证全指/恒生指数PB、PE可作为可选市场环境展示；指数PB等于2、大于2、缺失或异常，均不得因此关闭V2组合、强制现金、阻断日/周计算、个人测算、正式发布或回测可还原性。可选指数展示的质量单独标识，不纳入V2必需输入分区与质量门禁；个股行情/估值及原必需财务等质量仍须核验。现役V1和市场周期模块保留原实现及历史解释，开发时按策略分派移除V2路径的门槛，不全局改掉原消费者。

A 股按现行身份与市场范围；港股沿既有用户授权的港股通与恒生成分目标池及目标日证据，不将本次升级扩展成全港股采集。现有仓储按“主档＋有行情”筛池，开发时须与冻结目标池做差集，不能把未采到股票静默缩小为“全市场”。历史目标池无法还原则历史回测不可评估，不能拿今天名单回填。全港股扩围另作范围决定。

### 27.4 R01：PB 与 PE(TTM) 联合估值

规则为：`0<PB<=1.5`，或 `PB>1.5 AND PE(TTM)>0 AND PB×PE(TTM)<22.5`。第一条是闭边界，第二条是严格小于；乘积等于22.5且PB>1.5不通过。阈值及比较方式固化在V2公式/策略版本，建议参数名 `maxPb/maxPbPeProduct`，不可由浏览器请求覆盖公共策略。PB、PE 必须有限、同目标日、同币种/股份权益口径；不得混静态 PE。显示值舍入不参与判定。

| 输入 | R01 状态与原因 | 其他处理 |
|---|---|---|
| 有效 PB≤1.5，PE 任意或缺失 | PASS / `PB_THRESHOLD` | PE 缺失仍可能阻断既有排名就绪；负 PE 沿原盈利状态规则记分，不自动入选 |
| PB>1.5，有效正 PE，乘积<22.5 | PASS / `PB_PE_PRODUCT` | 保存完整原精度乘积 |
| PB>1.5，正 PE 但乘积≥22.5 | FAIL / `VALUATION_FAILED` | 等于22.5也不通过，不能用展示舍入值判断 |
| PB>1.5，PE≤0 且已核实利润事实 | FAIL / `PE_NON_POSITIVE` | 不让负乘积通过 |
| PB>1.5，PE 缺失/无穷/口径不一致，存在可补证据 | PENDING / `PE_PENDING` | 不回退静态 PE |
| PB<0 | FAIL / 既有负权益原因 | 不把负数当便宜 |
| PB=0 或可补 PB 异常 | PENDING / 既有异常原因 | 不补零、不无限重试 |
| PB 缺失 | 按现役“有报告待补/无报告不可评估”判据 | 保留证据，不能为 V2 擅自放宽 |
| 目标日有可靠停牌证据 | 先判风险暂缓：`riskStatus=RISK`；本轮不执行依赖当日价的R01，`valuationStatus=null`并标未评估 | 可展示停牌前最后有效PB及真实`valuationAsOf`，不冒充T日值，不因停牌缺T日PB/PE入补数队列；复牌后重新核验 |

统一返回 `valuationStatus`、`valuationPass`（PASS=true，FAIL=false，其余=null）、`valuationPassReason`、`pbPeProduct`。原稿仅列通过原因不足以覆盖“不可评估/异常/口径未知”，本章补全状态；所有原因枚举由服务端合同维护。无有效正 PB/PE 时乘积返回 null，不输出 NaN/Infinity。

**资格、规则与排名分开。** V2先按目标日证据判断交易资格，再计算适用规则；已核实停牌的本轮总体选择状态为RISK，不因规则汇总中的缺价PENDING退回“本轮待补”。缺停牌证据仍是未知，不能靠没有报价猜停牌。停牌不放宽历史PB缺口或永久免查财报；既有独立维护的真实数据缺口保留，但不把“停牌所以没有当日价”作为选股补数故障或正式发布阻断。现役V1在`riskHeld && ruleStatus===PENDING`时仍返回PENDING，此处为V2明确改造项，不能冒称复用现役代码已解决。

候选响应独立返回 `valuationStatus/valuationPassReason`、`rankReady/rankBlockReasons`、`riskStatus/selectionStatus`。R01通过不等于四规则、年度异常、风险和行业均通过；R01通过但PE(TTM)缺失时显示“估值条件通过；排名待补PE(TTM)”，不显示无解释的“已通过却未入选”。`rankBlockReasons`须随快照持久化并贯通API，不能只留内存字段或一个布尔值。

边界必须明确：0.8×30=24和1.5×30=45均由PB条件通过；1.8×12=21.6、2×11.2499=22.4998由乘积条件通过；2×11.25=22.5、2×11.26=22.52及PB=1.5001/PE=15均失败。采用 NUMERIC/十进制确定性比较或等价的明确精度实现，不能用任意 epsilon 将阈值放宽；单独验证十进制 0.3、0.9 和临界相邻值。

### 27.5 R02：最近十年 PB 波动与覆盖证据

窗口沿用 `(T减10个日历年,T]`，上市后有效区间包含上市当日，左端按原开区间排除；闰日由既有日期工具收敛。上市不足十年按上市以来有效历史计算并显示真实起止日/年限，**这只改变 R02 的观察长度，不免除原 11 财年异常识别**。

**当前待裁决基线**：历史日历与生命周期已核验、应有日全部得到同口径有效正PB，且`maxPb/minPb>=3`时正式通过；该“零缺口”完整性设计不是用户另行确认的业务阈值。按27.14先做逐股覆盖和可行性审计，在证据及最终采纳口径落本节之前，不得把它直接冻结为DEV-01/DEV-02正式发布逻辑。用户已确认的十年窗口、三倍阈值及上市不足十年按上市以来观察继续保留；不为凑30只擅改为任意可得区间或覆盖率阈值。比较宜用十进制`maxPb>=minPb×3`，展示再求商；极小正值保留来源和原精度，不能截断成零或擅自去掉极端值。

**审计要区分覆盖与可证明结论。** 旧记录“1,235,770行/688只”是历史批次总量，既可能混来源/不同上市年限，也没有逐证券窗口分布，不能由平均约1796行推导所有港股必然缺十年、也不能据此判定R02必定全不合格。仅凭覆盖率高或缺口短，无法证明缺失日期没有极值；不采用没有可验证上下界的“缺口不可能藏三倍”推测。

另需并列测算一个有数学依据的候选口径：在同窗口、同身份与同口径的**正PB有效子集**中，若已观测`max/min>=3`，补入其他正值只会维持或扩大该比值，已观测值是全正序列波动的下界，通常只需要两个可靠极值，不需要证明缺口没有更大极值。反之，已观测比值<3且有缺口不能据此判FAIL。该推论不自动解决非正PB资格、来源修订、生命周期/日历未知及PIT问题；审计须单列这些阻断。是否以可靠正证替代零缺口硬门槛，先比较27.14的分布/候选与实际证据，再在本节记录最终决策；当前没有静默启用另一套正式规则。

**逐日集合合同：**

1. 按证券实际交易所取本地交易日历，先核验窗口内日历覆盖和 unknown 状态，再按日期去重。不能只因查到一些开市行就称十年日历完整；A 股多交易所同日不得重复计数。
2. 应有集合为窗口、上市/退市生命周期交集中的开市日。停牌无 PB 的日只有存在完整库内停牌证据才可排除，并记录 `exemptDays/exemptReasons`；缺停牌事实不能用行情空白推断。无上市日/生命周期证据时覆盖未知。
3. 同证券同日先按现有来源优选及口径校验择一，随后统计；日历外、上市前、重复来源不能计入 covered。已选同日来源的 PB 缺失不能偷偷换成不相容备源。
4. 分别计 `observedDays`（有可解析 PB）、`coveredDays`（有效正 PB）、`nonPositiveDays`（已核实非正事实）、`invalidDays`（格式/单位/非有限等异常）、`missingDays`（应有却无观测）；`gapDays=expectedDays-coveredDays`，需能按集合核对，不能靠 MAX(date) 或两个可能重复的 COUNT 相减后截零掩盖错误。
5. `historyComplete=true`仅在日历/身份/口径可信、`expectedDays>0`、`gapDays=0`时成立；完整性字段无论最终R02判定采用何种证据政策都如实返回，不能因判PASS伪造完整。当前待裁决基线中，无完整有效序列不判正式PASS/FAIL；完整单点比值为1、不满足三倍，零应有日不可评估。候选正证政策只在审计中对照，并保持历史完整性与规则判定两个字段独立。
6. 非正 PB 不参加 min/max，也不能因剔除后比值达标而通过。已核实非正事实使正 PB 比值不可评估；采集异常则待补。先天来源不覆盖、有证据的不可恢复区间标 NOT_APPLICABLE，真实可补漏采标 PENDING；未查明原因保留 PENDING，不为清空队列伪称客观不可评估。每种状态都不入选，补数仍用既有入口和无进展止损。

输出 `minPb/maxPb/fluctuationMultiple/coveredDays/expectedDays/gapDays/historyComplete/historyYears`，补 `windowStart/windowEnd/effectiveStart/listDate/minPbDate/maxPbDate/observedDays/nonPositiveDays/invalidDays/missingDays/exemptDays/calendarComplete/coverageReason/sourceBasis`。历史年限按有效观察起止日期表达，可附交易日数量；不将交易日数÷365当年限。

同一股票的 min/max、覆盖和输入哈希必须来自同一冻结序列。保存选源规则、原始记录/版本、日序列摘要及可还原引用；只存两个极值无法证明覆盖或重现结果。厂商修订后历史可供有标签的当前研究，但不能因此标成历史时点可见（PIT），回测限制见 27.11。

### 27.6 每日与每周：日期、运行和历史

保留现有 run_kind，增加 `daily/weekly`；`preview/personal/backtest` 仍分别代表用途。增加 `period_type=day/week/quarter` 与 `period_start/period_end` 表示信号周期，避免把个人、预览误当新日历。weekly 共享批次必须 period_type=week，daily 必须 day；V1 quarterly 保留原 quarter。季度字段不再承担周键。

工程默认周边界为市场当地周一至周日；`period_key` 以周一起始日生成（例如 `W:2026-11-02`），避免公历年与周序号跨年冲突。显示可以用 ISO 周，但不能用“自然年＋第几周”作唯一键。day 使用 `D:YYYY-MM-DD`，quarter 使用 `Q:2026Q3`。`as_of_date=T` 是该市场本周最后一个开市日，可能早于 period_end。

A 股与香港按各自交易日历及实际收盘时刻确定 T 和信息截止。香港半日市不硬套 16:00，临时休市/日历未知不按星期五猜。周内全休市记录 `no_session` 运营证据，不造一次证券计算/周度正式组合；跨年、整周休市、临时调整纳入测试。

18:30 北京时间只是原稿建议的首次就绪检查时刻。按数据分区与缺口证据决定是否可算，不能以到点替代数据就绪。周四为最后交易日时可在周四确认整周日历后排队；未知后续日历时等待。未完成槽位按原调度续跑，业务目标 T 不随次周执行日漂移。修订交易日历改变 T 时保留原决策与纠正关系。

每日就绪窗口采用工程默认目标：T日18:30开始检查、至T日23:59:59（上海时间）争取完成，DEV-00须核对现有来源/原采集任务的真实发布时段并在启用前校准该配置；这不是声称上游保证T日供应。依赖未齐记`readinessStatus=not_ready`、缺少的精确分区/字段和`nextCheckAt`，任务沿原等待/blocked语义续跑，不能伪造质量通过或新增不被状态机认识的执行状态。达到日目标仍未齐只记延迟与同作用域一次告警，不改目标T；已完成证券计算的部分批次才标partial。

就绪后自动续算仍通过原Runner，持久化每个未完成T、剩余进度和下次续跑时间，不能用latest_only把跨日旧T丢掉。输出真实`computed_at`与`sourceReadyAt`；`computed_at`为本次计算完成时刻，不能借用入队/创建时刻。跨T日完成或超过约定就绪窗口显示“补算/延迟”，不改变`as_of_date/knowledge_cutoff/period_key`，也不改变周度T；例如T日23:00入库、T+1日完成应显示T日结果与T+1实际完成时间。重复等待不创建假交易日批次，来源更正才产生新revision。

每日计算保存独立批次与三态质量，展示为“每日动态”，即使全部通过也不更新weekly正式指针。周度默认重新核验输入并运行完整引擎；允许下述**同输入受控复用**替代相同纯计算，不允许原地把daily改名为weekly。`source_daily_run_id`可作追溯但非依赖，日任务失败不拖死已具备数据的周任务。

受控复用须同时满足：源为同市场/T/信息截止的共享非影子完整daily；策略/公式/参数/覆盖政策、基础仓位/行业约束相同；当前重新冻结的事实、证券集合、日历/停牌/财务/股息/行业/FX版本与源一致；源输出和可还原证据哈希有效；没有缺口待裁决或源撤销。独立定义`computation_input_hash`（只含所有计算语义与事实、排除run_kind及渠道封装），不能拿现有包含周期/用途元数据的`input_hash`直接作相等依据。满足条件时复用纯计算产物，**新建weekly run/manifest/候选和成员**、记录源run及双向输入/输出哈希证据，重新校验周末日历、当前租约、质量、权限、CAS和发布事务；daily保持不可变。任一条件或哈希不等、证据不可恢复、输入正在更正，一律完整重算。周度不重用个人过滤结果，且必须有“同数量但PB/年度事实/行业版本改变→不复用”的反例。

正式周度只包含共享基础策略。个人过滤在已发布的 weekly（或明确标示的完整 daily）冻结排名上派生；不得在共享发布事务中读取某个用户设置。不同源结果类型始终显示来源标签。

所有批次不可变，补数/更正生成 revision；同周期同版本同输入重跑返回原 run，输入变更生成新 revision 并带 `supersedes_run_id/revisionReason`。旧期重算只能修改旧期指针，不能把它当最新一期。没有当前周就绪结果时明确“本周待就绪＋最近一次历史正式结果日期”。每日变化和周度调入/调出只在同市场、同策略、同设置口径的完整结果间计算；缺失/部分批次显示无法比较，不当退出。

| 新增最小 publication 元数据 | `analytics.stock_selection_publications`，键 `(market,strategy_id,period_type,period_key)`，另存period_start/end DATE，指向run_id并有pointer_revision | period_key只作身份键；CHECK校验day/week/quarter与D:/W:/Q:前缀、日期/季度值匹配，period_start≤T≤period_end；不保存第二份成员 |

**证据存储硬约束：** candidates.detail只保存每证券摘要，run级manifest保存一次“证券→pbSeriesHash/版本化证据引用”的索引；把全池所有日点改塞入每个run的大JSON仍是相同数量级重复，不能据此宣称容量问题已解决。完整日序列优先引用经核验不可变且保留期满足回放的已有原始记录/冻结输入；必须新增冻结副本时，沿现有原始留证/任务产物入口按证券、来源、口径、日期块与内容哈希去重，daily/weekly/个人复用同一证据块，历史更正才生成新版本。不另建PB行情事实表，不用可被覆盖的当前估值表作为唯一历史证据，也不能只留不可还原的hash。DEV-00须实测`pg_column_size`、序列编码/压缩大小、证据增量、索引及保留成本；没有容量与恢复证据不能通过此门禁。

**旧版写入兼容：** 在V1仍写入的runs/candidates/members等表上，新增列必须可空或有不依赖V2请求上下文的兼容DEFAULT，新增CHECK不得让旧INSERT省略字段失败。V2的必填/主体约束按可识别版本或用途限定；新建指针表自身的必填约束不因此取消。先扩展schema和兼容读写，再切V2，禁止靠填假的历史值满足NOT NULL。迁移后用原V1代码实跑insertRun/insertCandidates、publishRun、latestPublishedRun及个人复制路径（其中latestPublishedRun为读取）；验证新装、旧库升级及回滚应用后的继续运行，不能只验证旧行可查。

新旧CHECK与索引兼容：保留V1季度唯一索引；非影子daily/weekly新增`(market,strategy_id,period_type,period_key,revision)`条件唯一约束，影子批次不能占用正式revision序列。V2 personal必须有不可复用主体身份。幂等键涵盖市场、策略/公式/适配/覆盖版本、周期键、T/信息截止、输入哈希、类型及is_shadow；个人还含owner_subject_id、source_run_id和设置哈希。复用计算使用27.6的computation_input_hash，批次幂等仍区分用途/渠道。未变化重试不生成新revision，影子/正式不能误命中同一run。

现役用户已有不可复用 `users.subject_id`（迁移 187）；新增私人批次绑定它，访问时按当前会话主体核验，不能仅按可复用 username。旧个人记录只有能证明原主体时才迁移关联；不能把账号重建后的同名用户自动关联为旧所有者。外部数字 ID 不跨环境复用，标准代码与来源证据可用于还原。

**发布事务：** 计算先冻结一致读视图或不可变输入清单/哈希，重计算不长时间占用发布锁；对同市场、策略和周期加原范围锁，锁内分配 revision、复核当前指针的 expectedRunId/pointerRevision、校验租约/执行令牌，然后一次提交候选、成员、正式元数据、精确 run_id 对应质量分区与审计。可先保存未发布候选供诊断，但发布切换只能在同一事务完成；失败保留旧指针。

当前 Runner 先调用服务发布，再单独写质量分区；V2 必须让既有分区发布仓储接受同一 tx，使“页面已正式/分区失败”不再发生。不得仅 catch 分区错误再称已经原子发布。故障注入覆盖“成员完成但分区失败”“指针 CAS 冲突”“租约被接管”“事务提交失败”。

指针目标必须是同市场、策略、周期和T的共享、非影子weekly/quarterly合格run，禁止指向personal、partial或另一范围；首次发布对“无前驱”也做CAS。影子计算只保存影子批次及27.8的影子质量分区，不写正式指针/正式分区，避免抢占正式渠道；回滚/重新激活时重新核验分区绑定的run_id与指针一致。

历史published_at不抹去；指针切换另存操作者、原因和前后run_id审计。V2按市场在现有配置机制登记当前展示策略/周期；`markets/latest/previous`先限定market、已激活strategy、period_type及非影子正式渠道，再按`period_start DESC, as_of_date DESC, revision DESC, run_id DESC`稳定选取，绝不按period_key字典序或跨day/week/quarter直接取最大值。混合历史列表可按实际信号日期T统一展示，但不据此自动选默认正式渠道。回滚到V1时显示真实历史周期和日期，不伪称本周结果；本项是显式加固，现役latest本来按as_of_date排序，并不存在已证实的period_key字典序事故。

### 27.9 个人过滤、设置和权限

行业用项目已有一级分类：CN=SW2021，HK=HSICS；保存 taxonomy、真实 version、行业代码，不伪造 HSICS 版本。无版本时明确 null 和版本未知依据。配置中的分类身份应包含体系、版本、代码；分类版本变化不按同名自动换码，标记待映射并由用户确认，历史结果继续使用源批次分类。

股票代码通过现有统一身份服务验证、规范化、唯一匹配，再保存 instrument_id＋标准代码＋市场＋可选备注。前端去重、服务端再次去重；A/H 同发行人只提示，不按名称连带排除。证券退市/更名不删除旧排除，历史显示原快照。备注纯文本转义、长度及配置规模按现有参数校验风格设置并公开错误，不静默截断。

设置仍在 users 原 JSONB 中增加 industryFilters/excludedInstruments/customFilterVersion，与预算、仓位和总资金共存。建议 schemaVersion=2；customFilterVersion 是结构版本，**不能替代每次保存递增的 revision**。保存必须显式 expected revision，冲突返回 409 并保留用户未提交输入。原资金客户端请求不含新字段时服务端保留已存排除，不把省略当清空；新版显式空数组才表示恢复全部，按市场作用域校验。

原稿建议的 exclusions 增删 API 首版不新增，优先沿已有 GET/PUT settings 与 POST simulations，避免两套写配置入口并发覆盖。将来确需逐项入口时也必须调用同一保存用例、使用同一 revision，不能绕开乐观锁。

个人结果流程为：**完整源排名快照 → 本人行业/股票排除 → 按原 selection_order 遍历 → 原年度异常/风险/行业限额/仓位约束 → 最多30席**。保存 baseRank/baseSelectionStatus 与排除原因；“重新排名”仅指个人显示顺序和席位，不重算三项竞赛分，避免个人偏好改变基础策略分数。不得只从源组合 30 只删股后补不到后续候选。

用户仓位 p 仍影响行业金额上限：`行业只数×p/30<=20%`，p=70% 的同行业 8 只仍可通过，不能写死 6 只；不足 30 席继续留现金，不因排除后人数减少而放大单股权重。个人结果沿用源批次的个股资格与质量，不重新施加已取消的市场指数PB配置门槛。

生成个人结果时在同一事务内核对会话 subject_id、用户设置 expected revision 和源 run 访问/质量，冻结配置后再派生；配置并发更新不得让返回的 settingsRevision 与实际使用内容错配。来自 daily 的源 run 可以没有 published_at，但必须 daily 完整质量通过并显式标动态；不能照搬旧 simulations 的“未发布一律拒绝”或“preview 一律允许”。

个人 run 保存源 run_id、完整配置快照/哈希/revision、主体、资金参数和公式；只从源候选派生，不重新读最新行情/财务/行业。设置变化不重算旧 run，也不自动生成所有用户结果；由用户主动生成，可缓存同主体同源同设置结果。读取列表、详情、候选、成员及分页全路径均核验主体；隐藏按钮不等于授权。

### 27.11 可复现性、回测与性能

manifest 必须含：策略/公式/参数/适配/风险/行业版本、市场和冻结证券集合、目标 T/信息截止、真实输入日期、来源/原始记录/报告版本、日历/生命周期/个股估值序列哈希、财务/分红/FX 证据、配置快照（仅个人）、规范化输入哈希。V2可选指数估值不进入筛选必需输入哈希，可另存带实际日期/质量的展示信息；缺失不能视为结果不可复现。集合排序、空值和十进制序列化固定；源码提交记录为计算版本证据，但不能拿提交号代替数据快照。

历史结果重放首先从已冻结输入读取。若旧标准表被覆盖，必须能通过现有原始记录或快照还原；只有 hash、没有输入或可恢复引用时只能检测变化，不能宣称可复现。缓存或存储保留不能使已正式结果的输入证据消失。

日序列按27.7的去重证据块与引用索引恢复；个人run引用源公共证据，不重存全池日点。日/周计算复用必须留下输入/输出摘要比对及新weekly封装证据，不能用“来源相同/行数相同”代替事实内容相同。

V1 保留季度回测；V2 扩展同一 backtest 引擎的周度信号日生成及策略分派，绝不把每天筛选当每天交易。周度信号在 T 截止，最早按**实际发布后**的下一个可交易时点执行；历史模拟若假设及时发布，必须保存假设和数据可用时刻，不用迟到的数据在已经过去的次日开盘成交。收益费用、未复权价/公司行为去重、期末估值、停牌/涨跌停/退市和基准口径复用现役实现及回归。

PIT 回测还需要目标日股票池/行业/生命周期及当时可见估值、财报/分红版本；厂商最新重述 PB 或当前港股通名单不能冒充。缺乏证据返回 not_evaluable 和可用区间，可保留明确标识的“以修订后数据研究”，不输出正式可还原收益承诺。V1/V2 比较使用相同可还原窗口、交易费用和基准；工程验收不要求 V2 跑赢。

PB 十年查询优先在原行情表上按市场/证券/区间批量优选与聚合，冻结序列复用缓存；新一天增量与窗口退出日、历史更正失效都纳入设计。缓存是可重建派生物，不能成为第二份手工维护 PB 事实表。禁止逐股回源或逐股多轮 SQL。先做 EXPLAIN ANALYZE、索引/峰值内存/扫描量实测，再判断是否需要额外派生索引或汇总。

性能沿原稿作为目标：单市场日计算/周重算≤10分钟（数据就绪后，不含外采等待）、设置保存≤1秒、个人结果≤5秒。开发记录相同硬件、PG版本、证券/十年行数、冷/热缓存、并发、重复次数、p50/p95、SQL次数、峰值内存和存储增长；目标未达不伪填通过。30成员不代表候选只有30条；测算保存全候选的日增长量，首版不自动删除每日/周度历史或原输入证据。
