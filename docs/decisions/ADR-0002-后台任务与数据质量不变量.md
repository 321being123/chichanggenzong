# ADR-0002：后台任务与数据质量不变量

状态：已采纳
日期：2026-09-16

## 背景

近一个月的修复和事故复盘反复出现同一类问题：接口限制被扩大为来源或 Token 熔断，任务写死批次上限后误报完成，目标日期在子阶段丢失，空结果和失败混淆，数据分区未完成却发布成功，以及告警没有按真实作用域恢复。这些问题不能继续靠单个事故补丁解决。

## 决策

将以下不变量作为全局研发规范，并由通用测试/静态检查逐步落地：

1. 外部限制只按已核验的具体接口配置；内部等待、任务止损和真实上游熔断分离，熔断状态统一存放在 `ops.external_circuits`，到期自动探测恢复。
2. 同一接口和业务窗口只有一个采集入口；自动、人工、启动补偿和脚本复用同一个 Runner，页面默认只读本地数据。
3. 任务成功必须同时满足结果、数据集分区、目标业务日、质量状态和子阶段完整性要求；空结果、失败、部分完成和业务状态不能混用。
4. 禁止隐性业务上限；分批必须持久化剩余工作、续跑时间和阶段状态，安全止损不能冒充完成。
5. 目标日期按上海时区贯穿全链路，游标单调前进；最新日期不代表中间连续，目标对象按目标日生命周期筛选。
6. 告警绑定准确作用域，恢复必须有对应数据集或来源成功证据，禁止空查询、手工改状态和批量清零。
7. 解析、身份映射和发布验收分别遵循目标隔离、统一身份服务和生产证据闭环。

## 备选方案与取舍

- **继续按事故逐项修复**：短期改动小，但无法阻止同类问题换一种写法再次出现，否决。
- **只增加更严格的全局数字限制**：会把内部保护误当成官方额度，造成误熔断和误阻塞，否决。
- **不变量规范 + 通用自动门禁（采纳）**：保留必要的业务差异，同时用统一状态、作用域和证据要求约束所有任务。

## 影响范围

- 任务定义、Runner、外部 Guard、数据集分区、游标、告警恢复和页面读取均受本 ADR 约束。
- 现有事故专用测试应在同类问题再次出现时升级为通用检查；`check:knowledge` 已加入续批、熔断、公告分页和分析页面刷新等跨业务静态门禁，业务运行态不变量仍必须由专项测试验证。
- 当前已有接口策略、熔断、分区和恢复证据基础。迁移 156 已清除来源/凭据级内部数字保护线，并禁止通配策略重新写入；可转债上市流通、港股 IPO 招股书/配发结果和港股日线补全已取消默认固定批次，显式调试上限不得宣告完整成功；分析页面默认只读快照，无快照或过期时只提示用户手动刷新。IPO 招股书、配发/上市流通等官方 PDF 已接入 Node/Python 共用的统一持久化缓存；显式批次续跑的通用运行态验收仍需补齐，必须在任务验收中明确列为 pending。

## 何时重新评估

出现新的任务状态类型、来源限制模型、数据分区模型或重复事故，且现有不变量无法表达时重新评估，并同步更新 `AGENTS.md`、`docs/技术架构.md`、`docs/知识索引.md` 和自动门禁。
