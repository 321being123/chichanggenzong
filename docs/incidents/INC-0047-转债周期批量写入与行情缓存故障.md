# INC-0047：转债周期批量写入与行情缓存故障

状态：跟踪中；2026-10-30 本地修复及真实 PostgreSQL 回归通过，生产未发布、未补算。

## 现象与根因

2026-10-30 只读核查生产 0.9.1.3：共享行情任务报告 10-29 的 311 只价格覆盖，但转债周期日事实最新为 10-28；10-30 估值任务因此阻断。安全评分按目标日只得到 2 条待上市债，低于上一有效快照的 313 条，质量门禁拒绝发布。`market.daily_bars` 中 10-29 已有 313 条转债日线，因此不能简单归因于当日行情整体缺失。

周期日事实与日线的批量 INSERT 在分层抽取后把参数序号拼成 SQL 数字常量，实际参数并未使用 `$1` 等占位符。周期计算在主同步后的独立事务中失败并被捕获，主任务仍可报告成功；生产未保存该次异常文本，代码中的确定性错误及缺表事实与该故障相符，不能冒称已取得运行时异常原文。估值、列表、强赎及安全评分均依赖周期日事实；页面保留已有有效结果，不能将行情主任务成功当作周期恢复。

同类扫描发现日行情缓存批量 INSERT 同样缺少参数占位符，且引用不存在的 `marketPure`；缓存保存异常被调用方吞掉。其他扫描范围内未发现同一连续数字占位拼接模式，不代表已穷尽所有 SQL 错误。

## 修复和验证

本地修复两处批量参数绑定；行情时间由服务层既有转换函数产生后传入仓储。`bond-cycle-batch-db.test.js` 在独立临时 PostgreSQL 库对两张周期事实表及行情缓存执行多行写入和重复更新，验证实际值；全量 277 通过、0 失败、0 跳过。尚需把周期子阶段失败和补漏结果纳入可查询的任务完成证据；当前主任务仍可能吞掉其他周期异常，该治理缺口未宣称修复。

生产需发布后按原 Runner 和限定目标日恢复周期事实、估值与安全评分，并核验各自日期、范围及质量证据。尚未进行生产写入、告警处置或线上专项验收；不得直接清告警或用新的日期替代旧日恢复。
