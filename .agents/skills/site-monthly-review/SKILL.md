# 存在小站月度复盘

适用：月度项目复盘、架构与数据健康检查、维护趋势回顾。
不适用：日常开发、单次任务收尾（用 site-doc-handoff）、发布（用 site-release-closeout）。

## 前置

1. 明确月份与截止时间，以及业务基线和文档基线提交。
2. 读 `docs/知识库公共规则.md` 第 11 节（11.4—11.6）作为审查框架，并读上月复盘。

## 流程

1. **收集证据**：按上海时区统计当月 Git 提交、部署回执、任务运行记录与事故文档。指标只用于定位线索，不做绩效结论。
2. **架构与数据审查**：核对分层现状、重复或高耦合代码、数据缺口分类（可补 / 已补有效 / 合法等待 / 权限阻塞）。
3. **复查上月行动**：逐条判定上次措施是「未实施 / 待验证 / 有效 / 无效复发 / 条件变化」，不接受月月复制同一条建议。
4. **同口径对比**：只有口径一致的数据才做趋势；缺上月同口径数据就写「未知」，不编趋势、不编费用和用户量。
5. **产出**：约一页健康摘要 + 重点分析 + 下月 3—5 项优先行动（每项带验收方式），其余待办留在原任务卡。
6. **原位同步**：结论写回 `docs/项目月度复盘_YYYYMM.md` 和知识索引对应摘要，跑 `npm.cmd run check:knowledge`。

## 必须交代

- 每项结论的证据出处；无法确认的标未验，并写明还差什么才能确认；
- 上次措施的实际效果，以及本次建议与上次的关系（延续 / 转向 / 停止）；
- 高风险项（例如无法确认存在独立可恢复的备份）升级为 P1，不压成常规建议。

## 边界

- 不为写月报擅自跑生产演练、高负载测试或大范围重构。
- 自动任务只做读取、复盘和准备文档，不能凭定时触发取得生产写入权限。
- 没有创建自动任务就不写「已自动执行」。
