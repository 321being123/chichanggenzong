# 可转债周期功能整改方案

> 状态：待整改  
> 编写日期：2026-07-27  
> 适用项目：`portfolio-server`  
> 对应方案：`可转债周期功能_研发方案.md`  
> 整改原则：不改变已确认的业务公式，只修复数据链路、页面展示和验收可靠性

## 1. 验收结论

当前版本暂不具备上线条件。

动态权重、综合估值、周期区间等核心业务逻辑已基本实现，但历史回填没有取得转股价值和转股溢价率，导致周期结果表为空。同时还存在回填日期永久跳过、事务相互影响、曲线字段不匹配和测试假通过等问题。

当前连接的本地数据库验收结果：

| 项目 | 结果 |
|---|---:|
| 原始事实记录 | 748,362 条 |
| 覆盖交易日 | 2,320 天 |
| 日期范围 | 2017-01-03～2026-07-24 |
| 周期结果 | 0 条 |
| 有效转股价值记录 | 0 条 |
| 有效转股溢价率记录 | 0 条 |
| 回填游标 | 2026-07-24 |

因此，当前页面只能显示“尚未完成首次历史回填，暂无周期数据”。

## 2. 整改边界

本次只整改以下内容：

1. 修复历史数据获取和回填；
2. 修复回填游标与失败重试；
3. 隔离每日同步和周期计算事务；
4. 修复前端曲线字段映射；
5. 修复自动化测试；
6. 修正过期状态、历史分位和版本隔离问题；
7. 重新生成历史周期数据并完成验收。

本次不得修改：

- 价格中位数和溢价率中位数的总体框架；
- `100 元及以下 20%，100～135 元逐步提升，135 元及以上 55%封顶`的权重规则；
- 综合估值公式；
- 周期区间划分；
- 可转债安全性原有功能和接口；
- 已确认的页面结构。

## 3. 必须整改项

### 3.1 P0：修复历史回填字段

涉及文件：

- `server/scripts/backfillConvertibleBondCycle.js`
- `server/services/convertibleBondAnalysis.js`

问题：

回填脚本引用了未导出的 `DAILY_FIELDS`，实际请求没有明确传入周期计算需要的字段。Tushare 默认不返回 `cb_value`、`cb_over_rate`等字段，因此已写入的历史记录只有价格，没有转股价值和溢价率。

整改要求：

1. 将可转债日线请求字段定义为明确、可复用的常量；
2. 确保回填和每日增量同步使用同一份字段清单；
3. 字段至少包含：
   - `ts_code`
   - `trade_date`
   - `close`
   - `cb_value`
   - `cb_over_rate`
   - `bond_value`
   - `bond_over_rate`
4. 请求完成后校验必要字段是否真实存在；
5. 当价格有数据但溢价率字段全部缺失时，必须判定为数据异常，禁止将该日标记为成功。

### 3.2 P0：修复回填游标和日期缺口

涉及文件：

- `server/scripts/backfillConvertibleBondCycle.js`
- `server/services/convertibleBondCycleService.js`

问题：

某个交易日为空或失败后，脚本仍继续处理后面的日期。后续日期成功时，游标会越过失败日期，导致缺失日期以后无法自动重试。

整改要求：

1. 游标只能推进到“连续成功”的最后一个交易日；
2. 单日请求失败、字段缺失或质量校验不通过时，不得推进该日及之后的游标；
3. 记录失败日期和失败原因；
4. 再次执行时必须从最早失败日期继续；
5. 增加缺失日期扫描，防止游标正常但中间仍存在空洞；
6. 重复执行同一日期不得产生重复记录。

### 3.3 P1：隔离每日同步事务

涉及文件：

- `server/services/convertibleBondAnalysis.js`

问题：

周期计算目前处于原有可转债同步事务中。周期 SQL 一旦失败，PostgreSQL 会把整个事务标记为失败，即使代码捕获异常，也可能导致原有同步数据一起回滚。

整改要求：

1. 原有可转债同步先独立完成并提交；
2. 周期计算在新的独立事务中执行；
3. 周期计算失败只能影响周期数据，不能影响原有可转债数据；
4. 日志必须分别记录主同步和周期计算的成功或失败状态。

### 3.4 P1：修复历史曲线字段映射

涉及文件：

- `public/js/bond-cycle.js`
- `server/routes/bondCycle.js`

问题：

前端读取字段为 `percentile`、`composite`，接口返回字段为 `rolling_percentile`、`composite_value`，导致“周期分位”和“综合估值”曲线无法显示。

整改要求：

1. 在前端建立明确的指标与接口字段映射；
2. 至少验证以下四条曲线均有有效数据：
   - 价格中位数；
   - 转股溢价率中位数；
   - 综合估值；
   - 周期分位；
3. 无数据时展示明确的空状态，不能绘制错误的零值曲线；
4. 自动化测试必须使用一组真实结构的接口数据验证曲线取值。

### 3.5 P1：修复服务测试假通过

涉及文件：

- `server/test/convertibleBondCycleService.test.js`

问题：

异步测试没有等待执行完成，汇总结果可能先显示全部通过，实际断言随后才执行。

整改要求：

1. 所有异步检查必须使用 `await`或统一交给 `Promise.all`；
2. 断言全部完成后才能输出汇总；
3. 任意断言失败时，进程必须返回非零退出码；
4. 新增一个故意失败的测试验证退出码，验证完成后删除该临时用例。

## 4. 建议同步整改项

### 4.1 修正数据过期判断

当前按星期推算最近交易日，会在交易日收盘前和法定节假日误报过期。

整改要求：

- 使用交易日历判断最近一个应有数据的交易日；
- 交易日数据发布时间之前允许展示上一交易日，不标记异常；
- 接口同时返回“最新数据日”和“预期数据日”，便于定位问题。

### 4.2 修正历史分位的相等值统计

当前相等值数量没有包含当天自身，全部数据相等时结果约为 49.8%，理论值应为 50%。

整改要求：

```text
历史分位 =
（小于当前值的数量 + 0.5 × 等于当前值的数量）
÷ 窗口有效样本数 × 100
```

窗口包含当前交易日，相等值数量也必须包含当天自身。

### 4.3 补齐版本隔离

涉及历史查询、最新结果查询和滚动分位计算时，必须同时使用：

- `formula_version`
- `universe_version`

不同样本池版本的数据不得混算，也不得在同一天重复返回。

## 5. 现有历史数据修复

由于现有事实表已经写入大量不完整记录，而且游标已经到最新日期，仅修复代码后重新运行不能解决问题。

修复步骤：

1. 修复请求字段和游标逻辑；
2. 操作前备份周期相关表；
3. 通过受控脚本把历史日期重新加入待处理范围；
4. 按交易日升序重新请求并覆盖缺失的转股价值、溢价率字段；
5. 每日通过质量检查后，再生成当日周期结果；
6. 按时间顺序重新计算滚动历史分位；
7. 对历史日期做连续性检查；
8. 确认全部完成后，再把游标推进到最后一个连续成功交易日。

不得只修改游标而保留现有不完整事实数据。

## 6. 自动化测试要求

必须补充以下测试：

| 场景 | 预期结果 |
|---|---|
| 请求字段完整 | 能取得价格、转股价值和转股溢价率 |
| 必要字段全部缺失 | 当日失败且游标不推进 |
| 中间某日请求失败 | 后续运行会从失败日期重试 |
| 同一日期重复回填 | 不产生重复记录 |
| 周期计算 SQL 失败 | 原有可转债同步仍正常提交 |
| 综合估值曲线 | 正确读取 `composite_value` |
| 周期分位曲线 | 正确读取 `rolling_percentile` |
| 全部历史值相等 | 历史分位为 50.0% |
| 两个样本池版本并存 | 查询结果不混合版本 |
| 节假日或盘中 | 不误报数据过期 |

## 7. 最终验收标准

以下条件全部满足后，整改才算完成：

- [ ] 历史事实数据中存在有效的转股价值和转股溢价率；
- [ ] 有效溢价率覆盖率满足研发方案要求；
- [ ] 周期结果表不为空；
- [ ] 历史结果覆盖全部具备合格数据的交易日；
- [ ] 不存在被游标越过的失败日期或中间空洞；
- [ ] 最新周期日期与最近应有数据的交易日一致；
- [ ] 页面能够显示当前周期卡片；
- [ ] 四条历史曲线均能正确切换和展示；
- [ ] 可转债安全性原有功能不受影响；
- [ ] 周期任务失败不会回滚原有同步；
- [ ] 所有异步测试真正执行后再汇总；
- [ ] 全量自动化测试通过；
- [ ] 抽查低价、中价、高价历史日期，权重分别符合 20%～55%的规则；
- [ ] 页面和接口中的公式版本、样本池版本保持一致。

## 8. 整改优先顺序

1. 修复字段清单；
2. 修复回填游标和失败重试；
3. 隔离数据库事务；
4. 修复前端字段映射；
5. 修复测试框架；
6. 修正分位、过期判断和版本隔离；
7. 重新回填历史数据；
8. 执行全量测试和数据库验收；
9. 验收通过后再上线。
