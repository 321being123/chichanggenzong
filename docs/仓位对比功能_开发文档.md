> 功能入口：持仓管理 → 持仓

## 1. 功能背景

不同账户目前只能分别查看自己的持仓，缺少统一的标杆对比能力。新增“仓位对比”后，用户可以将自己的账户与公开或半公开的标杆账户进行比较，查看证券、仓位比例、资产类型和持仓细类的差异，并测算复制标杆仓位需要买入的证券股数。

本功能只做仓位展示、差异分析和模拟买入测算，不自动下单。

## 2. 本期目标与边界

### 2.1 本期目标

- 每个持仓账户可以独立设置为“公开仓位、半公开仓位、不公开”。
- 其他用户可以选择公开或半公开账户作为标杆账户。
- 对比双方证券持有情况、单只证券仓位比例、资产类型比例和持仓“细类”列比例。
- 根据用户自己的账户规模、当前持仓、可用资金和交易单位，计算可实际买入的证券股数。
- A 股买入股数按市场规则区分：主板每手 100 股、科创板最低 200 股（超出部分 1 股递增）。
- 港股必须查询具体证券的每手股数，不能统一使用 100 股。
- 在资金和交易单位约束下，使复制后的仓位比例误差尽可能小。

### 2.2 本期不做

- 不自动提交交易订单。
- 不提供一键跟单或持续自动调仓。
- 不比较历史仓位和历史收益。
- 不新增行业、风格、市值规模等自定义分类。
- 不提供卖出建议；超配证券只提示“当前已超配”。
- 不允许导出半公开账户的数量、市值或可用于反推其资产规模的数据。

## 3. 名词定义

| 名词 | 定义 |
|---|---|
| 我的账户 | 当前登录用户选择参与对比的本人账户 |
| 标杆账户 | 公开或半公开、可被其他用户选择对比的账户 |
| 资产类型 | 当前持仓数据中的 `type` 列 |
| 持仓细类 | 当前持仓数据中的 `subtype` 列，不是重新生成的行业或风格分类 |
| 仓位比例 | 证券折算为人民币后的市值 ÷ 账户总资产 |
| 每手股数 | 一笔整手买入所要求的证券数量；A 股主板为 100 股、科创板最低 200 股（超出部分 1 股递增），港股按证券查询 |
| 复制测算 | 在不卖出现有持仓的前提下，用指定可用资金买入，使仓位接近标杆账户 |

## 4. 公开状态与权限

### 4.1 公开状态

在“持仓管理 → 持仓”页面增加“仓位公开状态”控件，按当前账户保存：

| 状态值 | 页面名称 | 其他用户是否可发现 | 是否可对比 |
|---|---|---:|---:|
| `public` | 公开仓位 | 是 | 是 |
| `semi_public` | 半公开仓位 | 是 | 是 |
| `private` | 不公开 | 否 | 否 |

新账户和历史账户默认值必须为 `private`。

修改为公开或半公开时需要二次确认；修改为不公开时立即生效。

| 信息 | 公开仓位 | 半公开仓位 | 不公开 |
|---|---:|---:|---:|
| 账户公开名称 | 展示 | 展示 | 不展示 |
| 证券代码、名称 | 展示 | 展示 | 不展示 |
| 最新价格、涨跌幅 | 展示 | 展示 | 不展示 |
| 数量 | 展示 | 隐藏 | 不展示 |
| 市值 | 展示 | 隐藏 | 不展示 |
| 持仓比例 | 展示 | 展示 | 不展示 |
| 资产类型 `type` | 展示 | 展示 | 不展示 |
| 持仓细类 `subtype` | 展示 | 展示 | 不展示 |
| 今日盈亏等可反推数量的金额 | 展示 | 隐藏 | 不展示 |
| 账户总资产、现金金额 | 展示 | 隐藏 | 不展示 |
| 现金比例 | 展示 | 展示 | 不展示 |
| 持仓备注、内部 ID | 不展示 | 不展示 | 不展示 |

半公开接口必须在服务端删除数量、市值、盈亏和总资产等字段，不能只靠前端隐藏。

⚠️ **脱敏范围（2026-08-01 验收修复）**：半公开只隐藏**标杆账户**的数量、市值、盈亏和总资产；**用户自己账户**的这些字段是本人数据，必须保留展示。前端在公开仓位下展示标杆数量/市值列，半公开下不展示该两列但始终展示我的数量/市值列。

### 4.3 状态变更规则

- 标杆账户改为“不公开”后，立即从可对比列表移除。
- 已打开的对比页面再次请求时返回“该仓位已取消公开”，不得继续返回旧明细。
- 从“公开”改为“半公开”后，后续接口立即隐藏数量、市值和衍生金额。
- 删除账户后，其公开入口同时失效。

## 6. 对比口径

### 6.1 统一估值

双方仓位必须使用同一批最新有效行情进行估值，不能分别使用两个账户中保存时间不同的价格。

```text
A 股证券市值 = 最新价格 × 持有股数

港股证券人民币市值 = 最新港币价格 × 持有股数 × 港币兑人民币汇率

账户总资产 = 全部证券人民币市值 + 现金

证券仓位比例 = 证券人民币市值 ÷ 账户总资产
```

计算使用未四舍五入的数值，页面比例保留两位小数。行情或汇率缺失时保留上一份有效缓存并标记数据时间；完全没有有效值的证券不参与正式对比，并在页面列入异常提示。

⚠️ **统一口径（2026-08-01 验收修复②）**：双方代码必须**合并后一次批量拉行情**（`fetchTencentQuotes`），并使用**同一个汇率**（优先实时汇率 `fetchHkRate`，回退标杆/我的账户汇率），不得各自请求行情、各自用账户汇率。估值时间取同一批行情中最新时间戳。

### 6.2 证券合并规则

- 优先使用内部证券 ID 识别同一证券。
- 尚未关联内部证券 ID 时，使用“市场 + 标准化证券代码”识别。
- 同一账户中同一证券存在多条持仓时，先合并数量和市值，再计算比例。
- 已清仓或数量小于等于 0 的记录不参与当前仓位对比。

### 6.3 对比概览

展示：

- 仓位相似度；
- 双方共同持有证券数；
- 我未持有证券数；
- 仅我持有证券数；
- 最大资产类型差异；
- 最大持仓细类差异；
- 双方持仓更新时间和本次估值时间。

> 更新时间来源（2026-08-02 收尾修复）：我的/标杆的**持仓更新时间**取 `account_data.updated_at`（真实持仓保存时间，随保存更新），回退 `accounts.updated_at`；**不用** `position_visibility_updated_at`（那是公开状态修改时间，公开后再改持仓会显示旧时间）。本次估值时间为统一行情中最新时间戳，汇率时间为实时抓取时刻（回退账户汇率时取 `accounts.hk_rate_updated_at` 专用列，迁移 039）。

仓位相似度：

```text
仓位相似度 = max(0, 1 - 0.5 × Σ|我的证券占比 - 标杆证券占比|) × 100%
```

双方未持有的证券占比按 0 计算；现金作为单独项目参与相似度计算。

### 6.4 证券持仓对比

| 字段 | 说明 |
|---|---|
| 证券代码、名称 | 双方证券并集 |
| 持有状态 | 双方持有 / 我未持有 / 仅我持有 |
| 我的占比 | 我的证券市值占账户总资产比例 |
| 标杆占比 | 标杆证券市值占标杆账户总资产比例 |
| 占比差异 | 我的占比 - 标杆占比 |
| 我的数量、市值 | 始终展示 |
| 标杆数量、市值 | 仅公开仓位展示 |
| 类型、细类 | 使用持仓现有 `type`、`subtype` 字段 |

默认按“占比差异绝对值”从大到小排序。

### 6.5 资产类型对比

按持仓数据的 `type` 列分组汇总，现金按现有现金类型归类。

```text
资产类型占比 = 该 type 下全部证券市值之和 ÷ 账户总资产

类型占比差异 = 我的类型占比 - 标杆类型占比
```

展示字段：资产类型、我的占比、标杆占比、占比差异。

### 6.6 持仓细类对比

按持仓数据中现有的 `subtype`（页面“细类”列）分组比较，不新增行业、市场、风格等二次分类。

例如当前系统已有细类：沪市、深市、京市、港股、美股、可转债、信用债、基金/ETF、场外基金、现金。实际结果以双方持仓中保存的 `subtype` 值为准。

```text
细类市值 = 该 subtype 下全部证券市值之和

细类占比 = 细类市值 ÷ 账户总资产

细类占比差异 = 我的细类占比 - 标杆细类占比
```

如果一方没有某个细类，该方占比按 0% 计算。展示字段：持仓细类、我的占比、标杆占比、占比差异。

## 7. 模拟复制仓位

### 7.1 输入项

用户点击“模拟复制仓位”后输入：

- 计划用于复制的新增资金；
- 确认使用当前账户已有持仓作为计算基础。

本期只计算买入，不计算卖出。当前已超过标杆比例的证券建议买入股数为 0，并标记“当前已超配”。

### 7.2 理论目标

```text
复制后总资产 = 我的当前总资产 + 计划新增资金

单只证券目标市值 = 复制后总资产 × 标杆证券占比

理论买入金额 = max(0, 单只证券目标市值 - 我的当前证券市值)

理论买入股数 = 理论买入金额 ÷ 证券最新价格
```

港股证券计算股数时先使用港币价格；预计占用的人民币资金按本次统一汇率折算。

### 7.3 交易单位

#### A 股

A 股按市场区分交易单位规则，不能直接用理论金额除以价格后四舍五入为任意股数：

- **沪深主板 / 创业板**：每手 100 股，买入按 100 股整数倍计算：

```text
可买股数 ∈ {0, 100, 200, 300, ...}
```

- **科创板**（沪市 688 开头）：申报买入最低 200 股，超过 200 股的部分可以 1 股为单位递增（如 201、202 股），限价申报单笔不超过 10 万股；卖出时余额不足 200 股的一次性申报卖出：

```text
可买股数 ∈ {0, 200, 201, 202, 203, ...}
```

实现时须按证券代码前缀（688/689 等）区分科创板与主板，不能所有 A 股都按 100 股整数倍处理。

#### 港股

港股每只证券的每手股数由发行人确定，可能是 50、100、200、500 或其他数量，必须按证券代码查询；港交所也明确说明港股每手数量并不统一，应按具体证券查询。[港交所说明](https://www.hkex.com.hk/Global/Exchange/FAQ/Securities-Market/Trading/Securities-Market-Operations?sc_lang=en)

每手股数数据源确认：使用项目已接入的 **Tushare `hk_basic` 接口**（港股列表），其返回字段 `trade_unit` 即为该证券每手股数；Tushare 数据源自港交所证券资料，权威性有保障。一次请求可返回全部在交易港股，无需逐只查询。项目已有 TUSHARE_TOKEN（2000 积分权限），复用现有 Tushare 链路即可，不新增外部数据源。

```text
港股可买股数 ∈ {0, 每手股数, 2 × 每手股数, 3 × 每手股数, ...}
```

系统必须返回：

- 每手股数；
- 每手股数数据来源；
- 数据更新时间；
- 是否使用了历史有效缓存。

如果没有查询到可靠的每手股数，则该证券不生成建议股数，显示“未取得每手股数，暂无法测算”，禁止默认按 100 股处理。

### 7.4 最小误差计算

复制结果必须同时满足：

1. 所有建议股数符合对应证券的整手买入规则；
2. 预计买入总金额不超过用户输入的可用资金；
3. 不建议卖出已有证券；
4. 在可行买入组合中，使复制后的总仓位误差尽可能小；
5. 无法用于整手买入的剩余资金保留为现金。

总仓位误差：

```text
总仓位误差 = Σ|复制后各证券占比 - 标杆各证券占比|
             + |复制后现金占比 - 标杆现金占比|
```

推荐实现方式：

1. 先按理论买入股数计算每只证券相邻的可交易数量；
2. 从 0 股开始，以最小增量尝试买入——主板/创业板以一手（100 股）为增量，科创板在 200 股以内以一手（200 股）为增量、超过 200 股后以 1 股为增量，港股以对应每手股数为增量；
3. 每次优先加入能最大幅度降低总仓位误差且资金足够的一手；
4. 加入后重新计算全部证券和现金比例；
5. 没有任何可买的一手能继续降低误差时停止。

⚠️ **实现关键约束（2026-08-01 验收修复，必须遵守）**：

- **买入预算只含用户输入的新增资金**（`availableCash`），账户已有现金不用于买入；复制后现金占比 =（原现金 + 新增资金 − 已买入金额）÷ 新总资产，方向必须正确（买入花掉钱现金减少）。
- **增量扣款**：维护模拟账户（各证券人民币市值 + 现金），每轮只评估"再加一手"的增量金额，不能把累计建议股数当作本轮新增金额重复扣款。
- **港股汇率折算**：理论股数 = 人民币缺口 ÷（港币最新价 × 汇率）；每手人民币金额 = 每手股数 × 港币价 × 汇率。
- **运算优先级**：误差比较必须写成 `Math.abs((simValue[code] || 0) − 目标市值) / 新总资产`，减法两侧都要正确括号。

该计算必须在服务端完成，前端只负责输入和展示结果。

### 7.5 测算结果

| 字段 | 说明 |
|---|---|
| 证券代码、名称 | 标杆持有且本次需要补足的证券 |
| 市场 | A 股 / 港股等 |
| 标杆占比 | 目标仓位比例 |
| 我的当前股数 | 复制前持仓数量 |
| 理论买入股数 | 未考虑每手限制的理论值 |
| 每手股数 | 主板/创业板 A 股为 100，科创板为 200（按规则递增）；港股按证券查询 |
| 建议买入股数 | 满足交易单位后的实际股数 |
| 预计买入金额 | 建议股数 × 最新价格，港股同时展示港币及人民币折算值 |
| 复制后占比 | 买入后的预计仓位比例 |
| 占比误差 | 复制后占比 - 标杆占比 |
| 数据时间 | 行情、汇率、每手股数的更新时间 |
| 状态 | 建议买入 / 已超配 / 资金不足 / 缺少每手数据 / 缺少行情 |

页面底部汇总：预计使用资金、剩余现金、复制前总误差、复制后总误差和误差改善值。

页面固定提示：

> 本结果仅根据当前持仓比例、参考价格和交易单位进行模拟，不构成投资建议，也不会自动发起交易。实际成交价格和数量以交易结果为准。

## 8. 技术方案

### 8.1 现有能力复用

- 账户、持仓、现金继续使用现有 `accounts`、`positions` 和账户读取链路。
- 用户隔离继续使用 `username + account_name`；本人账户接口继续复用登录和账户归属校验。
- 当前行情统一通过 `server/services/market.js` 读取，复用其现有批量行情、腾讯行情和缓存回退链路；业务代码不直接读写某个行情源的缓存表，也不新增逐只行情请求链路。
- 持仓市值、汇率和比例口径与现有持仓页面保持一致。
- 页面继续使用当前原生 HTML、CSS、JavaScript 架构，不引入新前端框架。

### 8.2 数据库调整

#### accounts 表

新增字段：

```sql
position_visibility TEXT NOT NULL DEFAULT 'private',
position_visibility_updated_at TIMESTAMPTZ
```

增加命名约束和公开账户查询索引（`accounts` 表已存在，必须用 `ALTER TABLE` + `DO $migration$` 的幂等写法，参照 `server/db/migrations.js` 现有约束模式，不能直接写建表内联约束）：

```sql
DO $migration$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname='chk_accounts_position_visibility' AND conrelid='accounts'::regclass) THEN
    ALTER TABLE accounts ADD CONSTRAINT chk_accounts_position_visibility
      CHECK (position_visibility IN ('public', 'semi_public', 'private'));
  END IF;
END
$migration$;

CREATE INDEX IF NOT EXISTS idx_accounts_position_visibility
  ON accounts (position_visibility, position_visibility_updated_at DESC)
  WHERE position_visibility <> 'private';
```

历史账户通过字段默认值统一设为 `private`。每次修改公开状态时同时更新 `position_visibility_updated_at`。公开账户直接使用现有 `accounts.id` 作为对外接口标识，不向其他用户返回 `username`。

#### positions 表与证券主数据关联

当前 `positions` 仍以证券代码为主。为保证仓位对比和交易单位规则使用统一证券身份，兼容性新增：

```sql
instrument_id BIGINT
  REFERENCES core.instruments(instrument_id)
  ON DELETE SET NULL
```

并增加索引：

```sql
CREATE INDEX idx_positions_account_instrument
  ON positions (username, account_name, instrument_id)
  WHERE instrument_id IS NOT NULL;
```

迁移后按 `core.instruments.canonical_code` 和 `core.instrument_identifiers` 回填现有持仓的 `instrument_id`。未匹配记录继续保留原 `code`，写入 `ops.data_quality_issues`，不得因映射失败删除持仓。现有 `code` 字段继续保留，完成全量核对前不替换旧链路。

回填由 **迁移 037**（`037_backfill_position_instrument_ids`）执行：先 `canonical_code` 精确匹配，再去符号纯代码唯一匹配（多映射不覆盖防错配），未匹配写质量问题。港股持仓需先有 `core.instruments` 主档（由港股每手股数同步落库）才能回填，因此 `syncHkTradeRules()` 成功后会自动调用 `backfillPositionInstrumentIds()` 补偿；未关联的 LOF/ETF/退债等无主档标的保留 NULL 并记录质量问题，属正常。

⚠️ **必须同步修改 `server/db/accounts.js` 的 `saveAccountData`**：该函数目前是「先 DELETE 该账户全部持仓再批量 INSERT」，批量 INSERT 的列清单（`bulkInsert` 的 columns 数组）**不含 `instrument_id`**。若不修改，用户每次编辑保存持仓都会把回填的 `instrument_id` 全部清空为 NULL。需在批量写入的 buildParams 中按 `p.code` 关联（查询或映射）对应的 `instrument_id` 一并写入；映射不到时写 NULL（不报错），由后续回填/同步补偿。

#### 证券交易单位缓存

证券每手股数属于可随时间变化的市场交易规则，新增标准化事实表 `market.instrument_trade_rules`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `instrument_id` | bigint | 关联 `core.instruments.instrument_id` |
| `source_id` | smallint | 关联 `ops.data_sources.source_id` |
| `valid_from` | date | 规则生效日期 |
| `valid_to` | date | 规则失效日期；当前有效时为空 |
| `buy_lot_size_shares` | integer | 每手买入股数，单位为“股/手” |
| `source_updated_at` | timestamptz | 上游数据时间 |
| `raw_record_id` | bigint | 关联 `ops.raw_records.raw_record_id` |
| `ingested_at` | timestamptz | 系统入库时间 |

目标结构：

```sql
CREATE TABLE market.instrument_trade_rules (
  instrument_id BIGINT NOT NULL
    REFERENCES core.instruments(instrument_id) ON DELETE CASCADE,
  source_id SMALLINT NOT NULL
    REFERENCES ops.data_sources(source_id),
  valid_from DATE NOT NULL,
  valid_to DATE,
  buy_lot_size_shares INTEGER NOT NULL,
  source_updated_at TIMESTAMPTZ,
  raw_record_id BIGINT
    REFERENCES ops.raw_records(raw_record_id) ON DELETE SET NULL,
  ingested_at TIMESTAMPTZ NOT NULL DEFAULT now(),

  PRIMARY KEY (instrument_id, source_id, valid_from),

  CONSTRAINT chk_trade_rules_lot_size
    CHECK (buy_lot_size_shares > 0),

  CONSTRAINT chk_trade_rules_validity
    CHECK (valid_to IS NULL OR valid_to >= valid_from)
);

CREATE INDEX idx_trade_rules_lookup
  ON market.instrument_trade_rules
  (instrument_id, valid_from DESC, source_id);
```

读取时筛选 `valid_from <= 计算日期` 且 `valid_to` 为空或不早于计算日期，再按 `ops.data_sources.priority` 和 `valid_from` 选择权威、最新的有效规则。

A 股交易单位不写入此表：主板/创业板每手 100 股、科创板最低 200 股（超出 1 股递增）属市场规则，由 `tradeLot` 服务按市场规则返回（科创板按证券代码前缀 688/689 识别）；`market.instrument_trade_rules` 主要保存港股等按证券变化、需要追溯历史的交易单位规则。

#### 原始数据与同步记录

港股每手股数外部返回先写入标准数据架构的 `ops` 层：

```text
外部证券资料
→ ops.ingestion_runs
→ ops.raw_records
→ core.instruments / core.instrument_identifiers
→ market.instrument_trade_rules
→ 仓位复制测算
```

- 数据来源统一注册到 `ops.data_sources`；港股每手股数使用 Tushare `hk_basic`（`tushare` source_code 已存在，priority=10），`dataset_code` 用 `hk_basic`，不能在业务表保存自由文本来源。
- 原始完整响应写入 `ops.raw_records`，标准化交易单位表只保存正式字段和 `raw_record_id`。
- 同步进度写入 `ops.sync_cursors`，数据缺失、非法每手股数和证券映射失败写入 `ops.data_quality_issues`。
- 所有数据库变化通过新的版本化迁移实现，保持幂等；不得直接修改生产表。

## 9. 每手股数的数据规则

### 9.1 数据来源

- A 股：系统市场规则——主板/创业板每手 100 股，科创板（688/689 开头）最低 200 股、超出部分 1 股递增。
- 港股：通过 Tushare `hk_basic` 接口按证券代码查询，返回字段 `trade_unit` 即每手股数；Tushare 数据源自港交所证券资料，作为权威数据源，并在 `ops.data_sources` 注册（复用现有 `tushare` 来源，dataset_code=`hk_basic`）。
- 当前腾讯行情解析只验证名称、价格、涨跌幅和行情时间，不能从未验证的返回字段中猜测港股每手股数。

### 9.2 查询与缓存

- 首次全量同步：Tushare `hk_basic` 一次返回全部在交易港股（含 `trade_unit`），全部写入 `core.instruments` / `core.instrument_identifiers` 与 `market.instrument_trade_rules`；至少覆盖所有现有港股持仓和公开标杆账户中的港股证券。
- 正常测算只读取数据库中的 `market.instrument_trade_rules`，不能因打开、刷新或重复测算页面反复调用外部数据源。
- 缓存缺失时允许服务端执行一次受限的批量补取；补取成功后必须先落库再计算，禁止逐只无限重试。
- 每个交易日执行一次增量检查，更新新增证券和发生交易单位变化的证券，并保留必要的短重叠窗口处理更正与漏数。
- ⚠️ **规则写入（2026-08-01 验收修复②）**：每手股数**无变化时不新增记录**（避免每日空记录累积）；有变化时先关闭旧规则 `valid_to`（补生效前一日），再新增以 `valid_from` 开始的记录，不得覆盖历史。
- 原始记录按 `source_id + dataset_code + source_key + payload_hash` 去重；标准化记录按 `instrument_id + source_id + valid_from` 去重。
- 同步批次写入 `ops.ingestion_runs`，同步游标写入 `ops.sync_cursors`，页面不自行维护同步状态。
- 上游超时、空值、非法值或返回代码不匹配时，不覆盖上一份有效数据。
- 有历史有效值时可以返回并明确标记“使用历史缓存”；完全没有有效值时停止该证券的股数测算。
- 每手股数必须是正整数；证券代码和市场必须与请求一致。
- 每日增量发现缺口时，对缺失证券进行一次定点补取；仍失败则记录 `ops.data_quality_issues`，等待下个同步周期，不无限重试。

### 9.3 变更处理

港股可能因拆股、合股或发行人调整而改变每手股数。新规则生效时，为上一条当前有效记录补齐 `valid_to`，再新增一条以 `valid_from` 开始的记录；不得直接覆盖历史记录。测算按计算日期读取当时有效的规则。

⚠️ **valid_to 取值（2026-08-02 收尾修复）**：旧规则的 `valid_to` 必须设置为**新规则生效日前一天**（而非生效当天），否则新规则生效当天两条规则同时满足 `valid_from <= day <= valid_to`，造成"当天两条规则同时有效"。

⚠️ **同日变更与时区（2026-08-02 修复）**：同一天内首次同步后若每手股数再次变化，应直接 **UPDATE 当天记录**（不关闭旧规则、不新增），否则 `valid_to=昨天 < valid_from=今天` 违反 `chk_trade_rules_validity` 导致同步失败。`valid_from` 是 timestamptz，与东八区日期字符串比较必须先用 `to_char(valid_from AT TIME ZONE 'Asia/Shanghai','YYYY-MM-DD')` 转换（服务器为 UTC 时区时直接字符串比较会把当天记录误判为历史，触发上述约束失败）。单条规则写入逻辑收敛在 `tradeLot.upsertTradeRule`（生产与测试共用）。

## 10. 安全与隐私

- 所有对比接口必须登录。
- 读取本人账户时必须校验账户归属。
- 读取标杆账户时每次都要校验当前公开状态，不能依赖前端传入状态。
- **计算返回前必须再次校验标杆公开状态**（文档 11：计算过程中标杆改为不公开时丢弃结果，不得返回旧明细）——compare 和 replicate 均在响应前复核。
- ⚠️ **竞态脱敏（2026-08-01 验收修复②）**：返回前复核后，脱敏判断必须使用**复核时拿到的最新 visibility**（若计算期间 public→semi_public，也要按半公开隐藏标杆数量/市值），不能继续用计算前的状态。
- ⚠️ **状态标签一致（2026-08-02 收尾修复）**：响应中的公开状态字段（`benchmarkAccount.visibility` / `benchmarkVisibility`）也必须同步为复核时的最新值——否则数据已脱敏但标签仍显示"公开仓位"，前后矛盾。
- 半公开脱敏在服务端完成，响应中不能出现隐藏字段或可直接反推隐藏字段的金额。
- 标杆列表和对比接口不返回用户名、持仓备注、数据库内部持仓 ID。
- 禁止通过修改 `benchmarkAccountId` 读取不公开账户。
- 对比和测算接口增加限频，避免批量枚举账户和反复触发行情查询。
- 服务日志不记录完整公开持仓响应。

## 11. 异常处理

| 场景 | 处理 |
|---|---|
| 标杆账户已取消公开 | 返回 404 或业务错误“该仓位已取消公开” |
| 我的账户不存在 | 返回 404 |
| 越权读取本人账户 | 返回 403 |
| 双方都没有持仓和现金 | 显示无可对比资产 |
| 某证券缺少行情 | 不生成该证券正式比例和买入股数，单独提示 |
| 港股缺少每手股数 | 不建议股数，不使用默认值 |
| 可用资金不足一手 | 建议买入 0 股，状态为“资金不足一手” |
| 停牌或最新价格无效 | 使用最后有效缓存并标记时间；无缓存则停止测算 |
| 汇率缺失 | 港股不参与金额和股数测算，提示缺少汇率 |
| 公开状态在计算中变更 | 返回前再次校验；已不公开则丢弃结果 |

## 12. 测试要求

### 12.1 权限测试

- 默认账户为不公开。
- 本人可以修改自己账户的公开状态，不能修改他人账户。
- 不公开账户不会出现在标杆列表。
- 修改接口参数不能读取不公开账户。
- 半公开响应中不存在数量、市值、总资产、盈亏等敏感字段。
- 半公开结果无法通过其他返回金额直接反推标杆数量或总资产。

### 12.2 对比计算测试

- 双方共同持有、我未持有、仅我持有判断正确。
- 相同证券多条持仓能正确合并。
- A 股、港股和现金的市值、汇率及比例计算正确。
- `type` 按资产类型正确聚合。
- `subtype` 严格按现有“细类”列正确聚合。
- 一方缺少类型或细类时占比按 0 计算。
- 相似度范围始终在 0%～100%。

### 12.3 股数测算测试

- 主板/创业板所有建议买入数量都是 100 的整数倍；科创板建议数量 ≥200 且 200 以上按 1 股递增（如 201、202），并正确识别 688/689 前缀。
- 理论买入 260 股时会比较相邻整手方案并选择误差更小且资金可行的结果。
- 港股 50、100、200、500 股一手的证券分别返回正确整数倍。
- 港股缺少每手数据时不按 100 股兜底。
- 全部建议买入金额不超过可用资金。
- 剩余资金正确计入现金比例。
- 已超配证券建议买入 0 股。
- 加入一手会扩大整体误差时停止继续买入。
- 上游查询失败不会覆盖历史有效的每手股数。

### 12.4 数据架构测试

- 新迁移首次执行成功，重复启动不会重复建表或破坏现有数据。
- 历史账户的 `position_visibility` 全部默认为 `private`。
- 现有持仓能按证券主数据回填 `instrument_id`；未匹配持仓保留原数据并产生质量记录。
- `market.instrument_trade_rules` 只能写入有效的证券、来源、日期和正整数每手股数。
- 同一来源、证券和生效日期不能重复写入。
- 新规则写入后历史规则仍可按日期查询。
- 原始记录、同步批次、同步游标和标准化交易单位记录可以相互追溯。
- 空值、非法值和失败批次不会覆盖上一份有效交易单位规则。
- ⚠️ **测试必须隔离（2026-08-02 阻断修复）**：任何会写 `market.instrument_trade_rules` / `positions` / `core.instruments` 的用例必须①使用**专用测试证券**（如 99998.HK，绝不选真实证券）②**事务包裹并最终 ROLLBACK**，验证回滚后无残留；涉及 `backfillPositionInstrumentIds` 的用例须清理可能产生的 `ops.data_quality_issues`。禁止在测试中 DELETE 真实证券的规则。

### 12.5 回归测试

- 现有持仓新增、编辑、删除、导入、导出和刷新不受影响。
- 原有账户切换、用户隔离、净值和收益计算不受影响。
- 原有行情批量刷新不产生 N+1 请求。

## 13. 验收标准

满足以下条件视为功能完成：

1. 每个账户可以独立设置三种公开状态，历史账户默认不公开。
2. 其他用户只能发现公开或半公开账户。
3. 公开账户能展示当前持仓表中的完整对比信息；半公开账户不返回数量、市值、总资产及其衍生金额。
4. 对比结果准确展示证券有无、双方仓位比例和差异。
5. 资产类型对比使用 `type` 列，持仓细类对比严格使用 `subtype` 列。
6. 复制测算输出实际可交易股数，不只输出金额。
7. 主板/创业板 A 股建议股数为 100 的整数倍；科创板 ≥200 股且超出部分 1 股递增。
8. 港股按具体证券查询每手股数；查询不到时明确停止该证券测算，不使用默认值。
9. 建议买入总金额不超过可用资金，且复制后总仓位误差小于或等于复制前。
10. 不自动下单，不泄露半公开或不公开账户的信息。
11. 账户公开状态位于 `public.accounts`，交易单位规则位于 `market`，证券和来源分别关联 `core.instruments`、`ops.data_sources`，原始数据可通过 `ops.raw_records` 追溯。
